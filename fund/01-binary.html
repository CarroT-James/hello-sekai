第 1 课 进制与编码

预计 30 分钟·约 5,707 字·计算机基础

数小棒的时候，数到十你就捆成一捆，于是有了个位和十位。这就是进位制：满一个数就往上进一位。

电脑没有十根手指，它只有两种状态——通电和断电。所以它只能两根一捆。二进制不是电脑的怪癖，是它唯一拿得出手的计数方式。这一课要把「0 和 1 怎么变成你屏幕上的中文」这件事彻底说通。

1.1 二进制只是两根一捆#

十进制里，123 的意思是 1×100 + 2×10 + 3×1。每个位置的价值叫位权，从右往左依次是 1、10、100。

二进制把 10 换成 2，位权就变成 1、2、4、8、16、32……所以 1011 是 1×8 + 0×4 + 1×2 + 1×1 = 11。看到一串 0 和 1，你只要从右往左标上 1、2、4、8，把是 1 的那几位加起来就行。

十六进制是给人类用的省事写法。原因很简单：4 个二进制位刚好对应 1 个十六进制位，16 种组合对应 0 到 9 加 A 到 F。11111111 太长了，写成 FF 一眼就能记住。C 语言里用 0x 开头表示十六进制，用 0 开头表示八进制。

C
#include <stdio.h>

int main() {
    int n = 45;   /* 二进制 101101，十六进制 0x2D */

    printf("十进制：%d\n", n);
    printf("八进制：%o\n", n);
    printf("十六进制：%x\n", n);
    printf("十六进制大写：%X\n", n);
    printf("直接写十六进制常量：%d\n", 0x2D);

    return 0;
}
运行结果
十进制：45
八进制：55
十六进制：2d
十六进制大写：2D
直接写十六进制常量：45

%o 和 %x 只是换了个显示的进制，变量里存的还是那 45。最后一行是关键：0x2D 和 45 在编译器眼里是同一个数，写法不同而已。

想让程序把十进制打印成二进制，得自己写循环。C 没有 %b。

C
#include <stdio.h>

void print_binary(unsigned int n) {
    int i;
    int started = 0;

    for (i = 31; i >= 0; i--) {
        int bit = (n >> i) & 1;
        if (bit) {
            started = 1;
        }
        if (started) {
            printf("%d", bit);
        }
    }
    if (!started) {
        printf("0");
    }
    printf("\n");
}

int main() {
    print_binary(45);
    print_binary(0);
    print_binary(1024);
    return 0;
}
运行结果
101101
0
10000000000

两个运算符要认一下：>> 是右移，把整个二进制往右推 i 位；& 1 是取出最低位。(n >> i) & 1 的意思就是「第 i 位是 0 还是 1」。

started 这个标志是为了跳过前面的前导零。不加它，打印 45 会变成 26 个 0 再接 101101。而 0 本身如果没有这个兜底，会一位都不打印。

手算的办法更土但更快：除 2 取余，写完从下往上读。45 ÷ 2 = 22 余 1，22 ÷ 2 = 11 余 0，一直除到 0，把余数倒着念就是 101101。

1.2 一个字节装 256 个数#

8 个二进制位叫 1 个字节（byte）。8 位能表示 2^8 = 256 种组合，编号从 0 到 255。

那负数怎么办？这里要请出补码，它是新手第一个真正抽象的概念。

思路是：不新增符号位，而是让「加上某个数」等于「减去某个数」。-1 定义成 11111111，因为 11111111 + 00000001 进位溢出正好变成 00000000，也就是 0。于是减法不用单独做电路，加法器顺手就干了。当年我盯着这个转换看了半小时才想明白它为什么合理。

算一个数的补码：按位取反，再加 1。1 是 00000001，取反得 11111110，加 1 得 11111111。所以 -1 的字节是 FF。

C
#include <stdio.h>

int main() {
    signed char a = -1;
    unsigned char b = 255;

    printf("-1 的字节：%02X\n", (unsigned char)a);
    printf("255 的字节：%02X\n", b);
    printf("-1 + 1 = %d\n", a + 1);

    unsigned char c = 250;
    c = c + 10;
    printf("250 加 10 存进 unsigned char：%d\n", c);

    return 0;
}
运行结果
-1 的字节：FF
255 的字节：FF
-1 + 1 = 0
250 加 10 存进 unsigned char：4

同一个字节 FF，看成 signed char 是 -1，看成 unsigned char 是 255。字节本身没有正负，正负是你给它的解释。

最后一行是溢出：250 + 10 = 260，一个字节装不下，从 256 开始重新数，落回 4。无符号整数的溢出是明确的「取模」，有符号整数的溢出在 C 标准里是未定义行为——它不一定回绕，编译器有权按「不会溢出」来优化。这是 C 语言 第 0 章 里提过但很容易忘的细节。

各类型的字节数也顺手记一下，sizeof 能直接查：

C
#include <stdio.h>

int main() {
    printf("char %zu\n", sizeof(char));
    printf("short %zu\n", sizeof(short));
    printf("int %zu\n", sizeof(int));
    printf("long %zu\n", sizeof(long));
    printf("double %zu\n", sizeof(double));
    return 0;
}
运行结果
char 1
short 2
int 4
long 4
double 8

注意 int 是 4 字节、long 是 4 字节，这是 Windows 上的结果。换到 Linux，long 会变成 8 字节。同一份代码在不同系统上 sizeof(long) 不一样，这就是为什么可移植的代码里更爱用 int 和 long long。

1.3 ASCII：字符其实是编号#

计算机里没有字母，只有数字。'A' 在内存里就是 65。

1963 年定下的 ASCII 表用 7 位给 128 个字符编了号：控制字符（换行、响铃）占前 32 个，数字 0 到 9 是 48 到 57，大写字母 A 到 Z 是 65 到 90，小写字母 a 到 z 是 97 到 122。

这几个数值得背下来：'0' 是 48，'A' 是 65，'a' 是 97。大小写差 32，正好是二进制里第 6 位（值 32）的差别。所以「转小写」可以写成加 32。

C
#include <stdio.h>

int main() {
    char c = 'A';

    printf("%c 的编号是 %d\n", c, c);
    printf("加 32 变成 %c\n", c + 32);
    printf("'0' 的编号是 %d\n", '0');

    int d = '7' - '0';
    printf("字符 '7' 减 '0' 得到整数 %d\n", d);

    return 0;
}
运行结果
A 的编号是 65
加 32 变成 a
'0' 的编号是 48
字符 '7' 减 '0' 得到整数 7

'7' - '0' 这一招在解析数字时天天用。你从文件里读到的是一位一位的字符，想要真正的整数，就得减去 '0' 的编号 48。直接写 - 48 也行，但写 - '0' 别人一看就知道你想干什么。

▲常见错误

把 '0' 和 0 混为一谈。'0' 的值是 48，不是 0。判空字符要用 '\0'（值 0），判数字零要用 '0'。少写一对引号，if (c == 0) 就从「判断是不是字符零」变成了「判断是不是字符串结束」。

1.4 Unicode：给全世界每个字符编号#

ASCII 只有 128 个位置，英文够用，中文完全不够。汉字有好几万个，日文假名、阿拉伯文、emoji 也都得占位置。

Unicode 的做法是只编号，不管怎么存。它给全世界每个字符分配一个叫码点的数字，写成 U+XXXX 的形式。A 是 U+0041（就是 65），中 是 U+4E2D，你 是 U+4F60。

问题是：码点最大到 U+10FFFF，需要 21 个二进制位才装得下。如果统一用 4 个字节存每个字符，一篇纯英文文章的体积会翻四倍。于是有了编码方式——把码点翻译成字节的规则。

UTF-8 是最流行的那个。它的规则是变长：

码点范围占用字节首字节特征
U+0000 ~ U+007F10xxxxxxx
U+0080 ~ U+07FF2110xxxxx
U+0800 ~ U+FFFF31110xxxx
U+10000 ~ U+10FFFF411110xxx

好处有两个。第一，英文还是 1 个字节，和 ASCII 完全兼容，老程序读新文件不会炸。第二，看首字节就知道这个字符有几个字节，程序不用猜。

中 落在第三行，占 3 个字节。这 3 个字节是 E4 B8 AD。

C
#include <stdio.h>
#include <string.h>

int main() {
    char s[] = "\xE4\xB8\xAD";   /* 「中」的 UTF-8 编码 */
    int i;

    printf("字节数：%d\n", (int)strlen(s));
    for (i = 0; i < (int)strlen(s); i++) {
        printf("%02X ", (unsigned char)s[i]);
    }
    printf("\n");
    printf("数组本身占 %d 个字节\n", (int)sizeof(s));

    return 0;
}
运行结果
字节数：3
E4 B8 AD
数组本身占 4 个字节

这里有个很实用的结论：strlen 数的是字节，不是字。strlen("中") 是 3，strlen("中文") 是 6。你在 C 里想按「字数」截断中文，直接用 strlen 会截出半个字符，屏幕上就是一个问号或方块。

数组比字符串多 1 个字节，是末尾的 '\0'。前面说的 '0' 是 48，'\0' 是 0，两个东西，别混。

★中文占几个字节

GBK 里一个汉字固定 2 字节，UTF-8 里常用汉字大多 3 字节，生僻字和 emoji 要 4 字节。所以「这个文件多大」和「这段文字多少字」没有固定倍数关系，得看编码。同一个「中」，GBK 是 D6 D0，UTF-8 是 E4 B8 AD，都对，只是规则不同。

1.5 乱码到底怎么产生的#

乱码只有一个原因：存的时候用一套规则，读的时候用了另一套。

比如一个 UTF-8 的文件里存着 中，字节是 E4 B8 AD。你用一个以为是 GBK 的编辑器打开它，编辑器会把 E4 B8 当成一个 GBK 汉字，AD 再和下一个字节凑成另一个字。屏幕上就出现一对毫不相干的怪字。字节一个没丢，是翻译错了。

TEXT
「中」这个字
UTF-8 编码：E4 B8 AD   （3 个字节）
GBK   编码：D6 D0      （2 个字节）

用 GBK 去读 UTF-8 的字节：E4 B8 | AD ...
     E4 B8 在 GBK 里是另一个字，AD 被拆去和下一个字节凑对
     所以后面的字全部错位，整段花掉

第二种乱码是截断。程序只取了前 2 个字节去显示一个 3 字节的字，最后那个字节被扔掉，解码器发现字节数不对，就吐出一个 ？ 或者一个黑菱形。

第三种是根本没法解释。某些字节序列在任何编码里都不合法，解码器只能给一个替换字符。

▲常见错误

看到乱码就去改字体，改了半小时没用。乱码是编码问题，跟字体一点关系都没有。正确做法是先确认这份数据是谁用什么编码存的，再用同一种编码去读。Python 里 open(..., encoding="utf-8")，浏览器里看 Content-Type 的 charset。硬猜不算办法。

讲到这里，顺便解释一个很多人见过的怪现象：在 VC++ 里调试，屏幕上会出现一串「烫烫烫」。原因是调试版的编译器把没初始化的栈内存填成 0xCC，两个 0xCC 拼在一起是 0xCCCC，这个编号在 GBK 里正好是「烫」字。所以你看到「烫」就说明那个字符串压根没赋过值。现在你知道它不是玄学了。

1.6 这些知识什么时候用得上#

写业务代码的时候，你可能一整年都不用自己转进制。但下面这些场景天天遇到：

  • 报文和协议里的字段是十六进制，抓包看到的是 0x0A 0x0D，你得知道那是换行符
  • 位运算压状态：一个 int 存 32 个开关，比 32 个 bool 省地方
  • 处理文本时判断「这个字节是不是 UTF-8 的首字节」，看最高位是 0、110、1110 还是 11110
  • 排查乱码、大小端、文件头（PNG 开头是 89 50 4E 47）
◆小结
  • 进制就是「满几进一」：二进制满 2 进 1，十六进制满 16 进 1，4 个二进制位换 1 个十六进制位
  • 1 个字节 8 位，能装 256 个编号；同一个字节 FF，按有符号读是 -1，按无符号读是 255
  • 负数用补码表示：取反加一，这样减法就能用加法器做
  • 字符就是编号：'0' 是 48、'A' 是 65、'a' 是 97；Unicode 只编号，UTF-8 把编号变成 1 到 4 个字节，一个汉字通常 3 字节，strlen 数的是字节
  • 乱码只有一个原因：存和读用了不同的编码
✎练习
  1. 手算 0b110101、0x3F、255 的十进制值，再用 print_binary 验证，写一张三种进制对照表（至少 8 行）。
  2. 写一个函数 int count_one(unsigned int n)，用位运算数出一个无符号整数里有多少个 1。提示：n & (n - 1) 能消掉最低位的 1。
  3. 用 strlen 分别测 "hello"、"中"、"中文abc" 的字节数，再算一算每个字符串的「字符数」，解释两者的差。
  4. 把一个 .txt 文件分别另存为 UTF-8 和 GBK，用 C 程序按字节打印前 16 个十六进制值，对比两份输出，说出哪几个字节变了。
