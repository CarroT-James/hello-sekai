第 3 课 操作系统与进程

预计 32 分钟·约 4,868 字·计算机基础

你打开任务管理器，几十个进程在跑，每个都有 PID、内存占用、CPU 百分比。这些数字不是装饰，每一个背后都是操作系统正在维护的一份档案。

这一课要回答三个问题：进程到底是什么、线程和它差在哪、为什么每个程序都以为自己独占了一整块内存。

3.1 操作系统是那个中间人#

你的程序想读文件、想在屏幕上画字、想发网络包，这些事它一件都干不了——硬件只认电信号，而且不允许随便哪个程序直接指挥硬盘。

所以中间必须站一个角色：操作系统。它管四件事：

  • 进程管理：谁能用 CPU，用多久
  • 内存管理：谁的内存是哪几页，不许越界
  • 文件系统：把「一块盘」变成「一棵目录树」
  • 设备驱动：把「往某个端口写一个字节」翻译成「硬盘转起来」

你的程序要和它打交道，只能通过系统调用。printf 看起来是个普通函数，其实它最后会调到 write 这个系统调用，把数据交给内核，内核再交给终端。

这个界线很重要：用户程序运行在用户态，权限受限；内核运行在内核态，可以为所欲为。想干特权操作，就得「敲门」进内核，办完再回来。这个切换有成本，所以 printf 会攒一批再写，不是每输出一个字符就敲一次门。

3.2 进程：食堂开着的那个窗口#

先分清两个东西。程序是硬盘上的一个文件，死的；进程是它跑起来的样子，活的。这个文件怎么变成能跑的东西，第 2 课 一个程序是怎么跑起来的 已经拆过一遍。

用食堂打比方。菜谱是程序，写在本子上，谁都能看，但它不能吃。窗口是进程——窗口开了，有阿姨、有锅、有排着的队，这才开始产出。同一份菜谱可以同时开三个窗口，就像同一个 chrome.exe 可以在任务管理器里出现十几次。

操作系统给每个进程准备了一份进程控制块（PCB），里面记着：PID、父进程是谁、占哪些内存、打开了哪些文件、当前执行到哪条指令。任务管理器显示的就是这份档案的一部分。

PID 是进程的身份证号，系统分配，进程死了号就回收。父进程创建子进程，形成一棵树。你可以在任务管理器里看「父进程」这一列，会看到一棵很长的树。

在 Linux（或者你装的 WSL）里，看进程用 ps：

Shell
ps aux | head -n 5
运行结果
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1 167432 11204 ?        Ss   09:01   0:03 /sbin/init
root         2  0.0  0.0      0     0 ?        S    09:01   0:00 [kthreadd]
huxiang   1842  1.3  2.4 812344 98220 pts/0    Sl   09:02   0:41 node app.js
huxiang   2011  0.0  0.0  21512  5124 pts/0    R+   10:15   0:00 ps aux

PID 是进程号，%CPU 是占用率，RSS 是实际占的物理内存（单位 KB）。最后一行的 ps aux 就是你自己这条命令——它也是一个进程，跑完就消失。

STAT 那一列是状态：R 在跑，S 在睡（等事件），Z 是僵尸。看到 R+ 里的加号，意思是它在当前终端的前台。

3.3 进程怎么来的：fork#

Linux 创建进程的方式很特别：复制自己。

一个进程调用 fork()，内核就把它整个复制一份，父子两个进程从同一行代码继续往下跑。返回值用来区分身份：父进程拿到子进程的 PID，子进程拿到 0。

C
#include <stdio.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        printf("我是子进程，pid = %d，我爸是 %d\n", getpid(), getppid());
    } else {
        printf("我是父进程，pid = %d，我儿子是 %d\n", getpid(), pid);
    }

    printf("这行父子都会打印\n");
    return 0;
}

在 WSL 里 gcc fork_demo.c -o fork_demo 然后运行，两行输出的顺序不固定，取决于谁先被调度。父子都能打印最后那行，因为 fork 之后两边各有一份完整的程序副本。

return 0 之后，进程不会立刻消失，它先变成僵尸状态等父进程来收尸（读取退出码）。父进程要是先死了，子进程就被 PID 1 收养。这两个概念听着吓人，其实只是回收机制的两个分支。

★Windows 上的对应物

Windows 用 CreateProcess，一步到位地把「复制自己」和「换成另一个程序」合并了。所以你在 Windows 上看到 fork 会觉得很别扭——它不是通用接口。学 fork 的价值在于理解「进程是复制出来的独立个体」，而不是记住这个函数名。

3.4 进程 vs 线程：一个窗口几个阿姨#

进程有两个特点：有独立的地址空间，切换代价大。

如果你的程序要同时干三件事——下载文件、更新界面、写日志——开三个进程会很浪费：每个进程都有一整套内存映射、一套文件描述符，互相传数据还得走管道或者共享内存。

于是有了线程。线程是进程内部的执行流，同一个进程的多个线程共享地址空间。

还是食堂：进程是窗口，线程是窗口里的阿姨。三个阿姨共享同一锅菜、同一本账（全局变量、堆内存），但每个人手上有一把自己的勺子（栈和寄存器）。共享带来效率，也带来麻烦——两个人同时改账本，数就记乱了。

C
#include <stdio.h>
#include <pthread.h>

int counter = 0;

void *work(void *arg) {
    int i;
    for (i = 0; i < 100000; i++) {
        counter++;
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;

    pthread_create(&t1, NULL, work, NULL);
    pthread_create(&t2, NULL, work, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);

    printf("counter = %d\n", counter);
    return 0;
}

两个线程各加 10 万次，理论上应该是 200000。用 gcc race.c -o race -lpthread 编出来跑，你会看到：

运行结果
第一次运行：counter = 200000
第二次运行：counter = 187654
第三次运行：counter = 200000
第四次运行：counter = 196201

结果不稳定，这就是数据竞争。counter++ 在机器层面是三步：读出来、加一、写回去。两个线程的这三步交错执行，就会互相覆盖。修法是加锁（pthread_mutex_t），让同一时刻只有一个线程能改这个变量。

对照一下两种方案：

进程线程
地址空间各自独立共享同一份
创建开销大小
通信方式管道、共享内存、socket直接读写同一个变量
一个崩了通常不影响别人整个进程一起崩
适合隔离性要求高，比如浏览器每个标签页需要频繁共享数据，比如同一个界面的多个任务

浏览器用多进程，正是为了「一个标签页崩了别拖垮全部」。你写的小工具用多线程就够，因为共享数据方便。

3.5 虚拟内存：每个进程都有一张假地图#

这是操作系统最漂亮的一个设计。

如果每个进程直接用物理内存地址，会有两个灾难：一是两个程序可能写到同一块地方，互相踩；二是一个程序能用多少内存完全看运气。

所以操作系统给每个进程发一张假地图——虚拟地址空间。进程里所有地址都是这张地图上的门牌号，跟真实物理内存在哪完全无关。真要访问时，CPU 里的内存管理单元拿着页表把假地址翻译成真地址。

TEXT
进程 A 的假地图            物理内存（真实）           进程 B 的假地图
┌──────────────┐          ┌──────────────┐          ┌──────────────┐
│ 0x400000 代码 │ ───────► │ 第 12 页      │ ◄─────── │ 0x400000 代码 │
│ 0x600000 栈   │ ───────► │ 第 30 页      │          │ 0x600000 栈   │
└──────────────┘          │ 第 31 页      │ ◄─────── │ 0x600000 栈   │
                          │ 第 45 页      │ ────────►│ 堆            │
                          └──────────────┘          └──────────────┘

关键点在图上：A 和 B 的代码都从 0x400000 开始，但它们落在不同的物理页上。两个进程永远不会真的撞车，因为页表根本不指向同一块。

好处有三个。第一，隔离：A 越界访问，最多碰到自己的东西，或者触发段错误被内核干掉。第二，简化：每个程序都以为自己从零开始独占内存，写起来不用操心别人。第三，灵活：物理内存不够时，可以把不常用的页换到硬盘上（这就是虚拟内存的另一层含义），程序毫无感觉。

页的大小通常是 4 KB。所以「内存」是按页管理的，一个进程用 1 个字节，也至少占 1 页。

▲常见错误

别把「虚拟内存」和「硬盘上的页面文件」当成一回事。日常说的「虚拟内存不足」多半指页面文件不够用，而操作系统课本里的虚拟内存指的是「每个进程一张独立地址空间」这个机制。同一个词，两个意思，跟人聊天时容易鸡同鸭讲。

3.6 状态、调度和任务管理器#

进程不是一直在跑。它有三个基本状态：

  • 就绪：万事俱备，等 CPU
  • 运行：正在 CPU 上跑
  • 阻塞：等某个事件，比如等硬盘读完、等你敲键盘

就绪和运行之间由调度器决定谁上。因为 CPU 只有一个（或者几个核），而进程可能有几百个，所以每个进程只能拿到一小段时间，叫时间片，通常几毫秒。用完就换人，这叫上下文切换。

切换不是免费的：要保存当前进程的寄存器、换掉页表、换掉栈。切换太频繁，时间全花在搬家上，真正干活的时间就少了。

想直观看看，用 top 按 CPU 排序，或者：

Shell
sleep 300 &
jobs
ps -o pid,stat,cmd -p $!
kill %1

& 把命令扔到后台，jobs 列出当前终端管的后台任务，$! 是最后一个后台进程的 PID，kill 发信号让它退出。这些命令在第 4 课会系统讲，这里先混个脸熟。

任务管理器上那几个数字的含义：

显示项真实含义
CPU采样周期内该进程占用 CPU 时间的比例，不是瞬时值
内存常驻物理内存（工作集），不含已被换出的页
磁盘读写速率，卡顿常常是它在飙
句柄 / 文件描述符打开的文件、socket、窗口等资源的数量，只增不减就是泄漏

结束进程就是给它发一个信号。Linux 上是 kill，Windows 上是任务管理器那个按钮。区别在于 Linux 有十几种信号，kill -9 是强杀，进程来不及保存任何东西，能不用就别用。

◆小结
  • 操作系统管四件事：进程、内存、文件、设备，用户程序只能通过系统调用请它办事
  • 程序是死的文件，进程是活的实例；进程有独立地址空间，线程共享地址空间，共享就会带来数据竞争
  • 虚拟内存给每个进程一张独立的假地图，页表负责翻译，进程之间因此互不干扰
  • 进程在就绪、运行、阻塞之间切换，靠时间片轮转，切换本身有开销
  • 任务管理器的 CPU 百分比是采样值，内存看的是常驻物理页
✎练习
  1. 打开任务管理器，按内存排序，找出占得最多的三个进程，记下它们的 PID 和父进程名，猜一猜各自是干什么的。
  2. 在 WSL 里跑第 3.3 节的 fork 程序五次，观察父子两行输出的顺序，解释为什么顺序不固定。
  3. 把第 3.4 节的 counter++ 改成 counter = counter + 1，结果会变好吗？再试试只开一个线程，说说你观察到的差别。
  4. 写一个程序，先申请 1 MB 内存并填满，再申请 100 MB 但完全不碰，用 ps 看两次的 RSS 有什么不同，解释原因。
