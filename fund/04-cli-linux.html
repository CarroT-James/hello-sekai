第 4 课 命令行与 Linux 基础

预计 35 分钟·约 5,020 字·计算机基础

图形界面是一层壳，剥掉它，底下的东西其实是一棵树加上一堆命令。

服务器上没有桌面，只有一行提示符；你以后交作业、跑实验、连实验室的机器，早晚要面对它。这一课的命令不多，但每一个都要能不看笔记敲出来。

4.1 先弄一个能敲命令的地方#

Windows 上你有两个选择：WSL（Windows Subsystem for Linux）和 Git Bash。推荐 WSL，因为它是一个真的 Linux，装的软件都是真 Linux 软件。Git Bash 也不是没用，第 5 课 Git 里就要用它。

以管理员身份打开 PowerShell，跑一行 wsl --install，然后重启。重启之后，开始菜单里会多一个 Ubuntu。第一次启动要设用户名和密码，密码输入时不显示字符，这是正常的，别以为键盘坏了。

进去之后你看到的那个 $ 就是提示符。前面通常是 用户名@主机名:当前目录$。

命令的格式永远是三段：命令 选项 参数。比如 ls -l /home，ls 是命令，-l 是选项（一个短横线，缩写），/home 是参数。选项也可以写成 --all 这种长格式。忘了怎么用就加 --help，或者 man ls 翻手册，q 退出。

4.2 认路：pwd、ls、cd#

Linux 的文件系统是一棵树，根目录是 /。注意方向：Linux 用正斜杠 /，Windows 用反斜杠 \。写错方向是新手第一个小时的固定节目。

  • / 根目录
  • /home/你的用户名 你的家目录，~ 是它的简写
  • . 当前目录
  • .. 上一级目录

三个命令管「我在哪」和「有什么」：

Shell
pwd            # 我现在在哪个目录
ls             # 列出当前目录的内容
ls -l          # 详细列表：权限、大小、时间
ls -a          # 连隐藏文件一起列（. 开头的都是隐藏文件）
cd notes       # 进入 notes 目录
cd ..          # 回上一级
cd ~           # 直接回家目录
cd /           # 去根目录

pwd 是 print working directory，ls 是 list，cd 是 change directory。三个词记住了，就不会迷路。

ls -l 的输出长这样，七个字段从左往右：

运行结果
drwxr-xr-x 2 huxiang huxiang 4096 Nov 24 10:12 notes
-rw-r--r-- 1 huxiang huxiang  128 Nov 24 10:15 hello.c

第一个字符 d 表示目录，- 表示普通文件。接着九位是权限，后面讲。然后是硬链接数、属主、属组、字节大小、修改时间、文件名。

路径分两种。以 / 开头的叫绝对路径，从根开始写全；其他的叫相对路径，从当前位置算起。cd notes 是相对，cd /home/huxiang/notes 是绝对。写脚本时用绝对路径更稳，手动敲时用相对路径更短。

★Tab 补全能救命

敲一半按 Tab，shell 自动补全剩下的部分。按两下 Tab 会列出所有可能的候选。目录名有空格或者很长的时候，这一个键能省掉大量拼写错误。另外 Ctrl+C 是中断当前命令，Ctrl+D 是发送文件结束符（也能退出 shell），这两个键必须会。

4.3 建、删、移：mkdir、touch、cp、mv、rm#

Shell
mkdir lab            # 建一个目录
mkdir -p a/b/c       # 一次建多级，父目录不存在也自动建
touch notes.txt      # 建一个空文件（已存在则更新修改时间）
cp notes.txt copy.txt        # 复制文件
cp -r lab lab_backup         # 复制目录必须加 -r
mv notes.txt docs/           # 移动
mv old.txt new.txt           # 同一个目录里就是重命名
rm copy.txt                  # 删除文件
rm -r lab_backup             # 删除目录必须加 -r

touch 这个名字有点反直觉——它原本的用途是「碰一下文件，更新修改时间」，只是顺手能创建空文件。

cp 和 mv 是两条命令，但 mv 兼了重命名的活。Windows 里重命名是右键菜单，Linux 里就是 mv，没有单独的 rename 命令。

rm 要单独说。它没有回收站，删了就没了。rm -rf 是最危险的组合：-r 递归进子目录，-f 强制不询问。网上那些「删库跑路」的段子，一半来自这条命令。敲之前用 pwd 和 ls 确认位置，养成先看清楚再按回车的习惯。

▲常见错误

rm -rf / 会试图删根目录（现代系统会拦下来，但别试）。更常见的事故是 rm -rf * 在错误的目录里执行——本来想删 build/ 里的东西，结果在 ~ 下敲了。还有 rm -rf $DIR/ 这种写法，如果 $DIR 是空字符串，就变成了 rm -rf /。变量用之前先判断非空。

4.4 看内容、找东西：cat、head、tail、grep、find#

Shell
cat hello.c          # 整个打出来，短文件用
less hello.c         # 分页看长文件，空格翻页，q 退出
head -n 5 hello.c    # 前 5 行
tail -n 5 hello.c    # 后 5 行
tail -f app.log      # 持续输出新增内容，看日志必备
grep -n "printf" hello.c        # 查内容：-n 显示行号
grep -i "error" app.log         # -i 忽略大小写
grep -rn "TODO" .               # -r 递归整个目录
find . -name "*.c"              # 按文件名找
find . -name "*.c" -size +1k    # 再按大小筛：大于 1 KB

cat 只适合短文件。几百行的文件用 cat 会把屏幕刷满，往上翻都找不到开头，这时候用 less。

tail -f 里的 -f 是 follow，文件被追加内容时会实时显示。调试时开一个窗口跑它，另一个窗口跑程序，比反复打开文件高效得多。

grep 查内容，默认行为是打印匹配的整行。加 -c 只输出匹配的行数，加 -v 反过来输出不匹配的行，加 -r 递归整个目录。这三个选项足够应付九成场景。

find 的语法是 find 起点 条件 动作，不写动作就默认打印路径。它的条件可以叠加，越往后越窄。

还有一个新手容易卡住的地方：grep "关键词" 后面不跟文件名时，它不会去搜当前目录，而是去读标准输入，然后停在那儿等你在键盘上打字，看起来像死机。搜整个目录要写成 grep -rn "关键词" .，末尾那个点表示「从这里开始」，Ctrl+C 可以退出卡住的命令。

★为什么 grep 比 Ctrl+F 强

编辑器里搜一次只能搜一个文件。grep -rn 能在整个项目里搜，还能配合管道继续处理结果。你以后读别人的代码，第一件事往往就是 grep -rn "函数名" .，看它到底在哪儿被调用。

4.5 重定向与管道：把命令接起来#

每个命令默认有三个通道：标准输入（键盘）、标准输出（屏幕）、标准错误（也是屏幕）。

重定向改变它们去哪：

Shell
ls /nonexistent              # 直接在屏幕上报错
ls /nonexistent 2> err.log   # 把错误信息写进文件
cat err.log
ls > list.txt                # 标准输出写进文件（覆盖）
ls >> list.txt               # 追加
wc -l < list.txt             # 把文件当标准输入喂给命令

> 是覆盖，>> 是追加。这两个符号搞反，日志文件会被清空——我第一次部署时干过这事，日志一夜之间只剩最后一行。

2> 里的 2 指标准错误。有时候你只想看错误，就写 1> /dev/null 把正常输出扔掉；反过来 2> /dev/null 是扔掉错误。

管道 | 把前一个命令的输出直接变成后一个命令的输入，中间不落盘：

Shell
ls -l | grep ".c"                    # 只留含 .c 的行
grep "error" app.log | wc -l         # 数有多少行错误

printf "banana\napple\nbanana\n" > fruits.txt
sort fruits.txt | uniq -c | sort -rn # 统计并排序
运行结果
      2 banana
      1 apple

最后一条拆开看：sort 排序，uniq -c 数相邻重复行出现几次（所以必须先排序），sort -rn 按数字倒序。三步拼起来就是「词频统计」，这就是命令行的思路——每个命令只干一件小事，靠管道拼出复杂功能。

4.6 权限：那九位字母怎么读#

回到 ls -l 的第一列，-rw-r--r-- 一共十位。第一位是类型，后面九位分三组，分别是属主、属组、其他人的权限，每组三位 rwx：

  • r 读（read），数字 4
  • w 写（write），数字 2
  • x 执行（execute），数字 1

rwx 加起来是 7，rw- 是 6，r-- 是 4。所以 755 就是 rwxr-xr-x，644 就是 rw-r--r--。

改权限用 chmod，给数字就行：

Shell
chmod 644 notes.txt   # 属主可读写，其他人只读：普通文本文件的标准权限
chmod 755 run.sh      # 属主可读写执行，其他人可读可执行：脚本和目录的标准权限
chmod +x run.sh       # 只加执行位，等价于 u+x
ls -l run.sh

脚本跑不起来，报 Permission denied，九成是忘了加执行权限。反过来，chmod 777 是「所有人随便改」，只在临时调试时用，别留在正式环境里。

sudo 是「以管理员身份执行这一条命令」。改系统配置、装软件才需要它，改自己家目录里的文件不需要。看到教程让你 sudo 一个普通的 ls，那教程多半有问题。

4.7 ssh：连上远处的机器#

ssh 让你在本地终端里操作远程机器，敲的命令在对面执行，返回的结果显示在你这儿。

Shell
ssh yourname@192.168.1.20      # 连过去，换成你的用户名和地址
exit                            # 退出，回到本地
scp notes.md yourname@192.168.1.20:~/papers/   # 上传文件
scp yourname@192.168.1.20:~/result.txt .       # 下载文件

第一次连接会问 Are you sure you want to continue connecting，输 yes。这是让你确认对方的指纹，防止连到假服务器。

scp 的语法是 scp 源 目标，远程路径写成 用户名@主机:路径。冒号前面是主机，后面是路径，冒号不能丢。

想在远程机器上跑一个耗时很长的程序，又不想一直开着终端，就用 nohup 把它挂到后台：

Shell
nohup python train.py > train.log 2>&1 &

这行里每个部分都有用：nohup 让程序忽略挂断信号，> train.log 把输出存文件，2>&1 让错误也进同一个文件，末尾的 & 把它扔到后台。断开 ssh 之后程序继续跑。

◆小结
  • 命令行格式是「命令 选项 参数」；pwd 看位置，ls -l 看内容，cd 换目录，~ 是家目录，.. 是上一级
  • mkdir -p 建多级目录，cp -r 复制目录，mv 兼重命名，rm 没有回收站
  • grep 搜内容，find 搜文件名，-r 递归、-n 行号最常用
  • > 覆盖、>> 追加、2> 重定向错误，| 把命令串成流水线
  • 权限九位分三组，rwx 对应 4、2、1；ssh 登录远程，scp 传文件，nohup ... & 让程序在后台活下去

  2. 用 grep 找出 /etc 下所有含 root 的行，把结果写进 ~/root_lines.txt，再用 wc -l 数出有多少行。
  3. 写一个 hello.sh，内容是打印 Hello from script，用 chmod 让它能直接执行，然后分别用 ./hello.sh 和 bash hello.sh 运行，说说两者差异。
  4. 用 tail -f 盯着一个日志文件，另开一个终端往里追加几行，观察输出；再用 sort | uniq -c 统计这几行里每个词出现的次数。
