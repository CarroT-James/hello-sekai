第 7 课 计算机网络入门

预计 34 分钟·约 5,275 字·计算机基础

在浏览器里敲一个网址，按回车，页面出来了。这一秒钟里发生的事，够写满一本书。但核心流程只有四步，这一课把它们拆开。

拆开的好处很实际：以后网页打不开，你能判断是域名解析的问题、端口不通、还是服务器自己 500 了。这比反复刷新有用。

7.1 一次点击的四步#

你在地址栏输入 https://example.com/index.html，浏览器做的事是：

  1. DNS 解析：把 example.com 翻译成一个 IP 地址，比如 93.184.216.34
  2. 建立连接：和那个 IP 的 443 端口握手，建立一条可靠的通道
  3. 发请求：按 HTTP 格式写一段文本发过去，说「我要 /index.html」
  4. 收响应：服务器回一段文本，浏览器解析 HTML、下载图片、跑脚本、画到屏幕上

用快递打比方：DNS 是查地址，建立连接是打通电话确认对方在，HTTP 是你说「我要三号楼那份文件」，响应是他把文件递过来。后面反复来回（图片、样式、脚本）就像又寄了几趟。

7.2 IP 和端口：楼号与房间号#

IP 地址是网络上一台机器的编号，作用是「找到这台机器」。现在常见的是 IPv4，四段数字，比如 192.168.1.20。

几个特殊的要认识：

  • 127.0.0.1 是本机回环地址，永远指向你自己，也叫 localhost
  • 192.168.x.x、10.x.x.x 是局域网地址，只在内部有效，外面访问不到
  • 0.0.0.0 在服务器配置里表示「监听所有网卡」，不是某个具体地址

一个 IP 只定位到机器，一台机器上同时跑着浏览器、微信、游戏，数据怎么分给对应的程序？靠端口。

端口是 0 到 65535 的编号，每个联网的程序占一个或几个。常用端口记几个：

端口服务
22SSH
80HTTP
443HTTPS
3306MySQL
6379Redis
8000随手起的开发服务器（约定俗成）

所以「IP + 端口」才是完整地址，像「楼号 + 房间号」。只有楼号找不到人，只有房间号不知道去哪栋楼。

局域网里的机器怎么访问外网？靠路由器做 NAT：家里所有设备共用一个公网 IP，路由器记账，谁发的包回来还给谁。这就是为什么你查到的「我的 IP」和路由器管理页上的不一样。

7.3 DNS：互联网的通讯录#

人记不住 93.184.216.34，但记得住 example.com。DNS 就是那本通讯录，负责把域名翻译成 IP。

查一次看看：

Shell
ping -c 3 example.com      # Linux/macOS，Windows 去掉 -c 3
nslookup example.com       # 各平台都有，直接问 DNS 服务器
curl -i https://example.com  # 看响应头，不含正文

ping 的输出第一行会告诉你域名解析成了哪个 IP，后面是往返时间。nslookup 更直接，专门干这件事。这几条都在终端里敲，不熟的话看 第 4 课 命令行与 Linux 基础。

域名是从右往左读的：www.example.com 里 .com 是顶级域，example 是二级域，www 是主机名。解析的时候，本机先查缓存，再问配置的 DNS 服务器，服务器如果不知道就一层层往上问，最后把答案带回来，顺手缓存一段时间（这叫 TTL）。

这也是为什么改了域名解析不能立刻生效——旧的答案还在各地缓存里，得等它过期。

▲常见错误

「网站打不开」先分清是哪一层的问题。ping 域名不通但 ping 8.8.8.8 通，说明网络没断、是 DNS 有问题；两个都不通，是本地网络断了；ping 通但浏览器打不开，才轮到端口、防火墙或者服务本身。别一上来就重装浏览器。

7.4 HTTP：一段有格式的文本#

HTTP 的本质简单到让人失望：客户端发一段文本，服务器回一段文本。

请求长这样：

TEXT
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Accept: text/html,application/xhtml+xml
Connection: close

三段结构：第一行是请求行（方法、路径、版本），中间是请求头（一行一个 键: 值），空一行之后是请求体（GET 通常没有体，POST 才有）。

响应也一样：

TEXT
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 1256
Cache-Control: max-age=3600

<!DOCTYPE html>
<html lang="zh-CN">
<head><title>示例</title></head>
<body><h1>Hello</h1></body>
</html>

第一行是状态行：版本、状态码、短语。

方法里最常用的两个：GET 拿数据，参数挂在 URL 上；POST 提交数据，内容放在请求体里。区别不只是「看得见看不见」——GET 会被缓存、会进浏览器历史、长度有限制，所以密码和文件上传必须用 POST。

状态码是三个数字，第一位决定大类：

开头含义常见例子
2xx成功200 正常、201 已创建、204 无内容
3xx重定向301 永久搬家、302 临时、304 用缓存
4xx你的请求有问题400 格式错、401 没登录、403 没权限、404 不存在、429 太频繁
5xx服务器自己出错500 内部错误、502 网关错、503 不可用

看到 404 别再怀疑自己的网，那是服务器明确告诉你「这个路径没有东西」。看到 500 才是对方程序崩了。

7.5 Cookie：无状态的 HTTP 怎么记住你#

HTTP 有个特点：每个请求都是独立的，服务器不记得上一个请求是谁发的。这叫无状态。

那登录状态怎么保持？靠 Cookie。

流程是这样：你登录成功，服务器在响应头里加一句 Set-Cookie: sessionid=abc123; HttpOnly; Secure。浏览器把这一小段存下来，之后每次访问同一个域名，自动在请求头里带上 Cookie: sessionid=abc123。服务器拿着 abc123 去自己的表里查，就知道「这是刚才登录的那个人」。

属性作用
HttpOnly禁止 JavaScript 读取，防 XSS 偷 Cookie
Secure只在 HTTPS 下发送
Max-Age有效期，单位秒；不写就是关浏览器就失效
SameSite限制跨站携带，防 CSRF

Cookie 存在浏览器里，可以被用户看到和修改，所以绝不能把密码或者权限判断的依据直接放进去。真正的内容存在服务器端，Cookie 里只放一个随机的编号，这就是 Session。

食堂打饭的类比：Cookie 是你手里的取餐号小票，Session 是后厨那本记录本。小票丢了可以补，编号被人捡走就麻烦了——所以 HTTPS 必须上，下面讲。

7.6 HTTPS 在防什么#

HTTP 是明文。你发出的每一个字符，都经过你家路由器、运营商、路上的若干台机器。任何一环都能看到，也能改。

用校园网连一个不加密的 WiFi，抓包工具十秒就能看到你登录某个网站的用户名密码。这不是危言耸听，是 HTTP 的默认状态。

HTTPS 在 HTTP 下面垫了一层 TLS，解决三件事：

  • 加密：中间人看到的是一堆乱码，看不到内容
  • 完整性：内容被改过能发现，不会悄悄塞进一段广告脚本
  • 身份认证：确认对面真的是 example.com，不是伪造的服务器

第三点靠证书。服务器出示一张由 CA（证书颁发机构）签发的证书，浏览器验证签名链，确认这张证书确实是给这个域名的。中间人就算截获了流量，也拿不出一张合法的 example.com 证书。

加密本身用了两种算法配合：非对称加密慢，但能在不安全的通道上安全地交换一个密钥；换完之后用对称加密传数据，因为快。这个组合叫密钥交换，是本课唯一不需要你手算的部分。

地址栏那个锁图标就是这套东西的总开关。看到「不安全」还继续输密码，等于把密码写在明信片上寄出去。

★自签名证书

你自己起的 HTTPS 服务用自签名证书时，浏览器会拦下来说「证书不受信任」。这不是配置错了，而是你的证书没有 CA 签名，浏览器没法确认你是谁。开发时可以点「继续访问」，正式环境必须用真证书，现在有 Let's Encrypt 可以免费签。

7.7 在自己电脑上起一个服务器#

看了半天，不如自己发一次请求。Python 自带一个静态文件服务器，一行命令就能用：

Shell
mkdir web-demo && cd web-demo
printf "<h1>Hello Sekai</h1>\n" > index.html
python -m http.server 8000

终端会显示 Serving HTTP on 0.0.0.0 port 8000，然后卡在那儿——它在等请求，不是死机。

另开一个终端，敲：

Shell
curl -i http://127.0.0.1:8000/
运行结果
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.12.3
Date: Tue, 25 Nov 2026 06:12:44 GMT
Content-type: text/html
Content-Length: 21

<h1>Hello Sekai</h1>

这就是一个完整的 HTTP 响应。-i 让 curl 把响应头也打出来，不加只看正文。Content-Length: 21 是正文字节数，<h1>Hello Sekai</h1> 加一个换行正好 21。

也可以直接用 Python 发请求，把响应拆开看：

Python
import urllib.request

with urllib.request.urlopen("http://127.0.0.1:8000/") as resp:
    print("状态码：", resp.status)
    print("内容类型：", resp.headers["Content-Type"])
    print("正文：", resp.read().decode("utf-8").strip())
运行结果
状态码： 200
内容类型： text/html
正文： <h1>Hello Sekai</h1>

如果想把「HTTP 就是文本」这件事看得更透，用 socket 直接说话：

Python
import socket

s = socket.create_connection(("example.com", 80), timeout=5)
s.sendall(b"GET / HTTP/1.0\r\nHost: example.com\r\n\r\n")
data = s.recv(2048)
print(data.decode("utf-8", "ignore")[:300])
s.close()

这段需要联网。sendall 发出去的就是那几个字节，\r\n 是 HTTP 规定的换行（不是 \n），最后那个空行表示「请求头结束了」。服务器不会检查你用的是不是浏览器，只要格式对，它就照回。

最后一个实用技巧：按 F12 打开开发者工具，切到 Network 面板，刷新一次页面。你会看到每一个请求的地址、状态码、耗时、请求头和响应头。这个是查网络问题最直接的工具，比猜快得多。

◆小结
  • 一次访问四步：DNS 解析域名、建立连接、发 HTTP 请求、收响应并渲染
  • IP 定位机器，端口定位程序；127.0.0.1 是本机，常用端口 22、80、443
  • DNS 是互联网的通讯录，有缓存，所以改解析不会立刻生效
  • HTTP 就是有格式的文本：请求行、请求头、空行、请求体；状态码第一位分大类；它无状态，靠 Cookie 记住你
  • HTTPS 解决加密、完整性、身份认证，第三点靠 CA 签发的证书；排查按「解析、连通、端口、服务」四层走
✎练习
  1. 用 nslookup 查三个你常去的网站，记下它们的 IP，再用 ping 看往返时间，说说差别。
  2. 在自己电脑上起 python -m http.server，用 curl -i 请求一个不存在的路径，把状态码和响应头抄下来。
  3. 打开开发者工具 Network 面板刷新一个网页，找出耗时最长的一个请求，看它的请求头和响应头里有没有 Set-Cookie。
  4. 用 socket 手动发一个请求，把路径改成 /nope，观察返回的状态行和 Content-Length，解释 404 和 200 的响应体有什么不同。
