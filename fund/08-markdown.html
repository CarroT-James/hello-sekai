第 8 课 用 Markdown 与 LaTeX 写作业

预计 30 分钟·约 4,348 字·计算机基础

写实验报告最亏的事，是内容想了半小时，调格式调了两小时。标题字号不对、公式对不齐、代码粘进去变成一坨彩色文字。

Markdown 的思路相反：你只管写「这是标题」「这是公式」「这是代码」，排版交给渲染器。写完之后换成 PDF 还是网页，都不用重新排一遍。

这一课先讲语法，再给一份可以直接抄的作业模板。

8.1 为什么不用 Word#

三个理由，都跟「以后」有关。

第一，Markdown 是纯文本。用记事本就能打开，十年后还能打开。Word 的 .docx 换个版本可能就跑版。

第二，纯文本能被 Git 管。你改了一个字，git diff 只显示那一行，而 Word 是压缩包，Git 只能告诉你「这个文件变了」，看不出改了哪里。这一点在第 5 课 Git讲过，用在作业上格外舒服：每次交作业前提交一次，改坏了随时回去。

第三，公式快。敲 \frac{1}{2} 比在 Word 里点插入公式、找分数线、再点两次快得多，而且写多了可以盲打。

它也有缺点：图片和复杂排版不如 Word 灵活，交给老师的最终版一般要导出 PDF。所以常见流程是 Markdown 写、导出 PDF 交。要写正式论文（比如毕业设计），还是得用 LaTeX 或者学校给的 Word 模板，那是另一套东西。

工具上推荐两个组合。想省事就用 Typora，所见即所得，写完直接导出 PDF；想免费就用 VS Code 装 Markdown All in One 和 Markdown PDF 两个扩展，编辑、预览、导出都能对付。公式特别多、对排版要求又严的课程设计，直接上 Overleaf 用真 LaTeX 写，别在 Markdown 里硬扛。

8.2 十分钟语法速览#

常用的就这些，一张表看完：

想要的效果写法
一级标题# 标题
二级标题## 标题
加粗**文字**
斜体*文字*
行内代码反引号包住文字
无序列表- 项目
有序列表1. 项目
链接[显示文字](https://example.com)
引用> 一句话
分割线三个减号单独一行

标题的 # 后面要有一个空格，这是最常漏的一处。#标题 在多数渲染器里不会变成标题，只会原样显示。

来看一份完整的样例：

TEXT
# 实验一 数组与指针

**姓名**：张三　**学号**：2024301001

## 一、实验目的

- 掌握数组下标与指针的关系
- 会用指针遍历一维数组

## 二、实验原理

数组名在大多数场景下会退化为指向首元素的指针，因此 `a[i]` 与 `*(a + i)` 等价。

> 注意：数组名本身不是指针变量，不能被赋值。

## 三、实验步骤

1. 编写遍历函数
2. 用两种写法各遍历一次，比较输出
3. 记录结果

---

## 四、结论

渲染出来就是一份结构清楚的报告。注意几点：

  • 标题层级别跳。用了 ## 就直接接 ###，不要从 ## 跳到 ####
  • 段落之间空一行。不空行，两段会被合并成一段
  • 中文标点用全角，中英文之间留一个空格，读起来舒服很多

还有一个语法上面没展示：代码块。写法是三个反引号开头，紧跟语言名（c、python、bash），内容写完后另起一行，再用三个反引号收尾。语言名不能省——省了就没有语法高亮，代码会变成一片黑白。

8.3 表格、图片和路径#

表格用竖线分隔，第二行是关键的分隔行，--- 表示左对齐，:---: 表示居中：

TEXT
| 组别 | 样本数 | 平均值 |
| --- | ---: | :---: |
| 对照组 | 30 | 12.4 |
| 实验组 | 30 | 15.8 |

---: 是右对齐，数字列用它更整齐。表格的竖线数量必须每行一致，少一根就会渲染错乱——这是 Markdown 最容易翻车的地方，比公式还容易。

图片的写法是 ![说明](路径)，方括号里是加载失败时显示的替代文字。路径建议用相对路径，把图片放在 images/ 目录里，写 ![结果截图](images/result.png)。绝对路径 C:\Users\... 在你电脑上能显示，发给老师就全变成裂图。

▲常见错误

路径里的反斜杠 \ 要改成斜杠 /。Windows 复制路径默认给的是 images\result.png，Markdown 不认，得手动改成 images/result.png。另外文件名里有空格也要小心，最好一开始就别用空格，用下划线。

8.4 数学公式：两个美元符号之间#

行内公式用一对 $ 包住，跟在文字里；独立成行的公式用两对 $$，会居中单独占一行。

TEXT
质能方程 $E = mc^2$ 说明了质量与能量的关系。

当 $n$ 趋于无穷时：

$$
\lim_{n \to \infty} \frac{1}{n} = 0
$$

公式里最常用的几类，抄一遍就记住了：

TEXT
上标 $x^2$，下标 $a_1$，多个字符要加花括号 $x^{10}$、$a_{n+1}$

分数 $\frac{1}{2}$、$\frac{a+b}{c+d}$

根号 $\sqrt{x}$、$\sqrt[3]{8} = 2$

求和 $\sum_{i=1}^{n} i = \frac{n(n+1)}{2}$

积分 $\int_{0}^{1} x^2 \, dx = \frac{1}{3}$

希腊字母 $\alpha$ $\beta$ $\gamma$ $\Delta$ $\theta$ $\pi$

比较 $\le$ $\ge$ $\ne$ $\approx$ $\times$ $\cdot$

花括号是必须的：x^10 只会把 1 变成上标，输出 x¹0；必须写 x^{10} 才对。同理 a_{n+1}，不加花括号变成 a_n+1。

矩阵和分段函数稍微复杂，但也就多几行：

TEXT
$$
A = \begin{pmatrix}
a & b \\
c & d
\end{pmatrix},
\qquad
f(x) = \begin{cases}
x^2, & x \ge 0 \\
-x, & x < 0
\end{cases}
$$

\\ 是换行，& 是对齐点。pmatrix 和 cases 这两个环境来自 amsmath 宏包：在正式的 .tex 文件里要写 \usepackage{amsmath}，Markdown 的公式渲染器一般已经内置好了，直接写就能用。

多行推导要让等号对齐，用 aligned：

TEXT
$$
\begin{aligned}
(a+b)^2 &= a^2 + 2ab + b^2 \\
(a-b)^2 &= a^2 - 2ab + b^2
\end{aligned}
$$

&= 的意思是「以等号对齐」，每行只有一个 & 当对齐点。

正体字（比如单位、函数名）用 \text{} 或者 \mathrm{}，比如 $v = 10\ \text{m/s}$。变量名默认是斜体，单位用斜体在排版规范里是错的，答辩时被老师指出来挺尴尬。

▲常见错误

两个 $ 的数量必须成对。少一个，后面整段都会变成斜体，看起来像「格式全乱了」，其实就是一个符号没闭合。

另外 LaTeX 里 % 是注释符，公式里的百分号要写 \%。100% 会让 % 后面的整行内容消失，排查半天都想不到是这个原因。

★本站的公式显示成源码

本站不支持公式渲染，上面那些 $...$ 会原样显示。这是故意的——你要复制到自己编辑器里看效果。Typora、Obsidian、VS Code 的 Markdown Preview Enhanced 都支持公式预览，Overleaf 则是专门的 LaTeX 在线编辑器。

8.5 画一张流程图#

实验报告里常有「系统结构」「算法流程」，用工具截图当然也行，但改起来麻烦。用 Mermaid 写几行文本就能生成流程图，改一个字重新渲染，不用重新拖框。

TEXT
graph TD
    A[开始] --> B{输入合法?}
    B -->|是| C[计算平均值]
    B -->|否| D[提示错误]
    C --> E[输出结果]
    D --> E
    E --> F[结束]

graph TD 表示从上到下（top-down），LR 是从左到右。A[文字] 是方框，B{文字} 是菱形判断，--> 是箭头，|是| 写在箭头上当标签。

在支持 Mermaid 的编辑器里，代码块的语言名要写 mermaid；本站只支持 c、bash、python、text 四种标记，所以上面标成了 text。GitHub 的 README、Typora、Obsidian 都能直接渲染它。

不想学新语法也有别的选择：draw.io 拖框图，或者干脆用纸笔画完拍照。工具不是重点，能把流程说清楚才是。

8.6 交作业前的六项检查#

模板在这里，新建文件时把这几行抄过去，比每次从零开始快：

TEXT
# 实验名称

**姓名**：　　　**学号**：　　　**班级**：　　　**日期**：

## 一、实验目的

## 二、实验环境

- 操作系统：
- 编译器 / 解释器版本：
- 编辑器：

## 三、实验内容与代码

## 四、实验结果

## 五、问题与分析

## 六、结论

交之前过一遍这六条：

  1. 文件名规范。老师一般有要求，常见是 学号_姓名_实验一.pdf，别交 新建文档(3).md
  2. 导出 PDF。Markdown 编辑器都能导出，公式和代码高亮要检查一遍，别出现半截公式
  3. 代码块标了语言。实验报告里的代码要能看清，缩进别被吃掉
  4. 每个图有说明文字。图下面一行 图 1 系统流程图，正文里提到「如图 1 所示」
  5. 数值带单位，有效数字一致。平均值写 12.4 就全写一位小数，别一会儿 12.4 一会儿 12.43
  6. 交之前自己完整读一遍。十分钟能捡回好几个错别字
◆小结
  • Markdown 是纯文本，专注内容、能被 Git 管、公式写得快，最终导出 PDF 交
  • 标题的 # 后面必须有空格，段落之间必须空一行；表格竖线每行要一致，图片用相对路径且分隔符写 /
  • 行内公式 $...$，独立公式 $$...$$，多字符上下标一定要加花括号
  • 矩阵用 pmatrix，分段用 cases，等号对齐用 aligned，单位用 \text{}
  • 流程图用 Mermaid，几行文本换一张图，改起来比截图省事
✎练习
  1. 用 Markdown 重写你最近一次实验报告的第一节，包含一个标题、一个列表、一段引用和一个表格，导出 PDF 看排版。
  2. 写出下面三个公式的 LaTeX：二项式系数 C(n,k)、一元二次方程求根公式、样本标准差。
  3. 用 Mermaid 画一个「输入成绩 → 判断是否及格 → 输出等级」的流程图，包含至少一个菱形判断。
  4. 找一份你以前用 Word 写的作业，把其中一段连同公式改写成 Markdown，用 git diff 对比两次修改，说说哪种方式更容易看出改了什么。
