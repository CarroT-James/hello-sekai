第 3 章 预处理与多文件工程

预计 40 分钟·约 5,663 字·C 语言实战

单个 .c 文件写到几百行，你还能忍。写到两千行，找函数要滚半天，改一个地方牵动全身。多文件工程不是「高级技巧」，是代码变长后的必然结果。

这一章讲三件事：预处理在编译前做了什么、怎么把代码拆成多个文件、拆完怎么编译。最后给一个能直接用的 Makefile。

3.1 编译不是一步#

从 .c 到能双击的 exe，至少四步：

  • 预处理：处理 #include、#define、#if，纯文本操作，生成 .i 文件
  • 编译：把 C 代码翻译成汇编
  • 汇编：把汇编翻译成目标文件 .o
  • 链接：把多个 .o 和库拼成一个可执行文件

gcc 一个命令把这四步串起来了，所以平时感觉不到它们的存在。想知道预处理做了什么，跑一下 gcc -E main.c -o main.i，再打开 main.i：#include <stdio.h> 变成几百行声明，#define N 5 消失，所有 N 被替换成 5。没有魔法，就是文本替换。

记住两句话，后面的坑都能解释：#define 是文本替换，不是赋值；#include 是复制粘贴，不是导入模块。预处理器不懂 C 语法，它只认行首的 #。

3.2 #define：文本替换，不是变量#

C
#include <stdio.h>

#define PI 3.14159
#define N 5

int main(void) {
    double r = 2.0;
    int a[N];

    printf("面积 %.2f\n", PI * r * r);
    printf("数组长度 %d\n", (int)(sizeof(a) / sizeof(a[0])));
    return 0;
}
运行结果
面积 12.57
数组长度 5

编译器看到的是 printf("面积 %.2f\n", 3.14159 * r * r); 和 int a[5];。PI 和 N 在预处理阶段就消失了，调试器里也看不到它们。

三个注意点：

  • 宏没有类型，没有 C 那种块作用域，也不以分号结尾。写 #define N 10; 再写 int a[N];，展开后是 int a[10;];，编译直接报错。
  • 宏名习惯全大写，和普通变量区分开。
  • 能写 const double PI = 3.14159; 的时候优先用 const：它有类型、能进调试器、有作用域。宏适合两件事：条件编译开关，以及必须出现在常量表达式里的值，比如数组长度。

#undef 可以取消一个宏。gcc -E 可以看展开结果，宏写错时这是最快的排查手段。还有一点要有心理准备：宏在编译前就展开了，报错行号经常指向使用宏的那一行，而不是定义宏的那一行。

3.3 带参数的宏：括号、括号、括号#

带参数的宏看起来像函数，实际还是文本替换，所以括号稍微少一层就会出事。

C
#include <stdio.h>

#define SQUARE_BAD(x) x * x
#define SQUARE(x) ((x) * (x))
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int main(void) {
    printf("%d\n", SQUARE_BAD(1 + 2));
    printf("%d\n", SQUARE(1 + 2));

    int i = 20;
    printf("%d\n", MAX(i++, 10));
    printf("i = %d\n", i);
    return 0;
}
运行结果
5
9
21
i = 22

SQUARE_BAD(1 + 2) 展开成 1 + 2 * 1 + 2，先乘后加，结果是 5。加上括号变成 ((1 + 2) * (1 + 2))，才是 9。所以规则是：每个参数加括号，整个表达式再加一层括号。

但括号救不了副作用。MAX(i++, 10) 展开后 i++ 出现了两次：条件里比较一次，选中的分支又取一次。i 从 20 变成 22，输出的 21 也不是你想要的 20。所以宏参数别传 i++、别传函数调用。

多行宏用反斜杠续行，最后一行不加反斜杠。如果宏里有多条语句，用 do { ... } while (0) 包起来，比如写一个交换两个变量的宏，这样把它放进 if 后面时才不会把 else 抢走。这几条不是洁癖，是别人踩过的坑总结出来的。

能写成函数就写成函数。宏只在需要「类型无关」或者「编译期展开」时才值得用。

3.4 条件编译：开关和守卫#

同一份代码，在调试时多打印几行，发布时一行不留，靠的就是条件编译。

C
#include <stdio.h>

#ifndef DEBUG
#define DEBUG 0
#endif

int main(void) {
#if DEBUG
    printf("调试模式，DEBUG = %d\n", DEBUG);
#endif

    int sum = 0;
    for (int i = 1; i <= 10; i++) {
        sum += i;
    }

#if DEBUG >= 2
    printf("sum = %d\n", sum);
#endif

    printf("结果：%d\n", sum);
    return 0;
}

编译时加 -DDEBUG=2，输出三行；不加，只输出最后一行。-D 等价于在文件开头写 #define DEBUG 2，但不用改源码。

#ifdef X 只关心 X 有没有定义，#if 还能算表达式，所以可以写 #if DEBUG >= 2 这种分级日志。比如只想在调试版里编译一段日志，用 #ifdef DEBUG 把它包起来就行。#if 0 ... #endif 常用来临时注释掉一大段代码，比 /* */ 安全，不会因为里面已经有注释而嵌套出错。

头文件守卫也是条件编译，写法固定：第一行 #ifndef STACK_H，第二行 #define STACK_H，最后一行 #endif，中间放声明。3.5 节的 stack.h 就是完整例子。第一次包含时 STACK_H 没定义，内容被保留；第二次包含时宏已经存在，整段跳过。没有守卫，同一个 .c 里直接或间接包含两次，结构体就会被定义两次，编译直接报错。#pragma once 更短，但不是 C 标准，老编译器可能不认，初学先用 #ifndef。

3.5 多文件：声明与定义分家#

一个能跑的工程至少三个文件：头文件放「别人需要知道的东西」，.c 放实现，main.c 放入口。下面是一个栈的最小版本。

stack.h：

C
#ifndef STACK_H
#define STACK_H

#define STACK_SIZE 100

extern int g_ops;          // 声明：这个变量在别处定义

int push(int value);
int pop(int *value);
int is_empty(void);

#endif

stack.c：

C
#include "stack.h"

int g_ops = 0;             // 定义：只此一份

static int data[STACK_SIZE];
static int top = 0;

int push(int value) {
    if (top >= STACK_SIZE) {
        return 0;
    }
    data[top++] = value;
    g_ops++;
    return 1;
}

int pop(int *value) {
    if (top == 0) {
        return 0;
    }
    *value = data[--top];
    g_ops++;
    return 1;
}

int is_empty(void) {
    return top == 0;
}

main.c：

C
#include <stdio.h>
#include "stack.h"

int main(void) {
    push(1);
    push(2);
    push(3);

    int v;
    while (!is_empty()) {
        pop(&v);
        printf("%d ", v);
    }
    printf("\n操作次数 %d\n", g_ops);
    return 0;
}
运行结果
3 2 1
操作次数 6

三个关键词：

声明和定义。 int push(int); 是声明，只告诉编译器「有这么个函数，参数和返回值长这样」；带函数体才是定义。变量也一样，extern int g_ops; 是声明，int g_ops = 0; 是定义。声明可以出现很多次，定义只能有一次。

extern。 它告诉编译器「这个变量在别的 .c 里，链接时再去找」。头文件里写 extern，定义放且只放一个 .c，这是标准分工。

static。 文件作用域的 static 让变量或函数只在当前 .c 可见，别的文件链接不到。stack.c 里的 data 和 top 是内部状态，外面本来就不该碰，加 static 既防误用，也避免和别的文件重名。它也能修饰函数，效果一样：这个函数只给本文件用。工具函数加 static，既避免重名，也告诉读代码的人「别在外面找它」。

#include "stack.h" 用引号，编译器先在当前目录找；#include <stdio.h> 用尖括号，去系统目录找。引号也能找到系统头文件，但语义上别混用。

3.6 头文件里该放什么#

该放的：

  • 函数声明
  • extern 变量声明
  • 宏和常量
  • 类型定义：struct、enum、typedef
  • 这个头文件自己需要用到的系统头文件

不该放的：

  • 函数定义（函数体）
  • 变量定义，比如 int g_ops = 0;
  • main 函数

原因很简单：头文件会被多个 .c 包含，定义也跟着出现多份，链接器就会报 multiple definition。声明可以重复，定义不行。

例外是 static inline 函数。它可以在头文件里给出函数体，因为每个 .c 都会得到一份内部副本，不会冲突。C99 的 inline 语义有点绕，初学先记住 static inline 这个组合。

头文件还要自包含：用到 size_t 就自己 #include <stddef.h>，不要指望别的文件先帮你 include。这样别人单独包含你的头文件时，不会因为缺类型而编译失败。

头文件里还常见 typedef struct Stack Stack; 这种写法，让别的文件只拿一个类型名，不用关心内部有几个成员。这种做法叫「不透明类型」，C 标准库里的 FILE 就是这么干的。

3.7 gcc 和 Makefile#

三个文件齐了，编译命令就是：

Shell
# 一次编译、链接、运行
gcc -std=c99 -Wall -g main.c stack.c -o app
./app

# 也可以先编译成目标文件，再链接
gcc -std=c99 -Wall -c stack.c -o stack.o
gcc -std=c99 -Wall main.c stack.o -o app

-std=c99 指定标准，-Wall 打开常用警告，-g 生成调试信息（第 4 章 调试实战要用），-o app 指定输出文件名。Windows 上生成的是 app.exe，运行时写 app 或 .\app。

分步编译就是先 -c 再链接，适合文件多、只改了一个 .c 的情况。改一个 .c 只需要重编那一个，再链接一次。文件多了以后，手敲这些命令不现实，于是有了 Makefile：

TEXT
CC = gcc
CFLAGS = -std=c99 -Wall -g
OBJ = main.o stack.o

app: $(OBJ)
	$(CC) $(OBJ) -o app

main.o: main.c stack.h
	$(CC) $(CFLAGS) -c main.c -o main.o

stack.o: stack.c stack.h
	$(CC) $(CFLAGS) -c stack.c -o stack.o

clean:
	rm -f app $(OBJ)

规则只有一条：目标: 依赖，下一行是命令。命令开头必须是 Tab，四个空格不行，这是 Makefile 最坑的地方，报错通常是 missing separator。我第一次写 Makefile 时，编辑器把 Tab 自动换成四个空格，这个报错看了半小时才反应过来。

make 会检查依赖的时间戳，只重编比目标新的文件。把头文件写进依赖是有意的：改了 stack.h，所有包含它的 .c 都得重编，否则结构体定义不一致，运行时会冒出很难查的错。make clean 清理产物。Windows 下 Dev-C++ 自带的是 mingw32-make，把 rm -f 换成 del 即可。

两个常见的链接错误，看到别慌：

  • undefined reference to 'push'：声明了但没定义，或者编译命令漏了 stack.c
  • multiple definition of 'g_ops'：把定义写进了头文件，被多个 .c 各包含了一次
◆小结
  • 预处理只是文本替换，#define 不是变量，#include 不是导入模块
  • 带参宏的每个参数和整个表达式都要加括号，参数别传 i++
  • #ifdef 看有没有定义，#if 能算表达式；头文件守卫用 #ifndef
  • 声明放头文件，定义放 .c；extern 声明外部变量，static 限制在文件内
  • gcc -c 分步编译，Makefile 用「目标: 依赖 + Tab 命令」组织
✎练习
  1. 写一个 MIN3(a, b, c) 宏，要求每个参数和整体都加括号；用 gcc -E 看它展开后的样子，再试试 MIN3(i++, j++, k++) 会发生什么。
  2. 把 3.5 节的栈改成存 double，拆成 stack.h、stack.c、main.c，用 gcc -c 分步编译并链接。
  3. 故意把 int g_ops = 0; 从 stack.c 挪进 stack.h，编译看看报什么错；再改回去，解释错误信息里的 multiple definition 指的是什么。
  4. 给 3.7 节的 Makefile 加两个目标：debug 用 -DDEBUG=2 -g 编译，release 用 -O2 编译，分别运行 make debug 和 make release 验证。
