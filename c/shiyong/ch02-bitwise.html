第 2 章 位运算与内存

预计 35 分钟·约 6,425 字·C 语言实战

位运算是 C 语言里最像「直接跟硬件说话」的部分。你写的每个变量，在内存里都是一串 0 和 1；平时编译器替你把这串位解释成整数、字符、浮点数，位运算则是把解释权拿回来，直接改那串 0 和 1。

它平时不常见，但一旦用上就很省。一个 unsigned 能当 32 个开关，一张权限表能压成一个整数，判断奇偶、取颜色分量、算哈希，都绕不开它。

2.1 先把二进制捡起来#

一个字节 8 位，从右往左编号，最右边是第 0 位，叫最低位。十六进制和二进制是天然一对：一位十六进制正好对应四位二进制。

TEXT
0x6  = 0110
0x3  = 0011
0xF  = 1111
0x0F = 0000 1111
0xF0 = 1111 0000

C 里没有标准的 0b 字面量，老编译器也不认，所以看位模式时习惯写十六进制。0x0F 表示低四位全 1，0xF0 表示高四位全 1，这两个数后面会反复出现。

位运算的运算符只有六个，规则比加减乘除还简单，难的是「什么时候该用」。先回忆一下 C 语言 第 2 章 运算 里的算术运算符，下面这六个是另一套体系。

2.2 与、或、异或、取反#

运算符名字规则典型用途
&按位与两个都是 1 才是 1取某一位、清零
|按位或有一个 1 就是 1置位、合并标志
^按位异或两个不同才是 1翻转某位、找不同
~按位取反0 变 1，1 变 0配合 & 清零
C
#include <stdio.h>

int main(void) {
    unsigned a = 0x6;   // 0110
    unsigned b = 0x3;   // 0011

    printf("a & b  = %u\n", a & b);      // 0010
    printf("a | b  = %u\n", a | b);      // 0111
    printf("a ^ b  = %u\n", a ^ b);      // 0101
    printf("~a     = 0x%08X\n", ~a);     // 全取反
    printf("a << 1 = %u\n", a << 1);     // 1100
    printf("a >> 1 = %u\n", a >> 1);     // 0011
    return 0;
}
运行结果
a & b  = 2
a | b  = 7
a ^ b  = 5
~a     = 0xFFFFFFF9
a << 1 = 12
a >> 1 = 3

~a 的结果看起来吓人，其实很直白：a 的低四位是 0110，取反后低四位是 1001，高二十八位全是 1，合起来就是 0xFFFFFFF9。

异或还有一个经典用法：不用临时变量交换两个数，写成 a ^= b; b ^= a; a ^= b;。但 a 和 b 是同一个变量时，这个写法会把它清零。实际项目里老老实实用临时变量，别为了省一行代码给自己挖坑。

有两个坑几乎每年都有人踩。

第一，& 和 &&、| 和 || 是两套东西。&& 是逻辑与，结果只有 0 或 1；& 是逐位与。写 if (x & 1) 是判断奇偶，写 if (x && 1) 只要 x 非零就永远为真。

第二，优先级。== 比 & 高，x & 1 == 0 会被解析成 x & (1 == 0)，结果恒为 0。判断偶数要写 (x & 1) == 0，括号别省。

2.3 移位：乘除 2 的快捷方式#

左移 k 位等于乘 2 的 k 次方，右移等于除以 2 的 k 次方并向下取整。比如 5 << 1 是 10，5 << 2 是 20，5 >> 1 是 2。这个结论只在非负、不溢出的时候成立。

三个坑：

  • 移位位数大于等于类型宽度是未定义行为，1 << 32 不是 0，是「随便」
  • 有符号数左移溢出也是未定义行为，1 << 31 别写，写 1u << 31
  • 负数右移是实现定义行为，不同编译器可能补 0 也可能补 1

所以只要你在处理位模式，一律用 unsigned。位模式没有负数，负数是「怎么解释这串位」的问题，下一节讲。

还有个常见误解：移位比乘法快。现代编译器看到 x * 2 自己就会生成移位指令，你手写 x << 1 不会更快，只会让读代码的人多停一秒。该用的时候用，别为了「优化」把代码写拧。

2.4 掩码：只动我想动的那几位#

掩码就是一个用来筛选位的数。想保留低四位，就和 0x0F 做与：x & 0x0F，高位全被 0 吃掉。想操作第 k 位，就构造 1u << k。

C
#include <stdio.h>

int get_bit(unsigned x, int k) {
    return (x >> k) & 1u;
}

unsigned set_bit(unsigned x, int k) {
    return x | (1u << k);
}

unsigned clear_bit(unsigned x, int k) {
    return x & ~(1u << k);
}

unsigned toggle_bit(unsigned x, int k) {
    return x ^ (1u << k);
}

int main(void) {
    unsigned flags = 0;

    flags = set_bit(flags, 2);
    flags = set_bit(flags, 5);
    printf("置位后 0x%X\n", flags);

    printf("第 2 位是 %d\n", get_bit(flags, 2));

    flags = toggle_bit(flags, 2);
    printf("翻转后 0x%X\n", flags);

    flags = clear_bit(flags, 5);
    printf("清零后 0x%X\n", flags);
    return 0;
}
运行结果
置位后 0x24
第 2 位是 1
翻转后 0x20
清零后 0x0

四个函数对应四个动作：置位用或，清零用「与上反码」，翻转用异或，取位用「右移再与 1」。它们都不修改原变量，而是返回新值，所以调用时要写 flags = set_bit(flags, 2)。

取连续几位也是同一套思路：(x >> start) & ((1u << len) - 1)。取低 8 位就是 x & 0xFF，取第 8 到 15 位就是 (x >> 8) & 0xFF。注意 len 等于 32 时 1u << 32 是未定义行为，这种情况要单独处理。

2.5 补码：负数不是「加个负号」#

计算机里没有负号，只有 0 和 1。负数用补码表示：-x 等于 ~x + 1。这样做的好处是加法和正数完全一样，不用为符号单独造一套电路。我当年背了半天口诀，最后是拿 -1 在纸上画了一遍才真记住。

-1 是 32 个 1，也就是 0xFFFFFFFF；-2 是 0xFFFFFFFE。由此得到一个很好用的恒等式：~x == -x - 1。~0 是 -1，~(-1) 是 0。

C
#include <stdio.h>

int main(void) {
    int neg = -1;
    unsigned raw = (unsigned)neg;

    printf("%d 的位模式是 0x%08X\n", neg, raw);
    printf("~0 = %d，~(-1) = %d\n", ~0, ~(-1));
    printf("-1 + 1 = %u\n", raw + 1u);
    return 0;
}
运行结果
-1 的位模式是 0xFFFFFFFF
~0 = -1，~(-1) = 0
-1 + 1 = 0

同一串位，%d 把它当有符号数解释，%u 把它当无符号数解释。位一个都没变，变的只是解释方式。这也解释了为什么 printf("%u", -1) 会打印 4294967295：格式符和参数类型对不上，标准里这其实是未定义行为，只是大多数编译器「碰巧」按位输出了。

补码的范围不对称：32 位 int 是 -2147483648 到 2147483647，负数比正数多一个。INT_MIN 取相反数会溢出，这是未定义行为，不是「得到 2147483648」。

2.6 sizeof 与内存布局#

sizeof 是运算符，不是函数，编译期就能算出结果（变长数组除外）。它返回 size_t，本站习惯转成 int 再用 %d 输出。

数组名在 sizeof 里代表整个数组，sizeof(a) 是总字节数；数组传进函数后就退化成指针，sizeof 只剩一个指针的大小。这个区别在 C 语言进阶 第 1 章 一维数组 里讲过，忘了就回去翻。

类型典型大小说明
char1标准保证
short2通常
int4本站环境
long4 或 8Windows 64 位是 4，Linux 64 位是 8
long long8
指针4 或 8取决于 32/64 位
double8

标准只规定相对大小和最小值，具体看平台。换编译器时不要假设 int 一定是 4 字节。

C
#include <stdio.h>
#include <stddef.h>

struct Student {
    char grade;
    int id;
    char name[3];
};

int main(void) {
    printf("sizeof(int) = %d\n", (int)sizeof(int));
    printf("sizeof(struct Student) = %d\n", (int)sizeof(struct Student));
    printf("offsetof(id) = %d\n", (int)offsetof(struct Student, id));
    printf("offsetof(name) = %d\n", (int)offsetof(struct Student, name));

    int x = 0x01020304;
    unsigned char *p = (unsigned char *)&x;
    printf("内存里的字节：%02X %02X %02X %02X\n",
           (unsigned)p[0], (unsigned)p[1], (unsigned)p[2], (unsigned)p[3]);
    return 0;
}
运行结果
sizeof(int) = 4
sizeof(struct Student) = 12
offsetof(id) = 4
offsetof(name) = 8
内存里的字节：04 03 02 01

结构体的大小不是成员大小的简单相加。char 占 1 字节，但 int 要放在 4 的倍数地址上，编译器就在 grade 后面塞了 3 个填充字节，最后总大小是 12 而不是 9。把 int id 挪到最前面，大小会变成 8。这就是「调整成员顺序能省内存」的由来，嵌入式里很常见。

最后那段是字节序。0x01020304 在内存里从低地址往高地址是 04 03 02 01，这叫小端，x86 和大多数手机都是小端；网络协议规定用大端，所以跨机器传二进制数据时要转换，不能直接把结构体写进 socket。

★位域

结构体里可以用 unsigned flag : 1; 这种写法把成员压到几位，这叫位域。它省空间，但布局依赖编译器，跨平台传输时不要用。细节可以看 C 语言进阶 第 15 章 枚举、联合体与位域。

2.7 开关、集合，以及数 1#

一个 unsigned 有 32 位，天然就是 32 个开关。Linux 的权限位、图形库的选项、fcntl.h 里的 O_RDONLY，都是这个套路。

C
#include <stdio.h>

#define PERM_READ  (1u << 0)
#define PERM_WRITE (1u << 1)
#define PERM_EXEC  (1u << 2)

int main(void) {
    unsigned perm = PERM_READ | PERM_WRITE;

    if (perm & PERM_READ)  printf("可读\n");
    if (perm & PERM_EXEC)  printf("可执行\n");
    else                   printf("不可执行\n");

    perm |= PERM_EXEC;      // 加上执行权限
    perm &= ~PERM_WRITE;    // 去掉写权限
    printf("改完 = %u\n", perm);
    return 0;
}
运行结果
可读
不可执行
改完 = 5

检查多个标志同时成立时，两边都要括号：if ((perm & (PERM_READ | PERM_WRITE)) == (PERM_READ | PERM_WRITE))。== 的优先级比 & 高，少写左边那层括号，比较就会先算，结果完全不是你想要的。

把这种思路放大，就是「位图」：用一个 bit 表示一个数在不在集合里。100 万个整数只需要 125 KB。

C
#include <stdio.h>

int main(void) {
    unsigned char present[16] = {0};   // 128 位，表示 0~127
    int data[] = {3, 5, 3, 9, 127};

    for (int i = 0; i < 5; i++) {
        int x = data[i];
        present[x >> 3] |= (unsigned char)(1u << (x & 7));
    }

    for (int x = 0; x < 128; x++) {
        if (present[x >> 3] & (1u << (x & 7))) {
            printf("%d ", x);
        }
    }
    printf("\n");
    return 0;
}
运行结果
3 5 9 127

x >> 3 算出在第几个字节，x & 7 算出在这个字节的第几位。它们分别等价于 x / 8 和 x % 8，但这两个式子只对非负整数成立。写成位运算更贴合这一章的语境，编译器对两种写法都会优化，性能上没有区别。

最后是这一章必须会写的例子：统计一个整数二进制里有几个 1。

C
#include <stdio.h>

int count_ones(unsigned x) {
    int n = 0;
    while (x != 0) {
        x = x & (x - 1);
        n++;
    }
    return n;
}

int main(void) {
    unsigned data[] = {0u, 1u, 0x0Fu, 0xFFFFFFFFu, 0x80000000u};

    for (int i = 0; i < 5; i++) {
        printf("0x%08X 里有 %d 个 1\n", data[i], count_ones(data[i]));
    }
    return 0;
}
运行结果
0x00000000 里有 0 个 1
0x00000001 里有 1 个 1
0x0000000F 里有 4 个 1
0xFFFFFFFF 里有 32 个 1
0x80000000 里有 1 个 1

关键在 x & (x - 1)：减 1 会把最低位的 1 变成 0，把它右边的 0 全变成 1，再和自己做与，最低位的那个 1 就被抹掉了。比如 1011000 & 1010111 = 1010000。循环每转一次少一个 1，转的次数正好等于 1 的个数，比逐位右移检查要快。

◆小结
  • & 取位、| 置位、^ 翻转、~ 取反；& 和 && 不是一回事
  • 移位处理位模式时一律用 unsigned，移位位数不能大于等于类型宽度
  • 掩码 1u << k 配合四个动作，可以精确改动某一位
  • 补码下 -x == ~x + 1，~x == -x - 1；有符号溢出是未定义行为
  • sizeof 是运算符；结构体有填充，字节序分大小端
  • 一个 unsigned 能当 32 个开关，位图能用 1 bit 表示一个元素在不在集合里
✎练习
  1. 写函数 int is_odd(unsigned x)，只用位运算判断奇偶；再写 unsigned low8(unsigned x) 取出低 8 位。
  2. 用一个 unsigned 存 8 门课的通过情况，第 i 位表示第 i 门是否通过。写三个函数：标记通过、查询是否通过、统计通过门数。
  3. 写 int count_ones_naive(unsigned x)，用逐位右移的方式数 1，和 2.7 节的写法比较循环次数。
  4. 用 sizeof 打印你机器上 char、short、int、long、long long、指针和 double 的大小，再定义一个含 char、int、double 的结构体，打印它的大小，解释多出来的字节是哪来的。
