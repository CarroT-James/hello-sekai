第 1 章 一维数组

预计 20 分钟·约 4,887 字·C 语言进阶

1.1 为什么需要数组#

假设要处理全班 60 个人的成绩。不用数组，你得这样写：

C
int s1, s2, s3, ..., s60;
scanf("%d", &s1);
scanf("%d", &s2);
...

60 个变量、60 行输入、想求平均值得把 60 个变量名全写一遍相加。如果有 60 个班呢？这种写法在数据量面前直接崩溃。

数组解决的就是这个问题：把一批同类型的数据放进一块连续的内存，用同一个名字加下标来访问。于是「60 个变量」变成「1 个数组 + 1 个循环」。

C
int score[60];
for (int i = 0; i < 60; i++) {
    scanf("%d", &score[i]);
}

一个数组由三个要素确定：

  • 元素类型——每个格子存什么（int、double、char……）；
  • 数组名——这块内存的代号，同时也是首元素地址；
  • 长度——一共有多少个格子，一旦确定不能改。

数组带来的三个能力，是后面所有算法的基础：

能力说明代价
批量存储一个名字管理成百上千个数据长度固定，不能动态伸缩
下标随机访问a[i] 一步定位，与 i 大小无关，O(1)无
可循环处理配合 for 实现批量读写无
■重要

「随机访问 O(1)」是数组最大的优势，也是它区别于链表的地方。原因就藏在下一节的内存布局里：第 i 个元素的地址可以用首地址加一个乘法直接算出来，不需要从头数。

1.2 定义与初始化#

语法格式：

C
类型  数组名[长度];

int    a[10];        // 10 个 int
double b[5];         // 5 个 double
char   c[20];        // 20 个 char

长度必须是编译期就能确定的常量表达式（C99 的变长数组是例外，见第 3 章）：

C
#define N 10
int a[N];              // 可以，宏在编译前被替换成 10
int b[5 * 2];          // 可以，常量表达式
const int n = 10;
int c[n];              // 在 C 里不推荐：const 变量不算"常量表达式"

int n;
scanf("%d", &n);
int d[n];              // C99 变长数组，见第 3 章，初学先别用

五种初始化写法#

C
// 1. 全部赋初值
int a[5] = {10, 20, 30, 40, 50};

// 2. 部分赋初值：剩下的自动补 0
int b[5] = {1, 2};              // 1, 2, 0, 0, 0

// 3. 省略长度：由初值个数推断
int c[] = {1, 2, 3};            // 长度自动为 3

// 4. 全部清零（最常用）
int d[100] = {0};

// 5. 指定下标初始化（C99）
int e[5] = {[2] = 7, [4] = 9};  // 0, 0, 7, 0, 9

第 4 种写法值得单独说：= {0} 是 C 语言里把整个数组清零的标准写法，因为第一个元素给了 0，剩下的按规则全部补 0。写 = {1} 得到的可不是全 1，而是 1,0,0,0,0。

▲易错点

局部数组不初始化时，里面是垃圾值（栈上残留的数据），不是 0。全局数组和 static 数组才会自动清零。见过太多人写了 int a[10]; 直接开始 a[i] += x; 结果加出一堆天文数字。

C
#include <stdio.h>

int g[5];              // 全局：自动全 0

int main(void) {
    int a[5];          // 局部：垃圾值，不可预期
    int b[5] = {0};    // 局部：全 0，安全

    printf("%d %d\n", g[0], b[0]);   // 0 0
    // printf("%d\n", a[0]);         // 未定义行为，别依赖
    return 0;
}

1.3 内存布局与 sizeof#

这是数组最重要的一节。理解了布局，后面指针那一章会顺理成章。

C
int a[5] = {10, 20, 30, 40, 50};

下标:    a[0]  a[1]  a[2]  a[3]  a[4]
       +-----+-----+-----+-----+-----+
       |  10 |  20 |  30 |  40 |  50 |
       +-----+-----+-----+-----+-----+
地址:  0x100 0x104 0x108 0x10C 0x110   (假设 int 占 4 字节)

三个结论：

  1. 五个元素挨着放，中间没有任何空隙，这就是「连续存储」。
  1. 相邻元素地址相差 sizeof(int) = 4 字节，不是 1 字节。
  1. 第 i 个元素的地址 = 首地址 + i × 4。有了这个公式，访问 a[4] 和访问 a[0] 一样快。

写成通用公式：

C
&a[i] 等价于 a + i * sizeof(元素类型)

sizeof 是 C 语言的运算符（不是函数），用来求「占多少字节」：

C
int a[5];

sizeof(a)               // 20：整个数组 5 × 4
sizeof(a[0])            // 4 ：一个元素
sizeof(a) / sizeof(a[0]) // 5 ：元素个数（标准写法）

double b[10];
sizeof(b) / sizeof(b[0]) // 10
■背下来

求数组元素个数的写法固定是 sizeof(a) / sizeof(a[0])。写成 sizeof(a) / sizeof(int) 也能用，但一旦数组类型改了（比如 int 改成 double），后者就会算错，前者不会。

sizeof 返回的类型是 size_t（一种无符号整数）。标准规定的格式符是 %zu，但这里有一个和你环境直接相关的坑：Dev-C++ 5.11 自带的 TDM-GCC 4.9.2 使用老式运行库，它的 printf 不支持 %zu，会原样输出 zu 或者乱码。

C
printf("%zu\n", sizeof(a));            // C99 标准写法，部分老编译器不支持
printf("%d\n",  (int)sizeof(a));       // 本书统一用这种，任何编译器都正确
■建议

sizeof 的结果一般很小，转成 int 用 %d 输出完全安全，而且兼容所有环境。等以后用 gcc 的新版本或 Visual Studio 2015 以上，再改用 %zu。

1.4 访问、遍历与越界#

访问一个元素用「数组名[下标]」，下标从 0 开始，范围是 0 到 n-1：

C
int a[5] = {10, 20, 30, 40, 50};

printf("%d\n", a[0]);      // 10  第一个
printf("%d\n", a[4]);      // 50  最后一个
printf("%d\n", a[5]);      // 越界！语法合法，行为未定义

遍历是数组最常见的操作，标准写法只有一种：

C
for (int i = 0; i < n; i++) {
    // 使用 a[i]
}

记住是 < n，不是 <= n。这一条每年都能刷掉一批人。

越界为什么可怕#

C 语言不做数组越界检查。a[5] 在语法上完全合法，编译器最多给个警告。运行时它只是算了个地址，然后照常读写——问题是那块内存可能属于别的变量、函数的返回地址、甚至不属于你的进程。

C
int a[5];
int x = 100;

a[5] = 1;      // 可能刚好改掉了 x，也可能直接段错误崩溃

所以越界的表现千奇百怪：有时什么都不发生，有时另一个变量莫名其妙变了，有时当场崩溃，有时在完全无关的地方崩溃。调试时如果看到「改 A 却影响了 B」，第一反应就查下标。

C 为什么不检查？两个原因：一是性能，每次访问都查边界会慢；二是设计哲学，C 假设程序员知道自己在干什么，把检查的权力交给你。这是 C 快的原因，也是 C 容易出 bug 的原因。

▲三个高频越界错误

① for (i = 0; i <= n; i++) 多走一步；② 数组长度 10，却用 a[10] 当最后一个；③ 输入时用 while (scanf("%d", &a[i]) != EOF) 却不限制 i < 10。

1.5 五个必会的基础算法#

下面五个套路覆盖了数组 80% 的课后题和考试题，要求能默写。

算法一：求和与平均#

C
#include <stdio.h>

int main(void) {
    int a[5] = {80, 92, 76, 88, 95};
    int n = sizeof(a) / sizeof(a[0]);
    int sum = 0;

    for (int i = 0; i < n; i++) {
        sum += a[i];
    }

    printf("sum = %d\n", sum);
    printf("avg = %.2f\n", (double)sum / n);   // 必须强转
    return 0;
}

注意 (double)sum / n。如果写 sum / n，两个 int 相除会做整数除法，小数部分直接丢掉。这是数组求和题里最常见的失分点。

算法二：找最大值及其下标#

C
int max = a[0];
int pos = 0;

for (int i = 1; i < n; i++) {
    if (a[i] > max) {
        max = a[i];
        pos = i;
    }
}

两个细节：① max 的初值取 a[0] 而不是 0，否则数组全是负数时答案就错了；② 循环从 i = 1 开始，因为 a[0] 已经用过了。

如果要同时求最大值和最小值，开两个变量分别更新即可。如果要求「最大值出现的位置」，注意有重复最大值时上面这个写法返回的是第一个；把 > 改成 >= 就返回最后一个。考试常考这个区别。

算法三：逆序#

方法一，首尾对调，原地完成，只走一半：

C
void reverse(int a[], int n) {
    for (int i = 0, j = n - 1; i < j; i++, j--) {
        int t = a[i];
        a[i] = a[j];
        a[j] = t;
    }
}

循环条件是 i < j 而不是 i <= j。如果写成 i <= j，中间那个元素（奇数个时）会和自己交换两次，结果碰巧是一样的，但白做一次；更糟的是有人写成 i < n 直接越界。

方法二，借助辅助数组，思路更直观但多占一份内存：

C
int b[5];
for (int i = 0; i < n; i++) {
    b[i] = a[n - 1 - i];
}
for (int i = 0; i < n; i++) {
    a[i] = b[i];
}

算法四：统计与计数#

以「统计每个数字出现次数」为例，用另一个数组当下标计数器，这是非常重要的技巧：

C
int cnt[10] = {0};          // 统计 0~9 各出现几次
int data[] = {3, 1, 4, 1, 5, 9, 2, 6};

for (int i = 0; i < 8; i++) {
    cnt[data[i]]++;         // 用值当下标
}

for (int i = 0; i < 10; i++) {
    if (cnt[i] > 0) printf("%d 出现 %d 次\n", i, cnt[i]);
}

「用值作为下标」这个思路后面会变成哈希表的雏形，现在先记住它能解决大量计数类题目。

算法五：插入与删除#

数组长度固定，所谓「插入」和「删除」其实是挪动元素并调整有效个数 n：

C
// 在下标 pos 处插入 x（前提：容量还够，n 是当前元素个数）
for (int i = n; i > pos; i--) {
    a[i] = a[i - 1];        // 从后往前挪，避免覆盖
}
a[pos] = x;
n++;

// 删除下标 pos 的元素
for (int i = pos; i < n - 1; i++) {
    a[i] = a[i + 1];        // 从前往后挪
}
n--;

插入必须从后往前挪。如果从前往后，a[pos] 会被 a[pos+1] 覆盖掉，后面全乱。在纸上画五个格子，手动挪一遍，比看十遍代码都清楚。
