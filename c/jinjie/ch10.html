第 10 章 动态内存

预计 10 分钟·约 2,323 字·C 语言进阶

10.1 为什么需要动态内存#

到目前为止，数组的大小都是写死的。但真实程序里，数据量往往只有运行时才知道：要读的文件多大？用户要输入几条记录？用固定数组只能猜一个上限，猜小了溢出，猜大了浪费。

动态内存让程序在运行时向系统申请任意大小的内存，用完再还回去。

对比项栈（局部变量、VLA）堆（malloc）
分配时机编译期或函数进入时运行时随时
大小限制通常 1~8 MB，超了栈溢出受物理内存限制
生命周期离开作用域自动释放手动 free 才释放
分配速度极快（移动栈指针）较慢（需要找空闲块）
失败处理无法检测返回 NULL，可检查

10.2 malloc / calloc / realloc / free#

四个函数都在 <stdlib.h> 里。先看最核心的 malloc：

C
void *malloc(size_t size);   // 申请 size 字节，返回首地址；失败返回 NULL

返回值是 void *（通用指针），可以自动转换成任何类型。标准写法：

C
int n = 10;
int *a = malloc(n * sizeof(int));   // 申请 10 个 int 的空间

if (a == NULL) {                    // 必须检查！
    printf("内存分配失败\n");
    return 1;
}

for (int i = 0; i < n; i++) {
    a[i] = i;                       // 用法和普通数组完全一样
}

free(a);                            // 用完必须还
a = NULL;                           // 防止变成野指针

三个细节：① 用 sizeof(int) 而不是写死 4，换平台才不会错；② malloc 申请的内存不清零，里面是垃圾值；③ 一定要检查 NULL。

calloc：申请并清零#

C
int *a = calloc(n, sizeof(int));    // 参数是「个数」和「单个大小」
// 等价于 malloc 之后 memset 清零，但更高效

需要初始为 0 时用 calloc，比 malloc + 循环赋值更省事。

realloc：调整大小#

把已有的一块内存扩大或缩小，原有内容会保留：

C
int *p = malloc(5 * sizeof(int));
// ... 使用 ...

int *q = realloc(p, 10 * sizeof(int));   // 扩到 10 个
if (q == NULL) {
    // 扩展失败，原来的 p 仍然有效，必须保留它！
    free(p);
    return 1;
}
p = q;                                    // 成功后才覆盖
▲经典错误

p = realloc(p, new_size); 是错的。如果 realloc 失败返回 NULL，你不仅没扩成，还把原来的指针弄丢了，那块内存再也 free 不掉，直接泄漏。必须用临时指针接住返回值。

10.3 动态数组#

动态一维数组#

C
int n;
scanf("%d", &n);

int *a = malloc(n * sizeof(int));
if (a == NULL) return 1;

for (int i = 0; i < n; i++) scanf("%d", &a[i]);
for (int i = 0; i < n; i++) printf("%d ", a[i]);

free(a);

动态二维数组：两种做法#

做法一，指针数组。先申请 n 个指针，再给每行申请 m 个元素：

C
int **a = malloc(n * sizeof(int *));       // n 个行指针
if (a == NULL) return 1;

for (int i = 0; i < n; i++) {
    a[i] = malloc(m * sizeof(int));        // 每行 m 个元素
    if (a[i] == NULL) { /* 处理失败，需回滚已分配的 */ }
}

// 使用：a[i][j] 和普通二维数组一样

for (int i = 0; i < n; i++) free(a[i]);    // 先释放每一行
free(a);                                    // 再释放行指针数组

这种做法直观，但内存不连续（每行可能分散在堆的不同位置），缓存不友好，而且 free 要分两步。

做法二，一维模拟。申请一块 n×m 的连续内存，自己算下标：

C
int *a = malloc(n * m * sizeof(int));

// 访问 a[i][j] 写成 a[i * m + j]
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++)
        a[i * m + j] = i * 10 + j;

free(a);        // 一次搞定

工程中更推荐做法二：一次分配、一次释放、内存连续、不容易出错。

10.4 五类内存错误#

动态内存是 C 里 bug 最集中的地方。下面五类错误必须认得出来：

类型表现例子后果
内存泄漏申请了没释放malloc 后忘了 free程序越跑越占内存
重复释放同一块 free 两次free(p); free(p);崩溃或堆损坏
释放后使用free 后还解引用free(p); *p = 1;数据错乱或崩溃
越界写写到分配范围外a[n] = 1;破坏堆结构，难查
未检查 NULL分配失败照用malloc 后直接 *p段错误
C
// 错误 1：内存泄漏
void leak(void) {
    int *p = malloc(100 * sizeof(int));
    // 忘了 free，函数返回后这块内存再也找不到了
}

// 错误 2：释放后使用
int *p = malloc(sizeof(int));
free(p);
*p = 10;              // 未定义行为：这块内存可能已经分给别人了

// 错误 3：重复释放
free(p);
free(p);              // 未定义行为
■内存泄漏不会立刻报错

泄漏的程序往往「看起来正常」，跑几分钟或几小时后才崩。所以写代码时就养成「谁申请谁释放」的习惯，每写一个 malloc，立刻想好它的 free 在哪。
