第 12 课 正则表达式：给文本画一张形状

预计 33 分钟·约 6,505 字·Python

假设要判断一个字符串是不是手机号。规则你张口就能说：一共 11 位，第一位是 1，第二位是 3 到 9，后面全是数字。写成代码：

Python
def is_phone(s):
    if len(s) != 11:
        return False
    if s[0] != "1" or not "3" <= s[1] <= "9":
        return False
    return s.isdigit()


for s in ["13812345678", "12812345678", "1381234567"]:
    print(s, is_phone(s))
运行结果
13812345678 True
12812345678 False
1381234567 False

能跑，逻辑也对。可它只回答这一个问题。换成「把一段文字里所有订单号找出来」，你又要从头写一遍扫描、判断、截取。这类「在一堆文本里找形状」的活儿，Python 有一个专门的小语言：正则表达式。同样的手机号规则，它写成 ^1[3-9]\d{9}$ 就够了。

第一次看确实像乱码。但常用的部分就一张小表，学完这一课，你能少写一堆 startswith、split、in 拼起来的判断。

12.1 五个函数够日常用了#

re 模块里天天用的就五个函数，先把它们跑一遍，找找手感：

Python
import re

text = "订单 A1024 金额 299 元，订单 B777 金额 58 元"

print(re.search(r"\d+", text).group())
print(re.findall(r"[A-Z]\d+", text))
print(re.sub(r"\d+", "#", text))
print(re.split("，", text))
print(bool(re.match("订单", text)), bool(re.match("金额", text)))
运行结果
1024
['A1024', 'B777']
订单 A# 金额 # 元，订单 B# 金额 # 元
['订单 A1024 金额 299 元', '订单 B777 金额 58 元']
True False
函数返回干什么
search第一个匹配或 None全文找，找到一个就停
match匹配或 None只从开头找
findall列表找出全部，返回字符串列表
sub新字符串替换
split列表按模式切分

search 和 match 的区别就在开头。上面 re.match("金额", text) 是 False，因为文本以「订单」开头；换成 search 就能找到。

sub 的第二个参数可以是函数，这个用法很多人不知道。需要「把每个数字加一」这种活儿时，传 lambda m: str(int(m.group()) + 1) 就行，不用先 findall 再拼回去。

sub 还能加 count 参数，re.sub(r"\d+", "#", text, count=1) 只替换第一处。split 的 maxsplit 同理，切够了就停，剩下的整体留作最后一段——"a,b,c".split(",", 1) 得到的是 ['a', 'b,c']。

▲常见错误

re.search(...) 找不到时返回 None，直接 .group() 就是 AttributeError: 'NoneType' object has no attribute 'group'。这个报错我见过太多次，包括我自己写的代码里。要么先判断 if m:，要么用 re.findall 拿一个空列表。

12.2 元字符和量词#

正则里那些有特殊含义的符号叫元字符，常用的就下面这些：

Python
import re

print(re.findall(r"\d+", "a1 b22 c333"))
print(re.findall(r"[a-z]+", "Hello World 2026"))
print(re.findall(r"\bcat\b", "cat category cat."))
print(re.findall(r"colou?r", "color colour"))
print(re.findall(r"a{2,3}", "a aa aaa aaaa"))
print(re.sub(r"\s+", " ", "  太    多   空格 ").strip())
运行结果
['1', '22', '333']
['ello', 'orld']
['cat', 'cat']
['color', 'colour']
['aa', 'aaa', 'aaa']
太 多 空格
写法意思
\d一个数字，等价 [0-9]
\w字母、数字、下划线（中文也算）
\s空白：空格、Tab、换行
.任意一个字符，除了换行
[abc]括号里任意一个
[^abc]不在括号里的任意一个
^ $开头、结尾
\b词的边界

量词管「重复几次」：* 零次或多次，+ 一次或多次，? 零次或一次，{3} 正好三次，{2,3} 两到三次。

[a-z]+ 匹配「Hello World 2026」得到 ['ello', 'orld']，因为 H 和 W 是大写，不在 a-z 里。想大小写都算，写 [A-Za-z]+ 或者加 re.IGNORECASE。

a{2,3} 对 aaaa 只切出 aaa，剩一个 a 不够两次，被丢掉。这是贪婪的默认表现：先尽可能多吃。

^ 和 $ 匹配的是「位置」不是字符。^ 是字符串开头，$ 是结尾——多行文本想按行匹配，得加 re.MULTILINE。反过来说，你要匹配的文本里真有 +、(、? 这些字符，用 re.escape("1+1") 转义，别自己手忙脚乱补反斜杠。

▲常见错误

正则字符串一定加 r，写 r"\d+" 而不是 "\d+"。普通字符串里 \b 是退格符，\n 是换行，\d 虽然没被定义，新版 Python 会给你一个 SyntaxWarning: invalid escape sequence '\d'。加上 r 就全当字面量，问题一次消失。

12.3 贪婪与非贪婪#

+ 和 * 默认是「能多吃就多吃」。这在抓标签时特别容易翻车：

Python
import re

html = "<b>加粗</b><i>斜体</i>"

print(re.findall(r"<.+>", html))
print(re.findall(r"<.+?>", html))
print(re.match(r"<(\w+)>(.*?)</\1>", html).groups())
运行结果
['<b>加粗</b><i>斜体</i>']
['<b>', '</b>', '<i>', '</i>']
('b', '加粗')

<.+> 从第一个 < 一路吃到最后一个 >，中间的标签全被吞了。

加个 ? 变成非贪婪：<.+?> 吃到第一个 > 就停。这个 ? 不是「可选」，是「别贪」。

</\1> 里的 \1 是反向引用，指第一个括号匹配到的内容。所以 <b>...</b> 能配对，<b>...</i> 不行。处理成对标签时这东西很好用。

re.DOTALL 让 . 也能匹配换行，默认它是不匹配的。抓多行 HTML 片段时经常要加这个标志，否则 .+ 在第一行末尾就断了。

不过话说回来，真要解析网页，别用正则。HTML 允许嵌套、允许属性里带引号，正则处理不了。装个 beautifulsoup4 或者用 lxml，正则留给「一行一条记录」的文本。

12.4 分组：把匹配结果拆开#

括号在正则里不只是「圈一下」，它会分组，把匹配到的那一小段单独保存下来：

Python
import re

log = "2026-11-25 21:30:07 ERROR 登录失败 user=小明"

m = re.search(r"(?P<year>\d{4})-(?P<month>\d{2})-(?P<day>\d{2})", log)
print(m.group("year"), m.group("month"), m.group("day"))
print(m.groupdict())

m2 = re.search(r"(\d{2}):(\d{2}):(\d{2})\s+(\w+)", log)
print(m2.groups())
print(m2.group(4), m2.start(), m2.end())
运行结果
2026 11 25
{'year': '2026', 'month': '11', 'day': '25'}
('21', '30', '07', 'ERROR')
ERROR 11 25

m.group(1) 拿第一组，m.group(0) 拿整个匹配。groups() 一次返回全部，groupdict() 只在用了命名分组时才有内容。

(?P<名字>...) 是给分组起名。日志、日期这种字段多的模式，起名比记数字强太多——半年后回来看 m.group(3) 是哪一段，你自己都不记得。

start() 和 end() 是匹配在原文里的位置。想把匹配到的片段替换掉又保留上下文时，用这两个比 replace 靠谱。

finditer 返回的是一串 match 对象，适合既要位置又要内容的场景。比如做搜索高亮：拿到每处的 start() 和 end()，往原文里插 <mark>，比 sub 更灵活。

▲常见错误

findall 一旦有分组，返回的就不是字符串，而是元组列表。写 re.findall(r"(\d+)-(\d+)", text) 会得到 [('2026', '11')] 这种，后面拿去做 int(x) 会直接崩。要字符串就别加括号，或者用 finditer 配 m.group(0)。

12.5 re.compile 与 re.VERBOSE#

正则一长就没法读。re.VERBOSE 让空白和 # 注释被忽略，你可以把一条长正则拆成好几行，每段旁边写中文：

Python
import re

DATE = re.compile(
    r"""
    (?P<year>\d{4})   # 四位年
    -
    (?P<month>\d{2})  # 两位月
    -
    (?P<day>\d{2})    # 两位日
    """,
    re.VERBOSE,
)

for s in ["2026-11-25", "2026/11/25", "26-11-25"]:
    m = DATE.fullmatch(s)
    print(s, m.groupdict() if m else None)
运行结果
2026-11-25 {'year': '2026', 'month': '11', 'day': '25'}
2026/11/25 None
26-11-25 None

re.compile 把模式编译成对象，存进变量反复用。循环里跑一万次的正则，编译一次比每次重新解析划算。

模式写成模块级常量、名字全大写，是惯例。DATE = re.compile(...) 放文件开头，别人扫一眼就知道这个模块依赖哪几种模式。

fullmatch 要求整个字符串都匹配，比 match 更严。校验手机号、日期这种「格式必须完全正确」的场景，用 fullmatch 少一半漏洞——match 只保证开头对，后面拖着垃圾它也认。

写完不确定对不对，去 regex101.com 粘进去。左边有逐字符解释，右边能实时测，比自己瞪着眼睛数括号快十倍。那个网站还能选 Python 模式，直接告诉你这段在 Python 里跑出来是什么。

12.6 实战：清洗一段脏数据#

三种格式混在一起的名单，要拆成干净的记录：

Python
import re

raw = """
  张三 , 138-1234-5678 , 2026/11/25
李四,139 8765 4321,2026.11.26
  王五,13712345678 ,2026-11-27
"""

rows = []
for line in raw.strip().splitlines():
    name, phone, date = [p.strip() for p in re.split(r"[,，]", line)]
    phone = re.sub(r"\D", "", phone)
    date = re.sub(r"[./]", "-", date)
    if not re.fullmatch(r"1[3-9]\d{9}", phone):
        print("号码有问题：", line)
        continue
    rows.append({"name": name, "phone": phone, "date": date})

for r in rows:
    print(r)
print(len(rows), "条")
运行结果
{'name': '张三', 'phone': '13812345678', 'date': '2026-11-25'}
{'name': '李四', 'phone': '13987654321', 'date': '2026-11-26'}
{'name': '王五', 'phone': '13712345678', 'date': '2026-11-27'}
3 条

这段脏数据有三种毛病：分隔符有全角半角、号码里混着 - 和空格、日期有 / 和 .。清洗思路是先切分，再逐个字段归一化，最后校验。

re.split(r"[,，]", line) 一次处理两种逗号。re.sub(r"\D", "", phone) 把所有非数字删掉，- 和空格一并消失。re.sub(r"[./]", "-", date) 把两种分隔符统一成 -。

顺序很重要。要是一上来就全局 sub 掉所有逗号，三个字段就黏成一坨，再想拆开得靠猜。先按分隔符切开，每个字段内部再自由清洗，才是稳的路子。

\D 是大写，意思是「非数字」。\d 是数字，\D 是它的反面，\w / \W、\s / \S 同理。大小写这一对，坑过的人不止我一个。

至于 1[3-9]\d{9}，它也不是万能的。虚商号段、境外号码、座机它都管不了。真实项目里别自己发明手机号规则，要么维护一份公开的最新号段表，要么干脆只校验长度和全是数字。

清洗完的 rows 是标准的列表套字典，第 13 课 的 json 能直接把它写出去，第 14 课 拿它做统计也顺手。

◆小结
  • search 全文找第一个，match 只从开头，findall 要全部，sub 替换，split 切分
  • 模式一律用 r"..."，量词 * + ? {m,n}，? 跟在量词后面表示非贪婪
  • 括号分组，group(1) 取第一组，(?P<name>...) 起名，\1 反向引用
  • 有分组时 findall 返回元组；校验格式用 fullmatch
  • 复杂正则用 re.compile 加 re.VERBOSE，长模式拆行写注释
✎练习
  1. 写一个正则，同时匹配 2026-11-25 和 2026/11/25，用命名分组取出年、月、日。再用 fullmatch 验证 2026-1-25 不通过，然后想一想：2026-13-45 为什么照样能匹配上，该在哪一步拦住它。
  2. 从一段英文里找出所有邮箱地址（简单版：\w+@\w+\.\w+），打印个数和第一个。想想为什么这个正则匹配不了 a.b@mail.co.uk。
  3. 把 "苹果5元,香蕉3.5元,橘子8元" 里的价格全抽出来求和。提示：findall 加 float。
  4. 用 re.VERBOSE 写一个匹配学号的正则：8 位数字，前两位是年级（24 到 26）。写完解释 fullmatch 和 match 在这里为什么结果不同。
