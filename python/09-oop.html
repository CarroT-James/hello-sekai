第 9 课 类与对象：把数据和行为装进一个盒子

预计 30 分钟·约 6,438 字·Python

「学生」这个词，你脑子里有一套现成的理解：他有名字，有一串分数；同时他还能做点事——算出自己的平均分，报告自己及格没有。注意这两半是一起出现的。你从不会先把「小明的分数」摊在桌上，再另外抽一张纸写「怎么算平均分」，然后提醒自己算的时候别忘了把分数拿过来。

写程序的时候，我们经常真的就这么干了。

9.1 先看看不打包的写法#

用已经学过的两样东西——字典装数据（第 4 课 讲过）、函数做动作——可以这么表示一个学生：

Python
student = {"name": "小明", "scores": [88, 92, 79]}


def average(scores):
    return sum(scores) / len(scores)


print(student["name"], average(student["scores"]))
运行结果
小明 86.33333333333333

能跑，结果也对。但把这段放到真实场景里，会露出三个毛病。

第一，名字靠字符串对。哪天手一抖写成 student["scroe"]，编辑器不会提醒你，因为对字典来说那只是个普通字符串，跑到那一行才甩你一个 KeyError。

第二，数据和动作是散的。average 只认一个列表，谁都能把别人的分数传进去，它也没法拒绝。调用的时候，你得自己记住「这个函数是给学生的分数用的」，程序不替你把关。

第三，字段一改，全线崩。哪天想把 scores 改名叫 grades，字典那一行要改，average 的调用点要改，所有用过它的地方都要改，漏一处就是运行时错误。

一句话：数据在一个地方，动作在另一个地方，中间靠人的记性绑着。类就是把这根绳系上。

9.2 第一个类#

把「学生有哪些数据」和「学生能做什么」写在同一段代码里，长这样：

Python
class Student:
    def __init__(self, name, scores):
        self.name = name
        self.scores = list(scores)

    def average(self):
        return sum(self.scores) / len(self.scores)


s = Student("小明", [88, 92, 79])
print(s.name, s.average())
print(type(s))
运行结果
小明 86.33333333333333
<class '__main__.Student'>

一段一段拆。

class Student: 是声明一个新类型，名字叫 Student。你可以把它当成一张空表格：表格上写着「一个学生应该有 name 和 scores，并且会算平均分」。

Student("小明", [88, 92, 79]) 是照着这张表造出一份具体的东西。造出来的这份叫实例，也叫对象。一个类可以造出无数个实例，每个实例的数据各管各的。

__init__ 是造实例时自动执行的方法，你从来没手动调用过它。它只干一件事：把外面传进来的数据挂到新对象身上。self.name = name 读作「我这个对象的 name，等于传进来的 name」。

self 就是「正在被操作的那个对象」。点号读作「的」：self.name 是「我的名字」，self.scores 是「我的分数列表」。

average 是定义在类里的函数，叫方法。注意它不需要外面把分数递进来，因为 self.scores 就长在自己身上。调用写 s.average()，括号里是空的——self 不用你传，Python 自动把 s 塞进去。

和 9.1 对比一下就很清楚：以前是 average(scores)，你得保证传对了列表；现在是 s.average()，对象自己算自己的。数据和行为第一次待在了同一个地方。

self.scores = list(scores) 里那层 list() 是复制一份。直接写 self.scores = scores 的话，外面那个列表以后被谁改了，你的对象也跟着变，这种 bug 查起来很烦。

▲常见错误

把 def __init__(self, name, scores): 写成 def __init__(name, scores):，创建时立刻报 TypeError: Student.__init__() takes 2 positional arguments but 3 were given。数一下：你只传了两个参数，报错却说给了三个——多出来那个就是对象自己。忘了 self 是新手第一道坎，报错里那个「多出来的参数」就是答案。

另一个坑是在 __init__ 里写 return。它只能返回 None，写 return 0 会得到 TypeError: __init__() should return None。想返回东西，用别的方法。

9.3 self 到底是谁#

一个类造出两个对象，同一个方法却输出不同结果，靠的就是 self：

Python
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def introduce(self):
        print(f"我叫 {self.name}，考了 {self.score} 分")


a = Student("小明", 88)
b = Student("小红", 95)

a.introduce()
b.introduce()
print(a is b)
print(a.__dict__)
运行结果
我叫 小明，考了 88 分
我叫 小红，考了 95 分
False
{'name': '小明', 'score': 88}

方法只有一份，输出却不一样，因为 self 指向的对象不一样。a.introduce() 和 Student.introduce(a) 是同一件事，点号只是帮你把 a 塞进第一个参数。

a is b 是 False，两个对象彼此独立。每个实例都有自己的属性字典，print(a.__dict__) 能看到里面装了什么：{'name': '小明', 'score': 88}。b 有它自己的一份。

如果写 Student.introduce() 不传东西，会报 TypeError: introduce() missing 1 required positional argument: 'self'。看到「missing self」，就知道是忘了造对象，或者忘了传实例。

反过来，把方法里的 self.name 错写成 name，Python 会去翻全局变量，翻不到就报 NameError；翻到了更糟——输出看着正常，读的却是别处的数据。

9.4 实例属性和类属性#

属性有两种住处：挂在每个对象上，还是挂在类上让所有对象共用。

Python
class Student:
    school = "武汉大学"
    tags = []

    def __init__(self, name):
        self.name = name


a = Student("小明")
b = Student("小红")

print(a.school, b.school)
Student.school = "武汉大学杜伦大学联合学院"
print(a.school)

a.tags.append("三班")
print(a.tags, b.tags, a.tags is b.tags)

a.score = 88
print(a.score, hasattr(b, "score"))
运行结果
武汉大学 武汉大学
武汉大学杜伦大学联合学院
['三班'] ['三班'] True
88 False

写在 class 下面、方法外面的变量是类属性，所有实例共用一份。改 Student.school，两个对象看到的都变了，因为大家读的是同一个格子。

a.score = 88 是实例属性，只挂在 a 身上。所以最后一行是 88 False——b 根本没有 score。

怎么判断该放哪？看「所有对象是不是该同步变」。学校名全班一样，放类属性；姓名分数一人一份，放实例属性。要是写 a.school = "北大"，那不会改类属性，只是给 a 新加了一个同名属性，把类属性遮住了，b 那边纹丝不动。这种遮蔽查起来很费劲，因为赋值看起来「成功了」。

真正的坑在 tags。tags = [] 是类属性，于是全班共用这一个列表。a.tags.append("三班") 之后 b.tags 也是 ['三班']，a.tags is b.tags 是 True。这不是 bug，是「共用一份」的字面含义。

▲常见错误

凡是可变的默认值——列表、字典、集合——都不要写成类属性。想给每个对象一份自己的，就放进 __init__ 里：self.tags = []。同样的坑在函数默认参数里也出现过：def f(x, items=[]) 的那个空列表，是所有调用共用的一份。

9.5 让对象会说话：__str__ 和 __repr__#

不写这两个方法，print(s) 打印的是 <__main__.Student object at 0x000001F...>。那串地址每次运行都不一样，除了证明「有这么个东西」没有任何信息量。

Python
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def __str__(self):
        return f"{self.name}（{self.score} 分）"

    def __repr__(self):
        return f"Student(name={self.name!r}, score={self.score})"


s = Student("小明", 88)
print(s)
print(repr(s))
print([s])
print(f"{s}")
运行结果
小明（88 分）
Student(name='小明', score=88)
[Student(name='小明', score=88)]
小明（88 分）

__str__ 管「给人看」。print(s) 和 f-string 都走它，输出是「小明（88 分）」这种人话。

__repr__ 管「给程序员看」。调试时你看到的几乎全是它，所以它该写成「一眼能看出怎么重建这个对象」的样子：Student(name='小明', score=88) 正好能复制回代码里。

print([s]) 打印列表时，元素用的是 __repr__，因为列表本身要靠它区分每个元素到底是什么。最后一行 f-string 又回到 __str__。

{self.name!r} 里的 !r 是「按 repr 转成字符串」，等价于 repr(self.name)。字符串不加 !r 就丢掉引号，Student(name=小明, ...) 会让人分不清小明是字符串还是一个变量名。

只写 __repr__ 不写 __str__ 也行，print 会自动退回去用它。反过来只写 __str__，列表里打印还是一坨地址。

9.6 完整例子：一个班级#

一个学生管好自己，一个班级管一群学生。两个类，各管一层：

Python
class Student:
    total = 0

    def __init__(self, name, score):
        self.name = name
        self.score = score
        Student.total += 1

    def passed(self):
        return self.score >= 60

    def __repr__(self):
        return f"{self.name}({self.score})"


class Classroom:
    def __init__(self):
        self.students = []

    def add(self, name, score):
        self.students.append(Student(name, score))

    def average(self):
        if not self.students:
            return 0
        return sum(s.score for s in self.students) / len(self.students)

    def top(self):
        return max(self.students, key=lambda s: s.score)


room = Classroom()
for name, score in [("小明", 88), ("小红", 95), ("小刚", 52)]:
    room.add(name, score)

print(round(room.average(), 1))
print(room.top())
print([s.name for s in room.students if not s.passed()])
print(Student.total)
运行结果
78.3
小红(95)
['小刚']
3

Classroom 里装着一堆 Student 对象，这种「一个类的对象里装着另一个类的对象」叫组合。它比继承更常用，因为大部分现实关系是「有」而不是「是」：班级有学生，不是班级是学生。

几个值得停下来看的地方：

  • Student.total += 1 写在 __init__ 里，造一个学生就加一。注意写的是 Student.total 不是 self.total，后者会给这个对象新造一个实例属性，计数就废了
  • average 先判断空列表。不加这行，空班级会 ZeroDivisionError
  • max(..., key=lambda s: s.score) 直接拿到最高分那个对象，不用先排序
  • add 只是 append 的包装，但它留了个入口：以后要查重、限制人数、打日志，改这里就行，调用方一行不动
  • passed 现在只是一行比较，等规则变成「期末 60 分且作业交齐」，也只改这一处，不用翻遍全项目找 >= 60

加字段同样轻松：Student 里添一句 self.major = major，Classroom 完全不用动。这就是把「一个学生长什么样」收在一处的回报。

下一步是把 Student 拆成「人」和「学生」两层，让子类少写一遍重复代码，再给对象配上比较和排序的能力，那是第 10 课的事。

◆小结
  • class 定义模板，Student(...) 造实例，__init__ 在造的时候自动执行，只负责挂属性
  • self 是实例自己，方法的第一个参数，调用时不用传
  • 类属性全班共用一份，实例属性各有一份；列表这类可变默认值一定放 __init__
  • __str__ 给人看，__repr__ 给调试看，列表里打印元素用的是 __repr__
  • 一个类里装着另一个类的对象叫组合，它比继承更常用
