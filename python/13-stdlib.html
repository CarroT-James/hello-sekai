第 13 课 常用标准库：六个模块顶掉一半手写循环

预计 33 分钟·约 7,186 字·Python

装了 Python，就自带一整套模块，叫标准库。不用 pip install，import 一下就能用。它有两百多个，背是不可能背的。这一课挑六个天天要碰的，把真正常用的那部分补齐——知道它们存在、知道遇到什么问题该找谁，这就够了。

看的时候顺手在交互式环境里敲一遍，比干读快得多。

13.1 datetime：别只会 now()#

「三天后是几号」这种问题，手写要考虑这个月有几天、二月是不是闰年。datetime 把这些都算好了：

Python
from datetime import datetime, timedelta

d = datetime.strptime("2026-11-25 21:30", "%Y-%m-%d %H:%M")
print(d)
print(d.isoformat())
print(d + timedelta(days=7, hours=2))
print(d - timedelta(hours=1))

t1 = datetime(2026, 3, 1, 8, 0)
t2 = datetime(2026, 3, 1, 10, 30)
print((t2 - t1).total_seconds() / 60)
print(d.weekday(), d.isoweekday())
print(d > datetime(2026, 1, 1))
运行结果
2026-11-25 21:30:00
2026-11-25T21:30:00
2026-12-02 23:30:00
2026-11-25 20:30:00
150.0
2 3
True

strptime 把字符串解析成时间，strftime 反过来。这两个名字差一个字母，p 是 parse，f 是 format，记不住就想想「p 进去，f 出来」。

isoformat() 输出 2026-11-25T21:30:00，那个 T 是国际标准的写法，写进数据库、写进 json 都用它。时间对象之间能直接比大小，d > datetime(...) 是 True。

weekday() 周一返回 0，isoweekday() 周一返回 1。差一位，写「每周几提醒」这种功能时错一次就要调半天。

datetime.now() 拿到的时间没有时区信息，叫 naive datetime。服务器在 UTC、你在东八区，两边各存各的，对起来就错八小时。涉及跨时区，用 datetime.now(timezone.utc) 或 zoneinfo.ZoneInfo("Asia/Shanghai")，别用 naive 的。

timedelta 只认 weeks、days、hours、minutes、seconds，没有「一个月」「一年」。因为月份长度不固定，没法当固定长度用。真要算「三个月后」，得装 python-dateutil 用 relativedelta，标准库不给你这个。

13.2 pathlib：把路径当对象#

拼路径、列目录、判断文件在不在，用字符串做全是坑：Windows 用反斜杠，拼错了要到运行时才发现。pathlib 把路径变成一个对象：

Python
import os
from pathlib import Path

root = Path("sandbox")
(root / "logs").mkdir(parents=True, exist_ok=True)

for name in ["a.txt", "b.txt", "c.log"]:
    (root / name).write_text(f"{name} 的内容\n", encoding="utf-8")

print(sorted(p.name for p in root.iterdir()))
print(sorted(p.name for p in root.rglob("*.txt")))

p = root / "a.txt"
print(p.stem, p.suffix, p.parts[-2:])
print(p.stat().st_size)

p.unlink()
print(p.exists())

print(os.getcwd() == str(Path.cwd()))
print(bool(os.environ.get("PATH")))
运行结果
['a.txt', 'b.txt', 'c.log', 'logs']
['a.txt', 'b.txt']
a .txt ('sandbox', 'a.txt')
17
False
True
True

最舒服的是用 / 拼路径：root / "a.txt"，Windows 和 Linux 都能跑，不用管分隔符是谁。Path.cwd() 是当前工作目录，Path.home() 是用户目录，p.resolve() 把相对路径变成绝对路径，这三个在写脚本时很常用。

iterdir() 列当前目录，rglob("*.txt") 递归找所有 .txt。想只看本层用 glob()，想连子目录一起翻用 rglob()，那个 r 是 recursive。

p.parts 把路径拆成元组，p.parts[-2:] 就是最后两段。stem 是去掉后缀的名字，suffix 是后缀，parent 是所在目录。比 os.path.splitext 好记。

stat().st_size 是文件大小，单位字节。这里输出 17 而不是 16，因为 Windows 把 \n 写成了 \r\n，多一个字节。第 7 课 讲 csv 时提过同一件事，newline="" 就是为它准备的。

os 还没退休。环境变量、当前目录、进程相关的东西都在它那儿：os.environ.get("PATH")、os.getcwd()。路径操作交给 pathlib，系统层面的活儿找 os，这个分工挺稳。

两个容易翻车的地方。第一，read_text() 和 write_text() 都有 encoding 参数，不写就用系统默认——Windows 上是 GBK，中文一写就乱。养成每次显式写 encoding="utf-8" 的习惯。

第二，相对路径是相对当前工作目录，不是相对脚本文件。你在 grade/ 下跑 python main.py，Path("data.json") 指 grade/data.json；换个目录敲 python grade/main.py，它就去别处找了。稳妥写法是 Path(__file__).parent / "data.json"，锚定脚本自己所在的目录。

13.3 collections：三种省事的数据结构#

数数、分组、两头进出，这三件事都有现成的容器：

Python
from collections import Counter, defaultdict, deque

words = "apple banana apple cherry banana apple".split()
c = Counter(words)
print(c)
print(c.most_common(2))
print(c["apple"], c["durian"])

rows = [("一班", 88), ("二班", 92), ("一班", 79)]
by_class = defaultdict(list)
for cls, score in rows:
    by_class[cls].append(score)
print(dict(by_class))
print({k: round(sum(v) / len(v), 1) for k, v in by_class.items()})

q = deque([1, 2, 3])
q.appendleft(0)
q.append(4)
print(q)
print(q.popleft(), q.pop())
print(q)
运行结果
Counter({'apple': 3, 'banana': 2, 'cherry': 1})
[('apple', 3), ('banana', 2)]
3 0
{'一班': [88, 79], '二班': [92]}
{'一班': 83.5, '二班': 92.0}
deque([0, 1, 2, 3, 4])
0 4
deque([1, 2, 3])

Counter 数数，most_common(n) 直接给你前几名。取一个不存在的键返回 0，不抛 KeyError——这一点跟普通字典不一样，做排行榜很舒服。

defaultdict(list) 解决「键不存在就先建个空列表」的重复劳动。用普通字典得写 d.setdefault(k, []).append(v)，能用，但每次都要想一下。注意 print 要 dict(...) 转一下，不然打出来是 defaultdict(<class 'list'>, ...)。

deque 是双端队列，两头加删都很快。列表的 insert(0, x) 要把后面所有元素挪一格，数据一多就慢；要频繁从头插，用 deque。它还能 deque(maxlen=5) 固定长度，新元素挤进来，最老的自动掉出去——存「最近五条日志」正合适。

Counter 之间还能做加减：c1 - c2 只留正数部分，+ 会把两边合起来。做词频对比时挺方便。

还有个 namedtuple，当轻量级小对象用：Point = namedtuple("Point", "x y")，之后 p.x 比 p[0] 好读，还省内存。字段一多、还要加方法，就回去用第 10 课 的 dataclass。

13.4 itertools：把嵌套循环写成一行#

「两个列表两两配对」「从五个人里选三个」这类活儿，自己写循环又长又容易错：

Python
from itertools import chain, combinations, product, groupby

print(list(chain([1, 2], [3], [4, 5])))
print(list(combinations("ABC", 2)))
print(list(product([1, 2], "ab")))
print(list(product([1, 2], repeat=2)))

records = [("一班", "小明"), ("一班", "小红"), ("二班", "小刚")]
for key, group in groupby(records, key=lambda r: r[0]):
    print(key, [g[1] for g in group])
运行结果
[1, 2, 3, 4, 5]
[('A', 'B'), ('A', 'C'), ('B', 'C')]
[(1, 'a'), (1, 'b'), (2, 'a'), (2, 'b')]
[(1, 1), (1, 2), (2, 1), (2, 2)]
一班 ['小明', '小红']
二班 ['小刚']

chain 把几个列表接起来，combinations 取组合（不管顺序），product 是笛卡尔积——两层 for 循环干的事，它一行出结果。

这些函数返回的是迭代器，不是列表——可以把它想成一根水管，接上才出水。要看得见结果得 list() 包一下，好处是不占内存：一百万个组合也只是躺在那里等你一个个取。

groupby 有个坑：它只合并相邻的相同键。上面 records 里两个「一班」挨着，所以能合成一组；要是中间插一个「二班」，「一班」会被拆成两组。用之前先按 key 排好序，这个坑我踩过，数据少的时候看不出来。

顺带分清两个名字：combinations 是组合，(A, B) 和 (B, A) 算一个；permutations 是排列，顺序不同算两个。抽 3 个人组队用前者，排 3 个人上台领奖用后者。

13.5 random：可控的随机#

抽签、发牌、按比例抽奖，都用它：

Python
import random

random.seed(7)
print(random.choice("石头剪刀布"))
print(random.choices(["A", "B", "C"], weights=[5, 3, 2], k=6))
print(random.sample(range(1, 50), 5))
cards = list(range(1, 6))
random.shuffle(cards)
print(cards)
运行结果
剪
['C', 'A', 'A', 'C', 'A', 'B']
[33, 14, 3, 6, 28]
[2, 3, 5, 1, 4]

choice 等概率挑一个，choices 可以带权重，weights=[5, 3, 2] 意思是第一项的中奖率是第三项的两倍半。抽奖、掉落、按比例抽样都用它。

sample 是不重复抽 k 个，shuffle 原地打乱。choices 允许重复，sample 不允许，这是它俩最实在的区别。

补两个常用的：randint(a, b) 两头都包含，uniform(a, b) 返回浮点数，random() 只给 [0, 1) 之间的浮点。名字很像，边界差一点，抽签抽到端点值时就能看出区别。

seed(7) 固定种子，后面吐出来的数就固定。上面的输出你照着跑，得到的是同一个结果。教学演示、写测试时很有用；正式程序里别 reseed，那样每次跑都一个样。

▲常见错误

random 是伪随机，不能用来生成密码、验证码、抽奖码。它的序列可以被推算出来，攻击者拿到几个输出就能预测下一个。这类场景用 secrets 模块：secrets.token_hex(16)、secrets.choice(...)。名字不同，用途完全不同。

13.6 json 进阶：日期和一行一条#

json.dumps 你用过，但它默认不认 datetime，输出也不好看：

Python
import json
from datetime import datetime

data = {
    "name": "小明",
    "when": datetime(2026, 11, 25, 21, 30),
    "scores": [88, 95],
}

text = json.dumps(data, ensure_ascii=False, sort_keys=True, indent=2, default=str)
print(text)

lines = [json.dumps({"id": i, "ok": True}) for i in range(2)]
print("\n".join(lines))
print([json.loads(x)["id"] for x in lines])
运行结果
{
  "name": "小明",
  "scores": [
    88,
    95
  ],
  "when": "2026-11-25 21:30:00"
}
{"id": 0, "ok": true}
{"id": 1, "ok": true}
[0, 1]

datetime 对象 json 不认，直接 dumps 会报 TypeError: Object of type datetime is not JSON serializable。default=str 的意思是「遇到不认识的类型，用 str() 转成字符串」，一行解决。想控制格式就传函数：default=lambda o: o.strftime("%Y-%m-%d")。

反过来读的时候没这么便宜。json 本身没有日期类型，写进去是字符串，读回来还是字符串，要用得自己 datetime.strptime 转回去。别指望它记得。

sort_keys=True 按键名排序，两次生成的 json 字节级一样，git diff 才好看。indent=2 是给人看的，机器读不需要。ensure_ascii=False 让中文原样输出，不加会变成 \u5c0f\u660e 这种转义，机器照样读，人看着头疼。

后半段是 JSONL（一行一条 json）。日志、爬虫结果、大数据文件常用这个格式：一行一条，读完一行就能处理一行，不用把整个文件塞进内存。它也方便追加——open(..., "a") 写一行就行，不用把原来的数据读出来再整体重写。

◆小结
  • datetime：strptime 解析、strftime 格式化、timedelta 加减；跨时区别用 naive 时间
  • pathlib：/ 拼路径、iterdir 列目录、rglob 递归找、stem / suffix / stat
  • Counter 数数、defaultdict 分组、deque 两头快；most_common 直接给排行
  • itertools 返回迭代器，groupby 只合并相邻的键，用前先排序
  • json 用 default=str 处理日期、sort_keys 稳定输出；大文件用 JSONL 一行一条
✎练习
  1. 算一下你从出生到今天活了多少天，再算 10000 天纪念日是几月几号。用 datetime 和 timedelta。
  2. 用 pathlib 遍历当前目录下所有 .py 文件，统计每个文件多少行、总共多少行。提示：read_text().splitlines()。
  3. 用 Counter 统计一段中文里每个字出现的次数，打印前 5 名（不含空格和标点）。
  4. 写一个小记账本：expenses.json 存 [{"date": "...", "cat": "吃饭", "amount": 25}]，用 defaultdict 按分类汇总，把结果写进 summary.json。
