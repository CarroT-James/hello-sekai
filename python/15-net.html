第 15 课 网络与接口：一次请求里到底装了什么

预计 34 分钟·约 5,966 字·Python

你每天都在发 HTTP 请求，只是没意识到。地址栏敲个网址回车、点一下刷新、滑一下手机上的信息流，背后都是一次请求加一次响应。

这一课把这件事拆开看，然后用 requests 让程序替你去问。这一课需要联网，也要先 pip install requests，本站跑不了这些代码，你复制回自己电脑上试。下面出现的响应内容都是示意的，真实接口的数字每天都在变，别照着核对。

15.1 一次请求到底发了什么#

浏览器做的事，本质上是往某个地址发一段纯文本：

TEXT
GET /repos/python/cpython HTTP/1.1
Host: api.github.com
User-Agent: python-requests/2.32.3
Accept: application/vnd.github+json

HTTP/2 200
content-type: application/json; charset=utf-8
x-ratelimit-remaining: 59

{"full_name": "python/cpython", "stargazers_count": 65000}

上半截是请求，下半截是响应，中间那个空行是分隔符，不能省。

地址 https://api.github.com/repos/python/cpython 拆成三段：https 是协议，api.github.com 是域名（要找哪台机器），/repos/python/cpython 是路径（要那台机器上的哪个资源）。第一行 GET 是方法，读作「我要拿东西」；HTTP/1.1 是协议版本。

下一行 Host 说明找哪台服务器——同一台服务器上可能跑着几百个网站，靠 Host 区分。

再往下是请求头，一行一个「名字: 值」。User-Agent 说明你是谁，Accept 说明你想要什么格式，Cookie 里装着登录状态。浏览器每次请求都会自动带上一堆，所以你在某些网站上「免登录」，其实是 Cookie 在替你说话。

空行之后是请求体。GET 一般没有，POST 才有——你填的表单、发的 json 都在这里。

响应结构一样：状态行、响应头、空行、响应体。200 是成功，404 是找不到，500 是服务器自己炸了。响应体才是你要的数据，在这张图里是一段 json。

地址开头的 https 比 http 多一层 TLS：内容在传输前先加密，中间的路由器、Wi-Fi 热点都看不到你发了什么。代价是握手多花几十毫秒，所以现在默认都用它。

15.2 requests 最小可用#

requests 是第三方库，先装：

Shell
pip install requests

装完之后，发一个 GET 就这么几行：

Python
import requests

resp = requests.get("https://api.github.com/repos/python/cpython", timeout=10)

print(resp.status_code)
print(resp.headers["content-type"])
data = resp.json()
print(data["full_name"], data["stargazers_count"])

requests.get 返回一个 Response 对象，你要的东西都在它身上：status_code 是状态码，headers 是响应头（像字典，但键不分大小写），text 是原始文本，json() 把响应体解析成 Python 对象。

json() 解析失败会抛 requests.JSONDecodeError，通常是接口返回了一段 HTML 错误页——你以为是 API，其实被重定向到登录页了。这时候先 print(resp.text[:500]) 看看拿到了什么，比盯着异常有用。

timeout=10 是必须的。不写的话，对方服务器卡住不回，你的程序就永远等下去。这个参数的单位是秒，指的是「连接和读取各自最多等多久」，不是总时长。

▲常见错误

requests 默认会跟随重定向，也会用系统代理。公司或学校网络挂了代理，请求可能莫名其妙超时；想绕过就 requests.get(url, proxies={"http": None, "https": None})。另外 resp.json() 不是只能调一次，但每次调都会重新解析，大响应别在循环里反复调。

15.3 参数、请求头与 URL#

查搜索接口要带查询参数，别自己拼字符串，用 params 字典：

Python
import requests

resp = requests.get(
    "https://api.github.com/search/repositories",
    params={"q": "python 教程", "sort": "stars", "per_page": 3},
    headers={"Accept": "application/vnd.github+json", "User-Agent": "hello-sekai-demo"},
    timeout=10,
)

print(resp.url)
print(resp.status_code)
if resp.ok:
    for item in resp.json()["items"]:
        print(item["full_name"], item["stargazers_count"])

params 字典会被自动拼成 ?q=...&sort=stars&per_page=3，中文和空格也会自动做 URL 编码（换成 %E4%BD%A0 这样的百分号形式，否则服务器认不出来）。别自己拼字符串，手工拼十有八九漏了编码，服务器收到一堆乱码。

print(resp.url) 是个好习惯：看一眼实际请求的地址，能发现参数拼错了、路径多了斜杠这类问题。

headers 用来伪装和声明。有些接口强制要求 User-Agent，不给就 403；有些要求 Accept 指定版本，比如 GitHub 的 application/vnd.github+json。文档里写了的头，一个都别省。

resp.ok 是「状态码小于 400」的简写。if resp.ok: 比 if resp.status_code == 200: 宽松一点，200、201、204 都算成功。

要连续请求同一个域名，用 requests.Session() 建一个会话，它会复用连接、保留 Cookie，比每次 requests.get 新建快不少。抓十页列表、调一串接口时差别很明显。

15.4 JSON 接口与状态码#

状态码是服务器的「一句话回复」，先记住分界线：4 开头是你的问题，5 开头是对方的问题。

状态码意思你该做什么
200成功直接解析
301 / 302重定向requests 默认自动跟
400请求参数不对检查你的参数
401 / 403没登录 / 没权限补 token，别硬试
404资源不存在别重试，检查路径
429请求太快被限流等一会儿，降频率
500 / 502服务器出错稍后重试，不是你的锅

401 和 403 别写循环重试，越试越像攻击。429 才是「慢一点还有救」的那种。

Python
import requests

try:
    resp = requests.get("https://api.github.com/repos/definitely-not-exist/x", timeout=10)
    resp.raise_for_status()
    print(resp.json()["full_name"])
except requests.HTTPError as e:
    print("HTTP 出错：", e.response.status_code)
except requests.RequestException as e:
    print("请求失败：", type(e).__name__)

raise_for_status() 在状态码是 4xx 或 5xx 时抛 HTTPError，200 时什么也不做。它让你能把「网络层面的失败」和「业务逻辑」分开写，不用每处都判断状态码。

RequestException 是所有 requests 异常的父类，超时、连接失败、域名解析不了都归它管。先捕具体的，最后兜一个 RequestException，这个结构跟第 7 课 讲异常时是一个套路。

15.5 写个小工具#

把请求和展示拆开，写一个查用户信息的小脚本：

Python
"""查一个 GitHub 用户的基本信息。需要联网。"""
import sys

import requests

API = "https://api.github.com/users/{}"


def fetch_user(name):
    resp = requests.get(API.format(name), timeout=10)
    if resp.status_code == 404:
        return None
    resp.raise_for_status()
    return resp.json()


def show(user):
    print(f"{user['login']}：{user.get('name') or '未填名字'}")
    print(f"仓库 {user['public_repos']} 个，粉丝 {user['followers']} 人")


if __name__ == "__main__":
    name = sys.argv[1] if len(sys.argv) > 1 else "torvalds"
    user = fetch_user(name)
    if user is None:
        print(f"没有叫 {name} 的用户")
    else:
        show(user)

sys.argv[1] 是命令行第一个参数，len(sys.argv) > 1 判断有没有传。这种写法够用，但参数一多就乱。换成 argparse 的写法在第 16 课 里。

fetch_user 把「发请求」和「展示」拆开，show 只管打印。这样你想改成输出 json、写进数据库，只动 show，请求逻辑一行不用改。

404 单独处理成 None，是因为「用户不存在」是正常情况，不该抛异常；其他错误才让 raise_for_status 抛出来。这个判断标准挺通用：预料之中的失败用返回值，预料之外的失败用异常。

POST 的写法顺手记一下，发 json 用 json= 参数，别自己 dumps 再拼头：

Python
import requests

payload = {"name": "小明", "score": 88}
resp = requests.post("https://httpbin.org/post", json=payload, timeout=10)
print(resp.status_code)
print(resp.json()["json"])

json=payload 会自动把字典转成 json 字符串，并设置 Content-Type: application/json。用 data=payload 则是表单编码，两者的服务端行为完全不同，别混。

15.6 爬虫的边界#

技术上能抓，不等于可以抓。这部分不是免责声明，是真会出事的地方。

先看 robots.txt。大多数网站的根目录下都能找到 /robots.txt，比如 https://www.douban.com/robots.txt，里面写着哪些路径不许爬。它是约定，不是法律，但违反它等于明着告诉对方「我是恶意流量」，被封 IP 是轻的。

控制频率。一个请求接一个请求地打，别开五十个线程轰。加个 time.sleep(1)，或者用 requests.Session 复用连接。对方服务器是别人花钱养的，你压垮它，性质就变了。

别碰个人信息和登录后的内容。手机号、身份证、成绩单、聊天记录，抓了就涉及个人信息保护法。绕过登录、破解验证码、伪造 token，这些不是「技术挑战」，是违法。

尊重版权。抓下来自己分析是一回事，把全文转载出去是另一回事。论文、小说、付费课程，抓取和传播都可能侵权。

看清用户协议。很多平台的条款明确禁止自动化抓取，注册时你点过「同意」。

还有个现实问题：大部分网站会反爬。改 UA、加 referer、用不开界面的浏览器，这些手段都在军备竞赛里，今天能用明天就失效。与其研究怎么绕，不如先找找有没有官方 API——15.5 那种接口，稳定、合法、还带文档，比爬页面省心一百倍。

◆记忆点

写爬虫之前问自己三个问题：这个数据有没有官方接口？robots.txt 允许吗？我抓它干什么、会不会伤到别人？三个都过了再动手。

◆小结
  • HTTP 就是「请求头 + 空行 + 请求体」，响应结构一样；状态码 4 开头怪你，5 开头怪对方
  • requests.get(url, params=..., headers=..., timeout=10)，timeout 一定要写
  • resp.json() 解析 json，resp.raise_for_status() 让 4xx / 5xx 抛异常，RequestException 兜底
  • POST 发 json 用 json= 参数，别手动拼 Content-Type
  • 爬虫有边界：看 robots.txt、控制频率、不碰隐私、优先找官方 API
✎练习
  1. 用 requests 请求 https://httpbin.org/get，把 resp.json()["headers"] 打印出来，找出里面的 User-Agent 和 Host。再自己传一个 params，看 resp.url 变成什么样。
  2. 把 15.5 的工具改成支持多个用户名：python user.py a b c，循环查询，查不到的打一行提示继续。想想要不要加 time.sleep。
  3. 访问一个你常去的网站，打开 /robots.txt，找出 Disallow 的路径，说说它为什么不让你爬。
  4. 写一个函数，接收 URL 列表，逐个请求，统计成功、404、其他错误各多少个。要求用 try / except 和 raise_for_status，不许让一个失败中断整批。
