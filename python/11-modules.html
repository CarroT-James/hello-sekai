第 11 课 模块、包与虚拟环境：把代码拆成能互相借用的文件

预计 32 分钟·约 5,754 字·Python

写到一个文件三百行、函数十几个的时候，你会开始烦：滚轮滚半天找不到 load_scores，改一个函数怕碰坏另一个，想把一段逻辑搬到新项目里还得复制粘贴。

Python 的解法很朴素：一个 .py 文件就是一个模块，拆成几个文件，互相 import。这一课先讲清 import 背后发生了什么，再顺手把虚拟环境解决掉。

拆文件不只是为了好看。函数有了固定的住处，找东西靠文件名而不是滚轮；想测一个函数，单独跑那个文件就行；两个人改不同文件，也不会天天冲突。

11.1 一个文件就是一个模块#

建一个 hello.py，注意这里有两处 print：一处在最外层，一处缩进在 if 下面：

Python
def greet(name):
    return f"你好，{name}"


print("模块名：", __name__)

if __name__ == "__main__":
    print(greet("世界"))

然后在同一个目录里，用两种方式跑它：

Shell
python hello.py
python -c "import hello; import hello"
运行结果
$ python hello.py
模块名： __main__
你好，世界
$ python -c "import hello; import hello"
模块名： hello

同一份代码，两种命运。

直接 python hello.py 时，Python 把这个文件当成主程序，__name__ 是 "__main__"，所以 if 里面那句执行了。

被 import hello 时，__name__ 变成 "hello"，if 里面的不执行，只把 greet 这个函数留给调用方用。注意「模块名：」那句还是打印了——import 会执行模块的全部顶层代码，只是同一个模块只执行一次。第二个 import hello 直接命中缓存，什么也没干。

if __name__ == "__main__": 干的就是这件事：让文件既能当脚本跑，又能被别的文件导入而不会顺手执行一遍。第 8 课 的项目结尾就有这一行，现在你知道它为什么在那儿了。

python -c 的意思是「执行后面这串代码」，不用建文件，临时试一行东西很方便。

▲常见错误

被 import 的模块里如果有一句 print("正在加载")，它会出现在别人的输出里。把调试用的 print 留在模块顶层，是最容易被忽略的脏东西。要么删掉，要么塞进 if __name__ == "__main__": 里面。

11.2 import 的四种写法#

同一个模块，有四种请它出场的方式：

Python
import math
import statistics as st
from random import randint, seed
from math import sqrt

print(math.gcd(12, 18))
print(st.mean([80, 90, 100]))
seed(1)
print(randint(1, 3))
print(sqrt(16))
运行结果
6
90
1
4.0

四种写法的差别只在「用的时候写不写前缀」：

写法调用什么时候用
import mathmath.sqrt(x)默认选这个，名字来源一目了然
import statistics as stst.mean(x)名字太长，给自己起个短名
from math import sqrtsqrt(x)只用一两个名字，且确定不会撞名
from math import *sqrt(x)别用，会悄悄覆盖你同名的函数

from math import * 的危害不是理论上的。你自己写了一个 sqrt，然后 from math import *，你的版本被覆盖，还不报错，调用时结果对不上，能查到怀疑人生。

import 一律写在文件开头，顺序按标准库、第三方库、自己的模块，中间空一行。PEP 8（Python 官方的代码风格约定）这么建议，格式化工具也按这个顺序检查。

math、statistics 这些是标准库，装了 Python 就有，不用装。第三方库的写法完全一样，只是得先 pip install 一下。

11.3 把自己的代码拆开#

假设成绩统计的活儿越来越多：一个 main.py 负责交互，一个 stats.py 只管算。目录这样安排：grade/main.py，外加一个 grade/tools/ 目录，里面放 __init__.py 和 stats.py。

tools/stats.py 里只放函数，不打印菜单：

Python
"""几个统计函数，给 tools 包里的其他文件用。"""


def average(numbers):
    if not numbers:
        return 0
    return sum(numbers) / len(numbers)


def top_students(records, n=3):
    return sorted(records, key=lambda r: r["score"], reverse=True)[:n]


if __name__ == "__main__":
    demo = [
        {"name": "小明", "score": 88},
        {"name": "小红", "score": 95},
    ]
    print(top_students(demo, 1))

main.py 只负责用：

Python
from tools.stats import average, top_students

records = [
    {"name": "小明", "score": 88},
    {"name": "小红", "score": 95},
    {"name": "小刚", "score": 62},
]

scores = [r["score"] for r in records]

print(f"平均分：{average(scores):.1f}")
for r in top_students(records, 2):
    print(r["name"], r["score"])

在 grade/ 目录里分别跑这两个文件：

Shell
python main.py
python tools/stats.py
运行结果
$ python main.py
平均分：81.7
小红 95
小明 88
$ python tools/stats.py
[{'name': '小红', 'score': 95}]

两条命令都能跑。python main.py 走的是 import 路线，tools/stats.py 是被直接执行，所以 if __name__ == "__main__": 那段自测代码打印了一行。

import 去哪儿找模块？先看当前目录，再看环境变量 PYTHONPATH 列的目录，最后是 Python 的安装目录。所以 main.py 里写 from tools.stats import ... 能找到同目录的 tools，换个目录运行就 ModuleNotFoundError。这不是玄学，是搜索路径的问题。

拆到什么程度算合适？我的土办法是：一个文件超过三百行，或者里面明显有两拨不相干的函数，就该拆。stats.py 只算数，main.py 只管交互，stats.py 完全不知道菜单长什么样——这样它才能被别处复用。

▲常见错误

自己写的文件别跟标准库重名。你建个 random.py 想试试随机数，结果 import random 导入的是你自己的文件，random.randint 直接 AttributeError。json.py、string.py、email.py 同理。命名前先搜一下，或者加个前缀，比如 my_stats.py。

11.4 包和 __init__.py#

带 __init__.py 的目录叫包，它能把一堆模块打包成一个名字。tools/__init__.py 里可以写两行：

Python
from .stats import average, top_students

__all__ = ["average", "top_students"]

开头那个点号是相对导入，意思是「同一个包里的 stats 模块」。这样写的好处是，外面的人只要 from tools import average，不用关心它藏在 tools 里面第几层。

__all__ 是给 from tools import * 用的白名单。虽然你自己不该用星号导入，但别人可能用，列一下算是有礼貌。

也能绕过这一层，直接 from tools.stats import average。能跑，但等于把内部结构暴露给调用方，哪天想把 stats 挪进子目录，所有调用点都得改。中间加一层出口，改起来只需要动 __init__.py。

__init__.py 可以是空文件，那就只是个「这里是包」的标记。写了导入语句，包在被 import 时会顺便把常用的名字准备好——这正是 import requests 之后能直接 requests.get() 的原因。

◆记忆点

目录里有 __init__.py 才是包。Python 3 有一种「命名空间包」可以不写它也能导入，但日常项目里老老实实写一个空文件，省得踩坑。

11.5 venv：给每个项目一间屋#

装第三方库之前，先解决一个现实问题：A 项目要 requests 2.31，B 项目要 2.32。全局只能装一个版本，你只能来回卸载重装。

venv 给每个项目建一个独立的库目录：

Shell
python -m venv .venv
.venv\Scripts\activate
# macOS / Linux 用 source .venv/bin/activate

pip install requests
pip freeze > requirements.txt
pip install -r requirements.txt
deactivate

第一行在项目里建出 .venv/ 目录，里面有一套独立的 Python 和 pip。激活之后，命令行前面会出现 (.venv)，这之后 pip install 装的东西全进 .venv，跟系统里那套互不干扰。deactivate 退出来。

Windows 上第一次执行激活脚本可能被拦，报「禁止运行脚本」。这是 PowerShell 的执行策略，不是 Python 的问题，用 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned 放开当前用户就行。不想动系统设置，就用 .venv\Scripts\python.exe main.py 直接指定解释器，不激活也能跑。

.venv 千万别提交到 git，里面几千个文件，换台机器还不能用。写进 .gitignore，别人自己 python -m venv .venv 建一份。

.venv 里面其实就是一个解释器副本加上 Scripts（Linux 上是 bin）目录。所谓「激活」，只是把 .venv\Scripts 塞到 PATH 最前面，让 python 和 pip 指向这一份。哪天搞乱了，整个目录删掉重建，两秒钟的事。

11.6 requirements.txt#

pip freeze 把当前环境装了什么、什么版本，一行一个列出来，长这样：requests==2.32.3、urllib3==2.2.3，后面几行是它们自己依赖的东西，pip freeze 也一并给你列上。命令里那个 > 是重定向，意思是把左边命令的输出写进右边的文件，屏幕上不会显示。别人拿到这个文件，pip install -r requirements.txt 就能装出一模一样的环境。

团队协作时这个文件是刚需。新人 clone 下来，建 venv、pip install -r requirements.txt，两条命令就能跑，不用挨个问你「你装的是哪个版本」。

版本号用 == 锁死，别只写 requests 或者 requests>=2.0。不锁的话，今天能跑的代码，半年后别人装个新版本就崩了，而你还不知道为什么「在我电脑上是好的」。

自己写库给别人用时反过来：依赖写宽松点（requests>=2.28），免得跟别人的环境打架。应用锁死，库放宽，这是惯例。

◆小结
  • 一个 .py 文件就是一个模块；目录加 __init__.py 就是包
  • import 会执行模块顶层代码，只执行一次，之后走缓存
  • if __name__ == "__main__": 让文件既能当脚本又能被导入
  • 优先 import x，别用 from x import *；自己的文件名别跟标准库重名
  • 每个项目一个 venv，依赖锁进 requirements.txt，.venv 不进 git

  2. 写一个 mymath.py，里面放 average 和 is_prime 两个函数。直接运行它时打印三个自测例子，被别的文件 import 时什么都不打印。两种方式各跑一次验证。
  3. 在桌面建个空目录，python -m venv .venv 建环境，激活后 pip install requests，再 pip freeze > requirements.txt 看看里面多了几行，最后 deactivate。
  4. 故意把 import statistics 写成 import statistic，看 ModuleNotFoundError 长什么样。然后建一个 random.py 写一行 print("我被导入了")，从别的目录运行一个用 random 的脚本，解释发生了什么。
