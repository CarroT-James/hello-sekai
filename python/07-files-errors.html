第 7 课 文件、编码与异常处理

预计 40 分钟·约 7,640 字·Python

前六课的数据都活在内存里，程序一停就没了。想留下来，得写进文件。文件操作也是最容易出意外的地方：路径不存在、编码不对、内容不是数字。所以这一课把异常处理一起讲。

7.1 open 与 with#

文件是硬盘上的一块数据，程序通过「打开 → 读写 → 关闭」三步操作它。open() 返回一个文件对象，后面的读写都通过它进行：

Python
f = open("hello.txt", "w", encoding="utf-8")
f.write("你好，文件")
f.close()

with open("hello.txt", "r", encoding="utf-8") as f:
    print(f.read())

print(f.closed)
运行结果
你好，文件
True

open() 的第一个参数是路径，第二个是模式，encoding 指定编码。"hello.txt" 是相对路径，意思是「当前目录下的 hello.txt」。当前目录就是你运行 python 文件名.py 时所在的那个目录，不是 Python 安装目录。

模式一共三种常用的：

模式意思文件不存在时
r只读，默认就是这个报 FileNotFoundError
w只写，先清空原内容新建一个
a追加，写到末尾新建一个

外加一个 b，表示二进制，跟前面组合成 rb、wb，处理图片、压缩包才用。

上面那段先用手动的 open / close，再用 with。两种都能跑，但只该用 with。

with 会在代码块结束时自动调用 close()，中途抛异常也照关不误。手动写 close() 的问题是：你总有忘的时候，尤其是中间 return 了或者抛异常了，close() 那行根本走不到。文件没关，写进去的内容可能还留在缓冲区没落盘，程序一崩就丢了。

◆记忆点

with open(...) as f: 是文件操作的标准写法。看到没有 with 的 open，先怀疑它会漏 close。

7.2 读文件：三种写法#

Python
with open("diary.txt", "w", encoding="utf-8") as f:
    f.write("苹果 5\n香蕉 3\n橘子 8\n")

with open("diary.txt", "r", encoding="utf-8") as f:
    text = f.read()
print(text)
print("总字符数：", len(text))

with open("diary.txt", "r", encoding="utf-8") as f:
    lines = f.readlines()
print(lines)

with open("diary.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
运行结果
苹果 5
香蕉 3
橘子 8

总字符数： 15
['苹果 5\n', '香蕉 3\n', '橘子 8\n']
苹果 5
香蕉 3
橘子 8
  • read() 一次把整个文件读成一个字符串，\n 也在里面，所以 print 出来末尾会空一行
  • readlines() 读成列表，每个元素是一行，行尾的 \n 保留。所以打印列表时你能看到 '苹果 5\n'
  • for line in f: 一行一行读，最省内存。文件几百 MB 时只能用这种

还有一个 readline()，一次读一行，需要自己写循环。用得比前三种少。

注意 line.strip()：文件里的每一行带着结尾的 \n，直接打印会多空行，比较字符串时 "苹果 5\n" != "苹果 5"。strip() 去掉两端空白，包括换行。

文件对象里记着一个「读写位置」，读完就停在末尾。同一个文件对象再 read() 一次，拿到的是空字符串。想重读要么关掉重开，要么 f.seek(0) 把读写位置移回开头。

▲常见错误

f.read() 之后再 f.readlines()，第二个一定是空列表。不是文件坏了，是读写位置在末尾。新手经常在这里怀疑人生，其实是顺序问题。

7.3 写文件、模式与编码#

Python
lines = ["第一行\n", "第二行\n"]

with open("notes.txt", "w", encoding="utf-8") as f:
    f.writelines(lines)

with open("notes.txt", "a", encoding="utf-8") as f:
    f.write("第三行\n")

with open("notes.txt", "r", encoding="utf-8") as f:
    print(f.read())

with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("重新开始")

with open("notes.txt", "r", encoding="utf-8") as f:
    print(f.read())
运行结果
第一行
第二行
第三行

重新开始

write() 只接受字符串。写数字要自己转：f.write(str(88))，直接写 88 报 TypeError。先用 f-string 拼好再写，最省事。

writelines() 收一个字符串列表，但它不会自动加换行。上面每个元素都自己带了 \n，不带你就会得到 第一行第二行 挤在一行。

a 模式把内容接在末尾，w 模式一打开就把原文件清空。第二次用 w 打开 notes.txt 时，前三行已经没了。这个坑很隐蔽：代码看起来只是「写一行」，实际上把整个文件重置了。

编码：一定要写 utf-8#

文本文件在硬盘上是一堆字节，编码决定「字符怎么变成字节」。

Windows 中文版的系统默认编码是 GBK，open() 不写 encoding 就用它。于是你写文件用 GBK，别人用 UTF-8 读，中文全变乱码，或者直接抛 UnicodeDecodeError。

解决办法很简单：每次 open 都写 encoding="utf-8"，不管读写。遇到别人给的 GBK 文件（比如 Windows 记事本存的），读的时候写 encoding="gbk"，别硬用 utf-8。

▲常见错误

UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd6 in position 0 这种报错，意思是「这个文件不是 UTF-8」。要么换 encoding="gbk" 试，要么用编辑器确认文件到底是什么编码。别用 errors="ignore" 糊过去，那会悄悄吃掉字符。

7.4 csv 与 json#

Python
import csv
import json

rows = [
    ["姓名", "分数"],
    ["小明", 88],
    ["小红", 95],
]

with open("demo.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerows(rows)

with open("demo.csv", "r", encoding="utf-8", newline="") as f:
    for row in csv.reader(f):
        print(row)

data = [{"name": "小明", "score": 88}, {"name": "小红", "score": 95}]

with open("demo.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

with open("demo.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)

print(loaded[0]["name"], loaded[0]["score"])
运行结果
['姓名', '分数']
['小明', '88']
['小红', '95']
小明 88

csv 就是逗号分隔的纯文本，一行一条记录，Excel 能直接打开。csv.writer 负责写一行或一批行，csv.reader 负责读。注意两件事：

  • 打开文件时加 newline=""，不然 Windows 上写出来的 csv 每行之间会多一个空行
  • 读回来全是字符串。88 写进去，读出来是 '88'，算数之前要 int()。这就是上面输出里带引号的原因

嫌下标麻烦可以用 csv.DictReader，它把第一行当表头，之后每行变成一个字典，按列名取值。文件大、列多的时候比数字下标清楚得多。

json 是带类型的文本格式：数字还是数字，字符串还是字符串，还能嵌套列表和字典。json.dump(对象, 文件) 写，json.load(文件) 读；如果处理的是字符串而不是文件，用 json.dumps 和 json.loads，多了个 s。

ensure_ascii=False 必须加，否则中文会写成 \u5c0f\u660e 这种转义，肉眼没法看。indent=2 让输出带缩进，好看，也方便手改。

选哪个？表格类数据用 csv，嵌套结构、程序之间传数据用 json。第 8 课 常用标准库与项目实战 的项目读的就是 json。

7.5 异常处理#

Python
def safe_div(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print("除数不能是 0")
        return None
    else:
        print("计算成功")
        return result
    finally:
        print("finally 一定执行")


print(safe_div(10, 2))
print(safe_div(10, 0))

try:
    age = int("abc")
except ValueError as e:
    print(f"转不成整数：{e}")

try:
    with open("找不到.txt", "r", encoding="utf-8") as f:
        f.read()
except FileNotFoundError:
    print("文件不存在，先建一个")


def set_age(age):
    if age < 0:
        raise ValueError("年龄不能是负数")
    return age


try:
    set_age(-1)
except ValueError as e:
    print(f"出错了：{e}")
运行结果
计算成功
finally 一定执行
5.0
除数不能是 0
finally 一定执行
None
转不成整数：invalid literal for int() with base 10: 'abc'
文件不存在，先建一个
出错了：年龄不能是负数

四个关键字各管一件事：

  • try 圈住可能出错的代码
  • except 接住指定类型的异常，程序不崩，继续往下走
  • else 在没有异常时执行，名字有点误导，你可以读成「一切顺利才走这里」
  • finally 一定执行，不管有没有异常、有没有 return

finally 用来收尾：关文件、删临时文件、解锁。就算 try 里 return 了，finally 也会先跑完再返回。

不写 try 会怎样？程序直接崩，打印一长串 traceback。那个 traceback 不是废纸，最后一行就是异常类型和原因，调试时先看最后一行。

▲常见错误

别写光秃秃的 except:。它会连 Ctrl+C、SystemExit 一起吞掉，程序明明出了大问题却一声不吭，bug 全被藏起来。至少写 except Exception as e:，最好写具体类型，比如 except FileNotFoundError:。多个 except 从上往下匹配，具体的放前面。

raise 是主动抛异常。上面的 set_age(-1) 本来能跑，你判断出参数不合法，就抛一个 ValueError 叫停。函数里越早检查越好，别等到算出一堆垃圾数据再回头找原因。

常见的内置异常：

异常什么时候出现
FileNotFoundErroropen 的文件不存在
ValueError类型对但值不对，比如 int("abc")
ZeroDivisionError除以 0
KeyError字典里没有这个键
IndexError列表下标越界
TypeError类型不对，比如 "1" + 1

7.6 完整程序：读 csv，写 json#

先在程序同目录建一个 scores.csv，内容如下：

TEXT
姓名,分数
小明,88
小红,95
小刚,62
小美,79

目标：读进来，算人数、平均分、最高分、最低分，写进 report.json。

Python
import csv
import json

INPUT = "scores.csv"
OUTPUT = "report.json"


def load_scores(path):
    try:
        with open(path, "r", encoding="utf-8", newline="") as f:
            reader = csv.DictReader(f)
            return [
                {"name": row["姓名"], "score": int(row["分数"])}
                for row in reader
            ]
    except FileNotFoundError:
        print(f"找不到 {path}，请先创建这个文件。")
        return []


def make_report(records):
    scores = [r["score"] for r in records]
    highest = max(records, key=lambda r: r["score"])
    lowest = min(records, key=lambda r: r["score"])
    return {
        "count": len(records),
        "average": round(sum(scores) / len(scores), 1),
        "highest": highest,
        "lowest": lowest,
    }


def main():
    records = load_scores(INPUT)
    if not records:
        return

    for r in records:
        print(f"{r['name']}：{r['score']} 分")

    report = make_report(records)
    with open(OUTPUT, "w", encoding="utf-8") as f:
        json.dump(report, f, ensure_ascii=False, indent=2)

    print(f"已写入 {OUTPUT}")
    print(json.dumps(report, ensure_ascii=False, indent=2))


if __name__ == "__main__":
    main()
运行结果
小明：88 分
小红：95 分
小刚：62 分
小美：79 分
已写入 report.json
{
  "count": 4,
  "average": 81.0,
  "highest": {
    "name": "小红",
    "score": 95
  },
  "lowest": {
    "name": "小刚",
    "score": 62
  }
}

这块代码把本课的东西全用上了：

  • with 打开文件，encoding="utf-8" 显式指定，读 csv 加了 newline=""
  • csv.DictReader 按表头取值，row["姓名"] 比 row[0] 好读
  • int(row["分数"]) 把字符串转成数字。不转的话，sum 会拿 '88' 和 '95' 去加，直接报 TypeError
  • max(records, key=lambda r: r["score"]) 直接拿到最高分那个人，第 6 课 函数与参数 的 lambda 在这儿派上用场
  • try 接住 FileNotFoundError，文件没建也不崩，给一句人话提示
  • json.dump(..., ensure_ascii=False, indent=2) 写出带缩进的中文 json，json.dumps 再打印一遍给你看内容

几个「如果」：

  • 把 scores.csv 删掉再运行，程序打印「找不到 scores.csv」，然后正常退出，不崩
  • 把某一行的分数改成「八十八」，int() 抛 ValueError，程序崩在这一行。想更稳，可以在 load_scores 里再包一层 except ValueError，跳过坏行
  • 把 json.dump 的 ensure_ascii=False 删掉，report.json 里的中文全会变成 \uXXXX，打开像乱码
◆小结
  • 文件操作一律 with open(路径, 模式, encoding="utf-8") as f:
  • r 只读、w 清空重写、a 追加；w 会清空，这是最常见的翻车点
  • 读：read() 全读、readlines() 读成列表、for line in f 逐行最省内存
  • 写：write() 只收字符串，writelines() 不会自动加换行
  • 编码永远显式写 utf-8；Windows 默认 GBK，中文乱码基本都是这个原因
  • csv 是表格、读回来全是字符串；json 保留类型，ensure_ascii=False 保住中文
  • try / except / else / finally，捕具体异常，别写裸 except:
  • raise 主动抛错，参数不合法就在函数开头抛
  • 上一课是 第 6 课 函数与参数，下一课 第 8 课 常用标准库与项目实战 用这些零件拼一个能用的程序
