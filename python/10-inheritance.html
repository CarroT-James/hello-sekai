第 10 课 继承与魔法方法：子类少写一遍，对象学会比较

预计 32 分钟·约 7,317 字·Python

第 9 课 的 Student 只有名字和分数。现在要加一种「研究生」：多了导师和专业方向，但名字、分数、打招呼这些全都要。

最直接的做法是复制一份改改。能跑，问题是往后每次改 Student，你都得记得同步改研究生那一份——总有一次会忘。

继承就是干这个的：把公共部分放进父类，子类只写自己多出来的东西。不过先说句实话，继承是面向对象里被用得最滥的机制，学会之后看什么都想继承，最后继承树长得像家谱，动一下基类整个项目抖三抖。判断标准其实很土：子类是不是父类的一种。研究生是人，对；汽车是发动机，不对，那叫组合。这一课先把正确用法讲清楚。

10.1 复制粘贴的老路#

把上一课的类抄一遍，改名，加两个字段：

Python
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def intro(self):
        return f"我是 {self.name}，{self.score} 分"


class GradStudent:
    def __init__(self, name, score, tutor):
        self.name = name
        self.score = score
        self.tutor = tutor

    def intro(self):
        return f"我是 {self.name}，{self.score} 分"


print(Student("小明", 88).intro())
print(GradStudent("小红", 92, "王老师").intro())
运行结果
我是 小明，88 分
我是 小红，92 分

注意第二个输出：研究生有自己的导师，介绍里却一个字没提。因为 intro 是从 Student 复制过来的，复制的人忘了改。

这就是复制粘贴的典型结果——改一处、忘一处。更麻烦的是「以后」：下周你给 Student 的 intro 加一个「请多指教」，研究生那份不会跟着变；你给 Student 加一个 email 字段，研究生那份也不会。程序不会当场报错，直到某处读到 g.email 才 AttributeError。错误发生在定义处，报错发生在几百行之外，这是最难查的一类 bug。

10.2 继承：把公共部分提到父类#

把「学生」抽出来当父类，研究生继承它：

Python
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def intro(self):
        return f"我是 {self.name}，{self.score} 分"


class GradStudent(Student):
    def __init__(self, name, score, tutor):
        super().__init__(name, score)
        self.tutor = tutor

    def intro(self):
        return f"{super().intro()}，导师是 {self.tutor}"


s = Student("小明", 88)
g = GradStudent("小红", 92, "王老师")

print(s.intro())
print(g.intro())
print(isinstance(g, Student), issubclass(GradStudent, Student))
运行结果
我是 小明，88 分
我是 小红，92 分，导师是 王老师
True True

class GradStudent(Student): 括号里写父类（也叫基类），子类立刻拥有父类的所有属性和方法，不用复制一行。

super().__init__(name, score) 的意思是「先请父类把它那两个字段挂好」。父类负责 name 和 score，子类只负责 tutor，各管各的。

intro 在子类里重新写了一遍，这叫重写。重写之后还想用父类的版本，就写 super().intro()——它返回「我是 小红，92 分」，子类在后面补上导师，不用把父类那句话再抄一遍。

要是子类干脆不写 intro，g.intro() 就直接用父类那份，输出里没有导师。默认全部继承、只改想改的，这才是继承最省事的地方。

isinstance(g, Student) 是 True，因为子类对象也算父类的对象。这条性质撑起了整个面向对象的多态，现在记住结论就够：需要 Student 的地方，塞一个 GradStudent 进去不会出问题。写函数时参数写「一个学生」，传研究生也行，函数不用改。

10.3 忘了 super() 会怎样#

子类不写 __init__ 没问题，一写就得先叫父类。看两种写法：

Python
class Student:
    _next_id = 100

    def __init__(self, name):
        Student._next_id += 1
        self.id = Student._next_id
        self.name = name


class Good(Student):
    def __init__(self, name, major):
        super().__init__(name)
        self.major = major


class Bad(Student):
    def __init__(self, name, major):
        self.name = name
        self.major = major


g = Good("小明", "计算机")
b = Bad("小红", "法学")
print(g.id, g.name, g.major)
print(hasattr(b, "id"), b.name, b.major)
运行结果
101 小明 计算机
False 小红 法学

Bad 把父类的 __init__ 完全绕过了。它自己写了 self.name，看着没漏——漏的是 id。程序不会在这里报错，Bad("小红", "法学") 照样造出一个对象，直到某处用到 b.id 才 AttributeError。

父类的 __init__ 里可能不只有 name 一个字段。它可能在计数、在注册、在校验参数、在连数据库。你手动复制字段，只能复制你看得见的那部分。

麻烦还会滚雪球。Student 哪天多一个 email，Good 一行不用改，Bad 得手动补一行；项目里有一百个子类，你就得补一百次，还得记得哪些补过。

规矩很简单：子类 __init__ 的第一行永远是 super().__init__(...)，除非你非常清楚自己在干什么。

★补充说明

super() 不带参数时会按 MRO（方法解析顺序）去找「下一个类」。现在只写单继承，把它当成「父类」三个字用就行。有人喜欢写 Student.__init__(self, name)，效果一样，但父类改名时得跟着改，不划算。

10.4 让对象能比较#

两个 Student 对象能不能比大小？直接写 a == b 比的是「是不是同一个对象」，跟分数无关，两个都考 88 分也会判不等。想让比较按分数来，得自己告诉 Python 规则：

Python
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def __eq__(self, other):
        if not isinstance(other, Student):
            return NotImplemented
        return self.score == other.score

    def __lt__(self, other):
        return self.score < other.score

    def __repr__(self):
        return f"{self.name}({self.score})"


a = Student("小明", 88)
b = Student("小红", 88)
c = Student("小刚", 62)

print(a == b, a == c)
print(a > c)
print(a != b)
print(sorted([a, b, c]))
print(max([a, c]))
运行结果
True False
True
False
[小刚(62), 小明(88), 小红(88)]
小明(88)

__eq__ 管 ==，__lt__ 管 <。有了 __lt__，sorted 就能排序，因为排序内部只用到「小于」。

a > c 你没有定义，Python 会自动反过来调 c < a。!= 也是从 __eq__ 推出来的，所以你只写了相等，不等于也能用。

return NotImplemented 那句值得留意。别人拿 a == "小明" 来比的时候，返回 False 等于把话说死；返回 NotImplemented 是告诉 Python「我这边不会比，你去问对方」。这是个体面的拒绝方式。

这类方法在 Python 里叫魔法方法（也叫双下划线方法）：你不用直接调它们，写对应的符号时 Python 自己会去找。

▲常见错误

定义了 __eq__ 却没定义 __hash__，这个类的对象就不能放进 set，也不能当 dict 的键，会得到 TypeError: unhashable type。原因是 Python 认为你改了「相等」的定义，哈希值（放进 set 和字典时用来定位的编号）也得跟着改，它不知道该怎么算，干脆把 __hash__ 设成 None。要用就自己补一个，或者干脆别拿它当键。

10.5 让对象用起来像列表#

len(team)、team[0]、"小红" in team 这些写法，背后都是 Python 在找对应名字的魔法方法：

Python
class Team:
    def __init__(self, name, members):
        self.name = name
        self.members = list(members)

    def __len__(self):
        return len(self.members)

    def __getitem__(self, index):
        return self.members[index]

    def __contains__(self, item):
        return item in self.members


team = Team("一班", ["小明", "小红", "小刚"])
print(len(team))
print(team[0], team[-1])
print("小红" in team)
print(team[1:3])
print(list(team))
运行结果
3
小明 小刚
True
['小红', '小刚']
['小明', '小红', '小刚']

len(team) 调的是 __len__，team[0] 调的是 __getitem__，in 调的是 __contains__。这三个方法一写，你的类就长得像列表了，别人用起来没有学习成本。

team[1:3] 能切片，是因为切片对象被原样传进了 __getitem__，而 self.members[1:3] 刚好支持。负下标也一样，-1 直接交给内层列表处理。

最后一行 list(team) 更有意思：类里并没有写 __iter__，但 Python 发现你有 __getitem__，就从头取 team[0]、team[1]……一直取到抛 IndexError 为止。所以 __getitem__ 越界时必须抛 IndexError。你要是吞掉异常返回 None，这个循环就永远停不下来。

__contains__ 其实可以不写。没有它，Python 会拿 __getitem__ 一个一个试，结果照样对，只是慢。数据量大时自己写一份更快，逻辑也更直白。

10.6 两个省事的工具：@property 与 @dataclass#

先看一个需求：分数不能是负数，也不能超过 100。最土的办法是写 set_score 方法，但那样所有 s.score = 95 的写法都得改。@property 能让你继续用属性的写法，同时在背后做检查：

Python
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    @property
    def score(self):
        return self._score

    @score.setter
    def score(self, value):
        if not 0 <= value <= 100:
            raise ValueError(f"分数必须在 0~100，收到 {value}")
        self._score = value

    @property
    def level(self):
        if self.score >= 90:
            return "优秀"
        if self.score >= 60:
            return "及格"
        return "不及格"


s = Student("小明", 88)
print(s.score, s.level)

s.score = 95
print(s.level)

try:
    s.score = 120
except ValueError as e:
    print(e)
print(s.score)
运行结果
88 及格
优秀
分数必须在 0~100，收到 120
95

@property 把方法伪装成属性。s.score 不带括号，读的时候自动调 getter；s.score = 95 自动调 setter。

关键一笔在 __init__ 里：self.score = score 走的是 setter，所以 88 能过、120 会被拦下。校验写在 setter 里，等于所有入口都设了岗，创建时也逃不掉。

level 只有 getter，没有 setter。s.level = "优秀" 会得到 AttributeError: property 'level' of 'Student' object has no setter。这正好——等级是算出来的，不该让人随便写。

_score 前面那个下划线是约定：内部用的，别直接碰。Python 不会拦你，但别人看到下划线就知道不该依赖它。

别给每个属性都套一层 property。写个什么都不做的 getter 和 setter，纯属给自己加工作量。只在需要校验、需要计算、需要改内部实现时用它。

如果这个类主要就是装数据，还有个更省事的：@dataclass 按字段声明自动生成 __init__、__repr__、__eq__：

Python
from dataclasses import dataclass, field, asdict


@dataclass
class Student:
    name: str
    score: int = 0
    tags: list = field(default_factory=list)

    def passed(self):
        return self.score >= 60

    def __str__(self):
        return f"{self.name}（{self.score}）"


a = Student("小明", 88)
b = Student("小明", 88)

print(a)
print(a == b)
a.tags.append("三班")
print(a.tags, b.tags)
print(a.passed())
print(asdict(a))
运行结果
小明（88）
True
['三班'] []
True
{'name': '小明', 'score': 88, 'tags': ['三班']}

三个字段，省掉了二十行手写的 __init__ 和 __repr__，而且不会写错。a == b 是 True，因为自动生成的 __eq__ 逐个字段比。

tags: list = field(default_factory=list) 是必须的写法。直接写 tags: list = []，dataclass 会当场报 ValueError: mutable default <class 'list'> for field tags is not allowed——它比你更早想起 9.4 那个共享列表的坑。

asdict(a) 把对象转成普通字典，写 json 时很顺手。

◆小结
  • class 子类(父类) 继承，super() 调父类，子类 __init__ 的第一行别忘了它
  • 子类对象也是父类对象，isinstance 判得出来，这是多态的地基
  • __eq__ 管 ==，__lt__ 管排序，不会比时返回 NotImplemented；定义了 __eq__ 记得想 __hash__
  • __len__、__getitem__、__contains__ 让自定义对象用起来像列表，越界必须抛 IndexError
  • @property 在校验和计算时用，@dataclass 省掉样板代码，可变默认值用 field(default_factory=...)
