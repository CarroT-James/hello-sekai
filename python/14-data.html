第 14 课 数据处理入门：从 csv 到一张班级报表

预计 34 分钟·约 6,425 字·Python

第 7 课 用过 csv，第 8 课 用字典装过成绩。那时候是「能读出来就行」，这一课把数据处理当正经事做一遍：读进来、清洗、统计、排序、写成报表。

全程只用标准库，不装任何东西。等你看完最后那节，会明白 pandas 省掉的到底是哪部分力气。

14.1 csv：读回来全是字符串#

csv 就是「逗号分隔的纯文本」，用 Excel 双击能打开，用记事本也能看。Python 用 csv 模块读写它：

Python
import csv

rows = [
    {"姓名": "小明", "班级": "一班", "分数": 88, "备注": "住校, 周末回家"},
    {"姓名": "小红", "班级": "二班", "分数": 95, "备注": ""},
]

with open("scores.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["姓名", "班级", "分数", "备注"])
    writer.writeheader()
    writer.writerows(rows)

with open("scores.csv", "r", encoding="utf-8", newline="") as f:
    for row in csv.DictReader(f):
        print(row)
        print(row["分数"], type(row["分数"]).__name__, int(row["分数"]) + 1)

with open("scores.csv", "r", encoding="utf-8") as f:
    print(f.read())
运行结果
{'姓名': '小明', '班级': '一班', '分数': '88', '备注': '住校, 周末回家'}
88 str 89
{'姓名': '小红', '班级': '二班', '分数': '95', '备注': ''}
95 str 96
姓名,班级,分数,备注
小明,一班,88,"住校, 周末回家"
小红,二班,95,

DictWriter 按 fieldnames 写表头，writerows 一次写一批。DictReader 反过来，第一行当表头，之后每行变成一个字典。这比 row[0]、row[1] 强太多——列顺序变了，代码不用改。

注意最后那段原始文件内容："住校, 周末回家" 被加了一对引号。因为字段里本身有逗号，不加引号会把一个字段拆成两个。csv 模块自动处理了这件事，这也是别自己用 split(",") 的原因。

再看那个 type：88 写进去是整数，读出来是 '88'，字符串。csv 没有类型，它只是一行行文本，所有值都是字符串。算数之前必须 int() 或 float()，不转就会得到 '88' + 1 这种 TypeError。

newline="" 别忘了。Windows 上不加会多出空行，因为 csv 模块自己会写 \r\n，文本模式再翻译一次就成了 \r\n\r\n。

DictReader 是迭代器，for row in reader 一行一行读，文件几个 G 也不会爆内存。list(reader) 才会全读进来，小文件无所谓，大文件是自杀。

14.2 用字典数数#

统计的本质就一句话：一个键对应一个计数器。先手写一遍，你会更清楚现成工具的底层在干什么：

Python
text = "苹果 香蕉 苹果 橘子 香蕉 苹果"

counter = {}
for word in text.split():
    counter[word] = counter.get(word, 0) + 1

print(counter)
print(sorted(counter.items(), key=lambda kv: kv[1], reverse=True))
print(max(counter, key=counter.get))
运行结果
{'苹果': 3, '香蕉': 2, '橘子': 1}
[('苹果', 3), ('香蕉', 2), ('橘子', 1)]
苹果

counter.get(word, 0) 的意思是「有这个键就取出值，没有就给 0」。于是第一次见到「苹果」时是 0 + 1，第二次是 1 + 1。

直接写 counter[word] += 1 会 KeyError，因为键还不存在。这个错误所有人都会犯，get 就是解药。

max(counter, key=counter.get) 取的是键，不是值——它按 counter.get 的大小找最大的那个键，得到「苹果」。想要「出现最多的键值对」就写 max(counter.items(), key=lambda kv: kv[1])。

这事儿有现成的：Counter 一行搞定，第 13 课 讲过。这里手写一遍，是为了让你知道它底下在干什么。

14.3 sorted 的多级排序#

「按分数从高到低，同分按年龄从小到大」——这种需求 sorted 的 key 一个元组就解决了：

Python
students = [
    {"name": "小明", "score": 88, "age": 20},
    {"name": "小红", "score": 95, "age": 18},
    {"name": "小刚", "score": 88, "age": 19},
    {"name": "小美", "score": 72, "age": 18},
]

print([s["name"] for s in sorted(students, key=lambda s: s["score"], reverse=True)])
print([s["name"] for s in sorted(students, key=lambda s: (-s["score"], s["age"]))])
print([s["name"] for s in sorted(students, key=lambda s: (s["score"], s["age"]))])

by_age = sorted(students, key=lambda s: s["age"])
print([s["name"] for s in by_age])
print([s["name"] for s in sorted(by_age, key=lambda s: s["score"])])
运行结果
['小红', '小明', '小刚', '小美']
['小红', '小刚', '小明', '小美']
['小美', '小刚', '小明', '小红']
['小红', '小美', '小刚', '小明']
['小美', '小刚', '小明', '小红']

key 返回一个元组时，Python 按元组逐位比较：先比第一个，相等再比第二个。所以 (score, age) 是「分数升序，同分按年龄升序」。

想「分数降序、同分年龄升序」，不能只写 reverse=True——那会连年龄一起降。正确做法是给要降序的那一位加负号：(-s["score"], s["age"])。负号只对数字有效，字符串不行。

最后两行在演示稳定排序：先按年龄排，再按分数排，分数相同的两个人会保持原来的年龄顺序。sorted 保证相等元素不换位置，于是「先排次要条件、再排主要条件」也能实现多级排序。

中文按拼音排序是个坑。默认按字符在 Unicode 里的编号比，结果既不是拼音也不是笔画。要拼音得装 pypinyin，把名字转成拼音再当 key；locale 那套在 Windows 和 Linux 上行为还不一样，别指望。

14.4 平均数、中位数、标准差#

三个指标，各自的用途不一样：

Python
import statistics

scores = [62, 72, 88, 88, 95]

print(len(scores), sum(scores))
print(round(sum(scores) / len(scores), 2))
print(statistics.median(scores))
print(round(statistics.pstdev(scores), 2))
print(statistics.mode(scores))
print(sorted(scores)[len(scores) // 2])
运行结果
5 405
81.0
88
12.13
88
88

sum / len 就是平均分，81.0。这个人人会算。

中位数是「排好序后中间那个」，88。它比平均数抗极端值：一个班九个人考 90，一个人考 10，平均分 82，看着还行；中位数 90，才对得上「大部分人的水平」。所以房价、工资这类数据都报中位数。

标准差 12.13 衡量「大家离平均分多远」。全考 81，标准差是 0；一半 100 一半 62，标准差就大。statistics 里 pstdev 是总体标准差，stdev 是样本标准差（分母是 n-1）。数据是你手上全部的人，用 pstdev；是从更大群体里抽的样本，用 stdev。

mode 是众数，出现最多的值，这里是 88。一组数据可能有多个众数，Python 3.8 之后 mode 遇到并列会返回第一个，multimode 才给你全部。

最后一行手写中位数，sorted(scores)[len(scores) // 2]，只对奇数个有效。偶数个要取中间两个的平均，这就是为什么建议直接用 statistics.median——边界情况它都替你想了。

14.5 完整流程：从原始数据到报表#

把前面几块拼起来：造数据、读进来、按班级分组、算指标、写报表。

Python
import csv
from collections import defaultdict

RAW = [
    ["姓名", "班级", "分数"],
    ["小明", "一班", 88],
    ["小红", "二班", 95],
    ["小刚", "一班", 62],
    ["小美", "一班", 79],
    ["小强", "二班", 71],
]

with open("scores.csv", "w", encoding="utf-8", newline="") as f:
    csv.writer(f).writerows(RAW)

with open("scores.csv", "r", encoding="utf-8", newline="") as f:
    rows = list(csv.DictReader(f))

by_class = defaultdict(list)
for r in rows:
    by_class[r["班级"]].append(int(r["分数"]))

report = []
for cls in sorted(by_class):
    scores = by_class[cls]
    report.append({
        "班级": cls,
        "人数": len(scores),
        "平均分": round(sum(scores) / len(scores), 1),
        "最高分": max(scores),
    })

with open("report.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["班级", "人数", "平均分", "最高分"])
    writer.writeheader()
    writer.writerows(report)

for row in report:
    print(row)

with open("report.csv", "r", encoding="utf-8") as f:
    print(f.read())
运行结果
{'班级': '一班', '人数': 3, '平均分': 76.3, '最高分': 88}
{'班级': '二班', '人数': 2, '平均分': 83.0, '最高分': 95}
班级,人数,平均分,最高分
一班,3,76.3,88
二班,2,83.0,95

by_class[r["班级"]].append(int(r["分数"])) 一行干两件事：键不存在时 defaultdict 自动建空列表，然后 append。转换 int 也在这一行完成——清洗要在入口做，别等算平均分的时候才发现有字符串混进来。

sorted(by_class) 对字典排序拿到的是键的列表，按班级名排。不加它也行，但输出顺序取决于插入顺序，两次跑可能不一样。

写出去的 report.csv 用 Excel 直接能打开。这是数据处理最实用的交付形式：你的程序算，别人在表格里看。

顺序上还有个小建议：先算完所有指标再一次性写文件，别在循环里反复开关文件。文件开关有开销，中途出错还会留下半个文件。

14.6 numpy 和 pandas 到底解决了什么#

上面这些代码，处理几十行数据毫无压力，几千行也还行。十万行、一百万行就难受了。

TEXT
# 同样的活儿，pandas 大概长这样（本站没有 pandas，看看就行）
import pandas as pd

df = pd.read_csv("scores.csv")
df["分数"] = df["分数"].astype(int)
df.groupby("班级")["分数"].agg(["count", "mean", "max"])

差别不在「代码短」，在底下怎么跑。

纯 Python 的列表里，每个数字都是一个独立的对象：带着自己的类型信息，散落在内存各处。循环一百万次，每次都要判断类型、创建一个新对象装结果，解释器一层层转。慢的不是你的算法，是这堆开销。

numpy 的 ndarray 是一整块连续内存，装的是同一种定长类型（比如 32 位整数）。加法由提前编译好的机器码一次扫过去，没有对象创建、没有类型判断，还能用上 CPU 的向量指令。同一件事快几十倍不奇怪。

pandas 在 numpy 之上加了「带名字的列」和「行索引」，于是你能写 df.groupby("班级")["分数"].mean()，还能 df.merge() 做表连接、df.pivot_table() 做透视表。这些操作纯 Python 也能写，但写出来是几十行循环，还容易错。

那什么时候该装？数据上万行、要做矩阵运算、要按多个维度分组汇总、要读 Excel，装。就处理一个班四十个人的成绩，装它属于杀鸡用牛刀，还多一个依赖要维护。

这一课的例子全用标准库，是因为它们真的够用，而且不用联网。等你手上真有一份十万行的表，再学 pandas 也不迟，那时候你会知道它每一步在替谁干活。

◆小结
  • DictReader / DictWriter 按列名读写，读回来全是字符串，算数前先 int()
  • 写 csv 记得 newline=""，字段里有逗号会自动加引号，别自己 split(",")
  • 数数用 dict.get(k, 0) + 1，分组用 defaultdict(list)，清洗在入口做
  • sorted 的 key 返回元组就是多级排序，某一位要降序就加负号；它是稳定排序
  • 平均数看整体、中位数抗极端值、标准差看离散程度；十万行以上再考虑 numpy 和 pandas
✎练习
  1. 把 14.5 的报表加一列「中位数」，用 statistics.median。再加一列「标准差」，判断哪个班更参差。
  2. 读 scores.csv，按分数从高到低输出，同分按姓名排序，只打印前三名。用 sorted 的元组 key，别用两次排序。
  3. 写一个函数 top_n(rows, n)，返回每个班分数最高的 n 个人，结果是「班级 → 名单」的字典。提示：defaultdict 加 sorted 加切片。
  4. 用纯 Python 生成 100 万个 1 到 100 的随机整数，算平均值，用 time.perf_counter() 计时。再想想 numpy 版本大概会快多少、为什么。
