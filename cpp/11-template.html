第 11 课 模板与泛型：写一遍，适配所有类型

预计 30 分钟·约 5,789 字·C++

给 int 写一个找较大值的函数，给 double 再写一个，给 string 又写一个——三个函数除了类型，几乎一个字不差。哪天发现逻辑写错了，得改三处；加一种新类型，还得再抄一遍。

模板的做法是把类型本身变成参数：函数只写一份，类型留空，编译器在你实际调用时按传进来的类型补上。要记的关键字只有 template 和 typename，语法就这么点。真正要想通的是它在编译期展开——这一句理解了，后面很多报错和限制都会顺。

11.1 一份函数，适配所有类型#

C++
#include <iostream>
#include <string>

template <typename T>
T bigger(const T& a, const T& b) {
    return a > b ? a : b;
}

int main() {
    std::cout << bigger(3, 7) << "\n";
    std::cout << bigger(2.5, 1.5) << "\n";
    std::cout << bigger(std::string("apple"), std::string("banana")) << "\n";
}
运行结果
7
2.5
banana

template <typename T> 里的 T 是个占位符，表示「某种类型，等调用时再定」。你写 bigger(3, 7)，编译器从实参推出 T 是 int，现场生成一个 bigger<int>；写 bigger(2.5, 1.5)，生成 bigger<double>。这两个是彼此独立的函数，各自做类型检查、各自生成机器码。

typename 和 class 在这里可以互换，template <class T> 完全等价。老代码里 class 更多，新代码倾向 typename，因为它更准确——T 不一定是个类，也可以是 int。

注意 bigger("apple", "banana") 不能这么写。双引号包起来的是字符数组，"apple" 的类型是 const char[6]、"banana" 是 const char[7]，长度不同，T 推不出统一类型，直接编译失败。就算长度碰巧一样，函数也没法把数组当返回值。想比字符串，就显式造一个 std::string，像上面那样。

模板的代价也在这里：每种类型都生成一份代码，用十种类型就膨胀十倍，编译时间变长，可执行文件变大。所以别为了「通用」而通用，真正常用的那几种类型才值得模板化。

11.2 类型可以推，也可以自己指定#

大多数时候编译器替你推，但有些场合推不出来，得你手动写。

C++
#include <iostream>

template <typename T>
T half(T value) {
    return value / 2;
}

template <typename T>
T maxOf(T a, T b) {
    return a > b ? a : b;
}

int main() {
    std::cout << half(5) << "\n";
    std::cout << half(5.0) << "\n";
    std::cout << half<double>(5) << "\n";
    std::cout << maxOf(3, 7) << "\n";
    // std::cout << maxOf(3, 7.5) << "\n";  // T 同时被推成 int 和 double
}
运行结果
2
2.5
2.5
7

half(5) 推出 T 是 int，5 / 2 是整数除法，结果是 2。half(5.0) 推出 double，得到 2.5。half<double>(5) 是你手动指定 T：编译器先把 5 转成 double，再算，同样得到 2.5。

最后一行如果取消注释，maxOf(3, 7.5) 会报错：第一个参数要求 T 是 int，第二个要求 T 是 double，推导冲突。解决办法有两个：写 maxOf<double>(3, 7.5) 显式指定，或者先 static_cast<double>(3)。标准库的 std::max 也有同样的限制，std::max(3, 7.5) 一样编不过。

显式指定还有一个用处：返回类型没法从参数推的时候。比如 template <typename T> T zero() { return T{}; }，参数列表是空的，编译器一点线索都没有，调用必须写 zero<int>()。

11.3 类模板：Box<T>#

函数能模板化，类也能。最直观的例子是一个盒子，里面装一个任意类型的值。

C++
#include <iostream>
#include <string>

template <typename T>
class Box {
public:
    explicit Box(const T& value) : value_(value) {}

    const T& get() const { return value_; }
    void set(const T& value) { value_ = value; }

private:
    T value_;
};

int main() {
    Box<int> bi(42);
    Box<std::string> bs("hello");

    bi.set(7);
    std::cout << bi.get() << " " << bs.get() << "\n";
}
运行结果
7 hello

Box<int> 和 Box<std::string> 是两个完全不同的类型，不能互相赋值，也不能把 Box<int> 传给接收 Box<std::string> 的函数。它们只是从同一份模板生成出来的，生成完就各过各的。

模板还能嵌套，Box<Box<int>> 是合法的，里面那个 Box<int> 本身也是一个类型。读这种类型时从最内层往外念，不容易晕。

成员函数写在类里面时，语法和普通类没区别。要把定义挪到类外，必须带上模板头：

template <typename T> const T& Box<T>::get() const { return value_; }

这里的 Box<T> 不能省成 Box。初学阶段建议先把成员函数写在类里，等熟悉了再拆出去，能少踩一半语法坑。

▲版本限制

Box b(42); 这种省略类型的写法叫类模板实参推导，是 C++17 才有的。我们用的 GCC 4.9 不支持，必须写全 Box<int> b(42);。写全也有好处：读代码时类型一眼就看得出来。

11.4 为什么模板的定义要放进头文件#

这是模板最反直觉的一条规则。普通函数可以声明放头文件、定义放源文件，模板不行。要说清为什么，得先知道程序是怎么拼出来的：每个 .cpp 会单独编译成一个目标文件（.o），最后由链接器把这些目标文件拼成可执行文件。

假设你把 maxOf 的声明写在 maxof.h，定义写在 maxof.cpp，然后在 main.cpp 里调用 maxOf(3, 7)。编译 main.cpp 时编译器只看到声明，不知道函数体长什么样，只能先留一个「这里要调用 maxOf<int>」的记号。链接时它去找这个函数的实现，可 maxof.cpp 里没有任何代码触发过 int 版本的生成，目标文件里根本没有它，于是报 undefined reference to 'int maxOf<int>(int const&, int const&)'。

原因在于：模板本身不是代码，只有被实例化（真的拿某个类型用一次）时才生成代码。而实例化发生在「既看到了调用、又看得到定义」的那个文件里。所以定义必须跟着声明一起放进头文件：

C++
// maxof.h
#ifndef MAXOF_H
#define MAXOF_H

template <typename T>
T maxOf(const T& a, const T& b) {
    return a > b ? a : b;
}

#endif

这样每个包含它的源文件都能看到完整定义，都能自己生成一份。多个 .cpp 各生成一份 maxOf<int> 也没关系，链接器会把它们合并，这不算重复定义。

代价是编译变慢：每个包含这个头文件的源文件都要重新解析、重新生成。大型项目会用显式实例化或者 extern template 来控制，那是后面的事了。头文件、源文件、编译和链接的整套流程，第 16 课 项目组织与调试：把代码拆成多个文件 会从头讲一遍。

11.5 std::vector 本来就是模板#

你从第 6 课 vector 与 string 开始天天用的 std::vector，本身就是 template <typename T> class vector。写 std::vector<int> 时，你就是在给模板填参数。

标准库里到处都是模板：std::map<std::string, int> 有两个参数，std::pair<A, B> 也是两个，std::array<int, 3> 干脆把长度也当成了模板参数。它们能互相嵌套，因为模板参数可以是任何类型，包括另一个模板实例。

模板也能用来写通用的容器处理函数。

C++
#include <cstddef>
#include <iostream>
#include <string>
#include <vector>

template <typename T>
void printAll(const std::vector<T>& items) {
    for (std::size_t i = 0; i < items.size(); ++i) {
        if (i != 0) {
            std::cout << " ";
        }
        std::cout << items[i];
    }
    std::cout << "\n";
}

int main() {
    std::vector<int> nums = {1, 2, 3};
    std::vector<std::string> words = {"C++", "template"};

    printAll(nums);
    printAll(words);
}
运行结果
1 2 3
C++ template

printAll(nums) 把 T 推成 int，printAll(words) 把 T 推成 std::string。同一份函数体处理两种完全不同的元素类型，而且各自类型安全：往 std::vector<std::string> 里塞一个 int，编译期就报错，不会等到运行时才发现。

嵌套的类型从里往外读：std::map<std::string, std::vector<int>> 是「键为字符串、值为一串整数的表」。C++11 之前两个右尖括号必须写成 > >，中间留个空格，否则会被当成右移运算符；现在不用了，但翻老代码还会见到。

★给学过 C 的同学

如果你以前用 void* 那种「什么都能装、用的时候再转回去」的办法写过通用容器，会发现模板的差别在于类型信息一直保留着，转错类型在编译期就被抓住。没学过可以完全忽略这段。

11.6 模板的边界：T 得撑得住你用到的操作#

模板不是万能的，它对你的类型有一个隐含要求：T 必须支持函数体里用到的每一个操作。

C++
#include <iostream>
#include <vector>

template <typename T>
T sum(const std::vector<T>& values) {
    T total{};
    for (const auto& v : values) {
        total += v;
    }
    return total;
}

int main() {
    std::vector<int> a = {1, 2, 3};
    std::vector<double> b = {1.5, 2.5};

    std::cout << sum(a) << " " << sum(b) << "\n";
}
运行结果
6 4

T total{} 是值初始化：int 得到 0，double 得到 0.0。写成 T total = 0; 对 int 和 double 也过得去，但换成某些自定义类型就不行了。{} 的要求更低，是模板里更稳的写法。

total += v 要求 T 支持 +=。如果写 sum<std::string>，string 支持 +=，能编过，但返回的是所有字符串拼起来的结果——模板不会替你想语义，它只检查语法。

模板报错也是一道劝退门槛。一个类型不满足要求，编译器会把整条实例化链打出来，几十行起步，真正有用的通常是最前面那句 no match for 'operator+='，以及后面那句 required from here。看模板报错先找「哪个类型、哪个操作不满足」，别从第一行开始逐句读。

最后，别过度泛化。只需要 int 和 double，写两个重载函数比写模板更清楚，报错也更好读。模板适合「逻辑确实一样、类型确实很多」的场景，比如容器、算法、智能指针。为了显得高级而模板化，后面维护的人会恨你。

◆小结
  • 模板在编译期按类型生成代码，bigger<int> 和 bigger<double> 是两个独立函数
  • 模板参数可以由实参推导，也可以显式指定；类型不一致时推导会失败
  • 类模板的每个实例都是独立类型，Box<int> 和 Box<std::string> 不能混用
  • 模板的声明和定义要放在同一个头文件里，否则链接时找不到实例
  • std::vector、std::map 都是模板；T 必须支持函数体里用到的操作
✎练习
  1. 写一个 clamp(T value, T low, T high) 函数模板，把 value 限制在 [low, high] 之间。用 int 和 double 各测一次，再试试 clamp(5, 0, 10.0)，解释为什么编不过。
  2. 写一个 Pair<A, B> 类模板，两个成员分别是 A 和 B 类型，提供 first()、second() 和 operator<<，用 Pair<std::string, int> 测试。
  3. 把 11.4 的 maxOf 拆成 maxof.h 和 maxof.cpp，在 main.cpp 里调用，记录链接错误；再把定义挪回头文件，解释错误为什么消失。
  4. 11.6 的 sum 对 std::vector<std::string> 能不能编译？如果能，运行结果是什么？如果不能，要改哪里？分别说明理由。
