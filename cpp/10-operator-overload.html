第 10 课 运算符重载与友元：让自定义类型也用上 + 号

预计 30 分钟·约 5,978 字·C++

1 + 2 能算，两个 std::string 用 + 也能拼起来，这说明 + 的含义不是固定的，取决于两边是什么类型。编译器看到 a + b 时的规则很朴素：去找一个名字叫 operator+ 的函数，参数类型对得上就调用。你写的类型没定义这个函数，它自然报错。

运算符重载做的就是给 + 这种符号挂一个函数，没有魔法。真正要动脑的是两件事：这个运算符该返回什么，以及它该写成成员函数还是普通函数。

10.1 a + b 就是 operator+(a, b)#

先写一个二维向量。数学上两个向量相加，是对应分量相加，结果是一个新向量。

C++
#include <iostream>

class Vec2 {
public:
    Vec2(double x, double y) : x_(x), y_(y) {}

    Vec2 operator+(const Vec2& other) const {
        return Vec2(x_ + other.x_, y_ + other.y_);
    }

    double x() const { return x_; }
    double y() const { return y_; }

private:
    double x_, y_;
};

int main() {
    Vec2 a(1.0, 2.0);
    Vec2 b(3.0, 4.0);
    Vec2 c = a + b;
    std::cout << c.x() << "," << c.y() << "\n";
}
运行结果
4,6

写成成员函数时，a + b 等价于 a.operator+(b)。左操作数自动变成 this（也就是 a 自己），右操作数变成参数 other，所以成员版的 operator+ 只接收一个参数。这一点和普通函数不太一样，别数错。

函数末尾那个 const 表示「这个函数不会修改 a」。这是第 4 课 类与对象：把数据和操作捆在一起 讲过的 const 成员函数，作用是让 const 的 Vec2 对象也能参与加法。参数写成 const Vec2& 是引用：不复制一份 b，也不允许在函数里改它。

返回值是 Vec2，不是 Vec2&。因为 a + b 产生的是一个全新的对象，函数里 return Vec2(...) 造出来的临时对象必须被复制出去。要是写成 Vec2&，返回的就是函数内的局部对象，函数一结束它就没了，调用方拿到的是悬空引用——这种错误编译器不一定报，运行时才炸。

运算符重载的自由度比想象中小：不能发明新符号，不能改优先级，不能改操作数个数，也不能给两个内置类型重载（至少得有一个操作数是你自己的类型）。a + b * c 永远先算乘法，你改不了。

10.2 += 返回引用，+ 返回新值#

返回值类型是运算符重载里最容易写错的地方，没有之一。

C++
#include <iostream>

class Counter {
public:
    explicit Counter(int v = 0) : v_(v) {}

    Counter& operator+=(int n) {
        v_ += n;
        return *this;
    }

    Counter operator+(int n) const {
        return Counter(v_ + n);
    }

    int value() const { return v_; }

private:
    int v_;
};

int main() {
    Counter c(1);
    Counter d = c + 2;
    (c += 3) += 4;
    std::cout << c.value() << " " << d.value() << "\n";
}
运行结果
8 3

c += 3 改的是 c 本身，然后返回 *this——也就是 c 自己——的引用，所以外面还能接着 += 4。如果 operator+= 返回的是 Counter 而不是 Counter&，(c += 3) += 4 改的就是一个临时副本，c 最后是 4，不是 8。这种 bug 很隐蔽，因为表达式看起来完全正常。

operator+ 返回 Counter，因为它不改 c，而是造一个新值。内置类型也是这个规矩：i += 1 改 i，i + 1 得到新值。你重载时跟着这个直觉走，别人读代码就不用猜。

自增运算符同理。前置 ++x 改完返回引用，写成 Counter& operator++()；后置 x++ 要返回旧值，只能按值返回，而且得带一个用不上的 int 参数做区分：Counter operator++(int)。那个 int 不是给你用的，只是让编译器分清前置和后置。

10.3 operator<< 为什么必须写成友元#

std::cout << v 这行看起来天经地义，但它的左操作数是 std::cout，类型是 std::ostream（一个输出流），不是 v。而成员函数的左操作数必须是你自己的类。这就决定了 operator<< 只能写成普通函数，靠 friend 进类里拿权限。

C++
#include <iostream>

class Vec2 {
public:
    Vec2(double x, double y) : x_(x), y_(y) {}

    friend std::ostream& operator<<(std::ostream& os, const Vec2& v);

private:
    double x_, y_;
};

std::ostream& operator<<(std::ostream& os, const Vec2& v) {
    os << "(" << v.x_ << ", " << v.y_ << ")";
    return os;
}

int main() {
    Vec2 v(1.5, -2.0);
    std::cout << v << "\n";
    std::cout << v << " 和 " << v << "\n";
}
运行结果
(1.5, -2)
(1.5, -2) 和 (1.5, -2)

现在 std::cout << v 调的是全局的 operator<<(std::cout, v)，左操作数类型对上了。函数返回 std::ostream&，所以还能继续 << "\n"，一个接一个串下去。参数 const Vec2& 既不复制也能接临时对象。

为什么类里要写那行 friend？因为函数体要读 v.x_ 和 v.y_，而它们是 private。不加 friend 只有三条路：给 Vec2 加 x()/y() 然后只用 getter、把字段改成 public、或者改成成员函数 v.print(std::cout)。getter 版能用，但为了输出多开两个接口；public 字段则把封装彻底拆了。friend 是折中：只给这一个函数开一扇小门，门开在哪、为什么开，都写在类里。

友元不是「破坏封装」的同义词，它是一次有意识、有范围的授权。真正的坏味道是满屏 friend 加上 public 数据成员。

operator>> 同理，写成 std::istream& operator>>(std::istream& is, Vec2& v)，第二个参数不能是 const，因为要往里写。

10.4 operator==：相等是什么意思，得你说了算#

自定义类型能不能用 ==，取决于你有没有告诉编译器「相等」指什么。

C++
#include <iostream>
#include <string>

class Student {
public:
    Student(std::string name, int id) : name_(name), id_(id) {}

    bool operator==(const Student& other) const {
        return id_ == other.id_;
    }

    bool operator!=(const Student& other) const {
        return !(*this == other);
    }

    const std::string& name() const { return name_; }

private:
    std::string name_;
    int id_;
};

int main() {
    Student a("小林", 2024001);
    Student b("林小林", 2024001);
    Student c("小林", 2024002);

    std::cout << (a == b) << " " << (a != c) << "\n";
}
运行结果
1 1

两个学生姓名不同、学号相同，a == b 为真，因为我把「相等」定义成了学号相同。这个决定没有对错，取决于你要拿它做什么：学号是唯一标识就这么写，要比对整条记录就把姓名也比上。关键是只能有一个定义，而且写进注释，别让调用方猜。

operator!= 直接复用 == 再取反，是个好习惯。哪天你把规则从「学号相同」改成「学号加姓名」，只需要改一处，!= 自动跟着变。

输出的时候记得加括号：std::cout << a == b 会被解析成 (std::cout << a) == b，因为 << 的优先级比 == 高。编译器会给你一屏看不懂的错误，其实就是少了两个括号。C++20 可以用 <=> 一次生成六个比较运算符，我们这套 GCC 4.9 不支持，老老实实两个都写。

还有一条：不要用 == 比较浮点数。给 Vec2 写相等时，x_ == other.x_ 在 0.1 + 0.2 这种场景下会返回 false。要比较就设一个误差范围，比如 std::abs(x_ - other.x_) < 1e-9，并把这个规则写清楚。

10.5 operator[]：读和写要分开#

下标运算符的特殊之处在于：同一个类往往需要两个版本。

C++
#include <cstddef>
#include <initializer_list>
#include <iostream>
#include <vector>

class Scores {
public:
    Scores(std::initializer_list<int> init) : data_(init) {}

    int& operator[](std::size_t i) {
        return data_[i];
    }

    const int& operator[](std::size_t i) const {
        return data_[i];
    }

    std::size_t size() const { return data_.size(); }

private:
    std::vector<int> data_;
};

int main() {
    Scores s = {90, 85, 77};
    s[1] = 95;

    const Scores& cs = s;
    std::cout << cs[1] << " " << s.size() << "\n";
}
运行结果
95 3

非 const 版本返回 int&，所以 s[1] = 95 能写进去。const 版本返回 const int&，只能读。cs 是 const 引用，编译器只考虑 const 版本；如果类里没有 const 版本，cs[1] 直接编译失败。

反过来也一样：如果只写了 const 版本，普通对象 s[1] = 95 也会失败，因为 const 版本返回的 const int& 不能当赋值目标。两个版本一起提供，才算完整。构造函数收一个 std::initializer_list<int>，只是为了让你能写 {90, 85, 77} 这种花括号列表，不用深究。

operator[] 不做越界检查，这一点和数组一样。越界是未定义行为，可能读到垃圾，也可能当场崩。需要检查就用 at()，越界时抛 std::out_of_range。std::vector 和 std::string 都是这么设计的：[] 快但不查，at() 查但慢一点。

10.6 哪些运算符该重载，哪些别碰#

目的是让自定义类型用起来像内置类型，不是炫技。判断标准只有一条：语义是否自然。Vec2 + Vec2 是加法，Scores[1] 是取元素，Student == Student 是比较，都很自然。如果你给 Employee 重载 + 表示「合并两份工资单」，读代码的人得先查文档才知道 + 干了什么，那不如老老实实写 mergeSalary(a, b)。

运算符建议
+ - * /返回值，语义和内置类型保持一致
+= -= *= /=返回 *this 的引用，支持链式修改
== !=成对实现，!= 复用 ==
<< >>非成员函数，通常声明为友元，返回流引用
[]同时提供 const 与非 const 版本
&& || , &不要重载

&& 和 || 重载后会失去短路求值：a && b 会把两个操作数都算出来，本来靠短路挡住的空指针访问就躲不掉了。逗号运算符重载后会丢掉从左到右的求值顺序。取地址 & 重载后，连 &obj 都可能拿到奇怪的东西。这三类除非你在写很底层的库，否则别碰。

友元也一样按需给。输出、输入运算符，加上少数要碰内部状态的辅助函数，给 friend 很合理。把整个类设成另一个类的友元，就要多想一步：这层耦合能不能用 public 接口替代。

最后一条经验：运算符重载写得越少，代码越好读。先把构造函数、const 成员函数、operator<< 这三样写扎实，剩下的等真需要再加。

◆小结
  • a + b 就是 operator+(a, b)；成员版左操作数是 this，所以只接一个参数
  • + 返回新值，+= 返回 *this 的引用；返回局部对象的引用一定出错
  • operator<< 的左操作数是流，只能写成非成员函数；要读私有成员时声明为 friend
  • == 和 != 要成对，!= 复用 ==；浮点数别直接用 ==
  • operator[] 提供 const 与非 const 两个版本；&&、||、,、& 不要重载
✎练习
  1. 给 Vec2 增加 operator-、数乘 operator*(double) 和 operator==。相等比较要求用误差范围，而不是直接比较 double。
  2. 给 10.5 的 Scores 写一个 operator<<，输出格式为 [90, 85, 77]，并保证 std::cout << a << " " << b 能正常链式输出。
  3. 写一个带 const 和非 const 两个 operator[] 的 IntArray 类，然后在 main 里分别用普通对象和 const 对象访问，解释编译器分别选了哪个版本。
  4. 下面三段重载各有一个问题，指出问题并说明运行时会怎样：bool operator<(Student a, Student b) 按值传参；Vec2& operator+(const Vec2& a, const Vec2& b) 返回局部对象的引用；operator== 比较姓名而 operator!= 比较学号。
