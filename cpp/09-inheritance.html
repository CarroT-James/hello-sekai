第 9 课 继承与多态：让不同的东西说同一种话

预计 30 分钟·约 7,234 字·C++

给教务系统建模，学生有姓名、年龄、专业，老师有姓名、年龄、职称，两边都要打印一句自我介绍。最直接的写法是写两个互不相干的类，各自存一份姓名和年龄。第一版能跑，等你要加一个手机号字段，就得改两个地方；改漏一个，输出就会一半对一半错。

继承解决的就是这种「两个类共享一大段东西」的问题：把共同部分提进一个类，另一个类声明「我基于它」，然后只写自己多出来的部分。

这一课还有个更重要的目标：让学生和老师能放进同一个容器，用同一个循环调用同一个函数，各自表现出不同的行为。这个能力叫多态，它是继承真正的价值所在。

9.1 基类与派生类：把共同点提上去#

C++
#include <iostream>
#include <string>

class Person {
public:
    Person(const std::string& name, int age) : name_(name), age_(age) {}

    std::string name() const { return name_; }
    int age() const { return age_; }

    void introduce() const {
        std::cout << "我叫" << name_ << "，今年" << age_ << "岁\n";
    }

private:
    std::string name_;
    int age_;
};

class Student : public Person {
public:
    Student(const std::string& name, int age, const std::string& major)
        : Person(name, age), major_(major) {}

    void study() const {
        std::cout << name() << " 在学 " << major_ << "\n";
    }

private:
    std::string major_;
};

int main() {
    Student s("小林", 19, "计算机");
    s.introduce();
    s.study();
}
运行结果
我叫小林，今年19岁
小林 在学 计算机

class Student : public Person 读作「Student 公开继承 Person」。Person 叫基类，Student 叫派生类。一个 Student 对象里完整地包含着一个 Person 部分，所以 s.introduce() 和 s.name() 都能直接调用——它们是继承来的，Student 里一个字都没写。

构造函数里的 : Person(name, age), major_(major) 是初始化列表。第一项的意思是「用这两个参数把基类那部分先构造好」。这一项不能省：Person 只提供了带参数的构造函数，编译器不知道该给 name 和 age 填什么，于是直接报 no matching function for call to Person::Person()。

冒号后面的 public 决定基类成员在派生类外面还能不能被访问。

基类里的写法派生类内部能直接用吗外部通过派生类对象能访问吗
public能能
protected能不能
private不能不能

省略 public（写成 class Student : Person）默认是私有继承，introduce() 跟着变成私有，外面一调用就是一屏 is inaccessible。遇到这个报错，先看冒号后面是不是漏了 public。

还有一条设计原则：继承表达的是「是一种」。学生是一种人，所以 Student 继承 Person 合理。如果只是「学生有专业」，那专业就该是成员变量。为了少写几行代码而继承，最后往往要在派生类里塞一堆用不上的函数。

9.2 构造从基类开始，析构倒着来#

顺序这件事，背结论不如看输出。下面三个类各自在构造和析构时打印一行，Derived 里还额外放了一个成员对象。

C++
#include <iostream>

class Base {
public:
    Base() { std::cout << "Base 构造\n"; }
    ~Base() { std::cout << "Base 析构\n"; }
};

class Member {
public:
    Member() { std::cout << "Member 构造\n"; }
    ~Member() { std::cout << "Member 析构\n"; }
};

class Derived : public Base {
public:
    Derived() { std::cout << "Derived 构造\n"; }
    ~Derived() { std::cout << "Derived 析构\n"; }

private:
    Member m_;
};

int main() {
    {
        Derived d;
        std::cout << "对象可用\n";
    }
    std::cout << "main 结束\n";
}
运行结果
Base 构造
Member 构造
Derived 构造
对象可用
Derived 析构
Member 析构
Base 析构
main 结束

顺序是：基类、成员、派生类函数体。析构完全反过来。原因不神秘：派生类的构造函数体可能要用基类已经准备好的东西，所以基类必须先就位；析构时派生类可能还要回头用基类，所以基类得活得久一点。

9.3 虚函数：一个循环，两种行为#

这段代码要用到指针，先把话说清楚。指针是一个变量，存的不是数据本身，而是一块数据在内存里的地址。int* p 读作「p 是一个指向 int 的指针」。&d 是取 d 的地址，Animal* a = &d 就让 a 记住了 d 的位置；a->speak() 的意思是「顺着 a 里的地址找到那个对象，调用它的 speak()」。

为什么非要绕这一道：Dog 和 Cat 是两种不同的类型，std::vector<Dog> 装不下 Cat。但「指向 Animal 的指针」只有一种类型，Dog 和 Cat 的对象都能被它指住——因为它们都是 Animal 的派生类。于是同一个循环就能处理所有派生类。

C++
#include <iostream>
#include <string>
#include <vector>

class Animal {
public:
    Animal(const std::string& name) : name_(name) {}
    virtual ~Animal() = default;

    virtual void speak() const {
        std::cout << name_ << "：……\n";
    }

protected:
    std::string name_;
};

class Dog : public Animal {
public:
    Dog(const std::string& name) : Animal(name) {}
    void speak() const override {
        std::cout << name_ << "：汪\n";
    }
};

class Cat : public Animal {
public:
    Cat(const std::string& name) : Animal(name) {}
    void speak() const override {
        std::cout << name_ << "：喵\n";
    }
};

int main() {
    Dog d("旺财");
    Cat c("咪咪");
    std::vector<Animal*> zoo = {&d, &c};
    for (const auto* a : zoo) {
        a->speak();
    }
}
运行结果
旺财：汪
咪咪：喵

去掉 Animal::speak 前面的 virtual 会怎样：输出变成两行「旺财：……」「咪咪：……」。因为编译器编译这个循环时，只看到 a 的类型是 Animal*，就按 Animal 的版本把调用地址定死了。对象明明是真的 Dog，调到的却是基类那一份。

加上 virtual，编译器就改成运行时再问一句「这个对象的真实类型是什么」，然后调用对应的版本。代价是每个带虚函数的类会多出一张虚函数表，每个对象多存一个指针，调用时多一次间接跳转。你不用手写这张表，但要知道它不是免费的。

override 写在派生类函数后面，作用是让编译器检查「这个函数确实覆盖了基类的虚函数」。最容易犯的错是签名差一点：基类写 virtual void speak() const，派生类漏了 const。没有 override 时这不是覆盖，而是一个同名的新函数，程序照样编过，运行时却调不到你想要的那个。加上 override，编译器当场报错。

▲环境设置

override、= default 都是 C++11 才有的写法。Dev-C++ 5.11 默认按老标准编译，不认这些关键字。到「工具 → 编译选项 → 在编译时加入以下命令」里补一行 -std=c++11；VS Code + MinGW 就在 tasks.json 的 args 里加同样的参数。本文代码都按 C++11 写，加这一个参数就能全跑通。

9.4 虚析构：delete 基类指针时的那半个对象#

new Derived 会向系统要一块内存、在上面造一个对象（这块地方叫堆，要手动用 delete 还回去）——第 5 课 构造、析构与 RAII 讲过这对动作要配对。麻烦在于，如果你手里是基类指针，delete 可能只帮你收拾半个对象。

C++
#include <iostream>

class Base {
public:
    Base() { std::cout << "Base 构造\n"; }
    ~Base() { std::cout << "Base 析构\n"; }
};

class Derived : public Base {
public:
    Derived() { std::cout << "Derived 构造\n"; }
    ~Derived() { std::cout << "Derived 析构\n"; }
};

int main() {
    Base* p = new Derived;
    delete p;
    std::cout << "删除完成\n";
}
运行结果
Base 构造
Derived 构造
Base 析构
删除完成

这段输出看着「正常」，其实已经错了：Derived 的析构函数压根没跑。标准把这种写法定为未定义行为——不规定会发生什么，可能只调用基类析构，也可能当场崩，换个编译器或优化级别表现就变。如果 Derived 里有一个 std::string 成员，那么连这个成员的析构函数也不会被调用，它占的那块字符内存就漏了。

修法只有一行：把基类的析构声明成 virtual，写成 virtual ~Base() = default;。改完再跑，会先打印 Derived 析构，再打印 Base 析构。

规则可以记成一句：只要一个类可能被基类指针 delete，它的析构函数就必须是 virtual。反过来，不打算被继承的类可以标成 final，让编译器更放心地优化。

9.5 纯虚函数与抽象类#

Shape 这个基类很尴尬：它可以有 area()，但「一个不知道具体形状的 Shape」面积是多少？没有意义。C++ 的写法是把这种函数声明成纯虚函数：我定接口，实现交给派生类。

C++
#include <iostream>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual const char* name() const = 0;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}

    double area() const override { return 3.14159 * r_ * r_; }
    const char* name() const override { return "圆"; }

private:
    double r_;
};

class Rect : public Shape {
public:
    Rect(double w, double h) : w_(w), h_(h) {}

    double area() const override { return w_ * h_; }
    const char* name() const override { return "矩形"; }

private:
    double w_, h_;
};

void printArea(const Shape& s) {
    std::cout << s.name() << " 面积 " << s.area() << "\n";
}

int main() {
    Circle c(2.0);
    Rect r(3.0, 4.0);
    printArea(c);
    printArea(r);
}
运行结果
圆 面积 12.5664
矩形 面积 12

virtual double area() const = 0; 里的 = 0 不是「返回 0」，而是「这个函数没有实现，类因此变成抽象类」。抽象类不能创建对象，Shape s; 直接编译失败，它只能作为基类被指针或引用指着。

派生类必须实现所有纯虚函数，否则它自己也是抽象类，一样不能造对象。这个机制很适合定义接口：基类只说「能做什么」，派生类决定「怎么做」。

printArea(const Shape& s) 的参数是引用，不是值。如果写成 void printArea(Shape s)，编译器会直接拒绝：抽象类不能按值传递。就算 Shape 不是抽象的，按值传也会切片——只复制基类那部分，派生类的字段全丢了。多态必须通过指针或引用发生，这是硬条件。

9.6 把派生类放进同一个容器#

实际项目里，派生类对象通常放在一个容器里统一管理。下面用 vector 存基类指针，遍历时统一算面积；如果某个对象确实是圆，再单独问它要半径。

C++
#include <iostream>
#include <vector>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual const char* name() const = 0;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}

    double area() const override { return 3.14159 * r_ * r_; }
    const char* name() const override { return "圆"; }
    double radius() const { return r_; }

private:
    double r_;
};

class Rect : public Shape {
public:
    Rect(double w, double h) : w_(w), h_(h) {}

    double area() const override { return w_ * h_; }
    const char* name() const override { return "矩形"; }

private:
    double w_, h_;
};

int main() {
    Circle c(1.0);
    Rect r(2.0, 3.0);
    std::vector<Shape*> shapes = {&c, &r};

    for (Shape* s : shapes) {
        std::cout << s->name() << " " << s->area() << "\n";
        if (auto* pc = dynamic_cast<Circle*>(s)) {
            std::cout << "  半径是 " << pc->radius() << "\n";
        }
    }
}
运行结果
圆 3.14159
  半径是 1
矩形 6

dynamic_cast<Circle*>(s) 在运行时检查 s 到底指向不指向一个 Circle：是就返回有效指针，不是就返回 nullptr（第 8 课 auto、nullptr 与范围 for 讲过的空指针常量）。一句话记住它的适用场合：偶尔需要问「你具体是什么」时才用它；如果代码里到处都在转，通常说明基类接口没设计好。

最后提醒一句所有权：std::vector<Shape*> 只存指针，不负责 delete。上面例子里对象都是直接定义出来的，不是 new 的，所以没问题；如果指针来自 new，就得有人说好谁来释放。第 14 课 智能指针与移动语义：让「谁负责释放」写进类型 里的 unique_ptr 会把这件事变简单。

◆小结
  • 继承把共同部分放进基类，派生类只写差异；public 继承表达「是一种」，不是省代码的工具
  • 构造顺序是基类、成员、派生类，析构顺序完全相反
  • 只有通过基类指针或引用调用虚函数才会多态；override 能当场抓住签名不一致
  • 基类析构必须是 virtual，否则 delete 基类指针只销毁半个对象，而且属于未定义行为
  • 纯虚函数让类变成抽象类，只能通过指针或引用使用；按值传递会发生对象切片
✎练习
  1. 写 Person、Student、Teacher 三个类，Person 里把 introduce() 设为虚函数，用 std::vector<Person*> 遍历调用。给每个类的析构函数加一行打印，观察销毁顺序。
  2. 把 9.3 例子中 Animal::speak 的 virtual 去掉，重新运行并解释输出。再把 Dog::speak 的 const 去掉、保留 override，记录编译器的报错。
  3. 给 9.5 的 Shape 增加一个纯虚函数 perimeter()，让 Circle 和 Rect 实现它，再写一个接收 const Shape& 的函数同时打印面积和周长。
  4. 用一段话解释：为什么 Base* p = new Derived; delete p; 在 ~Base() 不是虚函数时是未定义行为；改成虚析构后，构造和析构的完整顺序是什么。
