第 14 课 智能指针与移动语义：让「谁负责释放」写进类型

预计 32 分钟·约 6,783 字·C++

第 5 课 构造、析构与 RAII 留了个尾巴：new 出来的对象，谁来 delete？手写 delete 的问题不是难，是容易漏。智能指针把「谁拥有这块内存」写进类型里，让编译器替你记住。

这一课还有另一半：移动语义。它和智能指针常常一起出现，因为「把资源从 A 搬到 B」正是智能指针和容器最常做的事。

14.1 裸指针的三个麻烦#

先把三个词说清楚。栈是函数里定义的局部变量住的地方，函数一返回就自动收回。堆是一块公共的大内存，用 new 向它要一块，用 delete 还回去，编译器不会替你记。指针是存地址的变量：int* data = new int[10] 的意思是向堆要 10 个 int 的空间，把第一块的地址存进 data，之后用 data[0]、data[1] 访问每一格。new[] 要用 delete[] 还，new 用 delete 还，两者不能混。

带着这三个词看下面这段代码，它看起来很规矩。

C++
#include <iostream>

int* makeArray(int n) {
    return new int[n];
}

void process(int flag) {
    int* data = makeArray(10);
    if (flag < 0) {
        std::cout << "参数不对\n";
        return;
    }
    data[0] = 1;
    std::cout << data[0] << "\n";
    delete[] data;
}

int main() {
    process(1);
    process(-1);
}
运行结果
1
参数不对

第二次调用 process(-1) 时，return 之前没有 delete[] data，那十个 int 的空间就漏了。每次漏 40 字节，跑一万次就是 400KB。短命的小程序看不出来，长驻的服务器进程里，这就是内存曲线的起点。

第二个问题是重复释放。如果两个指针指向同一块内存，各自以为自己拥有它，析构时各 delete 一次，程序可能在第二次 delete 时崩，也可能过很久才崩，查起来毫无头绪。第三个问题是所有权不清：函数参数写成 int*，你根本不知道调用方期不期望你释放它。指针本身不携带「这块内存该由谁释放」的信息，全靠人记。

异常会让第一个问题变得更隐蔽。new 之后、delete 之前的任何一行如果 throw，后面的 delete 就不会执行，而编译器不会提醒你。智能指针解决的核心就是这件事：把 delete 写进析构函数，让栈展开替你调用。

14.2 unique_ptr：这块对象只归我管#

std::unique_ptr 表示「这个对象只归我管」。它不能拷贝，只能移动。

C++
#include <iostream>
#include <memory>
#include <string>
#include <utility>

class Connection {
public:
    explicit Connection(std::string name) : name_(name) {
        std::cout << "连接 " << name_ << "\n";
    }
    ~Connection() {
        std::cout << "断开 " << name_ << "\n";
    }

    void send(const std::string& msg) const {
        std::cout << name_ << " 发送 " << msg << "\n";
    }

private:
    std::string name_;
};

int main() {
    {
        std::unique_ptr<Connection> conn(new Connection("db"));
        conn->send("hello");

        // std::unique_ptr<Connection> copy = conn;  // 编译错误：不能拷贝

        std::unique_ptr<Connection> moved = std::move(conn);
        if (!conn) {
            std::cout << "conn 已经空了\n";
        }
        moved->send("world");
    }
    std::cout << "作用域结束\n";
}
运行结果
连接 db
db 发送 hello
conn 已经空了
db 发送 world
断开 db
作用域结束

离开最内层代码块时，moved 析构，自动调用 ~Connection，打印「断开 db」。整个过程没有出现一个 delete。

unique_ptr 不能拷贝，因为拷贝意味着两个指针都以为自己是唯一所有者，析构时就会 delete 两次。要转移所有权，用 std::move，转移后原来的指针变成空。if (!conn) 就是判断它手上还有没有对象。它通常和一个裸指针一样大，没有额外的堆分配，也没有引用计数，开销为零。日常写 C++，只要需要堆上的单个对象，默认就用它。

▲版本限制

std::make_unique 是 C++14 才进标准库的。Dev-C++ 5.11 自带的 GCC 4.9 按 -std=c++11 编译会报 'make_unique' is not a member of 'std'，所以本课统一写 std::unique_ptr<T>(new T(...))，这个写法 C++11 就有。

等你的编译器支持 C++14，可以用 make_unique，它不只是短：f(std::unique_ptr<T>(new T), g()) 里如果 g() 先执行并抛异常，new T 出来的对象就没人管了；make_unique 把分配和构造包在函数内部，没有这个窗口。

unique_ptr 还支持自定义删除器：你可以告诉它「不用 delete，收尾时调用这个函数」，比如包装一个打开的文件句柄，让它自动关文件。写法稍微绕，实际项目里更常见的是直接写一个 RAII 包装类，第 5 课的 FileGuard 就是。

14.3 shared_ptr：几个人一起管，最后一个走的关灯#

有些对象确实需要多个地方共同持有，谁最后放手谁负责销毁。这时用 std::shared_ptr。

C++
#include <iostream>
#include <memory>
#include <string>

class Resource {
public:
    explicit Resource(std::string name) : name_(name) {
        std::cout << "创建 " << name_ << "\n";
    }
    ~Resource() {
        std::cout << "销毁 " << name_ << "\n";
    }

private:
    std::string name_;
};

int main() {
    std::shared_ptr<Resource> a = std::make_shared<Resource>("缓存");
    std::cout << a.use_count() << "\n";

    {
        std::shared_ptr<Resource> b = a;
        std::cout << a.use_count() << "\n";
        std::cout << b.use_count() << "\n";
    }

    std::cout << a.use_count() << "\n";
    a.reset();
    std::cout << "main 结束\n";
}
运行结果
创建 缓存
1
2
2
1
销毁 缓存
main 结束

shared_ptr 内部有一个控制块，记录当前有多少个 shared_ptr 指向同一个对象。拷贝一个就加一，销毁一个就减一，减到零时删除对象。所以 b 离开代码块后计数从 2 回到 1，a.reset() 之后计数归零，对象立刻销毁。

make_shared 会把对象和控制块分配在同一块内存里，比 shared_ptr<T>(new T) 少一次分配，这是 C++11 就有的，放心用。

代价也明显：shared_ptr 通常是两个指针大小，引用计数的增减是原子操作，多线程下不会把数字弄乱，但对象本身的读写仍然要你自己加锁。它适合「真的需要共享生命周期」的场景，不是「不知道怎么管就用 shared_ptr」。

最典型的坑是循环引用。两个对象互相持有对方的 shared_ptr，引用计数永远至少是 1，谁也不会先放手，对象就永远不会销毁。打破环的办法是把其中一边换成 std::weak_ptr：它不增加计数，用之前调 lock() 拿一个临时的 shared_ptr，对象还在就拿到有效指针，不在了就拿到空。

还有一个必须避免的写法：用同一个裸指针构造两个独立的 shared_ptr。它们各有各的控制块，都以为自己是唯一管理者，最后会 delete 两次。要共享，就从已有的 shared_ptr 拷贝。

14.4 什么时候用哪个#

场景用什么
栈上放得下的对象直接定义，不用指针
需要堆上的单个对象，独占std::unique_ptr
多处共享同一个对象std::shared_ptr
只观察、不拥有T* 或 T&
一串对象std::vector
一串字符std::string

多态容器是一个典型场景。基类指针的 vector 能装不同的派生类，但谁来 delete？用 unique_ptr 存，所有权就清楚了。

C++
#include <iostream>
#include <memory>
#include <vector>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}
    double area() const override { return 3.14159 * r_ * r_; }

private:
    double r_;
};

class Rect : public Shape {
public:
    Rect(double w, double h) : w_(w), h_(h) {}
    double area() const override { return w_ * h_; }

private:
    double w_, h_;
};

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::unique_ptr<Shape>(new Circle(1.0)));
    shapes.push_back(std::unique_ptr<Shape>(new Rect(2.0, 3.0)));

    double total = 0.0;
    for (const auto& s : shapes) {
        total += s->area();
    }
    std::cout << total << "\n";
}
运行结果
9.14159

容器销毁时，每个 unique_ptr 依次析构，通过基类指针调用虚析构，派生类的资源被正确释放。基类的 virtual ~Shape() = default; 仍然不能省，第 9 课 继承与多态：让不同的东西说同一种话 讲过原因。

函数参数也要想清楚所有权。只是用一下对象，就传 const Shape&；要转移所有权，才传 std::unique_ptr<Shape> 并按值接收，调用方必须 std::move 进来。参数类型本身就是文档：看到 unique_ptr，就知道这个函数会把对象拿走。

14.5 移动语义：把资源搬走，而不是复制#

移动构造和拷贝构造长得很像，区别在参数：拷贝构造接收 const T&，移动构造接收 T&&。

C++
#include <iostream>
#include <string>
#include <utility>

class Token {
public:
    explicit Token(std::string text) : text_(text) {}

    Token(const Token& other) : text_(other.text_) {
        std::cout << "拷贝\n";
    }

    Token(Token&& other) noexcept : text_(std::move(other.text_)) {
        std::cout << "移动\n";
    }

private:
    std::string text_;
};

void take(Token t) {
    std::cout << "收到\n";
}

int main() {
    Token a("hello");
    take(a);
    take(std::move(a));
}
运行结果
拷贝
收到
移动
收到

take(a) 里 a 有名字、能取地址，叫左值，匹配拷贝构造，复制一份 string。take(std::move(a)) 把 a 转成右值引用，匹配移动构造，text_ 直接接管 a 里 string 的内部指针，一个字符都不复制。对长字符串来说，这是一次指针赋值加几次置空，和长度无关。

std::move 本身不移动任何东西。它只是一个类型转换，把左值转成右值引用，告诉编译器「这个对象我不要了，你可以搬」。真正干活的是移动构造函数。

被移动走的对象仍然有效，可以被析构、被重新赋值，但内容是不确定的。标准只保证「有效但未指定」，所以别在 move 之后读它的值。

移动构造要标 noexcept。std::vector 扩容时要把旧元素搬到新内存，如果移动构造可能抛异常，搬到一半失败就没法恢复原状，vector 为了保证强异常安全，会退回用拷贝。标了 noexcept，它才敢用移动。这一条在性能敏感的地方差别很大。

这也解释了「五法则」：如果你写了析构、拷贝构造、拷贝赋值、移动构造、移动赋值中的任何一个，通常五个都得写。只写一半，编译器生成的默认版本可能和你的资源管理方式冲突。第 15 课手写 MyString 时会把五个都过一遍。

14.6 别用 auto_ptr，以及一份检查清单#

std::auto_ptr 是老标准里的尝试，C++11 标记为废弃，C++17 直接删除。它的拷贝构造函数实际做的是转移所有权，传参、放进容器都会悄悄把源对象置空。你以为是拷贝，其实源已经空了，这种「看起来像值语义、实际是移动」的接口是灾难。见到它，改成 unique_ptr。

日常检查可以按这几条来：

  • 能在栈上定义的对象，别用 new
  • 需要堆对象，先想 unique_ptr，确实共享再上 shared_ptr
  • 用 make_shared；make_unique 要 C++14，环境不支持就写 unique_ptr<T>(new T)
  • 数组用 vector，字符串用 string，别用 new[]
  • 函数参数只观察就传 const T&，要接管所有权才传智能指针
  • 析构函数、移动构造、移动赋值该写就写，移动构造记得 noexcept
  • 看到 delete 先问一句：这个指针是我 new 出来的吗，会不会有别人也在 delete

智能指针不是让你从此不关心内存，而是把「谁拥有」这件事从注释里搬到类型里。类型编译器会检查，注释不会。

◆小结
  • 裸指针的问题是所有权不清：漏 delete、重复 delete、异常路径泄漏
  • unique_ptr 独占所有权，不能拷贝只能移动，通常和裸指针一样大
  • shared_ptr 用引用计数共享所有权，循环引用会泄漏，用 weak_ptr 打破
  • std::move 只是类型转换，真正搬资源的是移动构造；移动后源对象别再读
  • 移动构造标 noexcept，vector 扩容才会用它；auto_ptr 已被移除，别用
✎练习
  1. 用 unique_ptr 重写 14.1 的 process，让提前 return 时数组也能自动释放。把 return 改成 throw，再观察一次。
  2. 写两个类，互相用 shared_ptr 持有对方，打印 use_count()，制造循环引用；然后把其中一边改成 weak_ptr，验证对象能正常销毁。
  3. 给 Token 增加移动赋值运算符，写一个 vector<Token> 反复 push_back，观察拷贝和移动各发生了几次，并解释 noexcept 对结果的影响。
  4. 解释区别：std::shared_ptr<int> p(new int(1)); std::shared_ptr<int> q(p); 与 std::shared_ptr<int> q(p.get()); 各自会发生什么；再说明为什么优先用 make_shared。
