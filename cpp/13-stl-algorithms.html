第 13 课 STL 算法与迭代器：装进去之后，怎么处理

预计 30 分钟·约 6,994 字·C++

第 6 课 vector 与 string 和第 7 课 map、set 与 pair 里，你把数据装进了 vector 和 map。这一课处理另一个问题：装进去之后怎么操作。手写 for 循环不是错，但排序、查找、累加这几件事，标准库已经写了几十年，比你我写得好，也比你我写得快。

标准库的算法有个统一的设计：它们不直接接收容器，而是接收一对「位置」。这一对位置叫迭代器。

13.1 迭代器：容器里的「位置」#

begin() 指向第一个元素，end() 指向最后一个元素的再后面一个位置。记住 end() 不是最后一个元素，这是新手最容易差一的地方。

C++
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {10, 20, 30};

    for (auto it = v.begin(); it != v.end(); ++it) {
        std::cout << *it << "\n";
    }

    auto it = v.begin();
    std::cout << *it << " " << *(it + 1) << "\n";
    std::cout << (v.end() - v.begin()) << "\n";
}
运行结果
10
20
30
10 20
3

*it 是「取出 it 指着的那个元素」，++it 是「往后挪一格」，it != end() 是「还没走完」。这套用法和指针很像：指针（第 9 课 继承与多态：让不同的东西说同一种话 讲过）存的是内存地址，迭代器存的是容器里的位置，你可以先把它当成「更通用的指针」。

begin() 和 end() 构成一个左闭右开的区间 [begin, end)，循环条件习惯写 it != end()。it < end() 在 vector 上也能用，换个容器就未必了。空容器里 begin() == end()，循环一次都不跑，这个设计正是为了让你不用特判空容器。

end() 不能解引用。*v.end() 是未定义行为，因为它后面根本没有元素。

迭代器也分档。vector 的迭代器支持 it + n、it2 - it1 和 <；std::list 的迭代器只能 ++ 和 --，不能 + n；map 的迭代器是双向的。所以写通用代码时习惯用 != 而不是 <，用 ++ 而不是 += 1，换个容器也能跑。范围 for（for (int x : v)）本质上就是这套 begin/end 的语法糖。

算法只认迭代器、不认容器，带来一个好处：同一份代码既能处理 vector，也能处理普通数组。数组的「开始」就是数组名，「结束」写作「数组名 + 长度」，传给 std::sort 照样能排。C++11 起还可以直接用 std::begin(a)、std::end(a)，省得自己算。

13.2 sort 与 lambda 比较器#

std::sort 默认从小到大排。要改顺序，就传第三个参数：一个返回 bool 的比较器。C++11 之后最方便的写法是 lambda（就地写的小函数）。

C++
#include <algorithm>
#include <cstddef>
#include <iostream>
#include <string>
#include <vector>

struct Student {
    std::string name;
    int score;
};

void printInts(const std::vector<int>& v) {
    for (std::size_t i = 0; i < v.size(); ++i) {
        if (i != 0) {
            std::cout << " ";
        }
        std::cout << v[i];
    }
    std::cout << "\n";
}

int main() {
    std::vector<int> nums = {5, 2, 9, 1};
    std::sort(nums.begin(), nums.end());
    printInts(nums);

    std::sort(nums.begin(), nums.end(), [](int a, int b) {
        return a > b;
    });
    printInts(nums);

    std::vector<Student> students = {
        {"小明", 80}, {"小红", 95}, {"小刚", 88}
    };
    std::sort(students.begin(), students.end(),
              [](const Student& a, const Student& b) {
                  return a.score > b.score;
              });

    for (const auto& s : students) {
        std::cout << s.name << " " << s.score << "\n";
    }
}
运行结果
1 2 5 9
9 5 2 1
小红 95
小刚 88
小明 80

struct 在这里就是把几个字段打包成一个新类型，它和 class 几乎一样，区别只是默认成员是公开的。students 里每个元素是一个 Student，用 . 访问字段。

lambda 的写法是 [捕获列表](参数) { 函数体 }。捕获列表为空，说明它不用外面的变量；参数是两个待比较的元素；返回值是 bool，表示「a 应不应该排在 b 前面」。

比较器必须满足严格弱序，说人话就是：两个元素相等的时候必须返回 false。用 a < b 或 a > b 都对，用 a <= b 就错了。std::sort 内部假设「比较器说 a 不小于 b、b 也不小于 a」时两者等价，你写 <= 会让它把相等元素判成「a 在 b 前面」，排序过程可能越界，直接崩。这个错误编译器不查，运行时才炸。

std::sort 不保证稳定：两个分数相同的学生，谁排在前面是不确定的。要保留原始顺序，用 std::stable_sort，代价是稍微慢一点、多占一点内存。

sort 也只接受随机访问迭代器，std::list 用不了——链表节点不连续，跳到中间要一步步走。list 有自己的 sort 成员函数，别拿通用算法硬套。

13.3 find、find_if 与 count#

查找是另一个高频操作。std::find 找值，std::find_if 找第一个满足条件的元素，count 和 count_if 负责数数。

C++
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {3, 7, 7, 2, 9};

    auto it = std::find(v.begin(), v.end(), 7);
    if (it != v.end()) {
        std::cout << "找到 7，下标 " << (it - v.begin()) << "\n";
    }

    auto even = std::find_if(v.begin(), v.end(), [](int x) {
        return x % 2 == 0;
    });
    if (even != v.end()) {
        std::cout << "第一个偶数 " << *even << "\n";
    }

    std::cout << std::count(v.begin(), v.end(), 7) << "\n";
    std::cout << std::count_if(v.begin(), v.end(), [](int x) {
        return x > 5;
    }) << "\n";
}
运行结果
找到 7，下标 1
第一个偶数 2
2
3

find 找不到时返回 end()，所以每次都要和 end() 比一下再用。忘了比较、直接 *it，在空容器上就是未定义行为。

it - v.begin() 能算出下标，但只有随机访问迭代器支持减法。换成 list 或 map，要用 std::distance(v.begin(), it)，它对所有迭代器都能算，只是对非随机访问的容器是线性时间。

find 是线性查找，数据量大会慢。数据已经排好序时，用 std::binary_search 或 lower_bound，快得多。map 和 set 有自己的 find 成员函数，走的是平衡树，也别对 map 用 std::find，那会退化成从头扫一遍。

count 返回的类型是 std::ptrdiff_t，不是 int。直接输出或者和 0 比较问题不大，要把结果存下来时用 auto 最省心。

13.4 accumulate 与 for_each#

求和用 std::accumulate，它在 <numeric> 里，不在 <algorithm>。这个头文件很多人第一次找不到。下面这段同时用了 accumulate 和 for_each，所以两个头文件都要有。

C++
#include <algorithm>
#include <iostream>
#include <numeric>
#include <vector>

int main() {
    std::vector<int> v = {1, 2, 3, 4};

    int sum = std::accumulate(v.begin(), v.end(), 0);
    std::cout << sum << "\n";

    double avg = std::accumulate(v.begin(), v.end(), 0.0) / v.size();
    std::cout << avg << "\n";

    int even = 0;
    std::for_each(v.begin(), v.end(), [&even](int x) {
        if (x % 2 == 0) {
            ++even;
        }
    });
    std::cout << even << "\n";
}
运行结果
10
2.5
2

accumulate 的第三个参数是初始值，它的类型决定了整个累加过程的类型。传 0，累加在 int 里进行；传 0.0，才是 double。如果你对 vector<double> 传 0，每个元素会先被截成整数再加，{1.5, 2.5} 会得到 3 而不是 4。这个 bug 很隐蔽，因为结果看起来「差不多对」。

for_each 对每个元素调用一次函数。这里的 lambda 用了 [&even]，按引用捕获外面的变量，所以能改它。捕获列表写 [=] 是按值捕获所有用到的变量，改的是副本，外面的 even 不会变——和范围 for 里写 auto x 的坑一模一样。

说句实话，for_each 能做的事，范围 for 基本都能做，而且后者更好读。for_each 真正的价值在于它能作为算法链的一环，或者你想把「对每个元素做什么」抽成一个函数参数。日常代码里不必为了「用上 STL」而硬套。

accumulate 还能接第四个参数，自定义「怎么加」。比如把一串字符串用逗号拼起来，或者累乘。写这个 lambda 时注意参数顺序：第一个是当前的累计值，第二个是当前元素，返回值是新的累计值。

13.5 把算法串起来：筛选、变换、删除#

真正好用的地方，是把几个算法串起来处理一条数据流。

C++
#include <algorithm>
#include <cstddef>
#include <iostream>
#include <iterator>
#include <vector>

void print(const std::vector<int>& v) {
    for (std::size_t i = 0; i < v.size(); ++i) {
        if (i != 0) {
            std::cout << " ";
        }
        std::cout << v[i];
    }
    std::cout << "\n";
}

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5, 6};

    std::vector<int> evens;
    std::copy_if(v.begin(), v.end(), std::back_inserter(evens), [](int x) {
        return x % 2 == 0;
    });

    std::vector<int> doubled;
    std::transform(v.begin(), v.end(), std::back_inserter(doubled), [](int x) {
        return x * 2;
    });

    v.erase(std::remove_if(v.begin(), v.end(), [](int x) {
        return x < 3;
    }), v.end());

    print(evens);
    print(doubled);
    print(v);
}
运行结果
2 4 6
2 4 6 8 10 12
3 4 5 6

std::back_inserter 返回一个插入迭代器，赋值给它就等于对容器 push_back。它定义在 <iterator> 里，作用是让「往空容器里写」的算法不用提前 resize。它每次插入都可能触发扩容，元素多时效率不高；大概知道规模的话，先 reserve 预留，能省掉反复分配和搬移。

remove_if 是最容易误会的一个。它不删除元素，也不改变容器大小，只是把保留下来的元素往前挪，返回新的逻辑结尾，后面的元素内容是未指定的。所以必须再调一次 erase，把 [newEnd, v.end()) 这一段真正删掉。这个组合叫 erase-remove 惯用法，C++ 里用了二十年。C++20 有了 std::erase_if，一行就能搞定，但我们这套 GCC 4.9 用不上，老老实实写两行。

remove_if 挪动元素时用的是移动赋值，对 std::string 这类类型比逐个拷贝便宜。代价是它要求元素可移动或可拷贝。

13.6 迭代器失效与算法选择#

用算法和迭代器时，最危险的不是写错参数，而是容器变了、迭代器还指着老位置。

C++
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5, 6};

    for (auto it = v.begin(); it != v.end(); ) {
        if (*it % 2 == 0) {
            it = v.erase(it);
        } else {
            ++it;
        }
    }

    for (int x : v) {
        std::cout << x << "\n";
    }
}
运行结果
1
3
5

erase 会让被删位置及其后面的迭代器失效，但它会返回下一个有效位置。所以正确写法是 it = v.erase(it)，并且不要再 ++it，否则会跳过一个元素。如果先 ++it 再 erase，或者 erase 完还拿着旧迭代器，都是未定义行为。

push_back 可能触发扩容，一旦扩容，所有指向旧内存的迭代器、指针、引用全部失效。范围 for 里增删元素是重灾区，第 8 课 auto、nullptr 与范围 for 提过一次，这里再强调一遍：循环里别改容器大小。reserve 能减少扩容次数，但不能让迭代器永远有效——容量一变，位置就变了，这是 vector 连续存储的代价。

选算法的标准很简单：先看数据有没有序。有序就用二分（binary_search、lower_bound），无序就线性扫（find、count）。要排序就用 sort，需要稳定用 stable_sort。求和、求积、拼接用 accumulate。带条件的筛选和变换用 copy_if、transform、remove_if。

算法典型用途复杂度
sort排序O(n log n)
find查找某个值O(n)
binary_search有序区间查找O(log n)
count统计出现次数O(n)
accumulate累加、累乘O(n)
for_each对每个元素执行操作O(n)
◆小结
  • 迭代器是容器里的位置：*it 取值，++it 前进，区间是 [begin, end)
  • sort 的比较器必须严格弱序，相等时返回 false；要稳定排序用 stable_sort
  • find 找不到返回 end()；有序数据用 binary_search，map 用自己的 find
  • accumulate 的初始值类型决定累加类型，求平均值记得写 0.0
  • remove_if 只挪不删，必须配 erase；erase 之后要用它返回的新迭代器
✎练习
  1. 用 std::sort 和 lambda 把 vector<Student> 按分数降序排列；分数相同时按姓名升序。提示：比较器里先比分数，相等再比姓名。
  2. 用 find_if 找出 vector<string> 里第一个长度大于 3 的字符串，找不到时输出提示；再用 count_if 统计以 a 开头的单词个数。
  3. 用 accumulate 求 vector<double> 的平均值。然后把初始值从 0.0 改成 0，运行并解释结果为什么不对。
  4. 用 remove_if 加 erase 删除 vector<int> 里所有负数，再用迭代器打印剩余元素。解释为什么 erase 之后不能继续使用旧的迭代器。
