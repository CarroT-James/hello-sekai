第 1 课 第一个 C++ 程序

预计 20 分钟·约 4,459 字·C++

你双击一个图标，窗口弹出来，能点能滚。这背后是成百上千条指令在按顺序执行，只是被包装得很好看。写程序，就是把这些指令一条条写下来，交给计算机去跑。

麻烦的地方不在「想让它干什么」，在「用什么形式告诉它」。C++ 就是一种形式，而且性格比较严格：少写一个分号，它一句话都不肯跑。严格听起来烦，但好处是你写错的东西在跑起来之前就会被拦住，不用等到交作业前一天才发现。

这一课的目标很小：装好工具，让屏幕上出现一行字，再弄懂这行字是怎么出来的。

1.1 一行代码要经过几道手#

你写下来的东西叫源代码，存在一个后缀为 .cpp 的文本文件里。它就是纯文本，记事本也能打开，计算机本身并不能直接执行。

中间需要一个翻译。C++ 用的翻译叫编译器，它把 .cpp 整个读一遍，检查语法、检查类型、把每句话翻成机器指令，最后吐出一个 .exe（Windows 上）可执行文件。你双击的其实是这个 .exe。

所以每次改完代码，都要重新编译一次。只保存、不编译，运行的一定还是旧的程序——这是新手第一个大坑，改了半天没反应，最后发现忘了按编译键。

C++ 程序有一个硬性规定：必须有且只有一个 main 函数，程序从它开始跑。你可以把 main 想成大门，计算机永远从这扇门进来，门后面的顺序就是你写的顺序。

1.2 装一套能编译的环境#

两条路，选一条就行，不用都装。

路线一：VS Code + MinGW-w64（推荐）#

这条路前期麻烦十分钟，后面舒服四年。

  1. 装编译器。去 winlibs 或 MSYS2 下一个 MinGW-w64 压缩包，解压到 C:\mingw64，保证 C:\mingw64\bin\g++.exe 存在。
  2. 把这个 bin 目录加进系统环境变量 Path，然后关掉所有终端重新打开（不重开不生效）。
  3. 开一个终端，敲 g++ --version。能打出版本号就成了；提示「不是内部或外部命令」，说明第 2 步没做对。
  4. 装 VS Code，在扩展里搜 C/C++（微软那个）装上。
  5. 新建一个文件夹专门放代码，路径全用英文，比如 D:\code\cpp。中文路径会在某些环节莫名其妙地失败。
  6. 在里面新建 hello.cpp，把 1.3 的代码粘进去，Ctrl + 反引号打开终端，敲：
Shell
g++ hello.cpp -o hello.exe
./hello.exe

在 PowerShell 或 cmd 里运行就写 .\hello.exe。第一行是编译，第二行是运行。以后每改一次代码，这两条要重新来一遍。

路线二：Dev-C++ 5.11#

装完就能用，不用配环境变量，机房和考试常用它。

  1. 装 Dev-C++ 5.11，它自带 GCC 4.9.2。
  2. 文件 → 新建 → 源代码，写好代码后另存为 hello.cpp。后缀必须是 .cpp，存成别的后缀它可能不按 C++ 的规则编译。
  3. 按 F11（编译运行），看窗口里出结果。

按 F11 之前还有一步很关键：工具 → 编译选项 → 勾上「编译时加入以下命令」，填 -std=c++11。GCC 4.9 默认按很老的标准编译，不加这句，后面课程里的 auto、范围 for、nullptr 全会报错。报错信息通常很长，核心就一句「没听说过这个词」。

还要提前说清楚一件事：GCC 4.9 是 2014 年的版本，C++17 的新语法它不认识。本站遇到这种地方会明确标出来「Dev-C++ 5.11 自带的 GCC 4.9 不支持」，并且给出一个它能编译的替代写法。你按替代写法写，作业一样能交。

1.3 第一个程序#

C++
#include <iostream>

int main() {
    std::cout << "Hello, Sekai!\n";
    return 0;
}
运行结果
Hello, Sekai!

去掉空行一共五行，逐行看：

  • #include <iostream> 是把标准库里的输入输出工具拿进来。i 是 in，o 是 out，stream 是流。不写这一行，后面的 std::cout 就不认识。
  • int main() 是主函数，程序的入口。int 表示它最后要交回一个整数给操作系统。
  • 一对花括号圈出 main 的范围，里面就是它要干的事。
  • std::cout << "Hello, Sekai!\n" 把双引号里的内容送到屏幕上。\n 是换行符，光标移到下一行开头。
  • return 0; 报告「正常结束」，0 表示成功。

每句结尾的分号不能省，也不能用中文的「；」。这个错我当年犯过不止一次，编译器的报错会指到下一行，看起来跟分号毫无关系，实际就是它。

std:: 是什么？std 是标准库的命名空间，相当于一个姓。标准库里所有东西都姓 std：std::cout、std::string、std::vector。想省事可以在文件开头写 using namespace std;，之后直接写 cout。作业和练习里这么写没问题，但自己心里要知道这是借来的方便：

▲常见错误

using namespace std; 在真实项目里是大忌。两个库都有 count、distance 这类名字时，编译器分不清你指哪个，报错还指不到你写错的地方。初学先图省事可以，但写头文件时永远写全名。

1.4 让程序说话：cout#

cout 最舒服的地方是不用告诉它类型。你给什么，它自己认：

C++
#include <iostream>

int main() {
    int age = 19;
    double score = 91.5;

    std::cout << "年龄 " << age << "，分数 " << score << "\n";
    return 0;
}
运行结果
年龄 19，分数 91.5

<< 读作「插入」，方向是从数据流向屏幕。cout << a << b << c 就是依次把 a、b、c 塞进输出流，中间不用逗号，也不用写任何标记说明「a 是整数、b 是小数」。这个符号原本是数学里的左移运算符，在这里被重新定义成「往屏幕送」，你现在按这个理解就够。

双引号里面可以写中文，输出就是中文。但要留意：引号外面的符号必须是英文半角，分号打成「；」、逗号打成「，」，编译器一律不认。这是我见过最多的第一个错。

换行有两种写法："\n" 和 endl。endl 除了换行还会强制把缓冲区里的内容立刻推出去，屏幕上看不出区别。真要区别，在在线判题里疯狂用 endl 会明显拖慢程序，用 "\n" 更稳。平时写 "\n"，养成习惯。

◆记忆点

cout 不需要格式符，类型它自己判断。你以后会看到别人写 printf("%d", x) 这种带 %d 的写法，那是另一套东西；你只要记住：把值交给 <<，剩下的它负责。

1.5 让程序听话：cin#

程序总得从外面拿数据。cin 负责从键盘读：

C++
#include <iostream>
#include <string>

int main() {
    std::string name;
    int age;

    std::cout << "输入姓名和年龄：";
    std::cin >> name >> age;
    std::cout << name << " 明年 " << age + 1 << " 岁\n";
    return 0;
}
运行结果
输入姓名和年龄：小明 19
小明 明年 20 岁

>> 是提取，箭头方向跟 << 相反，意思是「从 cin 里取一个值，放进右边的变量」。cin >> name >> age 等价于先读 name 再读 age。

它按空格、回车、Tab 自动切分。所以输入 小明 19，小明 进 name，19 进 age，你不需要管中间空了几格。

这里有个细节值得记住：cin >> 读 std::string 时，遇到空格就停，只能读到一个词。想读一整行带空格的内容，得用 getline(std::cin, line)，第 6 课会详细讲。

std::string 是 C++ 的字符串类型，用之前加 #include <string>。它比你想的能干：拼接、比较、取长度、查找都有现成写法，后面专门讲。

注意 cin >> 后面直接写变量名就行，不需要额外加什么符号。这件事背后是 C++ 的引用，第 2 课的主题，你现在先记住结论。

1.6 第一次报错，多半是这三种#

报错信息是英文的、一长串，看着吓人，但真正有用的往往只有第一行的几个词。

第一种：'cout' was not declared in this scope，意思是「我不认识 cout」。两个原因：漏了 #include <iostream>，或者 include 了却写了 cout 而没写 std::（也没加 using namespace std;）。

第二种：expected ';' before ...，缺分号。先看报错那行的上一行结尾有没有分号，九成在那儿，而且经常是中文分号。

第三种：编译过了，结果不对。 这种最麻烦，因为编译器不会帮你找。比如这个：

C++
#include <iostream>

int main() {
    std::cout << 10 / 3 << "\n";
    std::cout << 10 / 3.0 << "\n";
    std::cout << 10 % 3 << "\n";
    return 0;
}
运行结果
3
3.33333
1

两个整数相除，结果还是整数，小数部分直接扔掉，不是四舍五入。10 / 3 得 3，10 / 3.0 得 3.33333，因为右边出现了小数，运算就按浮点数走。% 是取余数，10 % 3 是 1。

这条规则会在你算平均分的时候咬你一口：三个整数加起来除以 3，永远得不到小数。想要小数，把被除数或除数随便一个写成 3.0。

◆小结
  • 源代码是文本，编译器把它翻成可执行文件，改完要重新编译。
  • 程序从 main 开始，return 0; 表示正常结束。
  • std::cout << 往外送，std::cin >> 往里收，箭头方向站在数据流的角度看。
  • std:: 是标准库的命名空间，初学可以 using namespace std;，头文件里别用。
  • 两个整数相除只留整数部分，要小数就写 3.0。

✎练习
  1. 把 1.3 的程序里的文字改成你自己的名字，编译运行。再故意删掉一个分号，把报错信息抄下来，看看它指的是哪一行。
  2. 写一个程序，读入三个整数，输出它们的和与平均值（平均值要带小数，别让整数除法把它截掉）。
  3. 写一个程序，读入一个名字（一个词）和一个年龄，输出「XXX 今年 N 岁，十年后 N+10 岁」。
  4. 猜一猜 7 / 2、7 / 2.0、7 % 2 分别输出什么，先写答案再运行验证。
