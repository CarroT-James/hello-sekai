第 4 课 类与对象：把数据和操作捆在一起

预计 30 分钟·约 6,519 字·C++

第 3 课里那三个 show 重载，每个管一种数据。可如果这些数据本来就属于同一个东西呢？一个学生有姓名、三门成绩，「算平均分」「判断及格」这些操作天生就该跟着这个学生走，而不是散在文件各处，等别人想起来才调一次。

这一课就干这件事：把数据和对数据的操作装进同一个东西里。这个东西叫类，从它创建出来的具体实例叫对象。

4.1 数据一多，就散了#

不用类，一个学生大概长这样：

C++
#include <iostream>
#include <string>

double average(int a, int b, int c) {
    return (a + b + c) / 3.0;
}

int main() {
    std::string name1 = "小明";
    int chinese1 = 80, math1 = 90, english1 = 70;

    std::string name2 = "小红";
    int chinese2 = 50, math2 = 55, english2 = 60;

    std::cout << name1 << " 平均 " << average(chinese1, math1, english1) << "\n";
    std::cout << name2 << " 平均 " << average(chinese2, math2, english2) << "\n";

    chinese1 = 999;   // 没人拦得住这一句
    std::cout << "改完以后：" << average(chinese1, math1, english1) << "\n";
    return 0;
}
运行结果
小明 平均 80
小红 平均 55
改完以后：386.333

能跑，两个学生也没问题。但学生变成 40 个呢？你就得写 name37、math37。再给每个学生加一门物理，变量要加 40 个，average 的签名要改，所有调用点要改，漏一个就编译不过——这还算好的，编译器至少会提醒。真正的麻烦是编译器不会提醒的那种错：你把 math1 传到了 english 的位置，类型一样，编译通过，成绩单悄悄错了。

变量名后面那个 1、2，本质是你用命名在手工维护一组编了号的变量，这活儿应该交给机器。

还有第二个问题：数据全公开。上面那句 chinese1 = 999; 编译通过，运行通过，平均分从 80 变成 386.3，全程一声不响。等你发现成绩单不对，已经不知道是哪一行改的。

4.2 class：把函数也搬进去#

类解决的就是这两个问题：把一组相关数据打包成一个整体，再把操作这些数据的函数也放进去，顺便决定哪些能给外面看、哪些不给。

C++
#include <iostream>
#include <string>

class Student {
public:
    Student() : name_("未命名"), chinese_(0), math_(0), english_(0) {}

    Student(const std::string& name, int chinese, int math, int english)
        : name_(name), chinese_(chinese), math_(math), english_(english) {}

    double average() const {
        return (chinese_ + math_ + english_) / 3.0;
    }

    bool isPass() const {
        return average() >= 60;
    }

    void print() const {
        std::cout << name_ << "，平均分 " << average()
                  << "，" << (isPass() ? "及格" : "不及格") << "\n";
    }

private:
    std::string name_;
    int chinese_;
    int math_;
    int english_;
};

int main() {
    Student a("小明", 80, 90, 70);
    Student b;
    Student c("小红", 50, 55, 60);

    a.print();
    b.print();
    c.print();
    std::cout << "a 的平均分：" << a.average() << "\n";
    return 0;
}
运行结果
小明，平均分 80，及格
未命名，平均分 0，不及格
小红，平均分 55，不及格
a 的平均分：80

class Student { ... }; 定义了一个新类型，从此 Student 和 int、double 是一个级别的词，你可以用它声明变量——只是习惯上把类的变量叫对象。

几个新东西逐个说：

  • 结尾那个分号别漏。漏了会报一串看不懂的错，位置还指在下一行。
  • public: 下面的成员对外公开，private: 下面的只有类自己能用。成员函数放 public，数据成员放 private，这是最常见的布局。
  • 成员变量后面那个 _ 是我自己的习惯：参数叫 name、成员叫 name_，一眼分得清谁是谁。你也可以不加，全项目统一就行。
  • 成员函数末尾的 const 表示「这个函数保证不改成员变量」。average() 只读不写，标上之后你要是手滑在里面写 chinese_ = 0;，编译直接拦住。这是第 2 课那个 const 的自然延伸。

注意 average() 里能直接写 chinese_，不用 a.chinese_。成员函数本来就工作在某个对象内部，它看到的就是「我这个对象的成员」。

4.3 public / private：封装在保护什么#

封装这个词听着玄，其实就一句话：数据只能从你留的门进来。

假如 chinese_ 是 public，外面写一句 a.chinese_ = 999; 完全合法。成绩变成 999，average() 算出来毫无意义，而且没有任何地方报错。等你在成绩单上看到 386 分，已经查不出是谁干的。

改成 private，这句直接编译不过。想改成绩，必须走你写的入口：

C++
#include <iostream>

class Score {
public:
    explicit Score(int value = 0) : value_(value) {}

    bool set(int value) {
        if (value < 0 || value > 100) {
            return false;
        }
        value_ = value;
        return true;
    }

    int get() const {
        return value_;
    }

private:
    int value_;
};

int main() {
    Score s(80);

    std::cout << "改 90：" << (s.set(90) ? "成功" : "失败") << "\n";
    std::cout << "现在 " << s.get() << "\n";

    std::cout << "改 120：" << (s.set(120) ? "成功" : "失败") << "\n";
    std::cout << "还是 " << s.get() << "\n";
    return 0;
}
运行结果
改 90：成功
现在 90
改 120：失败
还是 90

set 就是你留的那扇门。它先检查范围，不合法的值根本进不来。这类函数通常叫 setter，配套的只读函数叫 getter。

这就是 private 的真正价值：不是「藏起来不让你看」，是「错的东西进不来」。一个班 40 个人的成绩，总有一两个地方会传错，把校验放在门口，比你事后一个个查便宜。

★补充说明

封装常被类比成电视机：你按遥控器（public 接口），不用打开后盖碰电路板（private 数据）。这个类比有一处不准——电视坏了大不了自己拆，类的 private 是真的碰不到。顺便说一句：C++ 里 struct 和 class 唯一的区别是默认访问权限，class 默认 private，struct 默认 public。struct 也能写成员函数和构造函数，两者不是两种东西。

4.4 构造函数：对象出生时该干什么#

Student b; 这句创建对象的时候，谁负责把 name_ 弄成「未命名」、把三个成绩弄成 0？构造函数。

构造函数的名字和类名一样，没有返回类型（连 void 都不写），可以重载。它在对象创建的那一刻自动执行，你没法跳过。

C++
#include <iostream>
#include <string>

class Book {
public:
    Book() : title_("无名"), price_(0.0) {}

    Book(const std::string& title, double price)
        : title_(title), price_(price) {}

    void print() const {
        std::cout << title_ << "：" << price_ << " 元\n";
    }

private:
    std::string title_;
    double price_;
};

int main() {
    Book a;
    Book b("C++ Primer", 128.0);
    a.print();
    b.print();
    return 0;
}
运行结果
无名：0 元
C++ Primer：128 元

冒号后面那一串叫初始化列表。Book(const std::string& title, double price) : title_(title), price_(price) {} 的意思是：进入函数体之前，先用参数 title 初始化成员 title_，用参数 price 初始化 price_。花括号里是空的，因为这个构造函数的活已经干完了。

为什么不写成花括号里赋值？区别在效率：初始化列表是直接构造，函数体赋值是先默认构造一次，再赋值一次。std::string 这么干，等于先建一个空串再把它扔掉，白做一遍功。如果成员是 const 或者引用，它们只能在创建时绑定，函数体赋值根本编不过——这是硬规定，不是习惯问题。

还有一条规则必须知道：只要你写了任何一个构造函数，编译器就不再免费送你无参的那个。 所以 Book a; 想编过，你必须自己写一个无参构造函数——上面那个类里两个构造函数就是这么来的：一个默认、一个带参。

▲常见错误

想用无参构造创建对象，写 Book a;，不要写 Book a();。后者在编译器眼里是函数声明：声明了一个叫 a、没有参数、返回 Book 的函数。等你写 a.print() 就会报一串怪错，因为 a 根本不是对象。这个坑有个专门的名字，叫 most vexing parse。口诀：带括号又不给参数，就是函数声明。

4.5 this：成员函数里的「我自己」#

成员函数里怎么指「当前这个对象」？用 this。

C++
#include <iostream>

class Point {
public:
    void setX(int x) {
        this->x = x;
    }
    int getX() const {
        return x;
    }
private:
    int x = 0;
};

class Counter {
public:
    Counter& add(int n) {
        count_ += n;
        return *this;
    }
    int value() const {
        return count_;
    }
private:
    int count_ = 0;
};

int main() {
    Point p;
    p.setX(7);
    std::cout << p.getX() << "\n";

    Counter c;
    c.add(1).add(2).add(3);
    std::cout << c.value() << "\n";
    return 0;
}
运行结果
7
6

this 是一个指向当前对象的指针，*this 就是当前对象本身。成员函数里你写 count_，编译器其实按 this->count_ 处理，所以大多数时候你看不见它。

只有两种场合必须亲手写：

一是参数和成员同名。 Point::setX(int x) 里两个都叫 x，this->x 明确指成员，右边的 x 是参数。不写 this，成员就被参数遮住了，x = x 变成自己给自己赋值，什么也没干。

二是想返回对象自己。 Counter::add 的返回类型是 Counter&——注意是引用，不是 Counter。return *this; 就是「把我自己交出去」，于是 c.add(1).add(2).add(3); 能连成一句。这就是链式调用：每一环都返回自己，下一环才能接着点。

返回 Counter& 而不是 Counter，是为了不复制。链式调用改的一直是同一个对象，复制一份出去改，改的就不是它了。

★补充说明

this 只存在于非静态成员函数里。静态成员函数属于整个类，不属于某个具体对象，里面没有「当前对象」，所以不能用 this。静态成员是后面的话题，先记住这一句。

4.6 成员函数写到类外#

上面的成员函数都写在类里面。稍微正式一点的项目，习惯是「声明放头文件、定义放源文件」，函数体写在类外：

C++
#include <iostream>

class Rectangle {
public:
    Rectangle(double width, double height);
    double area() const;
    double perimeter() const;

private:
    double width_;
    double height_;
};

Rectangle::Rectangle(double width, double height)
    : width_(width), height_(height) {}

double Rectangle::area() const {
    return width_ * height_;
}

double Rectangle::perimeter() const {
    return 2 * (width_ + height_);
}

int main() {
    Rectangle r(3, 4);
    std::cout << "面积 " << r.area() << "，周长 " << r.perimeter() << "\n";
    return 0;
}
运行结果
面积 12，周长 14

Rectangle:: 叫作用域限定符，告诉编译器「这个 area 是 Rectangle 的成员，不是外面随便一个函数」。构造函数也一样，写 Rectangle::Rectangle，前面是类名、后面是函数名，看着像重复，但这就是语法。

类内定义和类外定义有什么区别？类内定义的函数默认带 inline，适合一两行的短函数；类外定义适合长函数，也是工程里分文件的标准做法。类外定义时漏了 类名::，这个函数就变成了一个普通函数——带着 const 会直接编译报错，不带 const 则要等到链接时才发现「找不到成员函数的定义」，那时候报错信息会很难读。

◆小结
  • class 把数据成员和成员函数装进一个类型，private 保护数据，public 给出入口。
  • 构造函数负责初始化，能用初始化列表就别在函数体里赋值。
  • this 指向当前对象，参数同名和返回自身时要用它。
  • 类外定义成员函数，必须写 类名::函数名。
  • 下一课是第 5 课 构造、析构与 RAII，讲对象怎么死，以及「死的时候自动把资源还回去」。
