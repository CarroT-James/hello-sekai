第 2 课 引用与 const

预计 25 分钟·约 4,793 字·C++

第 1 课留了一句话没解释：cin >> name 后面为什么直接写变量名，不用加别的东西。答案就是这一课的主题——引用。

引用是 C++ 里最便宜也最容易被忽略的机制。它本身没有新语法花样，但后面讲传参、讲类、讲拷贝，全都建在它上面。这一课把它的脾气摸清楚，顺便把 const 一起讲了，因为这两个东西几乎总是同时出现。

2.1 引用就是给变量起个外号#

C++
#include <iostream>

int main() {
    int a = 10;
    int& r = a;          // r 是 a 的另一个名字
    r = 20;              // 改 r，就是改 a

    std::cout << "a = " << a << "，r = " << r << "\n";
    std::cout << "sizeof(r) = " << sizeof(r) << "\n";
    return 0;
}
运行结果
a = 20，r = 20
sizeof(r) = 4

int& r = a; 这个写法要念成「r 是 a 的引用」。& 跟在类型后面，只表示「这是个引用」，没有别的意思——你在别的地方可能见过这个符号，在这里它只有这一个用途。

执行完 r = 20，a 也变成 20 了。因为 r 和 a 指的根本就是同一个变量，只是名字不同。你可以想成给同一个人起了个外号，叫外号跟叫本名，答应的都是同一个人。

第二行输出 sizeof(r) = 4，跟 sizeof(int) 一模一样。这一条最能说明问题：引用不是一个新对象，它不占一块新内存，也没有自己的值。它就是那个变量本人，换了个称呼。编译器内部大概率是用地址来实现它的，但那是编译器的事，你按「别名」理解就够。

也正因为是别名，引用没有「拷贝」这回事。写 int r = a;（少一个 &）才是复制，那是两个独立的变量，改一个另一个不动。这一对差别后面会反复出现。

2.2 三条规矩，一条都不能破#

第一条：声明的时候就得绑好。

int& r; 这一行编不过。引用必须指着某个已经存在的变量，写成 int& r = a; 才算完整。这条规矩带来的好处很实在：只要你手上有一个引用，它就一定指向一个真实存在的东西，你不用检查它是不是空的。

第二条：绑上之后不能改绑。

C++
#include <iostream>

int main() {
    int a = 1;
    int b = 2;
    int& r = a;

    r = b;      // 注意：这不是「让 r 改指 b」
    std::cout << "a = " << a << "，b = " << b << "，r = " << r << "\n";
    return 0;
}
运行结果
a = 2，b = 2，r = 2

很多人第一次看这段会以为 r = b 之后 r 变成 b 的别名了。不是。r 永远是 a 的别名，r = b 只是「把 b 的值赋给 a」。所以 a 和 b 都变成 2，r 还是 2，因为它就是 a。

C++ 里没有「把引用改指向别人」这种操作。想换目标，只能换一个引用变量，或者用别的手段。这条限制听起来死板，实际是好事：函数收到一个引用，它就知道自己从头到尾动的是同一个对象。

第三条：引用不是对象，不能被存起来。

这条现在不用深究，你只要记住：引用是「别名」这个层次的东西，不是一份可以被保存的数据。所以「装引用的数组」这种东西不存在，int& arr[3] 编不过。

三条规矩合起来，效果就是：拿到一个引用，它一定指着某个真实存在的变量，而且从生到死都指着同一个。

◆记忆点

三句话概括引用：必须绑、不能改绑、不占新内存。它的所有好处和所有限制，都是从这三条推出来的。

2.3 引用做参数：省掉一次复制#

交换两个变量的值，是练习传参的经典题。先用引用写一遍：

C++
#include <iostream>

void swapValues(int& x, int& y) {
    int t = x;
    x = y;
    y = t;
}

int main() {
    int a = 1, b = 2;

    swapValues(a, b);
    std::cout << "a = " << a << "，b = " << b << "\n";
    return 0;
}
运行结果
a = 2，b = 1

调用的时候写 swapValues(a, b)，跟普通函数没区别。但函数里的 x 就是外面的 a，y 就是外面的 b，所以函数里的交换真的作用到了外面。

如果参数写成 int x, int y（不加 &），就是另一回事了：那是传值，函数收到的是实参的复印件。你在函数里把 x 和 y 换过来，调用者的 a、b 一点变化都没有。这是新手最容易懵的地方——函数里明明换了，回来一看没变。

复制这件事对小类型（int、double、char）无所谓，反正就几个字节。但对 std::string 这种装着一串字符的对象，复制就贵了：

C++
#include <iostream>
#include <string>

void addSuffixByValue(std::string s) {
    s += "同学";
}

void addSuffixByRef(std::string& s) {
    s += "同学";
}

int main() {
    std::string a = "小明";
    std::string b = "小红";

    addSuffixByValue(a);
    addSuffixByRef(b);

    std::cout << "a = " << a << "\n";
    std::cout << "b = " << b << "\n";
    return 0;
}
运行结果
a = 小明
b = 小红同学

addSuffixByValue(a) 改的是 a 的一份拷贝，函数一返回拷贝就没了，a 完好无损。addSuffixByRef(b) 里的 s 就是 b 本人，改完留在 b 身上。

开销差多少？a 有 100 万个字符，传值就得复制 100 万个字节；传引用只递一个位置信息，不管对象多大，成本都是固定的。这就是为什么见到「传参」你该条件反射地问一句：这玩意儿大不大。

2.4 const 引用：只读传大对象的标配#

引用有个副作用：函数能改你的东西。可很多时候你只想让它读一读，不许动手。这时候加 const：

C++
#include <iostream>
#include <string>

void show(const std::string& s) {
    std::cout << s << "\n";
}

int main() {
    std::string name = "小明";

    show(name);
    show("这是一个字符串字面量");
    show(name + " 同学");
    return 0;
}
运行结果
小明
这是一个字符串字面量
小明 同学

const std::string& 读作「绑定到 const 的引用」：不复制，也不许改。函数里你要是手滑写 s += "x"，编译器直接拦住，调用者可以放心。

注意后两次调用：传进去的不是变量，一个是用双引号直接写死的字符串（术语叫字面量），一个是当场拼出来的临时结果。这两行能跑，全靠 const。要是把 const 去掉，写成 void show(std::string& s)，这两行立刻编不过。

原因不难想：name + " 同学" 是当场算出来的临时结果，用完就没地方了。让你拿一个能随便改的引用绑上去，改完它已经销毁，改的是一场空。所以语言规定：非 const 引用只能绑变量，const 引用什么都能绑。const 相当于你保证只看不动，编译器才放行。

▲常见错误

void f(std::string& s) 配上 f("abc") 会报错，报错信息通常是 invalid initialization of non-const reference。看到这句，先想想是不是该加 const，而不是去怀疑字符串有问题。

2.5 最容易犯的错：返回局部变量的引用#

引用能当参数，也能当返回值。但当返回值的时候，有个坑必须提前讲。

函数里定义的变量叫局部变量，函数一执行完，它就销毁了，占的那块内存被回收。如果你把它的引用返回出去，外面拿到的就是一个「指向已经不存在的东西」的引用，这叫悬空引用。

C++
#include <iostream>
#include <string>

// 错误示范：返回局部变量的引用
const std::string& badTitle() {
    std::string s = "C++ 入门";
    return s;              // s 在函数返回时就销毁了
}

// 正确写法：老老实实返回值
std::string goodTitle() {
    return "C++ 入门";
}

int main() {
    std::cout << goodTitle() << "\n";
    // std::cout << badTitle() << "\n";   // 未定义行为，别取消注释
    return 0;
}

badTitle 里返回的那个引用，指向一块已经不属于你的内存。读出来是什么？可能还是原来的字符串，可能是乱码，也可能直接崩。C++ 管这种情况叫未定义行为：标准不承诺任何结果，全看你运气。

它最讨厌的地方是可能看起来正常。在你电脑上跑出正确结果，换台机器、或者中间多打一行日志，就崩了。这种 bug 找起来能花掉一晚上，因为你会怀疑所有地方，就是不怀疑返回值。

正确做法很简单：要返回就返回值。有人担心复制很贵，其实编译器会做优化，实际代价比你想的小得多。

★补充说明

能安全返回的引用只有三类：传进来的参数、对象的成员、static 变量。判断标准只有一句：这个对象活过函数返回了吗。活不过，就别返回引用。

2.6 传参怎么选：一张表收尾#

三种写法摆在一起，选型其实很快：

写法会不会复制能不能改实参能不能接字面量
void f(int x)会不会能
void f(int& x)不会会不能
void f(const int& x)不会不会能

口诀是这样的：

  • 小类型（int、double、char）直接传值，复制几个字节不算事，写起来还简单。
  • 要改调用者的变量，传 T&。
  • 只读的大对象（std::string、std::vector、自定义的类），一律 const T&。

第三条覆盖了你现在能遇到的绝大多数情况。养成「只读就加 const」的习惯，好处不只是性能：别人读你的函数签名，一眼就知道它会不会动我的数据。

★补充说明

标准库已经写好了 std::swap(a, b)，参数就是引用，直接用就行。2.3 那个 swapValues 是拿来看原理的，不用自己再写一遍。

◆小结
  • 引用是别名，声明时必须绑定，之后不能改绑，也不占新内存。
  • 传引用不复制，函数里改的就是外面那个变量；传值改的是复印件。
  • 只读的大对象一律 const T&，它还能接字面量和临时结果。
  • 返回引用之前先问：那个对象还活着吗？
  • 下一课是第 3 课 函数重载与默认参数，讲同名函数怎么共存。
