第 15 课 类设计实战：手写一个 MyString

预计 34 分钟·约 7,196 字·C++

标准库的 std::string 已经够用了，为什么还要自己写一个？因为面试会问，因为作业会留，更因为写一遍你才知道编译器默认送你的那几个函数有多危险。这一课就手写一个坑坑洼洼的 MyString，最后再收个尾做个 Matrix。

这不是要造一个比标准库更好的轮子，而是把轮子拆开，看看辐条是怎么断的。

15.1 动手前先定接口和所有权#

先列接口。一个能用的字符串类至少要有这些操作：

操作作用
MyString()构造空串
MyString(const char*)从一段字符数组构造
MyString(const MyString&)拷贝构造，深拷贝
operator=拷贝赋值，深拷贝
~MyString()释放内存
size()返回长度
c_str()返回内部那段字符数组
operator[]读写单个字符

比接口更重要的是「谁分配、谁释放」。我的约定是：构造函数分配，析构函数释放，拷贝必须复制一份自己的内存。这条约定在写第一行代码之前就得定下来，边写边想一定会漏。

内部成员只需要两个：一个 char* data_，存 new 出来的那块字符数组的首地址（new、堆、指针这三个词第 14 课 智能指针与移动语义：让「谁负责释放」写进类型 讲过）；一个 std::size_t size_ 记录长度，size_t 是专门表示大小和下标的无符号整数。

这块数组末尾永远留一个 '\0'。'\0' 是值为 0 的字符，约定它表示「字符串到此为止」。有了它，c_str() 可以直接返回 data_，任何按这个约定处理字符数组的函数也能直接用。

为什么不每次用 strlen(data_) 现算长度？因为那要一个字符一个字符数到 '\0'，是 O(n)；在循环里每次都算就变成 O(n²)。长度是构造时就知道的信息，存下来几乎不花代价。

15.2 构造、析构与 c_str#

C++
#include <cstddef>
#include <cstring>
#include <iostream>

class MyString {
public:
    MyString() : data_(new char[1]()), size_(0) {}

    explicit MyString(const char* text) {
        size_ = std::strlen(text);
        data_ = new char[size_ + 1];
        std::strcpy(data_, text);
    }

    ~MyString() {
        delete[] data_;
    }

    std::size_t size() const { return size_; }
    const char* c_str() const { return data_; }

private:
    char* data_;
    std::size_t size_;
};

int main() {
    MyString empty;
    MyString hello("hello");
    std::cout << empty.size() << " " << hello.c_str() << " "
              << hello.size() << "\n";
}
运行结果
0 hello 5

std::strlen(p) 从 p 开始一个字符一个字符数，数到第一个 '\0' 为止，返回字符个数；std::strcpy(dst, src) 把 src 连同末尾的 '\0' 一起复制到 dst。这两个都在 <cstring> 里，它们只认「以 '\0' 结尾的字符数组」这种布局，所以 +1 那个位置不能省——漏掉它，strcpy 会往后多写一个字节，这种错误有时候跑一百次都不崩，有时候当场炸。

默认构造函数用 new char[1]() 分配一个字节并清零，保证 c_str() 永远返回一个合法的空串，而不是空指针。多花一个字节，省掉调用方到处判空。

explicit 阻止编译器做隐式转换。没有它，MyString s = "hello"; 能编过，因为编译器会自动把 const char* 转成 MyString。这种隐式转换在传参时特别容易出意外，加上 explicit，想转换就必须显式写 MyString("hello")。

现在这个类能构造、能析构、能读，看起来没问题。但它还没有自己的拷贝构造函数。编译器会免费送你一个，做的事情是逐成员复制：把 data_ 指针复制一份，把 size_ 复制一份。于是两个对象指向同一块内存，谁先析构谁把它释放，另一个就成了悬空指针，再析构一次就是重复释放。

15.3 拷贝构造：深拷贝#

拷贝构造要做的，是给新对象分配一块自己的内存，再把内容复制过去。

C++
#include <cstddef>
#include <cstring>
#include <iostream>

class MyString {
public:
    MyString() : data_(new char[1]()), size_(0) {}

    explicit MyString(const char* text) {
        size_ = std::strlen(text);
        data_ = new char[size_ + 1];
        std::strcpy(data_, text);
    }

    MyString(const MyString& other) {
        size_ = other.size_;
        data_ = new char[size_ + 1];
        std::strcpy(data_, other.data_);
    }

    ~MyString() {
        delete[] data_;
    }

    std::size_t size() const { return size_; }
    const char* c_str() const { return data_; }

    char& operator[](std::size_t i) { return data_[i]; }
    const char& operator[](std::size_t i) const { return data_[i]; }

private:
    char* data_;
    std::size_t size_;
};

int main() {
    MyString a("hello");
    MyString b = a;
    b[0] = 'H';
    std::cout << a.c_str() << " " << b.c_str() << "\n";
}
运行结果
hello Hello

MyString b = a; 是拷贝初始化，调用的是拷贝构造函数，不是赋值运算符（虽然用了等号）。b 有自己的内存，改 b 的第一个字符不会影响 a。如果删掉拷贝构造、让编译器生成默认版本，输出会变成 Hello Hello，而且程序结束时大概率崩在第二次 delete[] 上。这就是浅拷贝的典型症状。

拷贝构造的参数必须是 const MyString&。如果写成按值传参 MyString(MyString other)，传参本身就要调用拷贝构造，而拷贝构造又需要传参，无限递归，编译器会直接拒绝。

operator[] 提供了 const 和非 const 两个版本，理由和第 10 课 运算符重载与友元：让自定义类型也用上 + 号 一样：const 对象只能读，普通对象可读可写。这里不做越界检查，和标准库的 string::operator[] 保持一致。

15.4 拷贝赋值：自赋值与「先分配后释放」#

拷贝构造只管「从无到有」，拷贝赋值要处理「已经有一块内存，现在要换成另一块」。这里有两个坑：自赋值，以及分配失败时的状态。

在 15.3 的类里加上这个函数，其余不动：

C++
MyString& operator=(const MyString& other) {
    if (this == &other) {
        return *this;
    }

    char* newData = new char[other.size_ + 1];
    std::strcpy(newData, other.data_);

    delete[] data_;
    data_ = newData;
    size_ = other.size_;

    return *this;
}

先看自赋值。a = a 这种写法看起来莫名其妙，但 v[i] = v[j] 在 i 和 j 相等时就发生了，排序、去重、容器搬移的代码里都可能出现。this 是成员函数里指向「当前对象自己」的指针，&other 是 other 的地址，两者相等就说明是自赋值。按最直觉的顺序写——先 delete[] data_，再分配、再复制——那时 other 就是自己，other.data_ 跟着变成悬空指针，strcpy 从已经释放的内存里读数据，结果不可预测。我当年就这么写过，测试时程序直接崩，还以为是编译器坏了。

再看顺序。正确的顺序是：先分配新内存、复制内容，确认成功后再释放旧内存、替换指针。如果反过来，先 delete[] data_ 再 new，而 new 抛了 std::bad_alloc（内存不够时它抛这个），这个对象就处于「指针已释放、内容全没了」的坏状态，调用方连重试都做不到。按现在的写法，new 失败时对象原封不动，这叫基本异常保证。

返回 MyString& 指向 *this，这样 a = b = c 能从右往左链式赋值。返回类型不能是 MyString，否则每次赋值多一次拷贝；也不能是 const MyString&，那样 (a = b) = c 就编不过了。

还有一种更省心的写法叫 copy-and-swap：先按值拷贝出一个临时对象，再和 *this 交换内部指针。它自带强异常保证，代价是多写一个 swap，而且多一次分配。先把上面这版写对，再去了解那个。

15.5 五法则与移动构造#

到这里，MyString 已经有了析构、拷贝构造、拷贝赋值。C++11 之后还有移动构造和移动赋值，合起来叫「五法则」。把这两个也加进类里。T&& 和 noexcept 都是 C++11 的语法，Dev-C++ 记得在编译选项里加 -std=c++11，具体怎么加第 9 课写过。

C++
MyString(MyString&& other) noexcept
    : data_(other.data_), size_(other.size_) {
    other.data_ = nullptr;
    other.size_ = 0;
}

MyString& operator=(MyString&& other) noexcept {
    if (this != &other) {
        delete[] data_;
        data_ = other.data_;
        size_ = other.size_;
        other.data_ = nullptr;
        other.size_ = 0;
    }
    return *this;
}

移动构造不分配内存，直接把 other 的指针接过来，再把 other 置空。对一块很长的字符串，这是一次指针赋值，和长度无关；拷贝构造则要逐个字符复制。delete[] nullptr 是安全的，所以被搬空的对象照样能正常析构。

移动赋值的自赋值检查同样不能省。a = std::move(a) 虽然少见，但模板和容器代码里可能出现，没有检查就会先删掉自己的内存，再把悬空指针赋回给自己。

被移动走的对象只能析构或重新赋值，不要调用 c_str()——这个实现里它的 data_ 是 nullptr，打印它是未定义行为。标准的要求是「有效但未指定」，工业级的 string 会让它回到空串状态，代价是要么多一次分配，要么做短字符串优化。

这里有一条容易忽略的规则：一旦你声明了移动构造或移动赋值，编译器就不会再隐式生成拷贝构造和拷贝赋值，它们会被定义为删除的。所以五个函数要么都写，要么一个都别写。只写移动不写拷贝，类就变成只能搬不能复制，往往不是你想要的。

15.6 Matrix：什么时候一个都不用写#

MyString 必须手写五个函数，是因为它直接持有裸指针。如果类里的成员自己会管理资源，情况就完全不同。

C++
#include <cstddef>
#include <iostream>
#include <stdexcept>
#include <vector>

class Matrix {
public:
    Matrix(std::size_t rows, std::size_t cols, double fill = 0.0)
        : rows_(rows), cols_(cols), data_(rows * cols, fill) {}

    double& at(std::size_t r, std::size_t c) {
        return data_.at(index(r, c));
    }

    const double& at(std::size_t r, std::size_t c) const {
        return data_.at(index(r, c));
    }

    std::size_t rows() const { return rows_; }
    std::size_t cols() const { return cols_; }

    Matrix operator+(const Matrix& other) const {
        if (rows_ != other.rows_ || cols_ != other.cols_) {
            throw std::invalid_argument("矩阵尺寸不一致");
        }
        Matrix result(rows_, cols_);
        for (std::size_t i = 0; i < data_.size(); ++i) {
            result.data_[i] = data_[i] + other.data_[i];
        }
        return result;
    }

private:
    std::size_t index(std::size_t r, std::size_t c) const {
        if (r >= rows_ || c >= cols_) {
            throw std::out_of_range("矩阵下标越界");
        }
        return r * cols_ + c;
    }

    std::size_t rows_;
    std::size_t cols_;
    std::vector<double> data_;
};

int main() {
    Matrix a(2, 2, 1.0);
    Matrix b(2, 2, 2.0);
    Matrix c = a + b;
    std::cout << c.at(0, 0) << " " << c.at(1, 1) << "\n";

    try {
        Matrix d(2, 3);
        Matrix e = a + d;
        std::cout << e.rows() << "\n";
    } catch (const std::exception& ex) {
        std::cout << ex.what() << "\n";
    }
}
运行结果
3 3
矩阵尺寸不一致

Matrix 用一维的 vector<double> 存二维数据，下标换算成 r * cols_ + c。这样整块内存是连续的，按行遍历时 CPU 的缓存能一次捞到一片相邻数据，比 vector<vector<double>> 快不少——后者每一行都是一次额外的指针跳转。

最关键的是，Matrix 一个析构、拷贝构造、拷贝赋值都没写，程序却完全正确。因为 std::vector 自己管理内存，它的拷贝是深拷贝，它的析构会释放，编译器生成的默认版本对 rows_、cols_、data_ 逐个处理，正好是想要的行为。这就是三法则的另一面，通常叫「零法则」：能用会管理资源的成员，就别自己拿裸指针，五个函数一个都不用写。

at() 做边界检查，越界时抛 std::out_of_range；operator+ 在尺寸不一致时抛 std::invalid_argument。这两个异常在第 12 课 异常处理：把「出错了」和「算完了」分开 讲过，调用方可以分别捕获。operator+ 里访问了 other.data_，这是同类对象的私有成员，C++ 允许。

写完一个类，过一遍这几条：成员里有没有裸指针（有的话五个函数都写了吗）；能不能换成 vector、string、unique_ptr（能的话五个变零个）；单参数构造函数加 explicit 了吗；只读函数加 const 了吗；大对象参数用 const T& 了吗；拷贝代价大的类，移动构造标 noexcept 了吗。

◆小结
  • 持有裸指针的类必须成套实现析构、拷贝构造、拷贝赋值，C++11 之后再加上移动构造和移动赋值
  • 拷贝赋值先分配后释放，并且检查 this == &other，否则自赋值会释放掉自己正在读的内存
  • 移动构造直接接管指针并把源对象置空，标 noexcept；被移动的对象只能析构或重新赋值
  • 成员用 vector、string、unique_ptr 时，默认生成的五个函数就是对的，这叫零法则
  • 类设计先定所有权，再定接口；能用现成的资源管理类型，就别手写裸指针
✎练习
  1. 给 MyString 增加 append(const char*) 和 operator+=，要求扩容后内容正确，并处理自己追加自己的情况。
  2. 用 copy-and-swap 重写 MyString::operator=，说明它提供的是基本保证还是强异常保证，以及为什么。
  3. 给 Matrix 增加 operator<< 和 transpose()，用 2 × 3 的矩阵测试转置后的尺寸和元素。
  4. 下面这个类至少有四个问题，逐一指出并说明后果：析构函数里 delete[] data_，但没有写拷贝构造；拷贝赋值没有自赋值检查；构造函数没有初始化 size_；c_str() 返回的指针在对象析构后仍被使用。
