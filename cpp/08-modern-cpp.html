第 8 课 auto、nullptr 与范围 for

预计 25 分钟·约 5,361 字·C++

auto、nullptr、范围 for，是 C++11 带进来的三个小工具。它们不解决什么大问题，但能让你少写类型名、少踩空指针、少写循环下标。

也正因为「看起来只是省事」，它们特别容易被用错。用对了代码短一截，用错了错误也更隐蔽。这一课把三个都过一遍，最后给一份新手避坑清单。

8.1 auto：让编译器替你写类型#

auto 不是弱类型，也不是「随便」。变量类型在编译期就定死了，只是这个类型由编译器从初始化表达式推出来。它必须初始化：写 auto x; 编译不过，因为编译器没东西可推。

C++
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> names = {"Amy", "Bob"};

    auto first = names[0];
    first += "?";
    std::cout << "names[0]：" << names[0] << "\n";

    auto& second = names[1];
    second += "!";
    std::cout << "names[1]：" << names[1] << "\n";

    const auto& third = names[0];
    std::cout << "third：" << third << "\n";
    return 0;
}
运行结果
names[0]：Amy
names[1]：Bob!
third：Amy

auto first = names[0] 推出 std::string，是一份拷贝。所以给 first 加个问号，names[0] 还是 Amy。

auto& second 推出 std::string&，是引用（第 2 课那个别名）。改 second 就是改 names[1]，于是打印出 Bob!。

const auto& third 推出 const std::string&，只读、不拷贝。读大对象时这是最常用的写法。

三个写法，三行代码，区别全在 & 和 const 上。auto 只是把类型名省掉，语义一点没变。

▲别把 auto 当「随便」

auto 省的是打字，不是思考。看到 auto，你仍然要知道它推出来是值、引用还是指针。尤其在范围 for 里无脑写 auto x：那是拷贝，你循环里改了半天，容器里一个元素都没变。下面 8.4 专门讲这个。

8.2 auto 的两条脾气#

auto 有个容易忽略的规则：它会丢掉顶层 const 和引用。

C++
#include <iostream>

int main() {
    const int n = 10;
    auto m = n;          // m 是普通的 int，不是 const int
    m = 20;

    int x = 1;
    int& r = x;
    auto y = r;          // y 是 int 的拷贝，不是引用
    y = 99;

    std::cout << "n = " << n << "，m = " << m << "\n";
    std::cout << "x = " << x << "，y = " << y << "\n";
    return 0;
}
运行结果
n = 10，m = 20
x = 1，y = 99

auto m = n; 之后 m 是普通 int，能改，而且改了不影响 n。想保留 const 就写 const auto m = n;。

auto y = r; 更值得注意：r 明明是引用，但 auto 只取它的「值类型」，于是 y 是一份独立的拷贝。想让 y 保持引用，写 auto& y = r;。

这条规则的存在是有道理的：如果 auto 老实地把引用和 const 都带上，你就很难用 auto 复制一个 const 对象。所以标准选择了「默认去掉」，需要的时候你自己加 & 和 const。

记住一个口诀就够了：要别名写 auto&，要只读写 const auto&，什么都不加就是拷贝。

8.3 nullptr：空指针就这一种写法#

先认识一个类型：int* 读作「指向 int 的指针」，装的是「某个 int 在哪儿」。你现在不用会指针的运算，只要知道它是一种跟 int 不同的类型——这一点很关键，因为接下来要讲的就是「0 到底算整数还是算指针」。

表示「什么也没指」的值，C++11 给了 nullptr。它的类型是 std::nullptr_t，只能转成指针，不会转成整数。

C++
#include <iostream>

void show(int) {
    std::cout << "调用了 int 版本\n";
}

void show(int*) {
    std::cout << "调用了 int* 版本\n";
}

int main() {
    show(0);
    // show(NULL);   // 有的平台是警告，有的是歧义，反正不该写
    show(nullptr);
    return 0;
}
运行结果
调用了 int 版本
调用了 int* 版本

show(0) 选 int 版本，因为 0 本来就是 int。如果你本意是传一个空指针，它不会报错，只会悄悄走错分支——这种「能编过但行为不对」的代码最难查。

NULL 更麻烦。它是个老式宏——你可以理解成编译器在编译前就替你替换好的一个名字，展开后通常就是 0，也可能是编译器内部的特殊值。同一个 show(NULL)，在这个平台调 int 版，在另一个编译器上直接报歧义。这种不确定性没有任何保留价值。

nullptr 只能转成指针，所以明确选 int* 版。判断空指针也统一写 if (p == nullptr)，赋值写 p = nullptr;。

还有一个反例值得看：如果当前只有 show(int*) 一个版本，show(0) 也能编译——0 被当成空指针。哪天你再加一个 show(int)，原来那行调用会突然换成本意之外的版本，而且不报错。用 nullptr 从一开始就把意图钉死：我要的是指针，不是数字 0。

★补充说明

第 5 课的 FileGuard 里，std::fopen 失败会返回 nullptr，所以我们写 if (!file.valid()) 来兜底。你现在看到的 nullptr 用法，基本就是「检查有没有拿到东西」这一种，够用了。

8.4 范围 for 要不要加 &#

范围 for 的本质是：每一轮从容器里取出一个元素，赋给循环变量。变量声明成值，就是拷贝；声明成引用，就是别名。所以加不加 &，结果完全不同。

struct Student { ... }; 就是把两个值打成一个包，初始化时用花括号按顺序填进去，比如 {"小明", 80}。它和 class 只差一个默认访问权限：struct 的成员默认公开。第 4 课的补充里提过这一点。

C++
#include <iostream>
#include <string>
#include <vector>

struct Student {
    std::string name;
    int score;
};

int main() {
    std::vector<Student> students = {
        {"小明", 80},
        {"小红", 95}
    };

    for (auto s : students) {
        s.score = 100;
    }
    std::cout << "按值改完：" << students[0].score << "\n";

    for (auto& s : students) {
        s.score = 100;
    }
    std::cout << "按引用改完：" << students[0].score << "\n";

    for (const auto& s : students) {
        std::cout << s.name << "：" << s.score << "\n";
    }
    return 0;
}
运行结果
按值改完：80
按引用改完：100
小明：100
小红：100

第一轮 auto s 把每个 Student 复制进 s，改 s.score 改的是临时副本，容器里还是 80。

第二轮 auto& s 是引用，s 就是容器里的元素，改完就是 100。

第三轮 const auto& s 只读、不复制。只是打印的话，这是最合适的写法。

选择其实很简单：要改元素用 auto&，只读用 const auto&，确实需要一份独立副本时才用 auto。元素是 int、double 这种小类型时，复制很便宜，按值也没问题；元素是字符串、结构体、类的对象时，按值就是白白复制一大块。

还有一条限制：范围 for 里不要增加或删除元素。push_back 可能触发扩容搬家（第 6 课说过），erase 会直接改动容器结构，循环的行为就不可预测了。要边遍历边改数量，用下标循环，或者先把要改的下标记下来，循环结束后统一处理。

8.5 值、引用、const 引用怎么选#

第 2 课给过一张表，这里用代码再确认一遍，因为它是你这几年写函数时最常做的决定：

C++
#include <iostream>
#include <string>

void byValue(std::string s) {
    s += "!";
    std::cout << "函数内按值：" << s << "\n";
}

void byConstRef(const std::string& s) {
    std::cout << "函数内只读：" << s << "\n";
}

void byRef(std::string& s) {
    s += "!";
}

int main() {
    std::string text = "C++";
    byValue(text);
    byConstRef(text);
    byRef(text);
    std::cout << "调用后：" << text << "\n";
    return 0;
}
运行结果
函数内按值：C++!
函数内只读：C++
调用后：C++!

byValue 拿到副本，函数里加感叹号不影响 text。byConstRef 不复制，同时保证不改。byRef 拿到引用，直接改原变量。

口诀还是那三句：读大对象用 const 引用，改调用方用引用，小类型和要副本用值。

再补一个理由：const T& 能接字面量和临时结果，比如 byConstRef("hello") 会临时造一个 string 绑上去。普通的 T& 绑不了临时值，编译器直接拦住。这也是只读参数优先写 const T& 的原因——它更宽容。

8.6 新手最容易踩的 8 个坑#

◆8 个坑
  1. 范围 for 里写 auto x 却想改元素。改的是副本，要改就写 auto& x。
  2. 空指针写 0 或 NULL，重载时可能选中整数版本。统一用 nullptr。
  3. 空 vector 直接 v[0] = 1。还没元素，先 push_back，或者一开始就 v(3)。
  4. 用 m[key] 只想查一下，结果表里凭空多了一项。只读用 at 或 find。
  5. 函数返回局部变量的引用。对象已经销毁，拿到的是悬空引用。
  6. 类里管着资源，却依赖编译器默认生成的拷贝。两个对象会释放同一份资源。
  7. 忘了编译选项 -std=c++11，auto、范围 for、nullptr 全线报错。Dev-C++ 里要在编译选项里手动加。
  8. vector 扩容之后还拿着旧元素的引用去改。元素已经搬家，旧引用指向作废的内存。

这八条，每一条都能在真实项目里制造一个下午的调试。好在它们有共同点：问题都出在「复制还是引用」和「资源谁负责」两件事上。把这两件事想清楚，剩下的都是细节。

到这儿，C++ 入门的地基就打完了：你能写函数、能组织数据、能让对象自己管资源、能用标准库的容器。接下来不是背更多语法，而是用它们写点东西。再往后是继承与多态、运算符重载、模板、异常、智能指针，一直到多文件项目——这些内容在本站后面的课里，会一件件接上。

◆小结
  • auto 从初始化表达式推类型，默认丢掉引用和顶层 const：要别名写 auto&，要只读写 const auto&。
  • 空指针统一用 nullptr，0 和 NULL 都会在重载时出意外。
  • 范围 for 里改元素用 auto&，只读用 const auto&。
  • 传参口诀：读大对象用 const 引用，改调用方用引用，小类型和要副本用值。
  • 真正的进步来自少写手工资源管理，多用容器和标准库。
