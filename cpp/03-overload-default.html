第 3 课 函数重载与默认参数

预计 25 分钟·约 4,908 字·C++

写函数的时候总会撞见这种局面：同一个动作，参数类型不一样，函数体几乎一模一样。如果语言规定「一个名字只能对应一个函数」，你就得起两套名字，addInt、addDouble，再加 addLong、addString 也不奇怪。名字越起越长，调用的时候还得先想一下「这次是哪种」。

C++ 允许你偷这个懒：函数名可以一样，靠参数区分。这一课讲两件省事的工具——函数重载和默认参数——最后顺手说一下 inline。

3.1 一个功能，一堆名字#

先看没有重载的世界长什么样：

C++
#include <iostream>

int addInt(int a, int b) {
    return a + b;
}

double addDouble(double a, double b) {
    return a + b;
}

int main() {
    std::cout << addInt(2, 3) << "\n";
    std::cout << addDouble(2.5, 3.5) << "\n";
    return 0;
}
运行结果
5
6

能跑，但你已经能感觉到哪里别扭：两个函数做的事完全一样，名字却必须跟着类型变。再算上 float、long、甚至字符串拼接，名字表越来越长。最烦的是调用时人脑要查表：这个变量是 double 还是 int？该用哪个名字？

这类「名字比代码还长」的函数，C++ 决定让编译器替你记。

3.2 重载：同名，不同参数#

把两个函数都叫 add：

C++
#include <iostream>

int add(int a, int b) {
    return a + b;
}

double add(double a, double b) {
    return a + b;
}

int main() {
    std::cout << add(2, 3) << "\n";
    std::cout << add(2.5, 3.5) << "\n";
    return 0;
}
运行结果
5
6

两个 add 能同时存在，这叫函数重载。编译器看到 add(2, 3)，实参是 int，就去调 int 版；看到 add(2.5, 3.5)，实参是 double，就调 double 版。你只管写 add，选版本这活儿交给它。

能区分它们的依据，只有参数：

  • 参数个数不同：add(int, int) 和 add(int, int, int)。
  • 参数类型不同：add(int, int) 和 add(double, double)。
  • 参数顺序不同：print(int, double) 和 print(double, int)。

不能拿来区分的，这几种：

  • 返回类型。int f(int) 和 double f(int) 编不过。因为你写 f(1) 的时候，光看调用处根本看不出你想要哪种返回值，编译器没有依据可挑。
  • 参数名。add(int a, int b) 和 add(int x, int y) 是同一个函数，写两遍就是重复定义，报错。
  • 顶层 const。void f(int) 和 void f(const int) 也是同一个函数，形参上的 const 在判断重载时被忽略。
▲常见错误

只改返回类型不算重载，编译器的原话大概是「functions that differ only in their return type cannot be overloaded」。另一个高频错误：复制粘贴改了参数名，以为就是新函数了。实际上参数名对编译器毫无意义，它只看见两个一模一样的签名。

3.3 选哪个版本，编译的时候就定了#

这句话要记牢：重载是编译期决定的，不是运行期。 你按下编译键的那一刻，编译器就按实参的类型挑好了函数，生成的机器指令里直接写死调哪个。程序跑起来以后，没有任何「按类型查找」的动作。

C++
#include <iostream>
#include <string>

void show(int x) {
    std::cout << "整数：" << x << "\n";
}

void show(double x) {
    std::cout << "小数：" << x << "\n";
}

void show(const std::string& s) {
    std::cout << "文本：" << s << "\n";
}

int main() {
    show(42);
    show(3.14);
    show("hi");
    show('A');
    return 0;
}
运行结果
整数：42
小数：3.14
文本：hi
整数：65

前三个好理解。第四个 show('A') 打出 65，说明它走了 show(int)。因为字符在 C++ 里本来就用一个整数编号表示，'A' 的编号是 65，从 char 到 int 是一步轻松的转换，编译器就选了它，虽然你心里想的是「A 是个字符」。

这就是关键：选择的依据是实参的静态类型——也就是这个值在代码里被认定的类型，不是你的意图。'A' 的类型是 char，std::string 版收不了它，能收的只有 int，于是就是 65。想让 'A' 打出字符，就再写一个 show(char)，让 char 版完美匹配。

编译器挑版本的思路，大概是：列出所有叫 show 的候选，给每个候选算一遍「把实参转成形参要几步」，挑代价最小的那个。如果两个候选的代价一样小，它不猜，直接报歧义。

顺带一句：show(3.14f) 也走 double 版。float 到 double 是放宽，几乎无损；float 到 int 要砍掉小数，代价大。编译器当然选前者。

★补充说明

重载能实现，是因为编译器把参数类型也编进了函数名，这叫名字修饰。add(int, int) 在目标文件里可能叫 _Z3addii，add(double, double) 叫 _Z3adddd。两个名字不一样，链接器就不会搞混。

3.4 默认参数：从右往左填#

有些参数在大多数调用里都是同一个值，每次写一遍很啰嗦。默认参数就是给它一个「不写就用这个」的值：

C++
#include <iostream>
#include <string>

void log(const std::string& msg, int level = 1, bool withTime = false) {
    std::cout << "[level " << level << "] ";
    if (withTime) {
        std::cout << "12:00:00 ";
    }
    std::cout << msg << "\n";
}

int main() {
    log("程序启动");
    log("磁盘快满了", 2);
    log("编译失败", 3, true);
    return 0;
}
运行结果
[level 1] 程序启动
[level 2] 磁盘快满了
[level 3] 12:00:00 编译失败

int level = 1 的意思是「调用时不给，就当 1」。于是三种调用都成立：只给一个、给两个、全给。

规则只有一条，但必须记牢：默认值只能从右往左排。上面的写法合法，因为带默认值的都在右边。写成 void f(int a = 0, int b) 编不过，因为 b 排在 a 后面却没有默认值，你没法跳过 a 去给 b。

同样的道理，调用时省参数也只能从右边省。你可以只传 msg，或者传 msg 和 level，但不能跳过 level 直接传 withTime。参数位置是固定的，编译器只管从左往右一个个对，不会猜你的心思。

还有一条容易被忽略：默认值只能写一处。通常写在函数声明里；如果声明和定义分开写（大型项目里很常见），默认值放在头文件那份声明上，定义里再写一遍会报「重定义默认参数」。

▲常见错误

别以为默认参数是「运行时发现你没传，自己补一个」。不是，编译器在调用点就把参数补齐了，这一步和重载一样发生在编译期。所以 log("x", 2) 里那个 2 一定对应 level，它不会去猜你想传 withTime。类型对不上就报错，不会自动跳过。

3.5 两个歧义坑#

第一个坑：几个重载都能接住你的调用，编译器挑不出最优的。

C++
// 反例，编译不过：ambiguous（歧义）
void print(int a, double b) {}
void print(double a, int b) {}

void test() {
    print(1, 2);
}

print(1, 2) 两个参数都是 int。版本一第一个参数完美匹配、第二个要把 int 转成 double；版本二正好反过来。两边各赢一半，编译器不猜，直接报 call of overloaded 'print(int, int)' is ambiguous。

同类问题还有 3.2 里的 add(2, 3.5)：一个 int 一个 double，add(int, int) 和 add(double, double) 也各匹配一半，同样歧义。混着传类型的时候，多留意一眼。

第二个坑：默认参数把两个重载变成了同一个调用。

C++
// 反例，编译不过：ambiguous（歧义）
void show(int a);
void show(int a, int b = 0);

void test() {
    show(5);
}

show(5) 既能配 show(int)，也能配 show(int, int = 0)，编译器不知道你想调哪个。

◆记忆点

写重载时记住一句：一次调用能匹配的版本越少越好。默认参数和重载混着用，最容易让两个版本同时接住同一次调用。真要给默认值，先想清楚它会不会和别的重载撞上。

3.6 inline 现在还有用吗#

inline 这个词你会在很多代码里看到：

C++
#include <iostream>

inline int square(int x) {
    return x * x;
}

int main() {
    std::cout << square(5) << "\n";
    return 0;
}

inline 的本意是「建议编译器把这个函数的代码直接贴到调用处」，省掉一次函数调用的开销。函数体只有一行，贴过去确实比调用快，这个建议听起来很合理。

但现在的编译器基本不听了。函数小、调用频繁，它开优化时自己就会内联；函数大，你写十个 inline 也没用。所以从「性能」角度看，inline 已经不太重要。

它如今真正的用处是另一件事：告诉链接器「这个函数的定义可以出现在多个源文件里而不算重复」。头文件里如果要写函数定义（而不只是声明），就得加 inline，否则每个包含它的 .cpp 都生成一份定义，链接时报重复符号。第 16 课讲多文件工程时会再碰到这个规则。

自己写单文件练习、交课程作业，加不加完全没区别。别在 inline 上纠结，先把手感练出来。

◆小结
  • 重载靠参数个数、类型、顺序区分，返回类型和参数名都不算。
  • 选哪个版本在编译期就定了，看的是实参的静态类型。
  • 默认参数从右往左写，调用时只能省掉尾巴上的参数。
  • 默认参数和重载混用，容易让一次调用同时匹配两个版本，报歧义。
  • 下一课是第 4 课 类与对象，把数据和操作装进同一个东西里。
✎练习
  1. 写三个 print 重载，分别打印 int、double、std::string，在 main 里各调一次，确认编译器挑对了。
  2. 写 void draw(int n, char c = '*')，输出 n 个字符 c。再加一个 void draw(int n) 重载，编译看看会发生什么，解释为什么。
  3. 写 double pay(double price, double rate = 0.9, int count = 1)，返回打折后的总价。写出三种合法调用（传 1 个、2 个、3 个参数），再解释为什么不能只传 price 和 count。
  4. 下面哪些能构成合法重载：f(int)、f(int, int)、f(double)、f(int, double)、int f(int)。说说判断依据。
