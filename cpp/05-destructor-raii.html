第 5 课 构造、析构与 RAII

预计 30 分钟·约 5,025 字·C++

上一课 第 4 课 类与对象：把数据和操作捆在一起 里的 Student，只是把几个变量捆在一起。从这一课起，对象开始有「出生」和「死亡」：创建时自动跑构造函数，离开作用域时自动跑析构函数。

这两件事看起来只是语法，其实是 C++ 最值钱的设计之一。它能把「打开的东西忘记关」这类错误，从「靠人记」变成「编译器管」。

5.1 对象什么时候生，什么时候死#

构造函数不只给某一种特殊写法用。你在函数里直接声明出来的对象（习惯上叫栈对象）、临时创建的对象，只要创建就会调用它。析构函数则相反：对象离开作用域的那一刻自动调用。

C++
#include <iostream>
#include <string>

class Tracker {
public:
    explicit Tracker(const std::string& name) : name_(name) {
        std::cout << "构造 " << name_ << "\n";
    }

    ~Tracker() {
        std::cout << "析构 " << name_ << "\n";
    }

    void use() const {
        std::cout << "使用 " << name_ << "\n";
    }

private:
    std::string name_;
};

int main() {
    std::cout << "进入 main\n";
    {
        Tracker a("a");
        Tracker b("b");
        a.use();
        b.use();
        std::cout << "离开代码块\n";
    }
    std::cout << "结束 main\n";
}
运行结果
进入 main
构造 a
构造 b
使用 a
使用 b
离开代码块
析构 b
析构 a
结束 main

注意最后两行：后构造的 b 先析构，先构造的 a 后析构。析构顺序永远和构造顺序相反，像叠盘子，后放的先拿。这个规则不是随便定的：后面的对象可能依赖前面的对象，先销毁前面的，后面的就会拿着一个已经没了的东西。倒着来最安全。

~Tracker() 就是析构函数。名字是类名前加一个波浪号，没有参数、没有返回值，也不能重载——一个类只能有一个析构函数。

包围 a、b 的那对花括号不是装饰。它划出了一个作用域：花括号结束时，里面创建的对象全部销毁。这个「对象活到它所在的代码块结束」的规则，是整个 RAII 的地基。

5.2 析构函数该做的事：还资源#

构造函数负责「拿」，析构函数负责「还」。这里的资源可以是内存、文件、数据库连接、网络套接字，也可以是一把锁。

先想想没有析构函数的世界。你打开一个文件，用完要关；中间有三处提前 return，每个出口都得记得关一次。函数一长、分支一多，漏掉是常态。漏掉以后程序不会立刻报错，只是文件一直被占着，别的程序打不开；或者数据还在缓冲区里没写出去，程序一崩就全丢了。

更麻烦的是，这种错误没有报错信息。程序看起来一切正常，直到某天有人发现文件是空的。

C++ 的做法是把这个关系写进类里：构造函数打开文件，析构函数关闭文件。对象的寿命就是资源的寿命，你不需要在十个出口各写一遍收尾。这个思路叫 RAII，全称 Resource Acquisition Is Initialization，直译是「资源获取即初始化」。名字起得不好，它真正的意思是：资源的生死，绑定在对象的生死上。

◆一句话记住 RAII

构造函数拿资源，析构函数还资源，中间不用手动收尾。

对象活着，资源就在；对象死了，资源自动归还。

5.3 自己写一个 RAII 类#

下面这个 FileGuard 把「打开的文件」包了起来：

C++
#include <cstdio>
#include <iostream>
#include <string>

class FileGuard {
public:
    explicit FileGuard(const std::string& path)
        : fp_(std::fopen(path.c_str(), "w")) {
    }

    ~FileGuard() {
        if (fp_ != nullptr) {
            std::fclose(fp_);
            std::cout << "析构：文件已关闭\n";
        }
    }

    FileGuard(const FileGuard&) = delete;
    FileGuard& operator=(const FileGuard&) = delete;

    bool valid() const {
        return fp_ != nullptr;
    }

    std::FILE* get() const {
        return fp_;
    }

private:
    std::FILE* fp_;
};

int main() {
    FileGuard file("demo.txt");
    if (!file.valid()) {
        std::cout << "打开文件失败\n";
        return 1;
    }

    std::fputs("hello, RAII\n", file.get());
    std::cout << "写完，准备离开作用域\n";
    return 0;
}
运行结果
写完，准备离开作用域
析构：文件已关闭

main 里根本没有出现 fclose，但文件确实关了。FileGuard 的对象一离开作用域，析构函数自动跑，顺手把文件关掉。你就算在 fputs 和结尾之间加十个 return，每个出口都会关。

几个细节：

  • std::fopen 返回的是一个句柄，你可以理解成「系统发给你的一个编号」，不是文件本身。打开失败时它是 nullptr，所以 valid() 先检查一次。nullptr 是 C++ 的空指针写法，第 8 课细讲。
  • path.c_str() 是把 std::string 转成老式接口要的格式。标准库里这类老接口还有不少，看到 c_str() 就用它转一下，不用深究。
  • 构造函数初始化列表里直接调 std::fopen，成员 fp_ 一出生就拿到了句柄，中间没有「先空着再赋值」的空档。

上面那两行 = delete 是故意的：禁止复制这个类。第二行那种 operator= 的写法属于运算符重载，第 10 课才讲，你现在只要知道它也在禁复制就够了。原因下一节说。

5.4 所有权不能复制#

如果允许复制一个 FileGuard 会怎样？fp_ 里存的是那个句柄编号。默认的复制行为是「把每个成员抄一遍」，于是两个对象手里拿着同一个编号，都以为自己是主人。

然后它们各自离开作用域，各自调用 fclose。第一次关闭成功，第二次关的是一个已经关掉的句柄——轻则报错，重则把别的文件搞坏。这种事最恶心的地方在于：程序可能不崩，只是偶尔丢数据。

所以 FileGuard 把复制明确禁掉了。= delete 的意思是「这个函数编译器不许生成，谁调用谁编不过」。这不是运行时的检查，是编译期直接拦住，错不到运行的时候。

▲常见错误

一个类只要「拥有」某个资源，就不能依赖编译器默认生成的复制行为。默认复制是逐成员抄一遍：对 int、double 没问题，对「资源的句柄」就等于把同一份所有权抄给了两个人。初学阶段最稳的办法：别让类自己去管资源。要一串数据用 std::vector，要独占一个对象用智能指针（第 14 课），需要文件就用现成的封装。

反过来说，标准库里的 std::string 为什么可以随便复制？因为它的复制是「真的复制内容」，不是抄一个编号：

C++
#include <iostream>
#include <string>

int main() {
    std::string a = "hello";
    std::string b = a;      // b 是 a 的副本，各自有一份内容
    b[0] = 'H';

    std::cout << a << " " << b << "\n";
}
运行结果
hello Hello

改 b 不影响 a。string 内部也有一块动态内存，但它的构造函数、复制、析构是一整套写好的逻辑，你不用操心。第 6 课开始，你会大量使用这种「自己管好自己」的类型。

5.5 作用域、提前 return，都逃不过析构#

再确认一遍析构的触发时机。下面这个 Timer 在构造和析构时各打一行，用来观察顺序：

C++
#include <iostream>
#include <string>

class Timer {
public:
    explicit Timer(const std::string& name) : name_(name) {
        std::cout << "开始 " << name_ << "\n";
    }

    ~Timer() {
        std::cout << "结束 " << name_ << "\n";
    }

private:
    std::string name_;
};

void work() {
    Timer outer("外层");

    {
        Timer inner("内层");
        std::cout << "干活\n";
    }

    std::cout << "内层已经结束\n";
}

int main() {
    work();
    std::cout << "work 返回了\n";
}
运行结果
开始 外层
开始 内层
干活
结束 内层
内层已经结束
结束 外层
work 返回了

规律很清楚：谁先出作用域，谁先析构。内层代码块先结束，inner 先死；函数返回时，outer 再死。

提前 return 也一样。因为析构跟着作用域走，不跟着 return 走——函数返回时，它所有的局部对象都要销毁，不管你是正常走到末尾还是中途 return。

这条规则还顺带解决了「中途出错怎么办」：哪怕函数中间抛了异常（第 12 课的内容），局部对象也会被销毁，资源照样归还。你不用写一堆 if (出错) { 关文件; return; }。

5.6 日常写法的几条硬建议#

把这一课落到习惯上，就四条：

第一，优先用普通对象，别手动申请。 你在函数里写 Timer t("x");，它就是栈上的对象，离开作用域自动销毁。这类对象最省心，因为它不需要你记得任何事。

第二，真要动态申请，就必须配对归还。 new 出来的对象不会自己死，得写 delete；忘一次就漏一次内存。所以日常代码里几乎不该出现裸的 new——第 6 课的 std::vector 和第 14 课的智能指针会替你做这件事。

第三，类里管着资源，就别依赖默认复制。 要么像 FileGuard 一样禁掉复制，要么把复制写对（真的复制内容），没有第三条路。

第四，析构、复制构造、复制赋值，要么都不写，要么成套写。 这条经验叫「三法则」。只写析构却让默认复制到处跑，比什么都不写更危险——因为你的析构会去释放一个可能已经被别人释放过的东西。

★补充说明

析构函数里不要做太复杂的事。它可能在程序异常退出的路径上执行，这时候别的地方状态已经不靠谱了。最稳的写法：析构函数只负责「把资源还回去」，不要在里面打印一堆日志、更不要去调用可能失败的网络操作。

◆小结
  • 构造在对象创建时自动跑，析构在对象离开作用域时自动跑，顺序相反。
  • RAII 的核心是：构造函数拿资源，析构函数还资源，资源寿命跟着对象走。
  • 拥有资源的类不能依赖默认复制，要么禁掉（= delete），要么自己写对。
  • 优先用普通对象，少写 new；漏掉的 delete 不会有任何报错，只会悄悄漏内存。
  • 下一课是第 6 课 vector 与 string，两个自己管好内存、可以放心复制的现成类型。
✎练习
  1. 写一个 Timer 类，构造时打印「开始」，析构时打印「结束」。在 main 里创建它，分别测试三种情况：正常走到末尾、中途 return、放在内层代码块里。
  2. 给 FileGuard 加一个 bool write(const std::string& text) 成员函数，内部调用 std::fputs，返回是否成功。再故意传一个不存在的目录路径，观察打开失败时析构函数是否安全。
  3. 用两个 FileGuard 对象依次打开两个文件，中途提前 return，根据输出判断哪个先关闭、为什么不用手动 fclose。
  4. 把 FileGuard 里那两行 = delete 删掉，写一句 FileGuard copy = file; 试试。解释编译器为什么放行、以及运行时会出什么问题。
