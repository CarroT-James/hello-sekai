第 7 课 map、set 与 pair

预计 30 分钟·约 6,671 字·C++

上一课 第 6 课 vector 与 string 讲的是「按下标存数据」：第 0 个、第 1 个，位置就是身份。可很多数据不是这么排的。你想知道「张三考了多少分」，张三不是第几个元素，他是一个名字。

这类「给一个 key，要拿到对应的 value」的需求，标准库用 std::map 解决。这一课还会顺手讲 set（只存不重复的 key）和 pair（把两个值捆成一对）。

7.1 从「按下标找」升级成「按键找」#

先想想用 vector 怎么办。存姓名和分数，最直接的办法是两个 vector 一一对应，查人的时候按下标扫一遍：

C++
#include <cstddef>
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> names = {"张三", "李四", "王五"};
    std::vector<int> scores = {90, 85, 78};

    std::string who = "李四";
    for (std::size_t i = 0; i < names.size(); ++i) {
        if (names[i] == who) {
            std::cout << who << " 的分数是 " << scores[i] << "\n";
            break;
        }
    }
    return 0;
}
运行结果
李四 的分数是 85

能跑，但三个学生还行，三千个就慢：每次查询都要从头比对。更要命的是两个 vector 必须永远同步——插入一个人忘了插另一边，从此所有查询都错位，而且不报错。

std::map<Key, Value> 就是为这件事设计的：

  • 每个 key 唯一，不存在两个「张三」。
  • 查找直接按键，不用从头扫。
  • 所有元素自动按 key 从小到大排好。

用它之前加 #include <map>。底层通常是一棵平衡树，所以查找、插入、删除都不需要把整张表扫一遍：数据从一千涨到一百万，耗时大约只翻十倍。这个增长速度写成 O(log n)，你现在按「翻倍地涨也不怕」理解就够。

key 必须能比较大小：int 按数值，std::string 按字典序。自定义类型要自己提供比较规则。value 不参与排序，它只是挂在 key 上的东西。

7.2 map 的基本操作#

C++
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> score;

    score["张三"] = 90;
    score.insert({"李四", 85});
    score.insert({"张三", 60});

    std::cout << "张三：" << score["张三"] << "\n";
    std::cout << "李四：" << score.at("李四") << "\n";
    std::cout << "人数：" << score.size() << "\n";

    std::cout << "查王五之前，人数：" << score.size() << "\n";
    std::cout << "王五：" << score["王五"] << "\n";
    std::cout << "查王五之后，人数：" << score.size() << "\n";
    return 0;
}
运行结果
张三：90
李四：85
人数：2
查王五之前，人数：2
王五：0
查王五之后，人数：3

先看 score.insert({"张三", 60})。表里已经有张三了，所以这次插入不生效，90 还是 90。insert 的规矩是「key 不存在才插入」，它不会覆盖已有的值。

再看王五。明明只是「读了一下」，人数却从 2 变成 3。原因在 []：它遇到不存在的 key 时，会先插入一个默认值（int 是 0，std::string 是空串），再把那个值的引用给你。于是「查一下」变成了「查一下并新增一项」。

这个行为和直觉相反，是 map 最常见的误用来源。三种写法摆在一起就清楚了：

写法key 存在key 不存在
m[key]返回值的引用插入默认值，再返回引用
m.at(key)返回值的引用抛出越界异常（第 12 课讲）
m.insert({key, value})不覆盖原值插入新键值对

所以选法很明确：要写值、或者本来就打算「没有就创建」，用 []；只读查表用 at 或 count；不想覆盖已有值用 insert。

把只读查表写成 m[key]，程序不会报错，只会让你的表悄悄变大，最后内存和逻辑一起出问题。

▲常见错误

「我只想看看他在不在，结果表里多了一个人」——这是 map 的头号事故。要判断在不在，用 if (m.count(key))：count 返回 0 或 1，key 存在就是 1，而且不会改动表。要读值又不想创建，用 at。这两种写法都不会让表变大。

7.3 遍历 map 的三种写法#

map 里每个元素是一个 std::pair：first 是 key，second 是 value。key 前面带 const，不能通过遍历改掉，否则整棵树的顺序就乱了。

C++
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> age = {
        {"Amy", 20},
        {"Bob", 19},
        {"Cindy", 21}
    };

    for (const auto& item : age) {
        std::cout << item.first << " " << item.second << "\n";
    }

    for (auto it = age.begin(); it != age.end(); ++it) {
        std::cout << it->first << " " << it->second << "\n";
    }
    return 0;
}
运行结果
Amy 20
Bob 19
Cindy 21
Amy 20
Bob 19
Cindy 21

两段输出一样，都按 key 的字典序，不是按你插入的顺序。

第一种用范围 for。const auto& 表示「不复制，也不改」。如果写成 auto item，每个元素都会复制一遍，key 是字符串时纯属浪费——这个细节第 8 课会展开。

第二种是迭代器。it 指向一个 pair，取成员用 it->first、it->second。map 没有整数下标：age[0] 不是「取第一个元素」，而是「查 key 为 0 的元素，没有就插一个」，又是一个 [] 陷阱。

map 的迭代器只能 ++ 和 --，不能 it + 3 跳着走。想直接定位某个 key，用 find，别从头遍历：if (score.find("张三") != score.end())，找到返回指向那一项的迭代器，找不到返回 end()。

还有第三种写法，用起来最舒服。把上面第一个循环换成这几行，输出完全一样：

C++
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> age = {
        {"Amy", 20},
        {"Bob", 19},
        {"Cindy", 21}
    };

    for (const auto& [name, years] : age) {
        std::cout << name << " " << years << "\n";
    }
    return 0;
}
运行结果
Amy 20
Bob 19
Cindy 21

这叫结构化绑定：把 pair 的两个成员直接拆成两个名字，不用再写 item.first。这段代码要求 C++17。

▲和你的环境直接相关

Dev-C++ 5.11 自带的 GCC 4.9 不支持结构化绑定，会报 error: expected unqualified-id before '[' token，报错位置就在那个方括号上。在 Dev-C++ 上能编过的写法是上一种：用 const auto& item 再取 item.first 和 item.second，功能完全一样，只是多打几个字。或者升级到 GCC 8 以上，编译时加 -std=c++17。

7.4 统计词频：一行顶十行#

现在用 map 做词频统计。这里用 std::istringstream 把一段字符串当成输入流，>> 会自动跳过空格，一次切出一个单词：

C++
#include <iostream>
#include <map>
#include <sstream>
#include <string>

int main() {
    std::string text = "red blue red green blue red";
    std::map<std::string, int> freq;

    std::istringstream input(text);
    std::string token;
    while (input >> token) {
        ++freq[token];
    }

    for (const auto& item : freq) {
        std::cout << item.first << ": " << item.second << "\n";
    }
    return 0;
}
运行结果
blue: 2
green: 1
red: 3

统计之前不用先判断这个词在不在表里。[] 已经包办了「不存在就插入 0」，所以循环体只有一行。

++freq[token] 是这一课最值钱的一行。第一次遇到某个词，freq[token] 插入 0 并返回引用，紧接着 ++ 变成 1；以后再遇到，直接加 1。三步并成一步。

注意输出顺序：map 按 key 的字典序输出，不是按出现顺序，也不是按次数。红色出现 3 次却排在最后。想按次数从多到少排，map 不擅长——得把数据复制到 vector 里再排序，那是第 13 课的内容。

还有一点：真实文本带标点，red, 和 red 会被当成两个词。要统计得先清洗标点、统一大小写。上面的例子故意保持最小，只演示容器怎么用。

7.5 set 去重，pair 装一对#

std::set<T> 可以理解成「只有 key、没有 value 的 map」。它自动去重，也自动按 key 排序：

C++
#include <iostream>
#include <set>
#include <string>
#include <utility>

int main() {
    std::set<int> nums = {3, 1, 2, 3, 1};

    std::cout << "set 大小：" << nums.size() << "\n";
    for (int x : nums) {
        std::cout << x << "\n";
    }

    nums.insert(2);
    std::cout << "再插 2 后大小：" << nums.size() << "\n";
    std::cout << "3 在不在：" << nums.count(3) << "\n";

    std::pair<std::string, int> math{"数学", 95};
    std::cout << math.first << " " << math.second << "\n";
    return 0;
}
运行结果
set 大小：3
1
2
3
再插 2 后大小：3
3 在不在：1
数学 95

{3, 1, 2, 3, 1} 里两个 3、两个 1，进 set 以后只剩 1、2、3，而且按升序排。重复 insert 不报错，只是大小不变。

set 适合去重、判重、维护「已经出现过的」集合。它只回答「在不在」，不回答「出现几次」——要计数还是用 map。

判断在不在用 count 最省事，返回 0 或 1。注意这里没有 [] 陷阱，因为 set 压根没有下标。

std::pair<A, B> 是装两个值的轻量结构，first 和 second 都是公开成员。map 的每个元素本质上就是一个 pair，差别只在 key 带 const。理解了这个关系，map 的遍历和插入就不神秘了。

7.6 unordered_map，以及「手写两个表」的代价#

如果只关心查得快、不关心顺序，用 std::unordered_map。它基于哈希表，平均查找和插入是常数时间 O(1)，比 map 快一截。

C++
#include <iostream>
#include <string>
#include <unordered_map>

int main() {
    std::unordered_map<std::string, int> freq;

    freq["red"] = 3;
    freq["blue"] = 2;
    freq["green"] = 1;

    for (const auto& item : freq) {
        std::cout << item.first << ": " << item.second << "\n";
    }
    return 0;
}

接口和 map 一样：[]、at、find、erase 都有。但迭代顺序由哈希函数决定，换编译器、换标准库版本都可能变。这段代码每次运行的顺序都不保证，所以我不给你贴输出——你自己跑，可能看到任意顺序。需要有序输出时，就不能用它。

代价还不止顺序：unordered_map 的 key 必须能算哈希值，自定义类型要额外提供哈希函数和相等比较；map 只要求 key 能比大小，门槛低得多。数据量大、查得频繁、顺序无所谓，用它；否则老老实实 map。

那不用 map 行不行？当然行，用上一课的 vector 手写：

C++
#include <cstddef>
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> words = {"red", "blue", "red", "green", "blue", "red"};
    std::vector<std::string> kinds;
    std::vector<int> counts;

    for (const std::string& w : words) {
        std::size_t i = 0;
        for (; i < kinds.size(); ++i) {
            if (kinds[i] == w) {
                counts[i]++;
                break;
            }
        }
        if (i == kinds.size()) {
            kinds.push_back(w);
            counts.push_back(1);
        }
    }

    for (std::size_t i = 0; i < kinds.size(); ++i) {
        std::cout << kinds[i] << ": " << counts[i] << "\n";
    }
    return 0;
}
运行结果
red: 3
blue: 2
green: 1

这段能跑，但它暴露了手写方案的三个成本：两张表要手动保持等长；查找是线性扫描，词种数一多就慢；输出顺序是首次出现顺序，想要字典序还得自己排。

map 版不需要预分配，不用写查找循环，还自动有序。代价是每个元素有额外的树结构开销，内存比紧凑的 vector 大。工具没有绝对的好坏，只有合不合适——但默认情况下，先想到 map 和 vector，等真遇到性能问题再换。

◆小结
  • map 是有序键值表，key 唯一，查找代价 O(log n)。
  • m[key] 遇到不存在的 key 会插入默认值；只读用 at 或 find。
  • 遍历可以用范围 for 或迭代器；结构化绑定要 C++17，Dev-C++ 的 GCC 4.9 不认。
  • set 自动去重并排序，pair 是 map 元素的基本形状。
  • 顺序不重要又查得频繁时用 unordered_map，但要接受它不保证顺序。
  • 下一课是第 8 课 auto、nullptr 与范围 for，把这几课的代码再缩短一截。
✎练习

  2. 统计一段英文的词频：先按字典序输出，再尝试按出现次数从多到少输出。提示：把数据复制到 vector 里再排序。
  3. 给定两个 std::vector<int>，用 std::set 求它们的并集和交集，要求结果去重并升序输出。
  4. 先写 if (m["某个人"]) 判断某人在不在表里，运行两次观察表的大小变化，然后把写法改成 find 或 count，说明差别。
