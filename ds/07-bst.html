第 7 课 二叉搜索树

预计 35 分钟·约 8,553 字·数据结构

第 6 课 树与二叉树 里，你把三种遍历写顺了。那时候树只是「有左右两个孩子」的结点堆在一起，谁大谁小无所谓。现在给它加一条规矩：左子树里所有的值都比根小，右子树里所有的值都比根大。这条规矩一加，树就从「能遍历」变成了「能查找」，名字也跟着变：二叉搜索树，英文缩写 BST。

它的好用之处很像查纸质字典。你不会从第一页翻到最后一页去找一个词，而是翻到中间，看目标在前面还是后面，然后只管剩下的那一半。BST 的每一次比较都在做这件事。

但它有个致命的弱点，这一课的最后会看到：这棵树可能长成一条链，那时它连链表都不如。

7.1 一条规矩，换来一半#

先不谈插入和删除，手工搭一棵树，看看这条规矩在代码里长什么样。

C
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node *left;
    struct Node *right;
} Node;

Node *new_node(int value) {
    Node *p = malloc(sizeof(Node));
    p->value = value;
    p->left = NULL;
    p->right = NULL;
    return p;
}

void inorder(Node *root) {
    if (root == NULL) {
        return;
    }
    inorder(root->left);
    printf("%d ", root->value);
    inorder(root->right);
}

int main(void) {
    Node *root = new_node(5);
    root->left = new_node(3);
    root->right = new_node(8);
    root->left->left = new_node(2);
    root->left->right = new_node(4);
    root->right->left = new_node(7);

    inorder(root);
    printf("\n");
    return 0;
}
运行结果
2 3 4 5 7 8

结点还是第 6 课那个结构体，只在里面加了个 value。真实项目里 malloc 之后要判 NULL，这一课为了让代码短省掉了这个检查，但心里要有这根弦。new_node 里把 left 和 right 置成 NULL 是必须的：malloc 拿到的内存是脏的，你不初始化，里面就是野指针，inorder 走到那里直接崩。

中序跑出来是 2 3 4 5 7 8，正好从小到大。这不是运气。中序的次序是「左、根、右」，而规矩保证了左边都小、右边都大，所以中序必然是升序。这条性质是后面一切操作的地基，连判一棵树是不是 BST，都是中序跑一遍看递增，比写一堆递归条件不容易错。

你可以试试把 3 和 8 的值对调：中序会变成 2 8 4 5 7 3，一眼就知道规矩破了。

7.2 查找：每一步砍掉一半#

查找的逻辑很直白：从根开始，比当前结点小就往左，大就往右，相等就返回。

C
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node *left;
    struct Node *right;
} Node;

Node *insert(Node *root, int v) {
    if (root == NULL) {
        Node *p = malloc(sizeof(Node));
        p->value = v;
        p->left = NULL;
        p->right = NULL;
        return p;
    }
    if (v < root->value) {
        root->left = insert(root->left, v);
    } else if (v > root->value) {
        root->right = insert(root->right, v);
    }
    return root;
}

int contains(Node *root, int v) {
    while (root != NULL) {
        if (v == root->value) {
            return 1;
        }
        if (v < root->value) {
            root = root->left;
        } else {
            root = root->right;
        }
    }
    return 0;
}

int main(void) {
    int keys[] = {5, 3, 8, 2, 4, 7, 9};
    Node *root = NULL;
    for (int i = 0; i < 7; i++) {
        root = insert(root, keys[i]);
    }

    int query[] = {4, 6, 9};
    for (int i = 0; i < 3; i++) {
        printf("找 %d：%s\n", query[i], contains(root, query[i]) ? "找到" : "没有");
    }
    return 0;
}
运行结果
找 4：找到
找 6：没有
找 9：找到

contains 写成了迭代版：一个 while 循环，不相等就往下走一层，走到 NULL 说明树里没有。它没用到栈，也不需要递归，比递归版省内存。

为什么快？每次比较之后，目标只可能落在剩下的一棵子树里，另一棵整片被排除。树是「矮胖」的时候，n 个结点的高度大约是 log2(n)，查 100 万个结点最多比 20 次左右。这就是「砍一半」的威力。

但注意「矮胖」这个前提。树要是长成一条链，高度就是 n，查找退化成 O(n)，和链表没区别。这也不是什么极端情况：往一棵空树里按顺序插 1、2、3、4，一定得到链。

◆记忆点

BST 的复杂度从来不是 O(log n)，而是 O(h)，h 是树的高度。O(log n) 只是 h 的期望值。

想亲眼看到这句话的后果，把 keys 改成 {1, 2, 3, 4, 5, 6, 7} 再跑一遍。程序不会报错，结果也全对，只是慢。

7.3 插入：新值一定落在空位#

插入不用发明新算法：按查找的路走，走到 NULL 就在那儿挂一个新结点。

C
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node *left;
    struct Node *right;
} Node;

Node *insert(Node *root, int v) {
    if (root == NULL) {
        Node *p = malloc(sizeof(Node));
        p->value = v;
        p->left = NULL;
        p->right = NULL;
        return p;
    }
    if (v < root->value) {
        root->left = insert(root->left, v);
    } else if (v > root->value) {
        root->right = insert(root->right, v);
    }
    return root;
}

int height(Node *root) {
    if (root == NULL) {
        return 0;
    }
    int l = height(root->left);
    int r = height(root->right);
    return (l > r ? l : r) + 1;
}

void inorder(Node *root) {
    if (root == NULL) {
        return;
    }
    inorder(root->left);
    printf("%d ", root->value);
    inorder(root->right);
}

int main(void) {
    int values[] = {50, 30, 70, 20, 40, 60, 80};
    Node *root = NULL;

    for (int i = 0; i < 7; i++) {
        root = insert(root, values[i]);
        printf("插入 %d 后，高度 %d\n", values[i], height(root));
    }

    printf("中序：");
    inorder(root);
    printf("\n");
    return 0;
}
运行结果
插入 50 后，高度 1
插入 30 后，高度 2
插入 70 后，高度 2
插入 20 后，高度 3
插入 40 后，高度 3
插入 60 后，高度 3
插入 80 后，高度 3
中序：20 30 40 50 60 70 80

重点看这一行：root->left = insert(root->left, v);。为什么非得把返回值赋回去？

因为 C 的函数是值传递。insert(root->left, v) 传进去的是指针的值，是那个地址的一份拷贝，不是「root->left 这个字段本身」。子调用新建了结点以后，只能通过返回值把新指针交回来，父结点负责挂上去。

新手常写 insert(root->left, v); 把返回值丢掉，然后发现树里什么都没有。这种 bug 不报错、不崩溃，只是数据静默消失，比段错误难查得多。

main 里写的是 root = insert(root, v);，因为空树插第一个值时根结点本身会变。同一个道理，只是发生在根上。

真不想用返回值，就得传二级指针 Node **，那是 C 语言 指针 里的东西。这里用返回值清楚得多。

再看高度：前两个插入高度在涨，之后稳定在 3。高度为 h 的树最多装 2^h - 1 个结点，7 个正好塞满三层，这就是「满」的状态。

重复的值呢？上面 v == root->value 时什么都没做，等于丢掉。也可以给结点加一个 count 字段，重复就加一。但别让树里出现两个相同的值，否则删除时你都不知道该删哪一个。

7.4 删除：三种情况，一种比一种麻烦#

这是全课最容易写错的一段，我当年在这上面画了半本草稿纸。先分类，别急着写代码。

  • 要删的是叶子：直接 free，让父结点指向 NULL。
  • 要删的只有一个孩子：把孩子交给父结点，自己 free。
  • 要删的有两个孩子：不能直接删，得找个替身。

替身是右子树里最小的那个结点，叫后继。为什么是它？因为它比被删结点大，又比右子树里其他所有结点都小，把它放到被删的位置，规矩仍然成立。

C
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node *left;
    struct Node *right;
} Node;

Node *insert(Node *root, int v) {
    if (root == NULL) {
        Node *p = malloc(sizeof(Node));
        p->value = v;
        p->left = NULL;
        p->right = NULL;
        return p;
    }
    if (v < root->value) {
        root->left = insert(root->left, v);
    } else if (v > root->value) {
        root->right = insert(root->right, v);
    }
    return root;
}

void inorder(Node *root) {
    if (root == NULL) {
        return;
    }
    inorder(root->left);
    printf("%d ", root->value);
    inorder(root->right);
}

Node *min_node(Node *root) {
    while (root->left != NULL) {
        root = root->left;
    }
    return root;
}

Node *remove_node(Node *root, int v) {
    if (root == NULL) {
        return NULL;
    }
    if (v < root->value) {
        root->left = remove_node(root->left, v);
        return root;
    }
    if (v > root->value) {
        root->right = remove_node(root->right, v);
        return root;
    }

    if (root->left == NULL) {
        Node *r = root->right;
        free(root);
        return r;
    }
    if (root->right == NULL) {
        Node *l = root->left;
        free(root);
        return l;
    }

    Node *s = min_node(root->right);
    root->value = s->value;
    root->right = remove_node(root->right, s->value);
    return root;
}

int main(void) {
    int values[] = {50, 30, 70, 20, 40, 60, 80};
    Node *root = NULL;
    for (int i = 0; i < 7; i++) {
        root = insert(root, values[i]);
    }

    int drop[] = {20, 30, 50};
    for (int i = 0; i < 3; i++) {
        root = remove_node(root, drop[i]);
        printf("删掉 %d 后：", drop[i]);
        inorder(root);
        printf("\n");
    }
    return 0;
}
运行结果
删掉 20 后：30 40 50 60 70 80
删掉 30 后：40 50 60 70 80
删掉 50 后：40 60 70 80

min_node 一路往左走到底，就是最小值。remove_node 的骨架和 insert 一样：先比较、往下找，找到后再分情况。

两个孩子那种情况只有两行关键代码：先把后继的值抄到自己身上，再去右子树里把那个后继删掉。后继是右子树的最小值，一定没有左孩子，所以这个递归最多再走一层就落到前两种情况。用递归把难题变回已经解决的简单题，这个套路在树里到处都是。

▲常见错误

第三种情况里直接 free(root) 再把后继返回上去，会把整片左子树丢掉。正确做法是先替换值，再删后继，原结点留着。

删完 20（叶子）、30（两个孩子）、50（根，有两个孩子），中序始终递增，说明规矩没破。注意删 50 之后 60 顶了上来，而不是 40，因为后继取的是右子树最小值。

7.5 它最难看的样子：退化成链#

做个实验：同一批数字，按升序插和按打乱顺序插，比较高度和查找步数。

C
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node *left;
    struct Node *right;
} Node;

Node *insert(Node *root, int v) {
    if (root == NULL) {
        Node *p = malloc(sizeof(Node));
        p->value = v;
        p->left = NULL;
        p->right = NULL;
        return p;
    }
    if (v < root->value) {
        root->left = insert(root->left, v);
    } else if (v > root->value) {
        root->right = insert(root->right, v);
    }
    return root;
}

int height(Node *root) {
    if (root == NULL) {
        return 0;
    }
    int l = height(root->left);
    int r = height(root->right);
    return (l > r ? l : r) + 1;
}

int search_steps(Node *root, int v) {
    int steps = 0;
    while (root != NULL) {
        steps++;
        if (v == root->value) {
            break;
        }
        root = (v < root->value) ? root->left : root->right;
    }
    return steps;
}

int main(void) {
    int sorted[] = {10, 20, 30, 40, 50, 60, 70};
    int mixed[] = {40, 20, 60, 10, 30, 50, 70};
    Node *a = NULL;
    Node *b = NULL;

    for (int i = 0; i < 7; i++) {
        a = insert(a, sorted[i]);
        b = insert(b, mixed[i]);
    }

    printf("顺序插入：高度 %d，找 70 用 %d 步\n", height(a), search_steps(a, 70));
    printf("打乱插入：高度 %d，找 70 用 %d 步\n", height(b), search_steps(b, 70));
    return 0;
}
运行结果
顺序插入：高度 7，找 70 用 7 步
打乱插入：高度 3，找 70 用 3 步

第一棵树里每个结点都只有右孩子，形状和单链表一模一样。找 70 要从 10 一路走到 70，比 7 次。要是数据是 100 万条已经排好序的记录，这棵树会变成 100 万层的「链表」，查找 O(n)，还白搭了一堆指针的内存。

这不是你代码写错了，是 BST 太老实：它完全按你的插入顺序长。有序的输入是 BST 的天敌。实际项目里通常这么对付：

  • 插之前把数据打乱，或者至少别保证有序
  • 用平衡树（AVL、红黑树），插入时自动旋转，把高度压回 O(log n)
  • 干脆不用树，换哈希表

第二条就是 C++ 里 std::map 底层是红黑树的原因。旋转要把左左、左右、右左、右右四种情况分开处理，比这一课的 insert 长得多，所以这里不写，知道有这回事就够了。

7.6 有序这件事，哈希表给不了#

哈希表查找是 O(1)，比 BST 快。那 BST 还有什么存在的价值？

因为 BST 存的是顺序，哈希表存的是位置。所有「按大小找」的需求，哈希表都答不上来。

C
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node *left;
    struct Node *right;
} Node;

Node *insert(Node *root, int v) {
    if (root == NULL) {
        Node *p = malloc(sizeof(Node));
        p->value = v;
        p->left = NULL;
        p->right = NULL;
        return p;
    }
    if (v < root->value) {
        root->left = insert(root->left, v);
    } else if (v > root->value) {
        root->right = insert(root->right, v);
    }
    return root;
}

int kth_smallest(Node *root, int k, int *visited) {
    if (root == NULL) {
        return -1;
    }
    int found = kth_smallest(root->left, k, visited);
    if (found != -1) {
        return found;
    }
    (*visited)++;
    if (*visited == k) {
        return root->value;
    }
    return kth_smallest(root->right, k, visited);
}

int main(void) {
    int values[] = {50, 30, 70, 20, 40, 60, 80};
    Node *root = NULL;
    for (int i = 0; i < 7; i++) {
        root = insert(root, values[i]);
    }

    for (int k = 1; k <= 7; k += 3) {
        int visited = 0;
        printf("第 %d 小：%d\n", k, kth_smallest(root, k, &visited));
    }
    return 0;
}
运行结果
第 1 小：20
第 4 小：50
第 7 小：80

找第 k 小，靠的还是中序有序：边走边数，数到第 k 个就停。它只用了 O(h) 的递归栈，不需要把整棵树读进数组再排序。visited 用指针传，是因为递归的每一层都要共享同一个计数器。这和 7.3 里讨论的是同一个问题：怎样让函数改动外面的变量。那里用返回值，这里用指针。

同样的思路还能做范围查询：找出所有在 [30, 60] 之间的值，中序遍历时加两个判断就能剪掉整片不可能的分支，不用访问全部结点。这种活哈希表只能把所有 key 捞出来逐个比。

所以选型很清楚。只按 key 查值，用哈希；还要按大小范围取、要顺序遍历、要第 k 小，用 BST，真在乎性能就上平衡树。

✎练习
  1. 写 int is_bst(Node *root)，用中序遍历判断一棵二叉树是不是二叉搜索树。提示：记住上一次访问的值，看它是不是一直变大。
  2. 给结点加一个 int count 字段，让 insert 支持重复值（重复只加计数），remove_node 减计数，减到 0 才真正删结点。
  3. 写一个用「左子树最大值」替换的删除版本，跑本课同样的测试，输出应该完全一样。
  4. 写 int count_less(Node *root, int x)，统计比 x 小的结点个数。要求不能遍历全部结点，得利用「左子树全小」这条性质剪枝。
◆小结
  • BST 的规矩是左小右大，中序遍历一定升序，这是一切操作的地基
  • 查找和插入都只走一条从根到叶的路径，复杂度是 O(h)，不是 O(log n)
  • 删除分三种情况，有两个孩子时用右子树最小值替换，再递归删掉它
  • 按有序数据插入会退化成链表；要范围查询、要第 k 小，哈希表替不了它
  • 下一课 第 8 课 堆：也是一棵二叉树，但不按大小排左右，只保证根是最值
