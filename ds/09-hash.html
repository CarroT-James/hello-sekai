第 9 课 哈希表

预计 40 分钟·约 9,236 字·数据结构

前面几课找东西，靠的都是比较：数组从头扫，链表一个个看，BST 一路比大小。哈希表换了个思路，它不找，它算。

你取快递时不会把柜子一个个打开看，而是看取件码，直接走到编号对应的柜子。哈希做的就是「取件码到柜子」这个映射。理想情况下，一次就到位，O(1)。

代价是柜子数量有限。快递一多，两个包裹的取件码可能指到同一个柜子。这一课有一半篇幅都在处理这件事，因为哈希表真正的难点从来不是「怎么算」，而是「撞了怎么办」。

9.1 用顺序换速度#

先说清楚哈希表放弃了什么。数组按下标访问是 O(1)，BST 有序遍历 O(n)，哈希表把「顺序」彻底扔了，换来任意 key 的 O(1) 存取。

扔掉的顺序会在很多地方咬你：

  • 遍历哈希表的顺序是乱的，按桶号走，跟插入顺序、大小顺序都没关系
  • 想输出「按学号排序的成绩单」，还得把 key 捞出来再排一次
  • 「找出分数在 80 到 90 之间的所有学生」这种范围查询，哈希表只能全表扫

所以哈希表不是「更好的数组」，它是另一种取舍。你只能按 key 精确查，它快得离谱；你要按顺序做任何事，它一无是处。

9.2 哈希函数：把任意 key 压成一个下标#

哈希函数干的事很朴素：输入一个 key，输出一个 0 到 cap-1 之间的整数，这个整数就是槽位下标。

它得满足三条：

  • 算得快，最好几条指令搞定，否则 O(1) 没意义
  • 分布均匀，key 稍微变一点，槽位就要跳得远
  • 确定性，同一个 key 任何时候都算出同一个值

整数最简单，取模就行。字符串麻烦些，得把每个字符混进去，常用的是 djb2：h = h * 33 + c。

C
#include <stdio.h>

unsigned int hash_int(int key, unsigned int cap) {
    return (unsigned int)key % cap;
}

unsigned int hash_str(const char *s, unsigned int cap) {
    unsigned int h = 5381;
    while (*s != '\0') {
        h = h * 33 + (unsigned char)*s;
        s++;
    }
    return h % cap;
}

int main(void) {
    int keys[] = {31, 51, 71, 12, 99};
    printf("cap = 10\n");
    for (int i = 0; i < 5; i++) {
        printf("key %2d -> 槽位 %u\n", keys[i], hash_int(keys[i], 10));
    }

    const char *words[] = {"apple", "banana", "cherry"};
    printf("cap = 16\n");
    for (int i = 0; i < 3; i++) {
        printf("%-8s-> 槽位 %u\n", words[i], hash_str(words[i], 16));
    }

    printf("-7 %% 10 = %d\n", -7 % 10);
    printf("(unsigned)-7 %% 10 = %u\n", (unsigned int)(-7) % 10);
    return 0;
}
运行结果
cap = 10
key 31 -> 槽位 1
key 51 -> 槽位 1
key 71 -> 槽位 1
key 12 -> 槽位 2
key 99 -> 槽位 9
cap = 16
apple   -> 槽位 7
banana  -> 槽位 6
cherry  -> 槽位 2
-7 % 10 = -7
(unsigned)-7 % 10 = 9

31、51、71 全进了 1 号槽。原因很明显：它们的个位都是 1，而 % 10 只看个位。这不是哈希函数写错了，是你的 key 太有规律。

这就是为什么桶的数量尽量取质数。假如 cap 是 1024，key % 1024 只用到 key 的低 10 位，高位完全不参与。真实数据里「低几位相同」的情况多得吓人：学号末位、身份证最后几位、时间的毫秒数。用质数当 cap，能把这些规律打散。

最后两行是 C 里的负数取模。-7 % 10 在 C 里是 -7，不是 -3，因为 C 的除法朝零取整。拿负数直接当下标，等于往数组前面乱写内存，通常当场段错误。所以 hash_int 里先转 (unsigned int)：转换后是一个很大的正数，再取模就落在正常范围了。

9.3 冲突是必然，不是意外#

20 个包裹，10 个柜子，你说会不会有两个挤一格？这不叫「可能」，这叫鸽笼原理：n 个东西放进 m 个笼子，n 大于 m 就一定有一个笼子装两个以上。

那 n 小于 m 就安全了？也没有。10 个 key 放进 100 个桶，一个都不撞的概率只有六成左右，撞的概率超过三分之一。这就是生日悖论：23 个人里有两个同生日的概率过半，而一年有 365 天。

C
#include <stdio.h>

#define BUCKETS 10

int main(void) {
    int keys[] = {17, 27, 37, 4, 14, 24, 35, 46, 57, 68};
    int count[BUCKETS] = {0};
    int n = 10;

    for (int i = 0; i < n; i++) {
        count[keys[i] % BUCKETS]++;
    }

    int bad = 0;
    for (int i = 0; i < BUCKETS; i++) {
        printf("桶 %d：%d 个", i, count[i]);
        if (count[i] > 1) {
            printf("   <- 撞了");
            bad++;
        }
        printf("\n");
    }
    printf("%d 个 key，%d 个桶，有 %d 个桶不止一个\n", n, BUCKETS, bad);
    return 0;
}
运行结果
桶 0：0 个
桶 1：0 个
桶 2：0 个
桶 3：0 个
桶 4：3 个   <- 撞了
桶 5：1 个
桶 6：1 个
桶 7：4 个   <- 撞了
桶 8：1 个
桶 9：0 个
10 个 key，10 个桶，有 2 个桶不止一个

10 个 key、10 个桶，结果最挤的桶塞了 4 个。而且注意 9 号桶是空的：有的桶空着，有的桶挤爆，这就是「分布不均」。

处理冲突只有两条路：

办法撞了之后优点缺点
拉链法在同一个桶里挂一条链表删除简单，负载因子可以大于 1每个结点一个指针，内存不连续
开放寻址顺着数组往后找下一个空位没有指针，缓存友好负载因子必须小于 1，删除麻烦

先定义一个量：负载因子 α = 元素个数 / 桶数。拉链法的 α 可以到 1 甚至更高，代价是链变长；开放寻址的 α 一般压在 0.7 以下，过了这个坎探测长度会爆炸。这件事 9.5 会细说。

9.4 手写拉链法哈希表#

拉链法的结构很好记：一个指针数组当桶，每个桶挂一条单链表。同样，下面 malloc 的返回值没判 NULL，省了几行，别学这个坏习惯。同一个槽位的 key 都在同一条链上，查找时先算槽位，再顺着链比 key。

C
#include <stdio.h>
#include <stdlib.h>

#define CAP 13

typedef struct Node {
    int key;
    int value;
    struct Node *next;
} Node;

Node *buckets[CAP];

unsigned int slot_of(int key) {
    return (unsigned int)key % CAP;
}

void put(int key, int value) {
    unsigned int i = slot_of(key);
    for (Node *p = buckets[i]; p != NULL; p = p->next) {
        if (p->key == key) {
            p->value = value;
            return;
        }
    }
    Node *p = malloc(sizeof(Node));
    p->key = key;
    p->value = value;
    p->next = buckets[i];
    buckets[i] = p;
}

int get(int key, int *out) {
    for (Node *p = buckets[slot_of(key)]; p != NULL; p = p->next) {
        if (p->key == key) {
            *out = p->value;
            return 1;
        }
    }
    return 0;
}

int remove_key(int key) {
    Node **pp = &buckets[slot_of(key)];
    while (*pp != NULL) {
        if ((*pp)->key == key) {
            Node *dead = *pp;
            *pp = dead->next;
            free(dead);
            return 1;
        }
        pp = &(*pp)->next;
    }
    return 0;
}

int main(void) {
    int v;
    put(31, 100);
    put(44, 440);
    put(70, 700);
    put(12, 120);
    put(31, 111);

    printf("31、44、70 的槽位：%u %u %u\n", slot_of(31), slot_of(44), slot_of(70));
    if (get(31, &v)) {
        printf("get(31) = %d\n", v);
    }
    if (get(44, &v)) {
        printf("get(44) = %d\n", v);
    }
    printf("get(99) %s\n", get(99, &v) ? "找到了" : "没找到");
    printf("删除 44：%s\n", remove_key(44) ? "成功" : "不存在");
    printf("删完再查 44：%s\n", get(44, &v) ? "找到了" : "没找到");
    return 0;
}
运行结果
31、44、70 的槽位：5 5 5
get(31) = 111
get(44) = 440
get(99) 没找到
删除 44：成功
删完再查 44：没找到

31、44、70 都落在 5 号槽，链表长度是 3。查 44 要先比 31、再比 44，两次比较。这就是拉链法的代价：同槽的元素越多，链越长，查找越慢。

三个细节：

put 里的第一段循环负责「key 已存在就覆盖」。少了它，同一个 key 会插两次，get 拿到的可能是旧值。哈希表语义上不允许重复 key，这跟 map 一样。

put 用头插，新结点直接挂到链首，O(1) 搞定。缺点是同槽元素的遍历顺序和插入顺序相反，反正哈希表本来就不保证顺序。

remove_key 那两行用了二级指针 Node **pp，把「前驱结点的 next 指针」当成一个变量来改，省掉了单独判空头的分支。不习惯的话写成 prev 也行，多几行而已。指针这块要是发虚，回去翻 C 语言 指针，二级指针是那章最后一个大坎。

▲常见错误

buckets 是全局数组，默认全 0，可以直接用。把它改成局部变量却不初始化，里面全是垃圾指针，put 一挂链就崩。

9.5 负载因子：什么时候该扩容#

固定 13 个桶，插 100 个元素，平均每条链 7 个结点，查找退化成链表。所以桶的数量不能写死，得跟着元素数涨。

规矩是：元素个数达到 cap * 0.75 就把桶翻倍。翻倍之后要把所有元素重新算一遍槽位，这一步叫 rehash。注意不能直接把旧桶照搬过去，因为取模的除数变了，key % 13 和 key % 26 完全是两回事。

C
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int key;
    int value;
    struct Node *next;
} Node;

typedef struct {
    Node **buckets;
    int cap;
    int size;
} Table;

Table *table_new(int cap) {
    Table *t = malloc(sizeof(Table));
    t->cap = cap;
    t->size = 0;
    t->buckets = calloc((size_t)cap, sizeof(Node *));
    return t;
}

unsigned int slot_of(Table *t, int key) {
    return (unsigned int)key % (unsigned int)t->cap;
}

void grow(Table *t) {
    int new_cap = t->cap * 2;
    Node **fresh = calloc((size_t)new_cap, sizeof(Node *));

    for (int i = 0; i < t->cap; i++) {
        Node *p = t->buckets[i];
        while (p != NULL) {
            Node *next = p->next;
            unsigned int j = (unsigned int)p->key % (unsigned int)new_cap;
            p->next = fresh[j];
            fresh[j] = p;
            p = next;
        }
    }

    free(t->buckets);
    t->buckets = fresh;
    t->cap = new_cap;
}

void put(Table *t, int key, int value) {
    unsigned int i = slot_of(t, key);
    for (Node *p = t->buckets[i]; p != NULL; p = p->next) {
        if (p->key == key) {
            p->value = value;
            return;
        }
    }

    Node *p = malloc(sizeof(Node));
    p->key = key;
    p->value = value;
    p->next = t->buckets[i];
    t->buckets[i] = p;
    t->size++;

    if (t->size * 4 >= t->cap * 3) {
        grow(t);
    }
}

int max_chain(Table *t) {
    int best = 0;
    for (int i = 0; i < t->cap; i++) {
        int len = 0;
        for (Node *p = t->buckets[i]; p != NULL; p = p->next) {
            len++;
        }
        if (len > best) {
            best = len;
        }
    }
    return best;
}

int main(void) {
    Table *t = table_new(4);

    for (int i = 0; i < 20; i++) {
        int old = t->cap;
        put(t, i * 4, i);
        if (t->cap != old) {
            printf("插到第 %2d 个时扩容：cap %d -> %d\n", t->size, old, t->cap);
        }
    }

    printf("最终 cap %d，元素 %d 个，最长链 %d\n", t->cap, t->size, max_chain(t));
    return 0;
}
运行结果
插到第  3 个时扩容：cap 4 -> 8
插到第  6 个时扩容：cap 8 -> 16
插到第 12 个时扩容：cap 16 -> 32
最终 cap 32，元素 20 个，最长链 3

三次扩容分别发生在 3、6、12 个元素时，负载因子每次都刚好摸到 0.75 那条线。

请注意最后一个数字：20 个元素，最长链只有 3。这批 key 全是 4 的倍数，如果桶数一直是 4，它们会全部落在 0 号桶，退化成一条 20 节的链表。扩容器的作用就是把链长按在一个常数附近，这样「O(1)」才不是嘴上说说。

扩容那一次是 O(n)，因为要把所有结点搬一遍。但每插入一个元素才扩容一次、而扩容后容量翻倍，所以把总代价摊到每次插入上，仍然是 O(1)。这就是第 2 课动态数组讲过的那套均摊分析，思路一模一样。

9.6 开放寻址：撞了就往后挪#

拉链法用链表解决冲突。开放寻址的思路是：一个桶只放一个元素，撞了就去数组里的下一个空位，还撞就再下一个，走到末尾绕回开头。

这叫线性探测。它省掉了所有指针和 malloc，整张表就是两个数组，对 CPU 缓存极其友好，实测通常比拉链法快。代价有三个：

  • 表满了就真的没地方放了，α 必须小于 1
  • 撞车会「传染」：连续被占的位置越排越长，叫一次聚集
  • 删除不能用置空，得打墓碑

第三条最反直觉，一定要看代码。

C
#include <stdio.h>

#define CAP 13
#define EMPTY 0
#define USED 1
#define DELETED 2

int keys[CAP];
int values[CAP];
int state[CAP];

unsigned int slot_of(int key) {
    return (unsigned int)key % CAP;
}

int put(int key, int value) {
    unsigned int start = slot_of(key);
    int reuse = -1;

    for (unsigned int step = 0; step < CAP; step++) {
        unsigned int i = (start + step) % CAP;
        if (state[i] == USED && keys[i] == key) {
            values[i] = value;
            return 1;
        }
        if (state[i] == DELETED && reuse == -1) {
            reuse = (int)i;
        }
        if (state[i] == EMPTY) {
            if (reuse != -1) {
                i = (unsigned int)reuse;
            }
            keys[i] = key;
            values[i] = value;
            state[i] = USED;
            return 1;
        }
    }

    if (reuse != -1) {
        keys[reuse] = key;
        values[reuse] = value;
        state[reuse] = USED;
        return 1;
    }
    return 0;
}

int find(int key, int *out, int *probes) {
    unsigned int start = slot_of(key);
    for (unsigned int step = 0; step < CAP; step++) {
        unsigned int i = (start + step) % CAP;
        (*probes)++;
        if (state[i] == EMPTY) {
            return 0;
        }
        if (state[i] == USED && keys[i] == key) {
            *out = values[i];
            return 1;
        }
    }
    return 0;
}

int erase(int key) {
    unsigned int start = slot_of(key);
    for (unsigned int step = 0; step < CAP; step++) {
        unsigned int i = (start + step) % CAP;
        if (state[i] == EMPTY) {
            return 0;
        }
        if (state[i] == USED && keys[i] == key) {
            state[i] = DELETED;
            return 1;
        }
    }
    return 0;
}

int main(void) {
    int v;
    int probes = 0;

    int add[] = {3, 16, 29};
    for (int i = 0; i < 3; i++) {
        put(add[i], add[i] * 10);
        printf("插入 %d：槽位从 %u 开始\n", add[i], slot_of(add[i]));
    }

    int ok;

    probes = 0;
    ok = find(29, &v, &probes);
    printf("查 29：%s，探测 %d 次\n", ok ? "找到" : "没找到", probes);
    printf("删除 16：%s\n", erase(16) ? "成功" : "不存在");

    probes = 0;
    ok = find(16, &v, &probes);
    printf("删完查 16：%s，探测 %d 次\n", ok ? "找到" : "没找到", probes);
    probes = 0;
    ok = find(29, &v, &probes);
    printf("删完查 29：%s，探测 %d 次\n", ok ? "找到" : "没找到", probes);
    return 0;
}
运行结果
插入 3：槽位从 3 开始
插入 16：槽位从 3 开始
插入 29：槽位从 3 开始
查 29：找到，探测 3 次
删除 16：成功
删完查 16：没找到，探测 4 次
删完查 29：找到，探测 3 次

三个 key 都从下标 3 出发，插进去实际占了 3、4、5。查 29 的时候要依次看 3、4、5，探测 3 次，这就是一次聚集的代价。

现在看删除。16 在下标 4。如果直接把它设成 EMPTY，5 号位的 29 就再也找不到了：查 29 从 3 出发，看到下标 4 是空的，程序会立刻判断「不存在」，直接返回。明明 29 还在 5 号位，你却找不到。这就是 DELETED 墓碑存在的全部理由：它告诉查找「这里原来有东西，别停，继续往后看」。

所以你看到「删完查 16」探测了 4 次：3 号（key 是 3）、4 号（墓碑）、5 号（key 是 29）、6 号（空的），才敢下结论。

◆记忆点

开放寻址的查找靠「遇到空位就停」来收尾，所以删除时不能真的留空。墓碑是把「删」变成「标记删」，代价是表会慢慢变脏，需要定期重建。

线性探测的聚集问题有解：二次探测按 +1, +4, +9 的步长跳，双哈希用第二个哈希函数决定步长。再往上还有 Robin Hood、布谷鸟哈希这些，都属于「把冲突处理做到极致」的方向，这一课不展开。

9.7 什么时候别用哈希表#

哈希表好用，但下面这几种情况它会坑你：

要顺序。哈希表的遍历顺序是按桶号来的，和 key 的大小无关。想按学号输出，必须把 key 取出来再排一次，等于多付一次 O(n log n)。

要范围。找 [30, 60] 之间的所有 key，哈希表没有任何办法跳过无关的桶，只能把整张表扫一遍。这种活 BST 一次中序就能剪枝。

怕最坏情况。如果所有 key 都撞进一个桶，哈希表退化成一条链表，O(1) 变成 O(n)。更糟的是，攻击者可以故意构造大量同槽的 key，把你的服务器拖死，这叫哈希洪水。所以生产环境的哈希函数通常带一个随机种子，每次启动都不一样，让攻击者算不出来。

key 会变。C 里用 char * 当 key，存进去的是指针。如果你后面改了字符串内容，或者那块内存被 free 了，哈希值就变了，key 再也找不回来。正确做法是把自己那份字符串复制出来（strdup），并且保证存进去之后不再修改。

一句话选型：只要「按 key 精确存取」，用哈希；只要「按大小顺序做事」，用树；两样都要，就两张表各存一份。

✎练习
  1. 把 9.4 的拉链法改成 char * 作 key，用 strcmp 比较，把 key 复制一份存起来。测一下用同一个字符串内容但不同地址去查，能不能查到。
  2. 给 9.5 的表加一个 get 和一个统计函数，输出「查找一次平均要比几个结点」。在 1000 个元素、不同初始容量下各测一次，看看负载因子的影响。
  3. 9.6 的线性探测换成二次探测：步长改成 +1, +4, +9, ...，也就是 (start + step*step) % CAP。同样的测试数据，探测次数变多了还是变少了？
  4. 用哈希表统计一段文本里每个单词出现的次数（单词用空格和标点分隔），按次数从多到少输出前 5 个。提示：哈希表只负责存，排序还得另外做。
◆小结
  • 哈希表用「算位置」代替「比较」，理想 O(1)，代价是丢掉顺序
  • 冲突必然存在，拉链法挂链表，开放寻址往后找空位
  • 负载因子到 0.75 就扩容，扩容要重算槽位，均摊下来仍是 O(1)
  • 开放寻址删除要打墓碑；要顺序、要范围查询、key 会变，就绕开哈希表
