第 1 课 复杂度与算法思维

预计 35 分钟·约 5,718 字·数据结构

刚学完数组和循环那阵，我判断一段代码好不好，办法特别土：掐表。同一个题写两版，哪版跑得快就用哪版。这个办法在小数据上从没骗过我，直到有次我把 n 从一万改成一百万，原本「快」的那版跑了十几秒，被我嫌弃的那版还是瞬间出结果。

后来我才想明白，秒表量的是「这台机器、这个数据量」下的结果，换台电脑、换个 n，结论就可能翻过来。复杂度问的是另一个问题：数据量翻倍的时候，工作量会翻几倍。

大 O 那套符号第一次看确实像天书。我当年盯着 O(n log n) 看了半天，心想这到底是个数还是个函数。这一课不背定义，用五个能跑的小程序把它拆开。复杂度这个词，你在 C 语言 第 8 章 数据结构与算法入门 里大概扫到过一眼，当时可能只记住了一个 O(n²)，没往深处想。现在把它捡起来。

1.1 同样的活，两种干法#

先算 1 加到 n。最直白的写法是一个循环，另一个人可能直接甩出求和公式。

C
#include <stdio.h>

int main(void) {
    int n = 100;
    int sum = 0;
    int steps = 0;

    for (int i = 1; i <= n; i++) {
        sum += i;
        steps++;
    }
    printf("循环：sum = %d，做了 %d 次加法\n", sum, steps);

    sum = n * (n + 1) / 2;
    printf("公式：sum = %d，只做了 3 次运算\n", sum);
    return 0;
}
运行结果
循环：sum = 5050，做了 100 次加法
公式：sum = 5050，只做了 3 次运算

两段都算出了 5050。n = 100 时，97 次加减在你电脑上连一毫秒都不到，根本感觉不出来。但把 n 换成 1 亿：第一种老老实实加 1 亿次，第二种还是那 3 次。这时候差距不是「快一点」，而是「能跑」和「跑不完」。

复杂度就是把这个「次数怎么随 n 涨」写成一句话。它不关心你的 CPU 是 i5 还是 M3，也不关心编译器开没开优化，只关心 n 变大时那条曲线的形状。

1.2 大 O：只留涨得最快的那一项#

看三段循环，每段都数一下执行了多少次。

C
#include <stdio.h>

int main(void) {
    int n = 1000;
    long long a = 0, b = 0, c = 0;

    for (int i = 0; i < n; i++) a++;

    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) b++;

    for (int i = 1; i < n; i *= 2) c++;

    printf("n = %d\n", n);
    printf("一层循环   %lld 次\n", a);
    printf("两层嵌套   %lld 次\n", b);
    printf("每次乘 2   %lld 次\n", c);
    return 0;
}
运行结果
n = 1000
一层循环   1000 次
两层嵌套   1000000 次
每次乘 2   10 次

比例是 1000 : 1000000 : 10。第二段比第一段多了一千倍，第三段反而只要十次。

真实程序的工作量通常长这样：3n² + 5n + 7。n = 1000 时它是 3005007，其中 3n² 占了 99.8%。n 再大一点，5n + 7 连零头都不算。所以大 O 把系数和低阶项全扔掉，只留 n²，记作 O(n²)。

扔系数不是耍赖。你只需要关心「n 变大时谁先撑不住」，而这件事由最高阶项决定。严格一点的说法是：如果存在常数 c，使得 n 足够大时步数不超过 c·f(n)，就记作 O(f(n))。你现在只用记住两件事——看上界，只留最高阶。

◆记忆点

大 O 描述的是增长趋势，不是精确次数。O(n) 的算法完全可能比 O(n²) 的算法慢：n 很小时，或者常数差得离谱时，就是这样。它回答的是「n 大了以后谁先垮」，不是「谁永远更快」。

最后一段 i *= 2 值得单独说。i 依次是 1、2、4、8……，跑到 1000 只要 10 步，因为 2^10 = 1024。这类「每轮砍一半」或「每轮翻一倍」的循环，复杂度是 O(log n)。后面的二分查找、平衡树、堆，全靠它吃饭。

1.3 常见的几档，和它们的生活原型#

复杂度典型场景n = 100 万时的量级
O(1)数组按下标取值、栈顶进出1
O(log n)二分查找、平衡树查找20
O(n)遍历一遍数组或链表100 万
O(n log n)归并排序、快速排序平均2000 万
O(n²)双重循环、冒泡排序1 万亿
O(2^n)枚举所有子集大到没法跑

表格里 O(n²) 那一行，1 万亿次运算够你的笔记本跑上几个小时。这就是「能跑」和「能过」的区别。

小区快递柜可以拿来对照。你知道格口编号，直接走过去开，不用从 1 号数起——O(1)。柜子按编号排好，你每次猜中间那个，猜错就砍掉一半——O(log n)。柜子没编号，只能从第一个挨个看——O(n)。要是每个包裹都得和其他所有包裹比一遍才能确定放哪，那就是 O(n²)。

二分查找是 O(log n) 最干净的样板。

C
#include <stdio.h>

int main(void) {
    int n = 1000000;
    int lo = 1, hi = n, target = 999999;
    int steps = 0;

    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        steps++;
        if (mid == target) break;
        if (mid < target) lo = mid + 1;
        else hi = mid - 1;
    }
    printf("在 1 到 %d 里找 %d，比较了 %d 次\n", n, target, steps);
    return 0;
}
运行结果
在 1 到 1000000 里找 999999，比较了 19 次

19 次。为什么这么少？每比较一次，候选范围就砍一半。2^19 = 524288，2^20 = 1048576，所以 100 万以内的数，20 次之内必然锁定。你把 n 再乘 1000，比较次数也只多 10 次——这就是 log 的脾气。

注意 mid = lo + (hi - lo) / 2 这个写法。直接写 (lo + hi) / 2 在教科书里很常见，但当 lo 和 hi 都接近 int 上限时，相加会溢出成负数，然后程序越界崩溃。这个 bug 在真实项目里出过，而且极难查。养成写差值的习惯，不亏。

▲常见错误

二分查找写不对，九成是边界：while (lo <= hi) 还是 <，hi = mid 还是 mid - 1，差一个等号就死循环或者漏掉答案。写完拿 n = 1、n = 2、target 在两端这几种情况各跑一遍，比盯着看十分钟有用。

1.4 最好、最坏、平均：别拿运气当性能#

同样是线性查找，目标在哪，代价差很多。

C
#include <stdio.h>

int search(int a[], int n, int target, int *cmp) {
    *cmp = 0;
    for (int i = 0; i < n; i++) {
        (*cmp)++;
        if (a[i] == target) return i;
    }
    return -1;
}

int main(void) {
    int a[10] = {3, 8, 15, 22, 31, 40, 55, 61, 78, 90};
    int cmp, pos;

    pos = search(a, 10, 3, &cmp);
    printf("找 3：  下标 %d，比较 %d 次\n", pos, cmp);
    pos = search(a, 10, 55, &cmp);
    printf("找 55： 下标 %d，比较 %d 次\n", pos, cmp);
    pos = search(a, 10, 100, &cmp);
    printf("找 100：下标 %d，比较 %d 次\n", pos, cmp);
    return 0;
}
运行结果
找 3：  下标 0，比较 1 次
找 55： 下标 6，比较 7 次
找 100：下标 -1，比较 10 次

同一个函数，最好 1 次，最坏 10 次，平均大概 5 次。那它的复杂度到底算哪个？

习惯上说最坏情况。原因很实际：决定你会不会超时、会不会崩的，是最坏那一次，不是运气好的那一次。你写个查找，自己的测试数据里目标恰好在第一个，跑得飞快，交上去被一组「目标不存在」的数据打回来——这种事每年都有人遇上。

平均情况一般也是 O(n)：平均找 n/2 次，系数 1/2 扔掉还是 n。所以这个查找就叫 O(n)，不管最好那次有多快。

★补充说明

有些算法最好和最坏差得非常远。快速排序平均 O(n log n)，最坏 O(n²)；哈希表平均 O(1)，最坏 O(n)。别人问「这个多快」，把平均和最坏都报出来，比只报一个数专业得多。

1.5 空间换时间：拿内存买速度#

数一下 100 万以内有多少个素数。最直接的办法是每个数都试除，另一个办法是开一个标记数组，把合数一个个划掉，也就是筛法。

C
#include <stdio.h>
#include <stdlib.h>

long long count_by_division(int n, int *primes) {
    long long ops = 0;
    *primes = 0;
    for (int x = 2; x <= n; x++) {
        int is_prime = 1;
        for (int d = 2; d * d <= x; d++) {
            ops++;
            if (x % d == 0) {
                is_prime = 0;
                break;
            }
        }
        if (is_prime) (*primes)++;
    }
    return ops;
}

long long count_by_sieve(int n, int *primes) {
    char *mark = malloc((size_t)n + 1);
    if (mark == NULL) return -1;
    for (int i = 0; i <= n; i++) mark[i] = 0;

    long long ops = 0;
    for (int i = 2; (long long)i * i <= n; i++) {
        if (mark[i]) continue;
        for (int j = i * i; j <= n; j += i) {
            mark[j] = 1;
            ops++;
        }
    }

    *primes = 0;
    for (int i = 2; i <= n; i++)
        if (mark[i] == 0) (*primes)++;

    free(mark);
    return ops;
}

int main(void) {
    int sizes[2] = {100000, 1000000};
    for (int k = 0; k < 2; k++) {
        int n = sizes[k];
        int p1, p2;
        long long a = count_by_division(n, &p1);
        long long b = count_by_sieve(n, &p2);
        printf("n = %d\n", n);
        printf("  试除法：%lld 次取余，找到 %d 个素数\n", a, p1);
        printf("  筛法：  %lld 次标记，找到 %d 个素数\n", b, p2);
    }
    return 0;
}
运行结果
n = 100000
  试除法：2745694 次取余，找到 9592 个素数
  筛法：  193078 次标记，找到 9592 个素数
n = 1000000
  试除法：67740404 次取余，找到 78498 个素数
  筛法：  2122048 次标记，找到 78498 个素数

结果一样，代价差 6500 万次运算。多花的那点空间是 1MB（100 万个 char），换来的是一台老笔记本也能瞬间跑完。n 从 10 万涨到 100 万，差距还从 14 倍拉到了 32 倍。

这就是空间换时间：拿一块额外的内存，记住「已经算过的东西」，让后面的计算不用重来。筛法的表建一次，之后想查多少遍都行。导航软件提前算好路网、游戏提前烘焙光照、数据库给字段建索引，都是同一笔账。

但这笔账不是永远划算。如果只查一次、查完就扔，或者内存本来就紧张（单片机、嵌入式），那 1MB 的代价可能比省下的时间还大。先算清「表能不能复用」，再决定换不换。

1.6 拿到题，先估一遍再动手#

写代码之前花两分钟做四件事，能省掉后面两小时的重写。

  1. 数循环层数。一层通常是 O(n)，两层嵌套 O(n²)。但别只看层数，要看每层到底跑多少次。
  2. 看边界。for (j = 0; j < i; j++) 里层总共跑 n(n-1)/2 次，还是 n² 那一档；i *= 2 是 log n。
  3. 乘起来，只留最高阶。两个独立的循环是 n + n = O(n)，不是 O(n²)。
  4. 用 n 的上限反推。

第 4 步有个粗糙但好用的经验值：C 语言一秒大约能做 1 亿次简单运算。照这个估：

n 的上限能过的复杂度说明
100O(n³) 也许行100 万次，随便跑
1000O(n²)100 万次，稳
10^5O(n log n)170 万次，稳
10^6O(n) 或常数小的 O(n log n)几千万次，看常数
10^9O(log n)、O(1)循环一遍就超时

这张表不是定律，机器有快有慢，常数有大有小。但它能挡住八成「本地跑得欢、交上去超时」的惨案。

最后回答一个你可能想问的问题：大一为什么要懂这个？因为后面每一课都会用 O(...) 给操作标价：数组按下标取 O(1)，链表找第 k 个 O(n)，栈和队列进出 O(1)，二叉搜索树查找平均 O(log n)。不先建立这套语言，后面听什么都是散的。而且它不只用于考试——你写个脚本处理十万行日志，卡不卡，就看这一眼估算。

✎练习
  1. 把 1.1 的程序里 n 改成 1 亿。先算 sum 会不会溢出（int 上限约 21 亿），再估时间，最后跑一次验证。跑不动就改成 1000 万，看估算误差多大。
  2. 判断下面三段的复杂度：a) 双层循环，内层 j < i；b) for (i = 1; i < n; i *= 3)；c) 先一个 n 次循环，再一个 n² 次循环。
  3. 把二分查找改成「找不到返回 -1」，并打印每一轮的 lo、hi、mid。n = 100 万、target = 1 时比较几次？先猜再跑。
  4. 把筛法的 char 数组换成 int 数组，用 sizeof 算内存，各跑三次比较耗时；再把上限提到 500 万，看哪个先撑不住。
◆小结
  • 复杂度看趋势：n 翻倍，工作量涨几倍，而不是掐表看秒数
  • 大 O 只留最高阶、扔掉系数，默认说最坏情况
  • 常备几档：O(1)、O(log n)、O(n)、O(n log n)、O(n²)
  • 空间换时间的关键是「表能复用」，不是无脑开数组
