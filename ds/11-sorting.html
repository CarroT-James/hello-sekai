第 11 课 排序算法总览

预计 40 分钟·约 6,568 字·数据结构

排序是算法课的门面。面试爱问，作业爱考，但真正在工作中，你多半只会调用一次 qsort 或者 sort。

那还学它干什么？因为排序是练「复杂度直觉」最好的靶子。同样把 6 个数排好，有的算法要比较 15 次，有的只要 9 次；同样 100 万个数，有的要几秒，有的要几分钟。这个差距不是优化出来的，是选错了算法。

这一课把五种主流排序各写一遍，都用同一组数据，最后给一张能直接拿去用的选型表。代码都不长，值得逐个敲一遍。

11.1 先看结论#

先给表，后面逐个验证表里的每一格。

算法最好平均最坏额外空间稳定
冒泡O(n)O(n²)O(n²)O(1)是
选择O(n²)O(n²)O(n²)O(1)否
插入O(n)O(n²)O(n²)O(1)是
归并O(n log n)O(n log n)O(n log n)O(n)是
快排O(n log n)O(n log n)O(n²)O(log n)否

「稳定」这个词容易被误解。它和快慢无关，说的是：两个相等的元素，排序后相对位置不变。

为什么要管这个？假设你有一份名单，先按姓名排好，现在要按分数从高到低排，同分的保持姓名顺序。一个稳定的排序能做到，因为姓名顺序被原样保留下来；不稳定的排序可能把同分的张三李四换个个儿。多关键字排序全靠这个性质，一层层叠上去就行。

11.2 冒泡：相邻两个比大小#

冒泡的做法笨得可爱：从左到右，相邻两个比一下，前大后小就交换。走完一轮，最大的那个一定被顶到了最右边，像气泡浮上水面。

C
#include <stdio.h>

void print(int *a, int n) {
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}

int main(void) {
    int a[] = {5, 2, 9, 1, 7, 6};
    int n = 6;
    int compares = 0;

    for (int i = 0; i < n - 1; i++) {
        int swapped = 0;
        for (int j = 0; j < n - 1 - i; j++) {
            compares++;
            if (a[j] > a[j + 1]) {
                int t = a[j];
                a[j] = a[j + 1];
                a[j + 1] = t;
                swapped = 1;
            }
        }
        printf("第 %d 轮：", i + 1);
        print(a, n);
        if (!swapped) {
            printf("这一轮没交换，提前收工\n");
            break;
        }
    }
    printf("比较 %d 次，结果：", compares);
    print(a, n);
    return 0;
}
运行结果
第 1 轮：2 5 1 7 6 9
第 2 轮：2 1 5 6 7 9
第 3 轮：1 2 5 6 7 9
第 4 轮：1 2 5 6 7 9
这一轮没交换，提前收工
比较 14 次，结果：1 2 5 6 7 9

第 1 轮结束，9 到了最后一格。第 2 轮结束，7 到了倒数第二格。所以内层循环的上界是 n - 1 - i，右边的 i 个已经排好，不用再看。

swapped 那个标记是唯一的优化：某一轮一次交换都没发生，说明整个数组已经有序，后面几轮纯属浪费。加上它，最好情况（输入已经有序）变成 O(n)：跑一轮，比 n-1 次，收工。这就是表里「最好 O(n)」的来历。

不加这个标记，冒泡的最好情况也是 O(n²)，因为循环照跑不误。这一个布尔变量值多少钱？在最常见的场景「数据基本有序、只差几个位置」里，它能把几秒变成几毫秒。

冒泡的缺点是交换太多。每次只把元素往前挪一格，逆序对有多少就换多少次，最坏 O(n²) 次交换。真实代码里没人用它，它存在的意义是当教学标本。

11.3 选择：每轮挑一个最小的#

选择排序换了策略：不急着交换，先扫一遍找出最小的，再和第一个位置换一次。第二轮在剩下的里找最小，和第二个位置换。

C
#include <stdio.h>

void print(int *a, int n) {
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}

int main(void) {
    int a[] = {5, 2, 9, 1, 7, 6};
    int n = 6;
    int compares = 0;
    int swaps = 0;

    for (int i = 0; i < n - 1; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++) {
            compares++;
            if (a[j] < a[min]) {
                min = j;
            }
        }
        if (min != i) {
            int t = a[i];
            a[i] = a[min];
            a[min] = t;
            swaps++;
        }
        printf("第 %d 轮：", i + 1);
        print(a, n);
    }
    printf("比较 %d 次，交换 %d 次，结果：", compares, swaps);
    print(a, n);
    return 0;
}
运行结果
第 1 轮：1 2 9 5 7 6
第 2 轮：1 2 9 5 7 6
第 3 轮：1 2 5 9 7 6
第 4 轮：1 2 5 6 7 9
第 5 轮：1 2 5 6 7 9
比较 15 次，交换 3 次，结果：1 2 5 6 7 9

第 1 轮找到 1，和第一个位置换一次，从此下标 0 就再也不用动了。第 2 轮在剩下的里找最小值，发现 2 本来就在下标 1，于是零次交换。全程 6 个数只交换了 3 次。

注意每轮打印出来的数组并不是「前几个已经排好」这么简单，而是前缀越来越长。第 3 轮结束，前三个位置 1 2 5 都定死了，后面还乱着——这是选择排序最标准的中间状态。

选择排序有个别人没有的优点：交换次数最少，最多 n-1 次。比较次数恒为 n(n-1)/2，和输入完全无关，不管数据多乱都要比 15 次。

所以它适合「元素很大、交换很贵」的场景。比如你要排序一堆几百字节的结构体，每次交换都要拷 300 字节，那选择排序就比冒泡划算得多。

代价是不稳定。看这个例子：数组是 [5a, 5b, 1]，第一轮最小的是 1，和第一个位置交换，变成 [1, 5b, 5a]。两个 5 的相对顺序反了，而且是一次远距离交换造成的。

11.4 插入：像整理手里的扑克牌#

摸牌的过程你应该很熟：手里已经有一把排好的牌，新摸一张，从右往左比，比它大的都往右挪一格，腾出位置插进去。

C
#include <stdio.h>

void print(int *a, int n) {
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}

int main(void) {
    int a[] = {5, 2, 9, 1, 7, 6};
    int n = 6;
    int compares = 0;

    for (int i = 1; i < n; i++) {
        int key = a[i];
        int j = i - 1;
        while (j >= 0) {
            compares++;
            if (a[j] <= key) {
                break;
            }
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;
        printf("插入 %d 后：", key);
        print(a, n);
    }
    printf("比较 %d 次，结果：", compares);
    print(a, n);
    return 0;
}
运行结果
插入 2 后：2 5 9 1 7 6
插入 9 后：2 5 9 1 7 6
插入 1 后：1 2 5 9 7 6
插入 7 后：1 2 5 7 9 6
插入 6 后：1 2 5 6 7 9
比较 10 次，结果：1 2 5 6 7 9

和前两个比，同一组数据，插入只比了 10 次，冒泡 14 次，选择 15 次。原因在于它不去碰那些已经就位的元素：a[j] <= key 一成立立刻停。

看这一行：a[j + 1] = key;。循环结束时 j 指向第一个不大于 key 的位置，key 应该插在它右边一格，所以是 j + 1。这个 +1 是插入排序里最容易写错的地方，尤其是 j 变成 -1 的时候（key 比所有元素都小），a[0] = key 正好正确。

插入排序的最好情况是 O(n)：输入已经有序，每次只比一次就 break。最坏是 O(n²)：输入完全逆序，每次都要挪到底。它的常数特别小，所以在小规模数据上比快排还快，这就是为什么真实实现的快排会在区间长度小于十几的时候切换成插入排序。

它还稳定：a[j] <= key 里的等号保证了相等的元素不会互相越过。要是写成 <，相等的元素就会被挤到前面去，稳定性就没了。一个等号的事。

11.5 归并：先分两半，各自排好，再合并#

归并排序是第一个用到分治的算法，思路三句话：

  • 分：把数组从中间劈成两半
  • 治：两半各自递归排好
  • 合：把两个有序数组合并成一个有序数组

前两步是递归，第三步是真正的活。合并两个有序数组很简单：两个指针各指一个数组开头，谁小取谁，取完往后挪。

C
#include <stdio.h>

int compares = 0;

void print(int *a, int n) {
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}

void merge(int *a, int lo, int mid, int hi, int *tmp) {
    int i = lo;
    int j = mid + 1;
    int k = lo;

    while (i <= mid && j <= hi) {
        compares++;
        if (a[i] <= a[j]) {
            tmp[k] = a[i];
            i++;
        } else {
            tmp[k] = a[j];
            j++;
        }
        k++;
    }

    while (i <= mid) {
        tmp[k] = a[i];
        i++;
        k++;
    }
    while (j <= hi) {
        tmp[k] = a[j];
        j++;
        k++;
    }

    for (int t = lo; t <= hi; t++) {
        a[t] = tmp[t];
    }
}

void merge_sort(int *a, int lo, int hi, int *tmp) {
    if (lo >= hi) {
        return;
    }
    int mid = (lo + hi) / 2;
    merge_sort(a, lo, mid, tmp);
    merge_sort(a, mid + 1, hi, tmp);
    merge(a, lo, mid, hi, tmp);
}

int main(void) {
    int a[] = {5, 2, 9, 1, 7, 6};
    int n = 6;
    int tmp[6];

    merge_sort(a, 0, n - 1, tmp);
    printf("比较 %d 次，结果：", compares);
    print(a, n);
    return 0;
}
运行结果
比较 11 次，结果：1 2 5 6 7 9

11 次，跟插入的 10 次差不多，还比快排的 9 次多。这不是说归并没用，而是 6 个数的样本太小，常数项盖过了复杂度的差距。n 上去之后，O(n log n) 和 O(n²) 才会拉开数量级。

if (a[i] <= a[j]) 里的等号又是稳定性的关键。左边的元素原本就在前面，相等时优先取左边，顺序就保住了。

归并的代价是那 6 个格子的 tmp。它要求 O(n) 的额外空间，这是所有 O(n log n) 排序里最贵的一项。也是它赢下另一个战场的原因：排序链表时，归并是最舒服的选择，因为链表不需要随机访问，也不需要那份额外数组（只要改指针），快排反而因为不能随机访问而难受。

int tmp[6] 这里写死了长度。真实代码会 malloc(n * sizeof(int))，或者用全局数组避免反复分配。数组和指针的这层关系在 C 语言 数组 里讲过，暂时糊涂也没关系，记住「数组名就是首地址」就够用了。

★补充说明

归并的另一个战场在内存外面：数据大到装不进内存时，把文件切成几块分别排好写回磁盘，再做多路归并。这叫外部排序，数据库和搜索引擎的底层都在用它。

11.6 快排：随便挑一个当基准#

快排也分治，但分法不一样：它先挑一个基准值，把数组分成「比基准小」和「比基准大」两堆，基准自己落到最终位置，然后两堆各自递归。

关键在「分」这一步，叫 partition。

C
#include <stdio.h>

int compares = 0;

void print(int *a, int n) {
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}

int partition(int *a, int lo, int hi) {
    int pivot = a[hi];
    int i = lo;

    for (int j = lo; j < hi; j++) {
        compares++;
        if (a[j] < pivot) {
            int t = a[i];
            a[i] = a[j];
            a[j] = t;
            i++;
        }
    }

    int t = a[i];
    a[i] = a[hi];
    a[hi] = t;
    return i;
}

void quick_sort(int *a, int lo, int hi) {
    if (lo >= hi) {
        return;
    }
    int p = partition(a, lo, hi);
    quick_sort(a, lo, p - 1);
    quick_sort(a, p + 1, hi);
}

int main(void) {
    int a[] = {5, 2, 9, 1, 7, 6};
    int n = 6;

    quick_sort(a, 0, n - 1);
    printf("比较 %d 次，结果：", compares);
    print(a, n);
    return 0;
}
运行结果
比较 9 次，结果：1 2 5 6 7 9

partition 里 i 的含义是「小于基准的区域有多长」。j 一路扫过去，遇到比基准小的就把它换到 i 的位置，i 往前挪一格。扫完之后，i 左边的全都小于基准，右边全都大于等于基准，把基准换到 i 上，位置就定了。

快排最坏是 O(n²)。什么时候？每次挑的基准都是最大或最小，分成 1 和 n-1 两堆，递归深度变成 n。对已经排好序的数组，上面这个「取最后一个元素当基准」的实现恰好每次都中招。

这个坑很隐蔽：你的测试数据是随机的，跑得飞快；上线之后数据基本有序，直接卡死。

▲常见错误

不要用「数组首元素」或「末元素」当固定基准去处理真实数据。要么随机挑一个，要么取首、中、尾三个数的中位数。C 标准库的 qsort 用的就是混合策略（小区间用插入排序，深度超限切堆排序）。

平均情况下快排是 O(n log n)，而且常数比归并小、不用额外数组，所以它是通用排序里实战最快的。代价是不稳定：partition 的交换是远距离的，相等的元素会被拆到两边。

11.7 到底该用哪个#

把上面的东西压成一张决策清单：

  • 数据量小（几十个以内），或者数据基本有序：用插入排序，常数最小
  • 要求稳定：用归并排序，或者干脆给每个元素加一个原始下标，排序时用它做第二关键字
  • 一般情况，数据在内存里：用快排，但基准要随机化
  • 绝对不能接受最坏情况（比如实时系统）：用堆排序，O(n log n) 且原地
  • 排序链表：用归并
  • 数据装不进内存：外部归并

实际写业务代码时，这些都不用你自己写。C 的 <stdlib.h> 里有 qsort，参数是数组、元素个数、元素大小和一个比较函数。比较函数返回负数表示第一个参数排在前面，正数表示第一个参数排在后面，0 表示相等。注意 qsort 不稳定，真需要稳定就自己加序号。

到这里，排序这条线就通了。你会发现 第 8 课 堆 里的堆排序也是这个家族的一员：它的思路是「先建一个堆，然后反复取最大值」，本质上是一种选择排序，只不过用堆把「找最大值」从 O(n) 降到了 O(log n)。

✎练习
  1. 给本课的冒泡加一个计数器，统计交换次数。分别在「已经有序」「完全逆序」「随机」三种输入上跑，把比较次数和交换次数记下来，解释差距。
  2. 把插入排序改成对结构体数组排序（每个元素有姓名、分数两个字段），按分数从高到低排。同分时保持原顺序，验证它确实是稳定的。
  3. 给快排加上随机基准：swap(a[lo + rand() % (hi - lo + 1)], a[hi])，然后构造一个 5000 个元素的有序数组，比较加不加随机化时的运行时间。
  4. 用归并排序求一个数组的逆序对个数：在合并两个有序段时，如果右边的元素比左边小，说明左边剩下的所有元素都和它构成逆序对。写出完整程序。
◆小结
  • 冒泡、选择、插入是 O(n²)，归并、快排、堆排是 O(n log n)
  • 稳定 = 相等元素保持原顺序，多关键字排序全靠它
  • 插入排序常数最小，是快排在小区间里的默认替补；归并稳定但要 O(n) 空间
  • 快排原地最快但最坏 O(n²)、不稳定；选择排序交换次数最少
