第 4 课 栈

预计 35 分钟·约 5,565 字·数据结构

栈是我最喜欢讲的一个结构，因为它太简单了，简单到你第一眼看不起它。进和出两个动作，而且只准在同一头动。就这么个东西，编译器靠它处理函数调用，编辑器靠它做撤销，手机浏览器的后退键也是它。

食堂那摞餐盘是最好的类比。阿姨把洗好的盘子往上一摞，你伸手拿最上面那个，不会从底下抽——抽出来整摞就塌了。最后放上去的最先被拿走，这叫 LIFO，last in first out，后进先出。

队列正好相反，下一课讲。这一课先把栈写出来，再用它做三道真正有意思的题。

4.1 后进先出：食堂那摞餐盘#

一个数组加一个下标，就是栈的全部家当。

C
#include <stdio.h>

int main(void) {
    int stack[3];
    int top = -1;          // -1 表示空栈

    stack[++top] = 1;      // 放 1
    stack[++top] = 2;      // 放 2
    stack[++top] = 3;      // 放 3

    while (top >= 0) {
        printf("%d ", stack[top]);
        top--;
    }
    printf("\n");
    return 0;
}
运行结果
3 2 1

放进去是 1、2、3，拿出来是 3、2、1。注意 top 不是「下一个空位」，而是「栈顶元素的下标」。所以入栈先 ++top 再赋值，出栈先取值再 --top。

换一种约定也常见：让 top 指向下一个空位，初始为 0，入栈写 stack[top++] = v。两种写法都对，但看别人的代码时先搞清楚他用的是哪一种，不然差一个位置。

你可能会问，这么简单也算数据结构？算。数据结构的价值不在代码行数，而在它给操作定了规矩——只准在栈顶动。规矩越少，能做的事越少，但剩下的那几件事反而变得特别清楚。

4.2 把它封装成一个像样的栈#

4.1 的写法能跑，但没有边界检查。栈满了再放会越界写，栈空了还取会读到垃圾值。把这两件事补上，才是一个能用的栈。

C
#include <stdio.h>

#define MAX 100

typedef struct {
    int data[MAX];
    int top;               // 栈顶元素下标，空栈为 -1
} Stack;

void init(Stack *s) {
    s->top = -1;
}

int is_empty(Stack *s) {
    return s->top == -1;
}

int is_full(Stack *s) {
    return s->top == MAX - 1;
}

int push(Stack *s, int v) {
    if (is_full(s)) return 0;      // 上溢
    s->data[++s->top] = v;
    return 1;
}

int pop(Stack *s, int *out) {
    if (is_empty(s)) return 0;     // 下溢
    *out = s->data[s->top--];
    return 1;
}

int peek(Stack *s, int *out) {
    if (is_empty(s)) return 0;
    *out = s->data[s->top];
    return 1;
}

int main(void) {
    Stack s;
    init(&s);

    for (int i = 1; i <= 3; i++) push(&s, i * 10);

    int v;
    peek(&s, &v);
    printf("栈顶是 %d\n", v);

    while (pop(&s, &v)) {
        printf("弹出 %d\n", v);
    }
    printf("再弹一次：%s\n", pop(&s, &v) ? "成功" : "失败，栈空了");
    return 0;
}
运行结果
栈顶是 30
弹出 30
弹出 20
弹出 10
再弹一次：失败，栈空了

几个设计选择值得说：

  • push、pop 返回 int 表示成功失败，而不是直接返回元素。这样「弹出一个 0」和「栈空了弹不出来」就能区分开。如果让 pop 直接返回 int，这两种情况都是 0，调用方没法判断。
  • peek 只看不动，用来实现「撤销前先看看上一步是什么」这类逻辑。
  • 栈的大小 MAX 是写死的。真实场景里要么动态扩容，要么改成链表栈。对初学者来说，先想清楚「最多可能压多少」，再定这个数。

top 用 int 存下标，注意 is_full 的条件是 MAX - 1，别写成 MAX。差这一个，就是越界写入。

不管栈里已经压了多少个，push 和 pop 都只动栈顶那一个位置，所以都是 O(1)。这是栈最值钱的地方：操作代价和数据量无关。

4.3 括号匹配：栈的第一个正经用途#

给你一行括号，判断是否配对。()[]{} 可以，([)] 不行。人眼是扫一遍凭感觉，程序得有个明确的规则。

规则其实很简单：每遇到一个右括号，它必须和最近一个还没关上的左括号配对。最近的那个，正好是栈顶。

C
#include <stdio.h>

#define MAX 200

int main(void) {
    char line[MAX];
    char stack[MAX];
    int top = -1;

    printf("输入一行括号: ");
    if (fgets(line, sizeof(line), stdin) == NULL) return 1;

    for (int i = 0; line[i] != '\0' && line[i] != '\n'; i++) {
        char c = line[i];

        if (c == '(' || c == '[' || c == '{') {
            stack[++top] = c;              // 左括号入栈
        } else if (c == ')' || c == ']' || c == '}') {
            char need = (c == ')') ? '(' : (c == ']') ? '[' : '{';
            if (top < 0 || stack[top] != need) {
                printf("第 %d 个字符 %c 不匹配\n", i + 1, c);
                return 0;
            }
            top--;                          // 配对成功，弹出
        }
    }

    if (top == -1) printf("括号全部匹配\n");
    else printf("还有 %d 个左括号没关上\n", top + 1);
    return 0;
}
运行结果
输入一行括号: {[()]}
括号全部匹配

把输入换成 ([)]，程序会在第 3 个字符 ) 那里停下：栈顶是 [，来的却是 )，不配对。人眼也觉得别扭，但说不清哪里别扭，栈替你把它说清楚了。

Python 里用列表当栈，append 是入栈，pop() 是出栈，逻辑一模一样。

Python
# Python 版
def check(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for i, ch in enumerate(s):
        if ch in "([{":
            stack.append(ch)
        elif ch in ")]}":
            if not stack or stack[-1] != pairs[ch]:
                return "第 %d 个字符 %s 不匹配" % (i + 1, ch)
            stack.pop()
    if stack:
        return "还有 %d 个左括号没关上" % len(stack)
    return "括号全部匹配"

print(check("{[()]}"))
print(check("([)]"))
运行结果
括号全部匹配
第 3 个字符 ) 不匹配

扫一遍字符串，每个字符最多入栈一次、出栈一次，时间是 O(n)，额外空间最坏也是 O(n)。别看它简单，这已经是这类问题的最优复杂度了——你至少得把输入看一遍。

▲常见错误

只在最后判断「栈空不空」是不够的。([)] 扫完栈也是空的，但它是错的。每次遇到右括号都必须当场和栈顶比对，错了立刻报。漏掉这一步，你的程序会把所有「数量对得上」的括号串都判成合法。

4.4 后缀表达式：栈当草稿纸#

平时写 3 + 4 叫中缀表达式，运算符在中间。后缀表达式把运算符放后面：3 4 +。看起来怪，但它不需要括号，计算机读起来特别顺。

规则：遇到数字就压栈；遇到运算符就弹出两个数，算完再压回去。

C
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    int stack[100];
    int top = -1;
    char token[32];

    printf("输入后缀表达式(以 = 结束): ");
    while (scanf("%31s", token) == 1 && strcmp(token, "=") != 0) {
        if (token[0] >= '0' && token[0] <= '9') {
            stack[++top] = atoi(token);
        } else {
            int b = stack[top--];
            int a = stack[top--];
            int r = 0;

            switch (token[0]) {
                case '+': r = a + b; break;
                case '-': r = a - b; break;
                case '*': r = a * b; break;
                case '/': r = a / b; break;
            }
            stack[++top] = r;
        }
    }
    printf("结果 = %d\n", stack[top]);
    return 0;
}
运行结果
输入后缀表达式(以 = 结束): 3 4 + 5 * =
结果 = 35

先算 3 4 + 得 7，压回去；再读 5，压栈；最后 *，弹出 5 和 7，得 35。

有个顺序坑：先弹出的是右操作数 b，后弹出的才是左操作数 a。加法和乘法无所谓，减法和除法就要命了。把输入换成 3 4 - 5 *，正确结果是 -5；如果你写成 b - a，会得到 5。

★补充说明

后缀表达式不是考试里的玩具。很多编译器和计算器内部就是先把中缀转成后缀再求值，转换过程也要用栈，还要处理运算符优先级。你以后学编译原理，这会是第一章的内容。

4.5 函数调用栈：递归为什么能一层层回来#

你写递归的时候，有没有想过：fact(5) 调用 fact(4)，fact(4) 又调用 fact(3)，等最里面返回了，外面的函数怎么知道该接着干什么？

答案是系统替你维护了一个栈。每进一层函数，就往栈上压一个「栈帧」，里面存着这一层的参数、局部变量和返回地址。函数返回时弹出一层，回到调用它的地方。递归本身的写法在 C 语言 函数与递归 里讲过，这一节看的是它底下发生了什么。

C
#include <stdio.h>

void indent(int depth) {
    for (int i = 0; i < depth; i++) printf("  ");
}

long long fact(int n, int depth) {
    indent(depth);
    printf("进入 fact(%d)\n", n);

    if (n <= 1) {
        indent(depth);
        printf("返回 1\n");
        return 1;
    }

    long long r = n * fact(n - 1, depth + 1);

    indent(depth);
    printf("返回 %lld\n", r);
    return r;
}

int main(void) {
    printf("5! = %lld\n", fact(5, 0));
    return 0;
}
运行结果
进入 fact(5)
  进入 fact(4)
    进入 fact(3)
      进入 fact(2)
        进入 fact(1)
        返回 1
      返回 2
    返回 6
  返回 24
返回 120
5! = 120

看输出的缩进，就是栈的样子：一层层压进去，到 fact(1) 触底，再一层层弹回来。每层算 n * 下一层的结果，谁也没丢。

这也解释了递归的两个毛病。第一，层数太深会把栈撑爆。系统给程序的栈一般只有几 MB，每层栈帧几十字节，递归十万层就可能段错误。第二，递归有额外的压栈、弹栈开销，同样的活，循环通常更快。

4.6 栈不是万能的：什么时候该用它#

栈的脾气很直：你只能碰最上面那个。所以只要问题满足「最近发生的先处理」，栈就是对的工具。

场景栈里存什么为什么是栈
括号匹配还没关上的左括号最近打开的，必须最先关上
后缀表达式还没参与运算的数运算符作用在最近两个数上
函数调用每层的参数和返回地址后调用的先返回
撤销操作每一步的反向操作最后一步最先撤销
浏览器后退访问过的页面最后访问的最先退回

反过来，如果问题需要「最早来的先处理」——食堂排队、打印机任务、BFS 找最短路——那就该用队列，下一课讲。

最后一个提醒：栈溢出不是理论问题。递归忘了写终止条件，或者在递归函数里开一个很大的局部数组，程序不会给你友好的报错，只会直接 Segmentation fault。看到段错误又找不到数组越界，先数数递归深度。

动手试一次：把 4.2 的 MAX 改成 3，压四个元素，看第四个是不是被拒绝；再把 pop 里的判空去掉，空栈弹一次，观察输出。边界检查不是装饰，少了它，空栈弹出会直接读到栈外面的内存，值是多少全看运气。

✎练习
  1. 用栈实现进制转换：读入一个十进制数和一个进制（2 到 16），输出转换结果。提示：不断取余压栈，最后依次弹出。
  2. 扩展 4.3 的括号匹配：除了判断是否合法，还要输出最大嵌套深度，比如 {[()]} 的深度是 3。
  3. 写一个中缀转后缀的程序，只支持 + - * / 和括号，操作数是一位数字。用 3+4*5 测，应该输出 3 4 5 * +。
  4. 用两个栈实现一个队列：数据只压进 A 栈；出队时如果 B 栈为空，就把 A 全部倒进 B，再从 B 弹。想清楚为什么每个元素最多被搬两次。
◆小结
  • 栈只允许在一头进出，后进先出
  • 数组实现 = 一个数组 + 一个 top，空栈时 top 为 -1
  • push 前查满，pop 前查空，上溢和下溢都算 bug
  • 括号匹配、后缀表达式、函数调用底层都是栈；递归就是系统替你维护的调用栈，层数太深会爆
