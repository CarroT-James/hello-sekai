第 2 课 线性表与动态数组

预计 35 分钟·约 5,904 字·数据结构

动态数组大概是你在 C 里第一个「原来还能这样」的东西。它要解决的是一个特别具体的麻烦：写程序的时候，你根本不知道要存多少个。

我大一写成绩统计，数组开了 100，老师转手发来 300 个学生的数据。改成 10000 吧，一个班又只有 80 人，剩下 9920 个位置纯属占着。后来我学乖了，直接开 100 万，作业交上去内存超限。你看，拍脑袋定一个「够大」的数字，从来都不靠谱。

这一课就把「数组」升级成「能自己长大」的版本，顺便把它的代价算清楚。

2.1 连续的一块内存，下标就是偏移量#

C 的数组在内存里是连续排的。连续这两个字，是它一切优点的来源。C 语言 数组 那章讲过基本用法，这里往内存里看一眼。

C
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};

    for (int i = 0; i < 5; i++) {
        int offset = (int)((char *)&a[i] - (char *)a);
        printf("a[%d] = %2d，相对 a 的偏移 %d 字节\n", i, a[i], offset);
    }
    printf("sizeof(int) = %d\n", (int)sizeof(int));
    return 0;
}
运行结果
a[0] = 10，相对 a 的偏移 0 字节
a[1] = 20，相对 a 的偏移 4 字节
a[2] = 30，相对 a 的偏移 8 字节
a[3] = 40，相对 a 的偏移 12 字节
a[4] = 50，相对 a 的偏移 16 字节
sizeof(int) = 4

a[i] 的本质就是 *(a + i)：先找到数组开头，再往后跳 i * sizeof(int) 个字节，然后取出那 4 个字节。跳多远是算出来的，不是数出来的，所以按下标取元素是 O(1)。

拿快递柜类比最贴切。一整排柜子编号连续，你知道 37 号，直接走过去开，不用从 1 号开始数。要是柜子分散在小区各个角落，你就只能拿张地图挨个找——那是链表，下一课讲。

连续还有个隐藏好处：CPU 读内存时会顺手把相邻的几十个字节一起拉进缓存。你顺序遍历数组，大部分数据已经在缓存里了，所以特别快。这个特性在数据量大时会拉开几倍的差距，后面讲链表还要回来说它。

▲常见错误

a[5] 越界不一定会立刻崩。它只是读到了数组后面那块内存，可能是一个无关变量，也可能是别的程序的残留。于是你的程序有时输出 0，有时输出一个天文数字，换个编译器又正常了。C 不会替你检查边界，这件事只能自己盯。

2.2 从定长数组到动态数组#

定长数组有两个绕不过去的麻烦：开小了装不下，开大了浪费。更麻烦的是，int a[1000000] 这种大数组写在函数里是放在栈上的。栈一般只有几 MB（Windows 默认 1MB，Linux 常见 8MB），100 万个 int 就是 4MB，在 Windows 上直接段错误。

解决办法是：数据放堆上，长度和容量分开记。

C
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *data;      // 指向堆上的那块内存
    int size;       // 已经存了几个
    int capacity;   // 这块内存最多能存几个
} SeqList;

int init(SeqList *list, int cap) {
    list->data = malloc((size_t)cap * sizeof(int));
    if (list->data == NULL) return 0;
    list->size = 0;
    list->capacity = cap;
    return 1;
}

int push_back(SeqList *list, int value) {
    if (list->size == list->capacity) {
        int new_cap = list->capacity * 2;
        int *p = realloc(list->data, (size_t)new_cap * sizeof(int));
        if (p == NULL) return 0;

        printf("  扩容：%d -> %d\n", list->capacity, new_cap);
        list->data = p;
        list->capacity = new_cap;
    }
    list->data[list->size] = value;
    list->size++;
    return 1;
}

void destroy(SeqList *list) {
    free(list->data);
    list->data = NULL;
    list->size = 0;
    list->capacity = 0;
}

int main(void) {
    SeqList list;
    if (!init(&list, 2)) return 1;

    for (int i = 1; i <= 10; i++) {
        printf("push %d\n", i);
        if (!push_back(&list, i * i)) {
            printf("内存不够，停在第 %d 个\n", i);
            break;
        }
    }

    printf("size = %d, capacity = %d\n", list.size, list.capacity);
    for (int i = 0; i < list.size; i++) printf("%d ", list.data[i]);
    printf("\n");

    destroy(&list);
    return 0;
}
运行结果
push 1
push 2
push 3
  扩容：2 -> 4
push 4
push 5
  扩容：4 -> 8
push 6
push 7
push 8
push 9
  扩容：8 -> 16
push 10
size = 10, capacity = 16
1 4 9 16 25 36 49 64 81 100

三个成员各管一件事，别混：

  • data 指向堆上那块内存，它随时可能被 realloc 换掉
  • size 是「现在用了几个」，用户看到的长度
  • capacity 是「申请了几个」，只有扩容逻辑关心

realloc 的行为要留意：如果后面还有空位，它原地扩；如果后面被别人占了，它会另找一块地方，把旧数据复制过去。所以扩容之后，指向旧内存的指针全部失效。这也是为什么 push_back 里先接住返回值 p，确认成功了再改 list->data。

▲常见错误

写成 list->data = realloc(list->data, ...) 很常见，但申请失败时 realloc 返回 NULL，原来的指针就被覆盖了，那块内存再也 free 不掉。正确写法是先存到临时变量，判断非空再赋值。多打两行，省一次内存泄漏。

2.3 为什么是乘 2，不是加 1#

扩容一次，得把旧数据全搬过去。既然都要搬，那每次扩多少就有讲究了。

C
#include <stdio.h>

long long count_moves(int n, int doubling, long long *final_cap) {
    long long cap = 1;
    long long moves = 0;

    for (int i = 0; i < n; i++) {
        if (i == cap) {                 // 放第 i+1 个时满了
            moves += cap;               // 把旧数据搬过去
            cap = doubling ? cap * 2 : cap + 1;
        }
    }
    *final_cap = cap;
    return moves;
}

int main(void) {
    int n = 1000000;
    long long cap1, cap2;

    long long m1 = count_moves(n, 0, &cap1);
    long long m2 = count_moves(n, 1, &cap2);

    printf("每次加 1：搬 %lld 次，最终容量 %lld\n", m1, cap1);
    printf("每次乘 2：搬 %lld 次，最终容量 %lld\n", m2, cap2);
    return 0;
}
运行结果
每次加 1：搬 499999500000 次，最终容量 1000000
每次乘 2：搬 1048575 次，最终容量 1048576

差距是将近 50 万倍。为什么？

「每次加 1」的策略下，容量是 1、2、3、4……，你在第 k 次扩容时搬 k 个元素。1 加到 100 万，就是 n²/2 这个量级。装 100 万个元素，做了 5000 亿次拷贝。

「每次乘 2」的策略下，容量是 1、2、4、8、16……，每次搬迁量翻倍，总搬迁量是等比数列求和：1 + 2 + 4 + … + 524288，总共 1048575 次，和元素个数差不多是同一个量级。装 100 万个元素，只搬了 105 万次。

算到这儿，答案就出来了：扩容按倍数长，总搬迁量是 O(n)；按固定长度长，总搬迁量是 O(n²)。前者摊到每次 push_back 上，平均不到 2 次拷贝，所以叫均摊 O(1)。这是第 1 课那个「复杂度看趋势」的直接应用。

2.4 插入和删除：O(n) 的搬家#

扩容只发生在尾部，代价还能摊薄。要是在中间插一个、删一个，就没这么便宜了。

C
#include <stdio.h>

int insert_at(int a[], int *n, int pos, int value) {
    if (pos < 0 || pos > *n) return 0;
    for (int i = *n; i > pos; i--) {
        a[i] = a[i - 1];
    }
    a[pos] = value;
    (*n)++;
    return 1;
}

int erase_at(int a[], int *n, int pos) {
    if (pos < 0 || pos >= *n) return 0;
    for (int i = pos; i < *n - 1; i++) {
        a[i] = a[i + 1];
    }
    (*n)--;
    return 1;
}

void print(int a[], int n) {
    for (int i = 0; i < n; i++) printf("%d ", a[i]);
    printf("\n");
}

int main(void) {
    int a[10] = {10, 20, 30, 40, 50};
    int n = 5;

    insert_at(a, &n, 2, 25);
    print(a, n);

    erase_at(a, &n, 0);
    print(a, n);
    return 0;
}
运行结果
10 20 25 30 40 50
20 25 30 40 50

在位置 2 插入 25，位置 2 及其后面的元素全部后移一格；删掉第一个元素，后面 5 个全部前移一格。最坏情况是在头部插删，要移动 n 个元素，所以是 O(n)。

这就像寝室的值日表。你在周三加一个人值日，后面所有人的日期都得往后挪一格；挪一格不累，挪一百格就烦了。数组的强项是「按下标直达」，弱项就是这种「中间动一下，后面全体搬家」。

搬的方向也有讲究。插入必须从后往前搬：先把最后一个元素挪到空位上，再挪倒数第二个。要是从前往后搬，第一个赋值就把还没搬走的数据覆盖了，最后你会得到一排一模一样的值。删除反过来，得从前往后搬。方向搞反，是手写顺序表最常见的错，而且错得很安静，程序不崩，结果不对。

★补充说明

insert_at 这里没有检查数组容量，因为示例里的 a 有 10 个位置、只用了 5 个。真实实现里，插入前必须先确认 size < capacity，否则就要先扩容。少这一句检查，就是越界写入。

2.5 均摊复杂度：把一次贵摊到很多次便宜上#

均摊 O(1) 这个说法容易被误解成「每次都是 O(1)」。不是。

push_back 平时确实是一次赋值，O(1)。但碰到扩容那一次，它要把 524288 个元素全搬走，那一次是实打实的 O(n)。只不过这种「贵」发生的间隔越来越长：第 1 次隔 1 个，第 2 次隔 2 个，第 10 次隔 512 个。把总代价摊到 n 次操作上，平均每次是个常数。

用值日表打比方：每周一次大扫除，一次两小时，很累；但摊到七天，每天不到二十分钟。均摊说的是这个平均值，不是「每天都很轻松」。

想自己验证一遍，拿张纸算：容量依次是 1、2、4、8……，第 k 次扩容搬 2^(k-1) 个，把前 10 次加起来，再和 1000 比一比。你会发现总搬迁量始终小于 2n。

这也意味着一个实际问题：某一次 push_back 可能突然卡一下。做实时系统、写游戏渲染循环的人会在启动时先预留足够容量，避免中途扩容。你自己写题时如果知道大概要存 10 万个，可以先 init(&list, 100000)，省掉十几次搬迁。

2.6 什么时候不该用它#

动态数组不是万能的。下面几种情况，它就不合适：

  • 频繁在中间插入删除。每次 O(n)，十万次操作就是 O(n²)，再快的机器也顶不住。这种活交给第 3 课 链表。
  • 需要元素地址稳定。扩容会把数据搬到新地址，你之前存下的指针全成了野指针。链表没有这个问题。
  • 元素本身很大（比如每个几百字节的结构体）。搬家时拷贝成本高，可以只存指针，或者干脆换一种结构。

Python 的 list 就是动态数组，只是扩容被藏起来了。

Python
# Python 版
scores = []
for i in range(10):
    scores.append(i * i)
print(scores)

scores.insert(0, -1)   # 头部插入，后面所有元素都要后移
print(scores)
运行结果
[0, 1, 4, 9, 16, 25, 36, 49, 64, 81]
[-1, 0, 1, 4, 9, 16, 25, 36, 49, 64, 81]

append 均摊 O(1)，insert(0, x) 是 O(n)，和 C 里一模一样。Python 让你少写代码，但没帮你消掉底层那次搬家——用错地方，一样卡。

✎练习
  1. 给 SeqList 加一个 pop_back，返回被删掉的元素；再写一个 clear。要求 size 为 0 时 pop_back 安全返回，不能崩。
  2. 把扩容策略改成「每次容量加 100」，统计装 100 万个元素总共搬了多少次，和乘 2 的策略对比。先估算再跑。
  3. 写一个带扩容的 insert_at：插入前若 size == capacity 先扩容。然后往一个 100 万元素的表头部连续插 1000 次，记录耗时，解释为什么慢。
  4. 给 SeqList 写一个 shrink_to_fit：当 size 小于 capacity / 4 时，把容量减半。想清楚为什么不能每删一个元素就缩容（提示：算一下均摊代价会变成多少）。
◆小结
  • 顺序表 = 一块连续内存 + 长度 size + 容量 capacity
  • 下标访问 O(1)，靠的是「基地址 + i × 元素大小」
  • 尾部追加均摊 O(1)，中间插入删除 O(n)
  • 扩容要按倍数长，按固定长度长会退化成 O(n²)；realloc 可能搬家，扩容后旧指针全部失效
